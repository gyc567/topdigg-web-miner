# novel-outline

给它一本小说加上目标参数，就能得到一套五件套短剧改编大纲：

- **改编说明** —— 一句话核心、保留/删除/合并表格、风险预案与决策结论（`cutNote` 的“这意味着……”/ `mergeNote` 的主角名单理由），关键决策都配有**来自原文的逐字引用**做支撑
- **演员表** —— 按资产体量分层：主角 ≤ 5，有名配角 ≤ 10，功能性角色 ≤ 10（只有一张脸，没有名字 —— 按功能标注），每人带一条 **← 变更记录**（对应书中谁、合并进了谁）
- **情节点表** —— 大/小情节点钉到具体集数，间隔 ≤ 3 集，没有空白区
- **分集梗概** —— 每集三个必填字段：梗概 + 钩子 + 悬念；只用叙述性文字，带引号的台词不算在内
- **资产清单** —— **由脚本计算，绝不由模型手写**：场景/角色使用情况、一次性场景的复用方案、制作风险预警

产出 `outline.json`、一份 Markdown 报告，以及一份自包含的 `outline-report.html`：

![outline-report.html](https://github.com/eternityspring/shuohao-skills/blob/main/skills/novel-outline/assets/report.webp)

## 质量门就是代码

这个技能的核心立场：**一份让模型给自己打分的检查清单毫无价值。** 全部 14 道门都是 `validate` 中的确定性检查，而不是给模型读的散文 —— 各层演员人数上限（主角 1–5，配角 ≤ 10，功能性角色 ≤ 10）、叙事道具上限（≤ 8；`props` 是可选的，门禁在缺失时会明确说明）、随**集数增长而伸缩**的主场景上限（4 + ⌈episodes/10⌉，钳制在 5–15 之间 —— 这是为 AI 制作调校的，因为场景是生成的，这个上限守护的是一致性资产，而不是搭建场景的预算）、一次性场景的复用方案、情节点间隔、第 1 集钩子、大情节点落点、每集三字段、人群场景方案、风险关键词标记、引用完整性（没有无归属的角色、没有未使用的场景、没有未使用的道具、没有悬空 ID），以及梗概中不得出现带引号的台词。

为什么分层而不是用单一上限：单一上限把*观众必须记住的人*和*制作必须维持的一致性面孔数量*混为一谈。主角上限守护的是出镜时长和记忆度；配角/功能性角色上限守护的是**AI 角色资产成本** —— 而资产清单会自动把层级换算成工作量（主角 → 完整模型设定表，配角 → 半身参考图，功能性角色 → 仅提示词）。无名群演完全不上表。功能性角色本来就不需要人物弧光 —— 医生在那里只是为了缝合伤口。

阈值是参数（`params.thresholds`），不是常量 —— 不同平台需要不同的情节点节奏。自测**故意逐个击破每一道门**，以证明每一道都确实会拦截。

## 流程中最有价值的规则

骨架（删哪些行 / 合并哪些角色 / 情节点放在哪）先以**快速草稿形式交付以便签字确认** —— 哪些行被砍、谁被合并、哪一集承载大高潮。只有用户点头之后才开始写分集剧本，而且这是以阶段门禁（`validate --stage beats`）强制执行的，不是一句承诺。之后分集按每批 ≤ 10 集的节奏写；一口气写 60 集，后半段一定会崩。

## 报告

报告默认使用中文界面渲染；传入 `--lang en` 可获得全英文报告（或在 `outline.json` 中设置顶层 `lang` 字段 —— 命令行参数优先）。界面和质量门标签会翻译；数据内容 —— 情节点类型、梗概、姓名 —— 保持原样，失败门禁的详情字符串也同样保持原样。在英文模式下，质量门标签也会被翻译（阈值保持计算结果）；失败门禁详情和所有数据都保持原样。

```bash
node scripts/novel-outline.mjs render outline.json --html --lang en > outline-report.html
```

一份单页、宽 1600px 的审阅文档 —— 所有内容平铺展开，可用 Cmd+F 检索：

- **KPI 条带**：集数、情节点、分层演员表、主场景、制作风险、改编模式 —— 开头六个统计方块
- **情节点节奏**：图表/表格两个标签页 —— 默认是故事时间线（大情节点填充、小情节点更淡，**空白间隔直接标注在坐标轴上**，超过阈值的部分呈铁锈红，每 20 集换行），一键进入详情表格
- **分集卡片** 三列排布，默认显示前三张并带淡出效果和展开按钮；每张卡片带情节点胶囊、钩子/悬念字段，以及场景/演员/风险标签
- **场景总览**：每个场景一张卡片 —— 右上角有淡化的集号、存在状态条、承载的情节点、出场演员或复用方案
- **关键决策**：纸面上的三项待签确认事项 —— 哪些行被删除（附“这意味着……”的结论），谁被合并（演员槽位数量和主角名单是**计算得出**的），以及大情节点落在何处（从情节点表自动列出，并标注首尾）
- **调度矩阵**：角色和场景在同一张网格上 —— 竖着读一列，就是那一集的要求
- **资产换算**：把演员层级、场景环境和制作风险换算成前期工作量 —— 全部为计算所得
- **质量门**：表头徽章、任何一项失败时的失败横幅，以及末尾完整的 ✓/✗ 列表 —— 由脚本内置生成
- **Export JSON** 原样下载 `outline.json` —— 编辑后可直接喂回 `render` / `validate`
- **内置中英文界面** —— 默认中文，`--lang en` 切换英文
- 所有图形均为内联 SVG/CSS，调色板经过校验器检查；零外部资源，可离线打开

## 体检模式

已经有了一份大纲，只想要一份诊断？

```bash
node scripts/novel-outline.mjs checkup outline.json
node scripts/novel-outline.mjs render outline.json --html > outline-report.html
```

失败的门禁不会阻止渲染 —— 展示问题本身才是目的。

## 长文本

一本 80 万字符的小说装不进上下文。`chunk` 会按章节标题切成若干卷（默认每卷 15 章），各卷并行摘要，然后合并。最多 60 卷，超出会明确报告 `truncated` —— 它绝不会悄悄丢掉尾部内容。关键决策必须指回原文（`keep[].evidence`，逐字引用）—— **绝不允许仅凭标题编造内容**。

## 与 novel-characters 的关系

novel-outline 负责改编结构（删减、合并、情节点排布、分集）；novel-characters 负责角色设计（人物档案、图像/语音提示词、模型设定表）。

**大纲位于角色圣经的上游**：`characters` 区块已经确定了谁进谁出、谁是主角，因此角色那一遍可以直接基于这份名单工作，而不必重新决策。反过来同样可行 —— 如果你已经有 `cast.json`，可以把它作为角色原始素材喂进去，而不必重读原文。本技能不写台词、不写分镜、不写生成提示词。
