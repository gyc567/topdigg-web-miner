# 依赖与许可

## 测试执行

- 在本地运行测试、浏览器检查、一致性检查、许可检查与构建。


- 不得引入 AGPL 许可的代码或依赖（无论是直接依赖、传递依赖、随包分发，还是远程加载）。
- 不得引入专有的第三方文档引擎，包括在测试或工具中。
- 每一个随包分发的二进制文件都必须有可获得的对应源码以及可接受的许可证。为随包分发的资产记录来源说明。
- 依赖发生变化后运行 `npm run check:licenses`。不要为了让检查通过而扩大许可证允许清单；应先审查实际的许可证。
- `src/engine` 中的新引擎是原创代码。不要把其他引擎的实现翻译或复制到其中。

# Canvas 里程碑

- 将文档变更、DOCX 序列化、排版与绘制相互分离。
- 保留未改动的 DOCX 包部件。以尽力而为的方式打开含不支持特性的文档。当无法安全编辑时使用只读近似，并且不要挂载可能丢弃不支持内容的保存处理器。
- 为新的引擎行为补充有意义的往返测试与编辑回归测试。运行单元测试、浏览器测试以及生产构建。
- `playground.html` 可在没有 Puter 账号的情况下本地运行。保持它可用，作为引擎的小型评估界面。
- 较早由应用自行编写的导入/导出辅助工具仍可用于未来的移植；它们的存在并不意味着 canvas engine 支持这些特性。

# 规范与一致性

- 对每一项编辑器特性，在 `docs/conformance.md` 中记录相关的 ECMA-376/OOXML 条款与所支持的子集。
- 添加行为测试以及独立生成的 DOCX 固定样本，并用 `npm run check:conformance` 校验浏览器导出结果。
- 在宣布某项特性完成之前，先修正规范评审发现的问题。明确记录遗留差距；schema 层面的通过并不等于完整的 OOXML 一致性或排版保真度。
- 把下载的标准 schema 放在临时测试缓存中。不要打包其他编辑器的源码或专有校验器。
