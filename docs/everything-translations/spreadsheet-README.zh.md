# Spreadsheet（电子表格）

Microsoft Excel 的开源替代品：一个快速、私密的电子表格应用，使用原生
JavaScript（无框架）、Vite 构建，并以 [Puter.js](https://developer.puter.com) 作为唯一后端。文件
是你自己 Puter 云端上的真实 `.xlsx` 文档，因此能在 Excel、Numbers 或 LibreOffice 中打开，
而不会存放在别人的服务器上。

无人必须登录才能使用：应用直接打开一张新的表格，只有在需要云端的第一个动作
（如保存、打开文件或表格列表 `#/home`，位于返回箭头之后）时，Puter 才会要求登录。在此之前，
编辑内容保留在标签页中（以及本浏览器的本地草稿中），状态标签显示"登录以保存"。

## 应用标识

`icon.png` 是界面标志与浏览器/安装图标的源文件。主品牌色为森林绿（`#356d49`），
取自图标本身，深色模式下使用更浅的绿色点缀。安装元数据位于 `public/manifest.json`。

替换源图标后，运行 `npm run icons`（需要 ImageMagick）以重新生成 PNG/ICO favicon、
Apple touch icon 以及标准/可遮罩（maskable）的安装图标。

  `IPMT`、`CUMIPMT`、`CUMPRINC`、`FV`、`PV`、`NPER`、`RATE`、`NPV`、`IRR`、

  相同的提示词只问一次，按 F9 会再问一次）、
  `TRANSLATE(text, [from], [to])`（或 `GOOGLETRANSLATE`）与
  `DETECTLANGUAGE(text)` 走同一个 AI、
  `IMPORTRANGE("Budget", "Sheet1!A1:B10")` 把另一张电子表格中
  位于你 Puter 云盘上的单元格溢出到指定位置（文件加载期间显示 `#BUSY!`）、
  `IMPORTDATA(url)` 取自 Web 的 CSV 或 TSV、`IMPORTHTML(url, "table",
  2)` 取自网页的表格或列表，以及 `IMPORTXML(url, "//item/title")`
  按 XPath 选出的节点，都溢出到指定位置（经由 Puter 的 fetch，因此多数地址都可用）、
  `QUERY(range, "select A, sum(C) where B > 5 group by A order by sum(C)
  desc limit 10 label sum(C) 'Total'")` 使用 Sheets 查询语言（select、
  带 and/or/not 的 where、contains、starts with、like、matches、is null、带
  sum/avg/count/max/min 的 group by、order by、limit、offset、label，以及
  year/month/day/upper/lower/len）、
  导入的 Excel 相对定义名称（包括上一行与上一列的
  偏移量）会在每个调用单元格处重算，并在导出时保留其原生定义、跨工作表引用（`Budget!B4`、
  `'Q1 Data'!A1:A9`）、跨一系列工作表的 3D 引用
  （`=SUM(Jan:Dec!B5)` 把 Jan 到 Dec 每个工作表的 B5 相加，包含隐藏的，
  并跟随重命名的工作表与插入的行）、整列与整行区域、命名区域、百分比
  字面量、悬停与状态栏中以通俗语言解释的电子表格错误值（`#NAME?` 会指出拼错的函数或
  未知名称，并建议最接近的真实函数——"没有名为 SUMM 的函数。你是想用 SUM 吗？"——
  而 `#REF!` 会指出缺失的工作表）、
  以及循环检测。显式启用迭代计算的
  工作簿会按其迭代上限与收敛容差重算循环公式；这些设置与计算结果在 XLSX 导出与
  草稿恢复中都会保留。`NOW()` 与 `TODAY()` 保持实时。
- **动态数组**：`UNIQUE`、`FILTER`、`SORT`、`SORTBY`、`SEQUENCE`、`RANDARRAY`、
  `TRANSPOSE`、`FLATTEN`、`SPLIT`、`TEXTSPLIT`、`CHOOSECOLS`、`VSTACK`、

- **超链接**：`HYPERLINK(url, label)` 单元格与键入的网址或电子邮件
  地址都可点击（Ctrl/Cmd+click 可打开，弹出浮层显示其去向）。Ctrl/Cmd+K 可插入或编辑指向网页地址、
  某个工作表与区域，或指向某个命名区域（`#Sheet!A1`，即 Excel 使用的形式）的链接；
  占位链接可跳转到那里；移除链接（在单元格菜单或链接对话框中）会让文字恢复为纯文本，
  键入的地址也一样。链接可通过 `.xlsx` 往返。复制此单元格

  打开该文件时会选中这些单元格，位于相应工作表上，便于粘贴到
  聊天或文档中。
- **AI 助手**：工作表旁的一个聊天面板，默认打开（"询问 AI"
  按钮、查看 → AI 助手，或 Ctrl/Cmd+J 可开关；关闭后，下次访问仍保持关闭），Puter 的 AI（Claude Opus 5.5）在此回答关于工作簿
  的问题并修改它：它读取单元格，通过
  公式引擎而非猜测来算出数值，并能写入数值与公式、填充一列、
  设置格式、排序、插入与删除行列、添加图表、表格、
  条件格式、下拉列表、备注与工作表、冻结窗格与调整列宽。每次工具调用都会在回复中显示为一步，
  并链接到它所触及的单元格；回复中的单元格引用可选中相应单元格。替换或删除数据的变更
  会等待你的允许（或按面板菜单所选的"全部变更"或"都不允许"）；每项变更都是一个撤销步骤，
  而修改过工作簿的回复会以"撤销全部变更"结尾（仅在此期间无人编辑过的情况下）。
  每条消息都会附带工作表与所选单元格的简短摘要，摘要中会列出相应名称；
  单元格内容被视为数据，绝不视为指令，它写入的抓取网页的公式
  需要该文件的允许，回复中的图片永远不会被加载。在手机上，该面板是覆盖在网格之上的一张工作表。
- **自动化（脚本）**：一个 Automate 功能区选项卡，用于 JavaScript 脚本，其
  `async function main(workbook)` 通过一套有文档的对象模型操作工作簿
  （工作表、区域、值与公式、填充、
  字体、对齐、边框、尺寸、插入与删除、排序、填充、合并、
  隐藏、备注、链接、表格与图表；"脚本参考"完整列出这些内容）。

  `FIXED` 与 `DOLLAR`，以及 `VALUE` 或 `">1.500"` 这类条件所读作数字的文本，全都遵循它；
  公式中的小数仍使用句点。货币与会计格式会为没有自身货币的单元格采用
  区域格式的货币（英式英语为英镑，德语为欧元，日语为日元），数字格式菜单的
  示例与"设置单元格格式"的日期样式会以工作表显示的方式展示每个格式，而以任意区域格式书写出来的金额
  （`US$1,234.50`、`1 234,50 kr`、`1.234,50 €`、
  `USD 1,234.50`）在键入、粘贴或导入时会被读作该货币。
  货币单元格导出与复制时，会把标签放在区域格式所放的那一侧数字旁
  （德语下为 `#,##0.00 €`，英语（美国）下为 `"$"#,##0.00`），
  完整书写的或长日期会带上该格式自身的顺序与
  语言标记（英语（英国）下为 `[$-809]d mmm yyyy`），因此工作表在 Excel 中打开时
  与在这里读起来一致。
  结果以区域格式书写的公式（`TEXT`、`DOLLAR`、
  `FIXED`）会在该格式变化时重新计算，就像按 F9 重新计算它们一样。
- **设计**：分组后的"开始"、"插入"、"页面布局"、"公式"、"数据"、"审阅"、"视图"与
  "自动化"功能区选项卡复用既有的命令与格式控件。方向键
  在选项卡间导航；向下进入分组，双击选项卡可折叠功能区。窗口较窄时，
  溢出的控件仍可访问。不支持的功能区功能会被禁用。原有菜单仍然可用。
  编辑栏在名称框旁保留"应用/取消"，状态栏滑块可改变工作表缩放。编辑栏
  会为长公式扩展为多行（Alt+Enter 可加一行），工作表标签，
  以及一个可对选区求和（并给出最小值与最大值）并解释活动单元格中错误的状态栏；
  右键点击它可选择要显示什么，
  每项都列出其当前值，切换多个选项时菜单保持打开。可在桌面、平板与手机上使用
  （点按选择、再点按编辑、长按打开菜单）。浅色、深色
  与系统主题，在首次绘制前即已应用。深色模式会改变应用控件，
  而电子表格保持其白色纸张背景与配色。
- **边输入边出现的表名**：公式自动补全会把其他

- **用值替换公式**：公式菜单（右键）或
  调色板会把选区的公式冻结为它们显示的值，

  或 SVG，并像上传的图片一样放置到工作表上。
- **单元格中的图片**：插入 ▸ 图片 ▸ 置于单元格中（来自你的设备、
  Puter 或一个 URL）会让图片成为该单元格的值，按比例适配在单元格内
  并按单元格的对齐方式对齐。它随其单元格移动、排序（在数值之后）、筛选、复制与撤销；
  `=A1` 会显示它，`TYPE` 回答 128，`ISNUMBER`/`ISTEXT` 则回答否。右键 ▸ 编辑替代文字… 可为其添加描述
  （`IMAGE(url, "alt text", sizing)` 对公式生成的图片做同样的事），
  而"置于单元格上方"会把它抬出来浮动；浮动图片的菜单或"图片格式 ▸ 置于单元格中"会把它放回其角下方的单元格。
  粘贴的图片在"粘贴选项"中同时提供这两种方式。在 .xlsx 中它们是标准的单元格内富值
  （带替代文字的本地图片，以及来自网页的 `IMAGE()` 结果作为网页图片），
  因此其他程序也能显示。无障碍检查会列出没有替代文字的单元格图片。
- **单元格的图片**：选择性粘贴 ▸ 图片 会粘贴所复制区域的图片；
  选择性粘贴 ▸ 链接图片 会粘贴一张持续显示那些单元格
  （值、数字格式、填充、字体、边框、合并单元格与单元格图片，不含网格线）变化的图片，
  它会跟随插入的行与重命名的工作表，
  并在编辑栏中显示其引用（`=Sheet1!$A$1:$C$5`），在那里输入另一个区域即可改变其目标；双击可跳转到
  这些单元格。保存到 .xlsx 时是一张指明其区域的单元格图片，因此在别处也保持链接。
- **图片格式**：选中的图片会带来自己的选项卡。"更正"
  （在图片上预览的亮度与对比度预设，或"图片更正"中的精确值）、"颜色"（灰度）、
  "透明度"、"重设图片"与"重设图片及大小"；"图片样式"（白色或黑色边框、
  细边框、投影、圆角、椭圆）；"替代文字"；"排列"；以及"大小"：带八个手柄的裁剪
  （可拖动或用方向键）与宽高比预设，图片在工作表上保持原位，
  另有锁定宽高比时的精确高度与宽度。所有这些都可打印、复制、撤销，
  并以 DrawingML 的形式通过 .xlsx 往返（亮度/对比度、灰度、透明度、轮廓、预设形状与阴影）。
- **CSV 编码**：导入的文本文件按 UTF-8 读取（带或不带
  BOM），当字节序标记如此指示时按 UTF-16 读取，
  而当字节不是有效的 UTF-8 时按 Windows-1252 读取，
  因此来自较旧 Windows 程序的带重音姓名也能保留下来。
- **从 URL 导入**：文件 → 从 URL 导入 会通过 Puter 从某个网址获取 .csv、.tsv、.xlsx 或 .ods
  并把其工作表加入当前打开的电子表格（格式由地址判断或从字节嗅探得出）。
- **一起协作**：共享 → 开始一起编辑 可让多人同时在一个电子表格中工作。
  每个人都能在一两秒内看到他人的编辑（单元格值与公式、格式、插入、删除与移动的行与列、
  新增、重命名、移动与删除的工作表、设置）而不会互相覆盖：变更通过一条有序日志传递，
  而在有人于其上方插入行时输入的公式，会像工作簿重写自身公式那样被重写。每个人的首字母缩写显示在共享旁（点击可跳到其所在位置），
  其选区以自己的颜色与姓名在网格上标出轮廓，
  工作表标签会显示谁在哪张工作表上。所有者发放邀请链接，可让对方编辑或仅查看
  （由所有者自己的协作服务器——一个 Puter Worker——强制执行，而不只是界面），
  可按用户名邀请他人，更改或移除访问权限，
  并且随时可以停止。撤销只回退你自己的改动，
  不触碰他人此后的修改。离线时所作的编辑会在设备上排队（也可跨重载），
  并在连接恢复后合并；状态会显示"实时"、"同步中"或"离线"以及待处理的内容。.xlsx 文件仍是所有者保存的那一份：
  它会在人们工作过程中被写回，因此在任何地方都能打开。参见
  [docs/collaboration.md](docs/collaboration.md)。
- **通过电子邮件发送**：文件 → 共享 → 发送副本 会把当前状态的工作簿作为邮件发给最多 20 个地址，
  带有主题与正文，发件人是已登录的用户（回复会发给他们）：可作为 .xlsx、作为整个工作簿或工作表或选区的 PDF

  或作为工作表或选区的 .csv。该副本会略去"显示更改"中记录的早期单元格值，

  地址（可查看或可编辑；没有 Puter 账号的人也会被邀请）
  并把一个能打开它的链接发给他们；实时工作簿的所有者可向其中发送邀请。共享对话框也提供"通过电子邮件发送链接"。地址会在输入时被校验，
  附件上限为 7 MB，对话框会显示附了什么以及有多大，
  部分失败后它只保留未送达的地址。邮件通过应用自己的

  自行组织每一封邮件，只接受它能识别的附件类型并附上应用链接，
  给每个人各发一封邮件，
  并限制单个用户每天可发送的数量。绝不会有任何凭证被放进请求中。
- **带 @提及的线程式评论**：在评论或回复中输入 @ 会列出
  可被提及的人（实时工作簿的成员、文件共享对象、
  工作簿中的其他评论者），并随输入逐步收窄；也可以完整键入一个 Puter 用户名或电子邮件地址。

  还可以把其线程指派给他们：卡片会显示指派给了谁，解决线程即标记为完成，

  且未按这种方式保留的文件所遗留的历史，会在另一个文件占用该名称时被搁置，其快照得到保留，

  按时间从新到旧列出最近的编辑：每项由谁所作（已登录的 Puter
  用户）、何时、在哪里，以及单元格此前与此后的内容，公式按公式显示。一次粘贴或填充是一张卡片，展开后对应它改动的单元格；

  记录保留最近 1,000 次编辑（每次最多列出 100 个单元格），随应用自己的附属部件与草稿在文件内传递，

- **不会丢失任何东西**：未保存的编辑也会在做出后稍作复制，存入浏览器的本地
  存储。若标签页在离线时关闭或某次保存失败，再次打开该文件会询问是否恢复这些更改
  （或丢弃它们并保持文件原样）；当文件此后已被保存时，
  它所含的内容会先被保留为一个版本，再由较旧的编辑覆盖。文件已持有的草稿会被悄悄丢弃。
  在该询问等待期间所作的编辑会与它并存，
  而当之后一次打开同时发现两者——一个在文件自身的名下，另一个在别处重命名给它的新名下——
  后来的编辑会被提供出来，而较早的草稿会移入主页的**未保存的电子表格**列表，因此两者都不会丢失。
  当工作簿大到浏览器无法保存副本时，状态标签会提示。
  在打开期间被别处重命名的文件会被跟随到新名称，而被别处删除的文件会询问是把它另存为新文件、
  放回去，还是继续编辑。被别处更改的文件会询问以谁的版本为准，
  包括恰好在本标签页上次看到该文件的那一秒内所作的保存：修改时间的精度是整秒，
  因此在覆盖这类保存之前会先把文件本身读回来。在尚未决定时离开编辑器
  并不会被拒绝：离开对话框会提供离开的选项，
  编辑内容保留在本设备上，并在下次打开时再次提供。
  从未完成首次云端保存的电子表格可从主页的**未保存的电子表格**列表恢复，
  离线时同样可以，已删除文件所保留的编辑也可如此恢复
  ——即使与此同时另一个电子表格已保存为该名称，两者也不会把那些编辑据为己有或将其覆盖。
  本地草稿、打印设置，以及最近打开文件与保存在应用文件夹之外的那些文件的列表，都限定在已登录的
  Puter 账号范围内。更早、未限定范围的浏览器记录会被保留，
  但不会自动提供给某个账号，因为无法验证它们的归属。

  可建在你自己的选项卡上或内置选项卡中；"恢复默认"会把功能区还原。
- **自定义键盘快捷键**（文件 → 选项 → 键盘快捷键）：
  每一项操作及其触发按键，可按名称或按键搜索。按下新的组合键即可为某项操作指定快捷键；
  对话框会说明该组合将从哪项操作那里取走，并拒绝浏览器或输入所需的组合键。内置
  快捷键可以被关闭或移动，菜单、命令面板与
  功能区工具提示会显示当前生效的按键。
- **无障碍**：网格是一个真正的 `role="grid"`，活动单元格通过 `aria-activedescendant` 暴露，
  每次选区变化都通过实时区域（live region）播报，菜单与对话框会锁定焦点并可用 Escape 关闭
  （Escape 也会消除屏幕底部的一条通知，
  带操作的通知的关闭按钮同样如此），主页列表在加载时标记自身为忙碌，
  随后说明它找到了多少电子表格或某次搜索匹配到什么，
  一个正在等待 Puter 的登录会用单独一行说明，
  工具栏按钮暴露按下状态并有 44px 的触摸目标
  （通知中的撤销与忽略按钮也是如此；
  各栏上较小的控件，如菜单标题、工作表标签的选项按钮与缩放控件，也有 40px 的触摸区），
  打开电子表格或导入文件时显示的界面会通过实时区域说明它在等待什么，
  而不只是一个转圈动画，
  减少动效会被尊重，颜色在两种主题下都满足 WCAG 对比度要求（图表的系列采用主题自身的配色，
  在 Windows 高对比度下它们就是图片本身，
  并且无论屏幕主题如何都印在白纸上）。

网格是虚拟化的：只有视口中的单元格才存在于 DOM 中，表头通过 transform 跟随滚动，
而选区、填充预览、公式引用高亮与单元格内编辑器都是同一滚动画布上的叠加层。

求值是惰性的，并带有一个在每次更改时整体丢弃的缓存，
因此渲染一屏单元格只会计算这些单元格真正依赖的内容。
循环会被检测并报告为 `#CYCLE!`，而不是让程序挂起。可能产生数组的
公式会从其语法树中被静态找出，并在读取任何单元格之前全表确定下来，
因此空白单元格也知道覆盖它们的是哪个溢出。

### 在 Puter 上的存储

| 位置 | 内容 | 原因 |
|---|---|---|
| FS `Spreadsheets/<name>.xlsx` | 每个文档的完整内容 | 是用户拥有的真实文件；可在任何地方打开 |
| `Spreadsheets/.versions/<name> ~<file id>/*.xlsx` | 版本历史快照 | 每约 10 分钟保存一个，保留 30 个无标签的；该 id 使历史在任意重命名后仍随文件而去 |
| KV `spreadsheet:settings:v1` | 主题与区域格式（无会话时保存在本浏览器中） | 很小、很热，启动时读取一次 |
| FS `Spreadsheets/Scripts/<name>.js` | "我的脚本"，即用户自己的脚本 | 用户可见的普通文件；可用于任何工作簿 |
| KV `spreadsheet:script-trust:v1:<sha256>` | 来自用户已同意运行的文件的脚本 | 每个脚本询问一次，在每台设备上 |
| KV `spreadsheet:pref:<name>` | 自动更正设置、自定义词典、拼写与翻译选项（同样按账号保存在本浏览器中） | 随账号同步到另一台设备 |

文件从不会存放在 KV 中。XLSX 导出器在 SheetJS Community
Edition 之上补充了原生单元格样式（字体、颜色、边框与对齐）、带格式的空白单元格、
行列默认值、表格样式、冻结窗格、标签颜色、
以及工作表视图。行高以点为单位，列宽以导出的 Normal 字体为单位，因此 Excel 得到相同的几何尺寸。标准图表保留原生 DrawingML 系列并链接到工作表单元格。图片与文本框也有原生绘图记录；导入的 SVG 素材与复杂的图表布局在浏览器导出时会被渲染为图片。

导入的仪表板会保留嵌套图表、链接的 KPI 文字、当前工作表与工作表缩放。当文件的点数不包括总计时，数据透视图会省略末尾的总计，并保留重叠的柱形与数值标签。嵌入的单元格内图片在引用与查找中仍是图片值，并保存为原生 Excel 富值。Excel 数据模型透视表仍保存为结果单元格；
不支持刷新其模型或操作 Excel 数据切片器。

一个名为 `_puter_meta` 的深度隐藏工作表保存 JSON，用于应用自有的
样式覆盖与继承、可编辑的图表/图片模型、条件格式、
行列分组、保护及其他设置。其他应用会忽略这张表；本应用会把它读回来。来自其他程序所写文件的
冻结窗格、标签颜色、网格线设置、工作表保护、行列分组、
默认行高、纯色单元格填充、边框、对齐、自定义表格样式，以及字体
（系列、粗体、斜体、下划线、删除线、字号与颜色），都直接从文件本身读取，
包括自定义的索引调色板，两处都存在时以附属部件自身的记录为准。
Calibri 工作簿会保留其分数字号与紧凑文字间距，
并附带 Carlito 作为无 Calibri 系统的回退字体、Caladea 作为无 Cambria 系统的回退字体。原始字体名称在原生导出中保持不变。被显式设置为 None 的表格
在保留其单元格格式的同时不会被加上表格主题。
导入的工作表会在空白单元格与新输入项上保留其原生的默认垂直对齐，
包括在合并默认设置不同的工作表时。Excel 的公式
与单元格比较类条件格式会带其优先级、停止规则、
填充与边框一并导入，包括甘特图排程所用的相对命名引用。
"包含"、"不包含"、"开头为"、"结尾为"文本规则、非空白单元格规则，
以及带数值或最小/最大边界的数据条也会导入，
包括隐藏其数值的数据条。全部 17 种标准的三、四、五图标族都可原生导入与导出，
支持数字、百分比、百分位与公式边界、排除式比较、反向顺序与仅显示图标。
它们的边界仍可编辑，并在复制与区域移动后保留；
网格与打印使用共享的矢量图标。还不支持 Office 扩展/自定义图标集。
其他原生条件格式类型尚不能读取。导入的规则会通过应用的附属部件在保存后保留。对新保存的文件，
受支持的原生规则的编辑、删除、添加与优先级变更优先于过时的条件格式
元数据；未改动的规则保留其可编辑的应用设置。原生色阶
与数据条的阈值在复制与保存后保留最低/最高值、数值、百分比与百分位
类型，并在管理器中拥有可编辑的阈值类型。
部分剪切与区域移动会携带条件格式（包括仅可见单元格的
选区），并让依赖的条件公式继续链接到被移动的单元格。
管理器接受以逗号分隔的应用区域，并会把兼容的相邻片段一起编辑，
包括导入的多区域规则。
位于空单元格之上的无标签、无链接 Excel 表单复选框
会导入为可编辑的复选框单元格，保留其勾选状态与方形外观。
带链接、带标签、由宏驱动与混合状态的表单控件不会被转换。
这些复选框在本应用的附属部件中随保存保留，而不是被导出为原生 Excel 表单控件。值、公式（带缓存结果；
溢出数组作为旧式数组公式，较新的函数带有 Excel 所要求的 `_xlfn.` 前缀，
而来自 Excel 的文件在导入时会被去掉该前缀）、包括自定义代码在内的数字格式、超链接、
列宽、行高、隐藏的行与列、工作表、合并单元格、
备注（作为评论）、命名区域，以及自动筛选区域及其
条件，都是标准的 `.xlsx`，可与任何电子表格程序往返。本应用无法读取的公式
（`=1+`，显示为 `#ERROR!`）会按该单元格自身的数字格式保存为文本 `=1+` 而非公式，
因此 Excel 打开文件时不会出现修复提示；
附属部件承载该公式，本应用在打开时将其恢复（`.ods` 及其设置块同理）。另一个程序的文件中
指向其他工作簿的公式（`[1]Sheet1!A1`）会保留该文件缓存的值，因为此处没有其他工作簿可读，
并且绝不会作为公式写回；附属部件保留其文本。

当应用运行在 Puter 桌面端内（`puter.env === 'app'`）时，
会话由桌面端掌管，因此不提供退出登录，导出也走 Puter 自己的保存对话框而不是浏览器下载。

## 分析统计

生产页面会加载 Plausible 以统计页面浏览量与四个值事件。请在站点的 Plausible 设置 → Goals 下创建对应的
自定义事件目标：

| 事件 | 触发时机 | 属性 |
| --- | --- | --- |
| `Spreadsheet Edited` | 编辑器会话中首次成功的数据更改，包括输入、粘贴或 AI 作出的更改 | 无 |
| `Spreadsheet Saved` | 一次云端写入完成，包括自动保存与"保存副本" | `method`：`manual`、`auto` 或 `copy` |
| `Spreadsheet Exported` | 一次浏览器下载开始或 Puter 的保存选择器完成，包括选区与图表导出 | `format`、`method`：`browser` 或 `puter` |
| `AI Interaction` | 收到非空的 AI 回答；侧边栏对话在整轮交换完成后计一次 | `feature`；侧边栏回复还会报告是否 `changed` 了工作簿 |

AI 功能为 `assistant`、`formula`、`translate`、`detect-language`、`ask-data`、
`explain-formula` 与 `generate-formula`。失败、取消、为空或被截断的侧边栏
回复不计入。未产生更改的保存不计入。浏览器导出衡量的是下载的开始，
因为页面无法判断用户是否把文件保存到了磁盘。

自定义事件属性中不包含任何电子表格内容、文件名、路径、提示词、回复或账号标识符。
分析统计失败绝不会阻塞应用操作。
开发用 mock 与手机测试台会省略跟踪脚本。测试使用桩掉的
`plausible` 函数，而不是把事件发送到线上站点。
