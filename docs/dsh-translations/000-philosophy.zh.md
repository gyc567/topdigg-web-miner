# 000 理念

dsh-superagent 是一个框架，同时也是一种与智能体协作的工作方式。它的核心原则是：

**尽可能少占用人的注意力，尽可能多地交付价值。**

项目的每一个部分，都以它消耗了多少注意力来衡量。一条消息、一次通知、一个问题、一项设置、一个面板元素、一段文档，每一样都会消耗某个人的注意力，并且必须交付比这更多的价值，否则就该被移除。

## 这对智能体的约束

- **它只在被要求时，或书面规则允许时才行动。** 只有当请求直接指向智能体、并且来自团队允许的人时才算数：要么在允许名单上，要么是团队开放了请求的某个会话中的任何人。没人要求过的工作，需要团队写下的规则来授权，并且以一种只记录智能体本来会做什么的模式启动。
- **它只在有人必须行动、或有人能利用某个结果时才发声。** 它确认一次请求，并说明自己要做什么。它工作时保持安静。当结果就绪、当它需要一次决策、或当它无法完成时，它才会再次写入。消息都很短，并发送到提出请求的那个会话。
- **它一次只问一个具体问题，** 并且采用结构化的形式，让问题能到达那个人，而不是埋在一份长报告里。
- **它按影响停止，而不是按努力停止。** 本地改动会推进到可评审的结果为止。需要设计决策的改动则以一个清晰的问题停下来。
- **它如实汇报。** 草稿会被标记为未完成，失败会被当作失败来汇报，绝不为了避免发问而绕过限制。

## 这对设计的约束

- **概念很少。** 设计中只有它的领域概念，例如 Source，以及它们的具体实现，例如 GitHub 和飞书。一个业务需求会变成其中某一个概念的属性，或者智能体遵循的一段提示词。设计不会为它新增概念。
- **设置很少。** 当某个默认值几乎适合所有团队时，它就替代了一项设置。团队用文字描述的行为属于提示词文本，而不是设置项。
- **面板只展示需要人来处理的事。** 它首先列出正在等待人处理的事项。健康状态下它不占空间。
- **文档按顺序阅读。** 每篇编号文档都只建立在此前文档的基础上，因此读者永远不需要尚未引入的概念。

## 责任

智能体会以你团队每天都能看到的账号身份发表评论、发起拉取请求、给人发消息。它发出的每条消息都消耗同事们的注意力，而这由你负责。智能体能做的事越多，它的运维者对团队所负的责任就越大：

- **从窄开始。** 先用一份简短的允许名单，并且只记录主动型工作。等智能体本来会做的事看起来没问题了，再把两者都放宽。
- **为更少的噪音做调优。** 当智能体太吵时，把它的提示词写得更短更严，或者先暂停它。不要用更多的消息去解释这些噪音。
- **不要用它来堆量。** 批量拉取请求、广播消息和无谓的杂活，给团队带来的负担大于它们交付的价值。
- **为它所说的话负责。** 看看智能体以你的名义发布的内容，当它说得不对时，在提示词中纠正它。

目标是在恰当的时间给出恰当的帮助，在其他任何时间都不给。
