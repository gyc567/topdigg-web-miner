### 2.1 潜在世界优先的任务合成

**阶段 0：任务来源。** 我们的训练数据面向 ALE-CM，其覆盖范围被归为七个大域。在每个域内部，我们随机采样规格说明（specification），并围绕每一条规格说明自行编写生成器。详情请参见附录 [A.1](#A1.SS1)。

**阶段 1：世界构建。** 每个生成器都是一个带种子的程序。给定一个种子和一个规模档位，它会程序化地生成潜在世界 $W$，即该领域完整且正确的状态（例如一个零售仓库的客户、产品与交易记录，或一个分布式检查点的张量分片与拓扑结构），随后我们依据该环境的不变量（唯一标识、合法连接、有限度量）对 $W$ 进行校验。同一步骤还会抽取一个由种子派生的缺陷计划：精确指明 $W$ 中哪些记录、分片或字段将在之后被损坏，以及由哪个已声明的算子来损坏。

**阶段 2：工作流图。** 我们把环境的工作流编译成一个带显式依赖、允许并行性以及每阶段语义工作量估算的有向无环图（DAG）（例如 profile-sources →\rightarrow reconcile-facts / normalize-dimensions →\rightarrow load-facts →\rightarrow aggregate-validate →\rightarrow package-sidecars）。该 DAG 由代码依据 $W$ 的规模生成，过程中没有任何模型参与。其关键路径（即最长的依赖阶段链）定义了任务的跨度（horizon），而其各个阶段构成了 §[3](#S3) 中进度势能的骨架。

**阶段 3：制品渲染。** 我们把 $W$ 投影到环境声明的公共接口上，将干净的输入文件按其目标线格式（wire format）物化出来：CSV 与 TSV 分区、JSON 记录、SQLite 数据库、safetensors 分片、去除符号的二进制文件，或基础设施清单。渲染是 $W$ 的纯函数；在继续之前，我们断言它能够往返还原（round-trip），即能够从渲染后的文件中精确地恢复出 $W$。与阶段 4 中可逆的损坏相结合，这使得 agent 的工作区 $s_0$ 完全决定 $W$，因此正确答案可由 agent 实际看到的内容计算得出，而真值在构造上就是正确的。

**阶段 4：受控损坏。** 我们把阶段 1 的缺陷计划施加到渲染后的文件上，注入模式漂移（schema drift）、重复与缺失记录、类别漂移、打乱的分片索引、过期缓存等（如图 [3](#S2.F3) 展示了某个环境的三个算子）。被损坏的目录树 $s_0$ 就是 agent 收到的任务，而未被改动的世界 $W$ 是真值。由于渲染可往返还原且损坏是已声明并可逆的，$s_0$ 就完全决定了 $W$：正确解可由 agent 所见内容计算得到，且无需运行求解器即可精确获知。更一般地，环境的每一个组成部分，

$$E=(x,s_0,\operatorname{ver}_{W},\Phi_{W}),\tag{1}$$

都是同一个 $W$ 的函数：任务提示 $x$、输入目录树 $s_0$、严格的通过/不通过验证器 $\operatorname{ver}_{W}$（它依据 $W$ 检查 agent 产出的输出文件），以及 §[3](#S3) 中的进度势能 $\Phi_{W}$。这唯一的锚点杜绝了制品漂移（artifact drift，[Ivanov and Rana, 2026](#bib.bib72)）——即环境、任务与验证器被分别生成、各自看似合理，却描述了不同的问题。

**阶段 5 与阶段 6：公开规格与隐藏测试套件。** 我们输出公开契约，即任务提示 $x$（输入角色、所需输出制品及其模式、有序的需求、权威优先级规则，以及允许使用的工具链），这是 agent 所能看到的唯一描述。在 agent 视野之外，我们封存一套用于验证阶段的隐藏套件：变形变换（metamorphic transform），即保持语义的重写，其不得改变评分；以及陈旧输出反事实（stale-output counterfactual），即貌似合理但错误的状态，其必须判为不通过。

**潜在世界优先合成的推广性。** 受资源限制，我们聚焦于 ALE-CM 的各领域，但该方法同样适用于其他 ALE 领域。附录 [A.10](#A1.SS10) 详细讲解了该流水线构建的三个环境：一个多模态的 AWS 成本优化任务（其账单仪表盘截图由我们的潜在世界渲染而来）（云运维）、对一个 EnergyPlus 模型的闭环建筑控制（工程），以及从 SEC 风格申报文件重建财务报表（金融）。

### 2.2 覆盖度、校准与准入门槛

**多样性。** 每个环境都在 19 条覆盖轴上被标注（附录 [A.3](#A1.SS3)），包括子领域、规模、四条跨度轴、工作流阶段、工具能力、制品角色、关系类型与损坏类别。对训练而言真正起作用的是行为性轴：改变某个轴的取值，会改变 agent 必须修复什么（损坏类别）、如何修复（工作流阶段、工具能力）、以及通过哪些文件修复（制品角色、关系类型）。更多细节请参见我们的附录 [A.3](#A1.SS3)。

**可控难度。** 有两个控制项可以改变任务难度。规模档位（默认为 unit、small 或 full）会增大 $W$（附录 [A.4](#A1.SS4)）并拉长操作跨度：需要读取、连接与写入的内容量。阶段 2 的工作流 DAG，连同缺陷计划中损坏类别的数量，共同决定了依赖深度：在任何输出正确之前必须完成多少个阶段、以及必须以何种顺序完成。附录 [A.5](#A1.SS5) 说明我们如何度量跨度与难度，并报告了 base model 与前沿模型的解题率。

**准入门槛与洁净性。** 一个合成出的环境只有在通过全部八道与基准无关的门槛（qualification gate）后才会被接纳，这些门槛在生成时自动检查，并且每一道都对应一个具名的失败类别（表 [7](#A1.T7)）。其中三道为 §[3.2](#S3.SS2) 的进度势能提供支撑：全部 14 个作弊探针（gaming probe）都必须得 0 分（抗利用性）；在部分正确的状态上势能必须严格介于 0 与 1 之间，并沿参考轨迹单调上升到 1（进度有效性）；进度打分器、严格验证器与参考求解器必须具有互不相交的代码闭包（角色独立性）。附录 [A.6](#A1.SS6) 形式化地陈述了每一道门槛，并给出与验证器无关的求解器审计；附录 [A.9](#A1.SS9) 描述了结构化的去污染（decontamination）检查。

## 3 面向长跨度 RL 的稠密奖励

对任务完成度进行评分的潜在世界，同时也为其中间过程评分。本节把它转化为训练信号：我们量化了为什么仅终止奖励会"饿死"组内相对 RL（§[3.1](#S3.SS1)），定义了每个 Tev-Gym 环境所提供的进度势能（§[3.2](#S3.SS2)），并详述整形后的奖励（§[3.3](#S3.SS3)）。

### 3.1 终止奖励使组内相对 RL 陷入饥饿

考虑 GRPO（[Shao et al., 2024](#bib.bib2)），这是我们以及大多数近期 agentic RL 流水线所采用的估计量。对于一个任务 $x$，policy 采样出 $G$ 条 rollout $\tau_1,\dots,\tau_{G}$，奖励为 $R_1,\dots,R_{G}$，每条 rollout 的权重由其组内归一化的优势值给出：

$$\hat{A}_{i}\;=\;\frac{R_{i}-\operatorname{mean}(R_{1:G})}{\operatorname{std}(R_{1:G})+\epsilon}.\tag{2}$$

该式即：把第 $i$ 条 rollout 的奖励减去组内均值，再除以组内标准差（加一个 $\epsilon$ 防止除零），得到它的组内相对优势值。

在终止奖励 $R_i=\mathds{1}[\tau_i\ \text{passes}]$ 下，一条 rollout 通过的条件是 policy 发出 submit 动作且严格验证器 $\operatorname{ver}_{W}$ 接受了所提交的工作区。此时，一个所有 rollout 全部失败的组对所有 $i$ 都有 $\hat{A}_{i}=0$：该任务对梯度没有任何贡献，而它的 $G$ 条 rollout 全部被浪费。若 policy 以概率 $p$ 解出该任务，被浪费的组所占比例为 $(1-p)^{G}$：在 $p=0.05$ 且 $G=8$ 时为 66%，在 $p=0.01$ 时为 92%（附录 [B](#A2)）。在长跨度任务上，未经训练的开放模型的 $p$ 大约只有十分之一或更低（§[4](#S4)），此时丢弃或重采样这样的组（[Ivison et al., 2026](#bib.bib29); [Yu et al., 2025](#bib.bib3)）会扔掉整个 batch 中的大部分数据。只有一条成功 rollout 的组也只好不了太多：它那唯一一条正样本 rollout 被拿去与 $G-1$ 条失败样本对比，而这些失败样本都得到相同的负优势值，因此梯度无法区分"差一点就对"与"毫无进展"。该式说明：在仅有终止奖励时，组内相对优势值在"全失败组"上恒为零，梯度信号被完全饿死。

### 3.2 来自潜在世界的进度势能

每个 Tev-Gym 环境都提供一个进度契约（progress contract）：一组节点 $V$，每个节点都是从 §[2.1](#S2.SS1) 的工作流 DAG 派生而来的、可检查的输出工作区状态，带有权重 $w_v>0$，满足 $\sum_v w_v=1$，以及前置依赖集合 $\mathrm{pre}(v)$（示例见附录 [B](#A2)）。一个部分打分器（partial scorer）$c_v(s)\in[0,1]$ 直接依据潜在世界，对 agent 当前的工作区 $s$ 在节点 $v$ 上打分。信用分配是前置依赖门控的（prerequisite-gated）：$\tilde{c}_v(s)$ 等于 $v$ 及其所有直接与间接前置依赖节点中部分得分最低者。势能（记作 $\Phi$，即式 ([1](#S2.E1)) 中的 $\Phi_W$）是加权和：

$$\Phi(s)\;=\;\sum_{v\in V}w_v\,\tilde{c}_{v}(s)\;\in\;[0,1].\tag{3}$$

该式即：对所有节点按权重 $w_v$ 加权求和，每一项是该节点经前置依赖门控后的部分得分 $\tilde{c}_v(s)$，因此势能取值落在 $[0,1]$ 区间内。

**防止奖励作弊。** 三条性质使 $\Phi$ 成为可用的训练信号，每一条都由一道准入门槛强制保证（§[2.2](#S2.SS2)）：它是**有锚定的**（抗利用性），未被改动的公共目录树以及每一个作弊探针都恰好得 $\Phi=0$，而当且仅当严格验证器接受该工作区时恰好得 $\Phi=1$；它是**单调的**（进度有效性），随着节点被完成而上升，当已完成的工作被破坏时下降；它是**独立的**（角色独立性），由一个代码闭包与验证器及参考求解器互不相交的打分器计算得出，因此某一个评分器中的缺陷不会被另一个继承；这些评分代码中没有任何一份会随公共目录树一起发布。

**可扩展的奖励设计。** 由于潜在世界在任务生成之前就已被定义，每一个正确的中间状态都可以被直接渲染出来并由 $c_v$ 求值。这为每一个生成的种子与规模档位提供了精确且确定性的进度反馈，无需像过程奖励模型（[Lightman et al., 2024](#bib.bib6)）那样依赖人工步骤标注，也无需训练好的奖励模型或语言模型评委。

### 3.3 进度势能奖励整形（PPRS）

设 $s_0,\dots,s_T$ 为一条 rollout $\tau$ 沿程的工作区状态，其中 $s_0$ 是未被改动的公共目录树，因此 $\Phi(s_0)=0$。与基于势能的奖励整形（potential-based reward shaping，[Ng et al., 1999](#bib.bib5)，PBRS）一样，每步的整形奖励为势能的变化量，

$$r_{t}=\Phi(s_{t})-\Phi(s_{t-1}),$$

而整条 rollout 的奖励为

$$R(\tau)\;=\;\mathds{1}[\tau\ \text{passes}]\;+\;\lambda\sum_{t=1}^{T}r_{t}\;=\;\mathds{1}[\tau\ \text{passes}]\;+\;\lambda\,\Phi(s_{T}),\tag{4}$$

其中所有实验运行均取 $\lambda=0.25$（附录 [C.1](#A3.SS1)）。求和项是势能变化的望远镜求和（telescoping），因此直接等于终态势能 $\Phi(s_T)$。

与 PBRS 不同——PBRS 会把终态势能清零从而使最优策略保持不变——PPRS 保留 $\lambda\Phi(s_T)$，并有意改变了优化目标（附录 [B](#A2)）。提交是一个动作，而不是一种状态：$\Phi$ 对工作区评分，而终止项对 policy 所提交的那个工作区评分。一条耗尽回合数或 token 预算却没有提交的 rollout 不会被终止性地评分，它只获得 $\lambda\Phi(s_T)$；这正是图 [4](#S2.F4) 中那条完整但未提交的 rollout 能够达到 $\Phi=1$ 而终止奖励为 0 的原因。由于 $\Phi$ 只是工作区的函数，$R(\tau)$ 只通过 rollout 的最终状态 $s_T$ 依赖这条 rollout：两条以不同路径、不同的步骤顺序或不同的实现方式到达同一工作区的 rollout，会获得相同的奖励。

望远镜求和形式同时也让终止奖励的排名保持在最前：由于 $\Phi\leq 1$，任何通过的 rollout 获得 $1+\lambda$，严格多于任何未通过的 rollout，因此不会出现任何单条 rollout 因为拿"完成度"去交换"部分进展"而获得奖励的情况；对随机性 policy 而言，附录 [B](#A2) 给出了这种偏好可能反转的边界条件。附录 [B](#A2) 同时说明了还有哪些性质被保留、哪些没有被保留。

把式 ([4](#S3.E4)) 代入式 ([2](#S3.E2))，即可看出为什么这修复了 GRPO 的饥饿问题。一个没有任何 rollout 通过的组现在拥有奖励

$$R_{i}=\lambda\Phi(s_{T}^{(i)}),$$

其中 $s_T^{(i)}$ 是 $\tau_i$ 的最终工作区。只要这些 rollout 推进到的深度不同，这些奖励就不同，因此该组的优势值不再为零，并能按进展程度对 rollout 排序；图 [4](#S2.F4) 展示了这样一个组，附录 [B](#A2) 则给出了我们探测过的 24 个组。

## 4.3 消融研究

受资源限制，我们在 §[4.1](#S4.SS1) 的 9B 配置下开展消融研究。

**数据构造方法的消融。** 我们的流水线与标准的 LLM 合成语料有两个关键区别：任务是从一个预先存在的潜在世界及其代码编译出的工作流 DAG 推导而来；验证器针对这一隐藏真值进行评估，而不是仅仅针对 agent 可见的文件。表 [5](#S4.T5) 展示了每个消融配置保留了哪些组件，并以 GPT-5.6（sol, xhigh）替代其余模型。"公开视野验证器"（public-view verifier）仅消融掉对隐藏真值的访问，改为让模型从 agent 的视角编写一个验证器。"Prompt-first"（一个标准的 self-instruct 基线）则用整个构造流水线做替换：先为每个 prompt 生成其输入、验证器与解答，完全没有潜在世界或 DAG。公开视野变体导致训练中 88% 的采样组被丢弃。由于这两个变体都使用终止奖励，我们将它们与 Sparse 行比较：两者在 S@1 上都没有优于 base model（分别为 0.24 与 0.23，对比 0.25），而我们的完整方法在 S@1 上领先它们 0.05–0.06，在 P@5 上领先 0.05。

**稠密奖励的消融。** 在固定 Tev-Gym 的前提下，我们比较我们的 PPRS（它使用 return-to-go $G_t$，取 $\gamma=1$，并按回合索引归一化优势值）与仅终止的稀疏奖励、按 rollout 归一化的 PPRS（pooled norm.），以及使用 $\Phi(s_t)$、取 $\gamma=0$ 的直接加性奖励（[Yuan et al., 2026](#bib.bib19)）。我们的方法在性能与训练效率之间取得了最佳平衡，S@1 比稀疏奖励高出 0.04。回合索引归一化避免了把后期回合较小的回报与整条 rollout 的均值相比，从而保留了后期回合的信用；而 $\gamma=1$ 则把进展向前传播回更早的动作。相比之下，直接加性奖励反复奖励高势能状态却不传播信用，导致更多 rollout 在提交之前就耗尽上下文窗口，并产生更长的轨迹。在 27B 上，我们相对稀疏奖励的优势进一步扩大：整形后的奖励能够训练至完成，而仅终止奖励产生的组几乎全部是零优势值，无法完成哪怕一步优化器更新。
