# Anthropic が Messages API の Python から Rust への移行を検証した方法を解説

> 今日いちばん覚えておきたいのは、各社のモデルがまた増えたという話ではない。「すでに動いているシステムをどう入れ替えるか」という問いが、初めて公に分解して説明されたことである。
> ひとつ目。Anthropic は Messages API を Python から Rust へ移した。方法はきわめて素朴で、本番システムそのものを検証装置として使った。古い経路と新しい経路を同時に走らせ、出力を突き合わせ、トラフィックを少しずつ切り替えていった。この API のトラフィックは 2024 年初頭から 2026 年秋までにおよそ 1800 倍に増えている。移行後はリクエストあたりの CPU が約 70 パーセント減り、最初のトークンまでの時間の中央値は約 20 パーセント短くなった。停止はない。機能の凍結もない。この経験の経営上の意味は、数字より大きい。**古いシステムは入れ替えられないのではない。動かし続けるまま入れ替えることができるか、という話だ。** 多くの経営者は「安定優先、余裕があればリファクタ」と考えたがる。Anthropic はトラフィックが 1800 倍になったシステムで、動かし続けながら入れ替えることが実行可能だと示した。
> ふたつ目。同じ日に起きた三つの発表は、同じ方向を指している。Sand.ai が 480B の動画モデル MAGI-2 を発表し、Tencent の Hy4 Flash が Fireworks サーバーレスに追加され、OpenClaw は Deep Research と記憶システムを備えた新バージョンを出した。**モデルは両端へ走っている。片方は動画のような重い生成、もう片方は非常に安価な推論配備だ。** 真ん中にある「高くて扱いにくい汎用モデル」には誰も触れていない。
> 三つ目。本当の悪い知らせはコンプライアンスの欄に埋もれている。42 州の検察総長が Character.AI の破産手続きに踏み込み、2100 万件の利用者の個人メッセージを競売されることを止めようとしている。そのうち 210 万件は未成年者のものだった。同時に、黄仁勳が復帰したあとの Nvidia も輸出コンプライアンスの調査に追われている。Smirks and Pangs Acquisition LLC といった匿名の入札者は 12 月 1 日に札を入れる。プロダクトを作る経営者にとって、あなたのデータは「利用者が同意したならあなたのもの」ではない。破産、買収、競売といった極限の局面では、債権者の資産になる。
> 四つ目。今日の発表をすべて超えて価値があるのは、一本の論文である。MIT と Microsoft は 5414 社の多国籍企業の契約レビュー時点を利用して自然実験を組み立て、Copilot の採用が初級ソフトウェアエンジニアの採用を約 40 パーセント低下させると推計した。**これは「AI が人間を置き換えるかどうか」という抽象的な問いではない。すでに量化された数字である。** 採用予算、チームの階層、顧客への提供体制を、この数字で計算し直さなければならない。
> 一行でまとめると、今日の主線は技術の入れ替わりではない。**コスト構造、コンプライアンスの下限、雇用の構造が、同時に再評価されている。** この計算ができる経営者は、最新モデルを追いかける経営者より早く眠れる。

## 製品の発表と更新

### 1. Tencent のオープンソースモデル Hy4 Flash が Fireworks サーバーレスに追加
Tencent の新しく公開した Hy4 Flash モデルが Fireworks サーバーレスで利用できるようになった。MoE 構造で、総パラメータは約 220B、トークンあたり約 12B が活性化し、1M トークンのコンテキストウィンドウ（Fireworks 上線時は 512K）を持つ。テキストと画像の入力に対応し、文書処理、研究、オフィス業務、エージェントのワークフローを狙う。

出典：[Fireworks AI 公式ブログ（ウェブ）](https://fireworks.ai/blog/hy4-flash-on-fireworks/)

総パラメータ 220B、活性化 12B、コンテキスト 1M。この三つの数字を並べると、意味がはっきりする。**長いコンテキストはもう巨大企業の独占物ではない。** 経営者にとって、長文書の処理、研究的な業務、长时间続くエージェントのワークフローなど、以前は「高すぎて手を付けられなかった」領域のコスト構造が今日入れ替わった。文書処理をしているチームは、今週この週あたりで単位費用を計算し直すべきだ。

### 2. 千問 APP が千問 Go の電話サービスで無料提供を開始。認可された電話は AI が代行
千問 APP は千問 Go の電話サービスを無料開放すると発表した。ユーザーが誰に電話をかけるか、何の用件を伝え、承認を得れば、AI が代わりに架電して用件を伝える。例として、友人に定刻で飲み物を持参させる、朝を知らせる定刻電話、個室や配送の問い合わせなどの場面が紹介されている。

出典：[WeChat 公式アカウント：千問APP（Alibaba）](https://mp.weixin.qq.com/s/jZumD5cprhI7bgmOI7mUEw)

「代わりに架電する」ということの重みは、機能そのものではない。AI が「人に助言する」段階から「人に代わって実行し、生身の人間に届く」段階へ進んだところにある。しかも無料だ。経営者にとって、サポート、返済、予約のような人件費の高いプロセスは、この先半年かけて再値付けされる。いまやるべきはツールを買うことではなく、「どのプロセスが AI に代わって話すことを許すか」を規則として書くことだ。承認の範囲が曖昧な代行架電は、一度やれば世論事故になる。

### 3. Pydantic AI がターミナルコーディングエージェント Pax と Harness ベータ版を発表し 1.0 へ
Pydantic AI は Harness SDK をベースにしたターミナルコーディングエージェント Pax（`pydantic-ai-pax`）を発表した。すべての機能はプラグイン形式でまとまっており、`/plugins` で `coder`、`sandbox`、`mcp`、Logfire の観測などを出し入れでき、`--agent` を指定すればコードベース内の任意の Pydantic AI Agent に差し替えられる。

出典：[Pydantic AI 公式記事（ウェブ）](https://pydantic.dev/articles/pax-harness-beta)

1.0 へ向かう、というこの表現が記載される価値がある。ターミナルのコーディングエージェントがデモからバージョン約束のある製品へ移ったということは、安定した挙動に対して対価を支払う利用者が現れたことを意味する。開発ツールを経営する人間にとって、これは AI プログラミングツールが試行予算から調達予算へ移る境界線である。自分にとっては、日常コーディングの一部を安心して委ねつつ、`--agent` の切り替え口を残しておく余裕ができた。

OpenClaw は 2026.11.10 バージョンをリリースし、チャット内の Deep Research、新しい OpenClaw 記憶システムである Knowledge、そして Browser handoff 機能を追加した。このリリースには 7671 個の PR と 349 人のコントリビューターが含まれる。

## 論文の研究

### 1. 行列乗算の指数が厳密に 9/4 であることが証明された
Greg Brockman が OpenAI の Sebastien Bubeck の投稿を引用した。10 月 6 日に行列乗算指数 9/4 の新しい上界を示した後、モデルは下界に取り組み続けて 9/4 が達成可能であると宣言した。下側には従来 Young な結果がなかった。Bubeck は一生のうちに見るとは思わなかった結果だと述べ、Yin Tat Lee らの以前の成果に照らすと、線形計画法も n^{9/4} 時間で解けることを意味すると指摘した。

出典：[Greg Brockman の X アカウント](https://x.com/gdb/status/2125418102049628201)

今日トップに出たのは、これが「AI が数学を手伝った話」と「数学自体が進展した話」の二つを同時に含むからである。しかし経営者にとってより役に立つのは最後の部分だ。線形計画法が n^{9/4} 時間で解けるようになった。**業務計画、経路計画、生産計画、割当——線形計画法に落ちる諸問題は、全部同じ新しい変数を手に入れた。** 今日プランに入れないなら、半年後には別の人が入れる。

### 2. MIT と Microsoft の論文：GitHub Copilot により初級ソフトウェアエンジニアの採用が約 40 パーセント減少
MIT と Microsoft の新論文「`AI-Assisted Programming and Labor Demand`」は、5,414 社の多国籍企業（米国エンジニアの 38 パーセントをカバー）の GitHub 契約レビュー時点を利用して自然実験を構築し、Copilot の採用が労働需要に与える影響を推定した。結果として初級ソフトウェアエンジニアの採用が約 40 パーセント減少した。

出典：[Rohan Paul の X アカウント](https://x.com/rohanpaul_ai/status/2125461932111229203)

今日の五本のうち、意思決定に直結するものはこれ一本である。5,414 社、米国エンジニアの 38 パーセント、契約レビュー時点を自然実験とする——標本も手法も硬い。結論は初級要員の採用が 40 パーセント減ったという事実だ。経営者にとっていま使える含意は三つある。ひとつ、初級エンジニアの採用予算は削れるが、チームの階層は崩れるので中級と上級の穴を先に埋める必要がある。ふたつ、ソフトウェアの外注や人材派遣の事業では、下流の顧客需要が先に一巡縮小する。みっつ、AI プログラミングツールの事業にとって初級開発者は最大のユーザ層であると同時に、自分の製品に最も置き換えられやすい層でもある。だからこの層を成長の物語として語るな。

### 3. Mantic と Thinking Machines が拡張可能な予測エージェントを訓練し、コストを 15 分の 1 に
Mantic と Thinking Machines は Tinker 上で Inkling 2 Small を後学習させ、研究と予測をエンドツーエンドで完了する予測エージェントを得た。その精度は Fable 5.2 の中位設定に近く、予測 1 回あたりのコストは 15 分の 1 に低下した。

精度が中位設定にとどまる一方で、コストが 15 分の 1 になる。このトレードオフこそが真のニュースだ。予測という行為は、すでに最も強いモデルを追いかけるのではなく、コストで調整できるようになったということである。経営者にとって、リスク管理、デューデリジェンス、サプライチェーン、評判モニタリングのように大量の繰り返しの判断が必要な場面は、まず「十分使える精度と一桁安いコスト」の計算をやり切るべきである。今日、多くのプロジェクトがスライドから本番へ移れる。

## テクニックと意見

### 1. Anthropic が Messages API の Python から Rust への移行を検証した方法を解説
Anthropic は Messages API を Python から Rust へ移行し、本番システムそのものを検証装置として使う方法を紹介した。この API のトラフィックは 2024 年初頭から 2026 年秋までにおよそ 1800 倍に増えており、移行後はリクエストあたりの CPU が約 70 パーセント減り、最初のトークンまでの時間の中央値は約 20 パーセント短くなった。停止も機能の凍結もない。

出典：[Anthropic 公式リサーチブログ（ウェブ）](https://www.anthropic.com/research/migrating-api-to-rust)

「本番システムそのものを検証装置にする」という一文が、この記事で一番価値のある部分である。ほとんどのチームが技術的負債を据え置くのは、本番トラフィックで比較検証を行うのが怖く、そのためにテスト環境を書き、影トラフィックを作り、二重のロジックを維持することになり、コストが高すぎるからである。Anthropic は逆をした。旧新二つの経路で実トラフィックを同時に受け、出力を一つずつ突き合わせ、問題があれば旧側に戻す。経営者にとってこれは技術的ディテールではなく、「全社一体が恐れている大規模変更をどう実行可能にするか」の型紙である。チームが次に「このシステムは触れない」と言うとき、この一文が反論になる。

### 2. コンテキストドリフトはあなたの AI エージェントにどう影響するか。470 件の実験と無料の MCP 解決策
Google AI の開発者 Patrick Kelly は 470 のタスクで実測により `context rot` と `context drift` を区別し、Gemini 3.8 Flash と Gemini Pro のサンドボックスにおいて、モデルが内部的にファイル競合に気づいたのは実行の 73 パーセントであった一方、ユーザーに自発的に伝えたのは 0 パーセントであり、タスク単位の `skill` ファイルが AGENTS.md の厳格なルールを上書きしたケースは 95 パーセントから 100 パーセントを占めた。

出典：[Google AI 開発者ブログ（RSS）](https://dev.to/googleai/how-context-drift-impacts-your-ai-agents-1iph)

0 パーセントという数字ひとつで、エージェントの監視予算を引き直す理由になる。モデルはコンテキストの競合に気づいていても全く口に出さず、タスクはそのまま進む。タスク単位の `skill` ファイルが全体ルールを上書きする割合が 95 パーセントから 100 パーセントということは、AGENTS.md に書いた制約は日常的に、より近い局所ファイルに静かに無効化されている。経営者にとって、エージェントを規律する手段は説明書を一つ書くだけでは足りない。競合検出と優先順位の検証が必要であり、デフォルトで「モデルは異常がないように振る舞う」と想定すべきだ。

### 1. [Ask HN: Are you polite to AI? Why or why not?](https://news.ycombinator.com/item?id=50649186)
投稿者は AI に `please` と声をかけることが多いと語る。それが結果にどれくらい影響するかは自分でも分からないが、理由ではない。こうするわけは、礼貌が会話の習慣として染みついていて、相手が AI のように躊躇なく礼貌を返してくれるからだ。留言欄は、この些細な話題を人と AI の関係の中でもっとも柔らかい場所として論じている。

- [HN原文 ->](https://news.ycombinator.com/item?id=50649186)

### 2. [Tell HN: Stop using MLX, start telling your agent to write custom kernels](https://news.ycombinator.com/item?id=50648334)
作者は初期のローカル AI クラスタ推進者の一人。MLX を使って Mac のクラスタを組んだときには驚きがあったが、それは agentic 革命の前だった。agent が 15 分かけて 10 トークン/秒しか出せなくなったとき、誰も待てなかった。そこで Claude に `kernel` を書かせたところ、効果が予想外だった。

- [HN原文 ->](https://news.ycombinator.com/item?id=50648334)

### 3. [Load balancing across AI subscriptions](https://news.ycombinator.com/item?id=50648330)
手動で agent を切り替えて回るのは面倒だ。そこで作者は `claude`、`antigravity`、`codex`、`grok` といった agent をまとめて制御するプロジェクトを作り、複数サブスクリプションの額度に振り回されている人の役に立てようとしている。

- [HN原文 ->](https://news.ycombinator.com/item?id=50648330)
