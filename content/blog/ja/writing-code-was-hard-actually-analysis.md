# Promptless「Writing code was hard, actually」徹底解説：「コードを書くことは元々難しくない」が流行語になった時、そろそろ決算をはっきりさせよう——市場、機械、そしてエンジニア

> 核心となるアイデア：**「コードを書くことは元々難しくない」は便益的修正主義（revisionism）であり、ちょうど AI がコードをほぼ無料にした瞬間に発明された。Promptless のエンジニアリングブログ記事「Writing code was hard, actually」は 4 本の証拠ラインでそれを解体する——タイミング（2018 年には誰もそう言わなかった。当時も要件問題は同じくらい存在した）、機械（数十億ドル + ギガワット + 専用スーパーコンピュータで「些細な」ことを*部分的に*自動化した）、市場（30 年間にわたるソフトウェアエンジニアの給与上昇——市場が 30 年間集団的に非合理だったか、コードを書くことは実際に難しかったかのどちらか）、エンジニア（LLM を作った人々は*まさに*ソフトウェアエンジニアだ——彼らはそのスキルを使ってそのスキルを部分的に自動化した）。** しかし最も鋭い一撃は、論駁の中での譲歩である：「このスキルは希少になっている」——ただし「元々すごくなかった」と書き換えないでほしい。前者は誠実な市場評価であり、後者は歴史の書き換えだ。**これはあらゆる「AI が誰を置き換え/置き換えないか」の議論に最もクリーンな論証テンプレートを提供する：「この機械は高いか？」と「市場はどれほど長く判断してきたか？」と「誰が機械を作ったか？」の 3 つの問いを立てよ——3 つの問いでナラティブは立っていられない。**

## 一、プロジェクト概要

### 1.1 これは何か？

本記事が分析するのは、**Promptless**（promptless.ai）のエンジニアリングブログに掲載された短い記事 **「Writing code was hard, actually」** である。

Promptless 自身の機能：製品を出荷し顧客サポートをする中で、カスタマー向けドキュメントを自動更新する AI ツール（"automatically updates your customer-facing docs as you ship features and support customers"）。同サイトのエンジニアリングブログは「エンジニアリングナラティブ + ドキュメント技術」を主調とし、短く、意見が明確で、無駄がない——この記事はその典型例。

記事は約 900 語（英単語）で構成されるが、構造は非常にきれいである：

1. **現象**：数日ごとに「コードを書くことは元々難しくない」という投稿が出回る
2. **暴露**：このナラティブは「便益的修正主義」である
3. **4 本の証拠**：タイミング / 機械 / 市場 / エンジニア
4. **譲歩**：その中に 1 つの真実がある——「スキルは希少になっている」（「元々すごくなかった」ではない）
5. **結び**：エンジニアがこの機械を作った——彼らは置き換えられた側ではなく、「次に来るもの」に最も答えられる側である

## 二、詳細チュートリアル：4 本の証拠ライン + 1 つの正直な譲歩 + 1 つのエンジニアへの警鐘

記事は「コード」を与えない——「論証」を与える。このセクションは論証構造を分解し、それぞれに認識可能な証拠、再利用可能な反論テンプレート、類似の実世界アナロジーを与える。

### 2.1 証拠 1：タイミングがナラティブを露呈する

**原文の論証**：

> "If writing code was never the hard part, someone should have been saying this in 2018. The requirements problem existed then. System design existed then. But nobody was writing blog posts about how coding was a trivial formality, because it obviously wasn't."

**この証拠の構造**：

- **もし X が真なら、X は X の時点より前に言われていなければならない**（時間反証）
- 2018 年、要件問題、システム設計、利害関係者とのコミュニケーション——これらの問題はすでに存在していた
- しかし**その当時「コードを書くことは元々難しくない」と書く人はいなかった**——明らかにそうではなかったから
- ナラティブは AI がコードを安くしたまさにその瞬間に現れる——**つまりこれは AI 時代の産物であり、エンジニアリングの真実ではない**

**再利用可能な反論テンプレート**：

> "もし君が主張する『X はずっとそうだった』が 2018 年には言われていなかったなら、それは『ずっとそうだった』のではなく、『新しい立場を支えるために最近発明された』だ。"

**アナロジー**：

- 2010 年には「飛行機を操縦することは元々難しくない」とは誰も言わなかった——当時は事実そうではなかった。AI 駆動の自律性が現れた後、「飛行機を操縦することは元々単なるルールマッチングに過ぎなかった」と言う人が現れ始めた
- 2015 年には「翻訳は元々難しくない」とは誰も言わなかった——当時それは事実ではなかった。ニューラル機械翻訳が品質バーを超えた（2016-2017）後、「翻訳は元々単なる言語変換に過ぎなかった」が現れた

### 2.2 証拠 2：機械が証明である

**原文の論証**：

> "If writing code were easy, you would not need the machine. You don't spend billions of dollars training a model on purpose-built supercomputers to automate something trivial."

**この証拠の構造**：

- **ツールの存在自体がタスクの些細さに対する反証である**——人間はできないこと、うまくできないことのためにツールを作る
- LLM 訓練：数十億ドル、専用スーパーコンピュータ、ギガワットの電力、数十年のアルゴリズム研究——コード生成を*部分的に*自動化するだけ
- この規模の資源を投入する対象は**「元々難しくない」ものではない**

**記事は非常に鋭い反問を使う**：

> "Can you describe the chip architecture, power delivery, and network topology required to run the coding tool you're using to declare that coding was never hard?"

コーディングを*簡単*に見せかけているツール自体が、地球上でほとんど誰も完全に理解できないエンジニアリングの奇跡である。「簡単」を作り出している機械が、まさに「難しさ」を証明している。

**再利用可能な反論テンプレート**：

> "もしそれが本当に簡単なら、それを部分的に自動化するのにこんなに高い機械を造る必要はない。"

**アナロジー**：

- 自動車フレームのロボット溶接——我々は「溶接は元々難しくない」とは言わない；溶接エンジニアは難しい問題を解決したと言う
- 執筆支援 AI——我々は「執筆は元々難しくない」とは言わない；作家は難しい問題を解決したと言う
- 「元々難しくない」レトリックを**選択的に**使うのは、**自動化されるのが君であるかどうかに依る**

### 2.3 証拠 3：市場は 30 年間騙されていなかった

**原文の論証**：

> "For thirty years, companies fought over software engineers. Salaries climbed steadily. Entire recruiting industries existed just to find people who could do the job. Was the market wrong this entire time? The 'never the hard part' crowd has to pick one: either the labor market was wildly irrational for three decades, or writing software was in fact hard."

**この証拠の構造**：

- 市場はすべての情報を集約する——**30 年間嘘はつかない**
- ソフトウェアエンジニアの給与は 30 年間着実に上昇し、専用のヘッドハンティング産業が存在し、査証政策は技術労働者に傾く——これらすべてが「コードを書く人は価値あることをしている」と語っている
- 「元々難しくない」派はどちらかを選ばなければならない：**市場は 30 年間間違っていたか、コードを書くことは実際に難しかったか**
- 市場は明らかに間違っていなかった

**再利用可能な反論テンプレート**：

> "30 年の給与データを前にして、君の『元々難しくない』は、ヘッドハンティング会社、査証政策、給与カーブがすべて逆方向に進んだ理由を説明しなければならない。"

**アナロジー**：

- 外科医は高給 / 法律事務所パートナーは高給 / シニアトレーダーは高給——市場の価格は「難しいこと」と一致している
- **「コードを書くことは元々難しくない」が成り立つなら、30 年間にわたりソフトウェアエンジニアにプレミアムを支払ったすべての人——取締役会、HR、ヘッドハンター、入国管理局——が間違っていたことになる**

### 2.4 証拠 4：エンジニアが「自分を置き換える」ツールを自分で作った

**原文の論証**：

> "It's not like a bunch of outsiders looked over at software engineers and thought, 'those lazy bastards soaking up all that pay for easy work—let's build AI to expose them.' Coal miners did not do this. Management consultants did not do this. The people who built LLMs are software engineers. Researchers who write code. Infrastructure teams who write code. ML engineers who write code. They spent their careers mastering the skill, and then used that mastery to partially automate it."

**この証拠の構造**：

- LLM を書いた人々は**まさに**ソフトウェアエンジニアである——彼らは 30 年かけて「コードを書く」スキルを習得し、その熟達を活かして**部分的に自動化した**
- これは「外部の人間が内部の人間の高給に腹を立てる」ではない——**内部の人間が自分のスキルを使って新しいツールを作った**
- 溶接ロボットを作るロボット工学者と同じ——**「溶接は元々難しくない」とは誰も言わない**

**再利用可能な反論テンプレート**：

> "ツールを作った人こそ、『簡単な仕事』をしていると言われてきた人々だ——簡単な仕事を習得することがツール作成に必要だったと認めるか、その仕事は元々難しかったと認めるか。"

**アナロジー**：

- 溶接工学者による溶接ロボットの作成——**「溶接は元々平凡」とは再構成されない**
- 翻訳者による翻訳ツールの作成——**「翻訳は元々平凡」とは再構成されない**
- 唯一の違いは、エンジニアは**組合を持たない**し**目に見える職業の盾を持たない**——だから「元々平凡」レトリックが障害なく流れる

### 2.5 正直な譲歩：その中に 1 つの真実がある

反駁の後、記事は自発的に**真実の一部を譲る**：

> "The economic value of writing code, in isolation, is declining. AI tools are making it cheaper and faster to produce working software. The mix of skills that makes an engineer valuable is shifting. Those are true, defensible claims."

**譲歩した内容**：

- **「コードを書く」という単一スキルの経済的価値は低下している**
- AI は「動作するソフトウェアを生産する」ことをより安く、より速くしている
- **エンジニアを価値あるものにするスキルの組み合わせは変化している**——コードの比率は変化し、他のスキルが上昇中

**これが誠実な部分。**

しかし記事はすぐにこの誠実さを別の主張から切り離す：

> "But that's not what people are saying. They're reaching backward in time to retroactively trivialize the skill. There's an enormous difference between 'this skill is becoming less scarce' and 'this skill was never impressive.' One is an honest market assessment. The other is rewriting history."

**記事で最も鋭い一撃**：

- 「このスキルは希少になっている」——**誠実な市場評価** ✓
- 「このスキルは元々すごくなかった」——**歴史の書き換え** ✗

**この 2 つは根本的に異なる**——後者を前者に包むことが修正主義である。

**再利用可能な認知フレーム**：

> "傾向 ≠ 書き換え"。「AI が X を安くした」は傾向であり、「X は元々簡単だった」は書き換えである。

### 2.6 エンジニアへの警鐘：エンジニアがこの機械を作った

**記事の結び**：

> "But as we adapt, it's worth remembering who made the machine. Not the executives. Not the thought leaders. Engineers made it. The same people now being called trivial built the tool being used to call them trivial. That should give everyone pause."

> "The engineers who built the modern digital world aren't suddenly less capable because their hardest problem got automated. If anything, they're the ones best positioned to tackle what comes next. They've already proven they can do hard things. Now they have better tools."

**このセクションの姿勢**：

- 感情的ではない；「エンジニアが過小評価されている」でもない
- 事実の記述 + 検証可能な予測
- **事実**：LLM を作り、スーパーコンピュータを作り、分散学習コードを書いた人々はソフトウェアエンジニアである
- **予測**：この集団が「AI 時代に次に何が起きるか」に最も答えられる
- **慰めではなく、立ち位置の回復**

### 2.7 一文要約

> **「スキルが安くなっている」≠「スキルは元々平凡だった」。** Promptless は 900 語でこの区別を明確にした。方法は単純だ：3 つの問いを立てよ——機械は高いか？市場はどれほど長く判断してきたか？誰が機械を作ったか？——3 つの問いの後、「元々平凡」は立っていられない。

## 三、洞察の要約：900 語を 5 つの核心的判断に分解する

記事の核心的論証を集約し、エンジニアリングナラティブに関する 5 つの判断を得る。

### 3.1 洞察 1：便益的修正主義が最も反駁しにくいナラティブである理由——それは「完全に間違っている」のではなく「部分的に正しい」から

**核心**：

> "It is convenient revisionism, because it arrives at exactly the moment that AI tools are making code free to produce, and it flatters exactly the people who never wrote any."

**展開**：

- 「コードを書くことは元々難しくない」は完全に間違っているわけではない——「AI がコードを安くした」という真実が混じっている
- しかし**「今安くなっている」を「元々平凡だった」へ書き換える**——これがレトリック的動作
- このレトリックは反駁しにくい。反駁者はまず真実の一部を認め、それから「だが君がほのめかしているような意味ではない」と言わなければならない——**心理的障壁が高い**

**結論**：

- この種のナラティブに反駁するには「完全に間違っている」から始めてはいけない——**「部分的に正しい」から始める**：「最初の部分は正しいが、最後の部分はその通りではない」
- 修正主義が「便益的」であるのは、**その「正しい部分」が読者に予防接種を打つ**からだ——正しい部分に反論するのは失礼だと感じ、間違った部分まで飲み込んでしまう

### 3.2 洞察 2：ツールの存在自体がタスクの些細さに対する反証である

**核心**：

> "If writing code were easy, you would not need the machine."

**展開**：

- 人間はうまくできないことのためにツールを作る
- LLM は「魔法」ではない——**数十億ドル、専用スーパーコンピュータ、ギガワット電力、数十年アルゴリズム研究**の上に構築されている
- この規模の資源が投じられるのは**部分的な自動化のためだけ**——完全な自動化は不可能だから
- 「コードを書くことを簡単にする」ツールは**それ自体がエンジニアリングの奇跡**——「簡単さ」を作り出す機械が「難しさ」を証明している

**結論**：

- あるスキルが「元々平凡だった」かどうかを評価する——**まずそれにどれだけの資源が投じられたかを見よ**
- より多くの資源 → より難しいタスク
- 逆もまた真：AI 自動化の「軽さ」≠ 元のタスクの「軽さ」——自動化は単に「軽さ」を簡単に見せかけているだけ

### 3.3 洞察 3：30 年の給与データはいかなるブログ記事よりも説得力がある

**核心**：

> "Was the market wrong this entire time?"

**展開**：

- 市場はすべての情報を集約する——**30 年間嘘はつかない**
- ソフトウェアエンジニアの給与は 30 年間着実に上昇した——これは**複数の経済周期、複数国、複数サブディシプリンにまたがる**
- 「元々難しくない」派はこれを説明しなければならない：**なぜ市場は連続 30 年間間違っていたのか？**
- 一貫した唯一の説明は：コードを書くことは難しかった

**結論**：

- あるナラティブが 30 年の市場データと矛盾するとき——**まずナラティブを疑え**
- 修正主義の特徴：「速く、もっともらしい」——しかしそれは**反事実的仮定**（「市場は馬鹿である」）を成り立たせる必要がある
- どんな「X は元々平凡だった」という主張も評価するには——**30 年の給与カーブを調べよ**

### 3.4 洞察 4：「スキルが希少になっている」と「スキルが元々平凡だった」は根本的に異なる

**核心**：

> "There's an enormous difference between 'this skill is becoming less scarce' and 'this skill was never impressive.' One is an honest market assessment. The other is rewriting history."

**展開**：

- 傾向判断 vs 歴史の書き換え——**根本的に異なる 2 つのこと**
- 「AI がコードを書くことを安くした」——**2023 年に始まった現象**（GPT-4 以降）
- 「コードを書くことは元々難しくない」——**2018 年には存在しなかった立場**
- **「今希少になっている」を「元々平凡だった」に見せかけるのは時間次元の詐欺**

**結論**：

- 「未来に関する判断」と「過去に関する判断」を区別せよ——**未来判断に過去を書き換えさせない**
- 修正主義の標準操作：「X は今 X だ」というフレーミングで「X はずっと X だった」と思わせる——前者は観察、後者は主張
- 「X が安くなっている」という誠実なフレーミングは**「X は元々平凡だった」という尾を必要としない**——尾を付けることは修正主義

### 3.5 洞察 5：機械を作った者は「次に来るもの」に最も答えられる

**核心**：

> "The engineers who built the modern digital world aren't suddenly less capable because their hardest problem got automated. If anything, they're the ones best positioned to tackle what comes next."

**展開**：

- 慰めではなく、立ち位置の回復
- LLM を書いた人々は**まさに**ソフトウェアエンジニアである
- この集団には**30 年のエンジニアリング経験**がある——「コーディング」だけが部分的に自動化され、他の能力（システム設計、要件理解、クロスチーム・コミュニケーション、機械理解）は**自動化されていない**
- この集団は**「AI 時代に何をする価値があるか」を判断する**のに最も適している——機械を理解しているから

**結論**：

- 「AI 時代に誰が置き換えられるか」を評価するには——**スキルリストではなく、スキル保持者を見よ**
- ソフトウェアエンジニアは「コーディングが部分的に自動化された」からといって置き換えられ**ない**——彼らの**職業アイデンティティ全体**はかつて「コーディング」ではなく「エンジニアリング手法で難しい問題を解決する」だったから
- 真に置き換えられるのは**単一スキルの職種**（システムを理解せずにコーディングしかしない人）であり、**エンジニアリング職業ではない**

### 3.6 5 つの洞察の関連構造

```
洞察 1：便益的修正主義（「部分的に正しい」で「部分的に間違い」を包む）
   ↓ (レトリック的手法)
洞察 2：ツールの存在がタスクの些細さに対する反証
洞察 3：30 年の市場データは嘘をつかない
   ↓ (歴史的事実)
洞察 4：傾向 ≠ 書き換え
洞察 5：エンジニアは置き換えられず、単一スキルの職種が置き換えられる
```

洞察 1 はレトリック層（「なぜこのナラティブが反駁しにくいのか」）、洞察 2/3 は事実層（「何を証拠に反駁するか」）、洞察 4 は区別層（「真実と嘘をどう切るか」）、洞察 5 は予測層（「エンジニアの今後は何か」）。**5 つ合わせて完全な「AI 時代のエンジニアリングナラティブ」論証テンプレートを構成する。**

## 四、設計哲学：900 語から Promptless のエンジニア姿勢を読む

Promptless の 900 語記事（と同サイトの他の技術投稿）は、**稀少なエンジニア姿勢**を示している——**「AI が誰を置き換え/置き換えないか」のような話題に、クリーンで、再利用可能で、感情的でない論証テンプレートを打ち立てた。** この姿勢から 4 つの設計哲学を抽出する。

### 4.1 哲学 1：「部分的に正しい」を誠実に認め、「部分的に間違い」をきれいに切る

**姿勢**：

記事は「AI がコードを安くした」を否定しない——**それは本当だ**。記事が行うのは**本当の部分を受け入れた上で、嘘の部分をきれいに切る**：

> "Those are true, defensible claims. But that's not what people are saying."

**なぜこれがよいエンジニア姿勢か**：

- 「全か無か」の二項思考を拒否——**現実世界の判断は部分的なもの**
- 「正しい部分」を読者に残す——**すでにそのナラティブを受け入れている人を辱めない**
- 「間違った部分」をきれいに切る——**読者がどちら側に従うかを選べるようにする**

**再利用可能なテンプレート**：

> "君が言ったことは本当だ——ただしその文までだ。その文から先は、君の言ったことは本当ではない。"

**アンチパターン（やってはいけない）**：

- 「AI がコードを安くした」を完全に否定する——**それは逆方向の修正主義**
- 反駁を暴言に変える——**感情的エスカレーションは論証を失敗させる**
- 「エンジニアは弱者」という姿勢を取る——**誰も保護を必要としていない**

### 4.2 哲学 2：ナラティブの反駁には感情ではなく証拠を使う

**姿勢**：

記事の全 4 つの証拠——タイミング、機械、市場、エンジニア——**はすべて検証可能な事実**。感情も、泣き言も、大げさな主張もない。

**なぜこれがよいエンジニア姿勢か**：

- エンジニア読者は**証拠だけを見る**
- 証拠に基づく反駁は**引用、複製、検証できる**
- 感情に基づく反駁は**感じることしかできず、忘れられる**

**再利用可能な反論構造**：

> "君は X と言った。X は Y 年に言われたか？X には Z の投資が必要か？X の市場データ W はどうか？X のツールは誰が作ったか？——4 つの問いがすべて立たなければ、X はナラティブであり事実ではない。"

**アンチパターン**：

- 「エンジニアとして胸が痛い」——**感情はナラティブを反駁しない**
- 「AI 炒作の人たちは分かっていない」——**人身攻撃はエンジニア読者を遠ざける**
- 「今後 5 年で君が間違っていると証明される」——**未来予測は論証ではない**

### 4.3 哲学 3：「AI 時代」の判断を時間次元に置き戻す

**姿勢**：

記事は繰り返し**時間次元**に戻る：

- "If writing code was never the hard part, someone should have been saying this in 2018."
- "For thirty years, salaries climbed steadily."
- "The 'never the hard part' crowd has to pick one"

**なぜこれがよいエンジニア姿勢か**：

- どんな「X はずっとそうだった」という主張にも**時間次元の証拠**が必要
- 時間次元の欠けた判断は**現在のナラティブ**であり、ナラティブは AI 能力と共に動く
- エンジニア読者は**歴史に敏感**——LLM 以前のエンジニアリング史を読んでいる

**再利用可能な判断フレーム**：

> 「X はずっと X だった」という主張には「なぜ 2018 年、2010 年、2000 年にはそう言われなかったか？」と問え
> 「X は今 X だ」という主張には「いつ始まったか？何が引き金か？」と問え

### 4.4 哲学 4：「それを行う人」を中心に置き直す

**姿勢**：

記事の最も鋭い一撃は、機械でも市場でもなく——**「この機械を作った人こそ『簡単な仕事』をしていると言われてきた人々だ」**：

> "The people who built LLMs are software engineers. Researchers who write code. Infrastructure teams who write code. ML engineers who write code. They spent their careers mastering the skill, and then used that mastery to partially automate it."

**なぜこれがよいエンジニア姿勢か**：

- レトリック的ナラティブは**「それを行う人」を空にする**ことがよくある——残るのは「物」と「抽象的能力」のみ
- 「それを行う人」を中心に戻すと——**ナラティブは即座にそのレトリック的力を失う**
- 「ロボットを作った人」=「簡単な仕事をしていると言われた人」——**この自己言及は避けられない**

**再利用可能な書き方**：

> 「X は AI に置き換えられている」という主張には「AI を作った人は、以前 X を行っていた人か？」と問え
> もしそうなら——**ナラティブは立たない**。
> もし違うなら——**それは新しい職業シフトだ**（議論の価値がある）。
> しかし多くの場合は前者だ。

### 4.5 哲学要約：4 つの哲学が Promptless 記事の姿勢を成す

| 哲学 | 一行 | 記事が行うこと |
|---|---|---|
| 1. 部分的に正しいを認め、部分的に間違いを切る | 二項思考を拒否 | 「スキルが希少になっている」を認め、「元々平凡だった」を切る |
| 2. 証拠がナラティブを反駁、感情ではない | エンジニアは証拠だけを見る | タイミング / 機械 / 市場 / エンジニア——4 本の証拠 |
| 3. 判断を時間次元に置き戻す | レトリックは歴史を恐れる | 2018 / 1990 / 30 年給与カーブ |
| 4. 「それを行う人」を中心に戻す | ナラティブは自己言及を恐れる | LLM を書いた人 = ソフトウェアエンジニア |

**4 つは独立ではない——それらは反駁ツールキットを構成する**：

- AI 時代ナラティブに反駁したい——**まず哲学 3 で時間次元に置く**（「以前は？」）
- 時間が持たない——**哲学 2 で証拠を探す**（市場、機械、人）
- 証拠も持たない——**哲学 1 で「正しい部分と間違った部分」を切る**
- 最後に——**哲学 4 で人を舞台上に出す**（AI を作った人が「簡単な仕事」をしていると言われた人）

**Promptless の 900 語記事は評論ではない——「AI 時代エンジニアリングナラティブ反駁」の再利用可能な方法論である。**

## 五、核心となる要約

Promptless の「Writing code was hard, actually」が AI 時代エンジニアリングナラティブに残した最も重要な遺産は、**便益的修正主義に反駁する 4 ステップの方法論**である：

1. **部分的に正しいを認める**——「AI がコードを安くした」は本当だ
2. **部分的に間違いを切る**——ただし「コードを書くことは元々平凡だった」は書き換えだ
3. **証拠で反駁する**——30 年の市場データ、機械への数十億ドル、エンジニアが作った
4. **「それを行う人」を中心に戻す**——AI を作った人こそ「簡単な仕事」をしていると言われた人

**あらゆる「X は元々平凡だった」ナラティブを倒す 3 つの問い**：

- この機械は高いか？（高い → 平凡ではない）
- 市場はどれほど長く判断してきたか？（長年 → 平凡ではない）
- 誰が機械を作ったか？（それを行う人 → 平凡ではない）

**記憶すべき一文**：

> **「スキルが希少になっている」≠「スキルは元々平凡だった」。** 前者は誠実な市場評価であり、後者は歴史の書き換えだ。Promptless は 900 語でこの区別を明確にした——AI 時代の現実の変化を否定せず、変化が「書き換え」になることを拒否した。
>
> エンジニアは「コードは元々平凡だった」というレトリックには説得されない——しかし「市場は 30 年間嘘をつかなかった」、「この機械を作った人は簡単な仕事をしていると言われた人だ」という論証には説得される。**これは反駁であり、泣き言ではない**。**Promptless の 900 語記事が AI 時代エンジニアリングナラティブに残した最もクリーンな贈り物**。
