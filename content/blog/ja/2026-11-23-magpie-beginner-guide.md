# スター 40000 の Magpie：もうツールごとに API Key を設定しなくていい、このゲートウェイがすべてのモデルをすべての AI ツールに接続する

**先に結論：** Magpie は「AI ツールをヘビーに使う人のために作られた、統一された入口」です。Magpie 自身はモデルを提供しません。行うのは 3 つのことです。手元のモデル供給元（API Key、ログイン済みのサブスクリプション、ローカルモデル）を 1 つのリストにまとめること。そのリストの中のモデルを、どの AI コーディングツールにも設定として書き込むこと。そして自分のマシン上でローカルゲートウェイを動かし、異なるベンダーのモデルがどのツールからも呼び出せるようにすること。

**その価値は「より強力」ではなく、「コスト削減と手間の削減、そして特定ベンダーへのロックインからの解放」にあります。** 手元に 3 つのサブスクリプションと 5 本の API Key があれば、以前は設定を 5 つ書き、ベース URL を 5 つ覚えておく必要がありました。Magpie を入れた後は、それらが 1 つのリストになり、速い方は速い方、安い方は安い方を使えばよくなります。

**これから紹介するのは、ゼロから始める社長のための完全入門です。** コードを書く必要はありません。コマンドをコピー＆ペーストして、マウスでクリックできるだけで十分です。

---

**一、先に押さえておく：Magpie はあなたの代わりに何をしているのか**

手を動かす前に、まず 3 つの用語を理解する必要があります。この 3 つの意味が分かれば、記事全体がスッと通ります。

**① Agent（ツール）**：普段 AI と対話して作業に使うソフトウェアのことです。Claude Code、Codex、Gemini CLI、OpenCode、Cursor CLI、Cline、OpenClaw、Windsurf、Cursor エディタの中の Chat など、数十種類あります。各 Agent はもともと自前の設定しか認識しません。

**② Provider（モデル供給元）**：モデルはどこから来るのか、ということです。3 つの形態があります。

- **API Key**：DeepSeek、Kimi、Zhipu、MiniMax、OpenAI、Anthropic の公式サイトでチャージして買った API キー。`sk-` で始まる文字列です。
- **サブスクリプション**：すでに Claude Code でログイン済みの Claude Pro/Max、ChatGPT Plus/Pro、GitHub Copilot など。Magpie はローカルにログイン済みのこれらのアカウントを読み取り、その中のモデルを直接ほかのツールと共有できます。
- **ローカルモデル**：Ollama や LM Studio が自分のマシン上で動かしているモデル。キーは不要です。

**③ Gateway（ゲートウェイ）**：Magpie が自分の PC 上で開けるローカルサービスです。アドレスは `127.0.0.1:3425` です。すべての Agent がここを指すように書き換えられ、Magpie がリクエストを実際にモデルを提供するベンダーに転送し、並行して OpenAI 形式、Anthropic 形式、Gemini 形式を相互に翻訳します。**技術的な細部を理解する必要はありません。すべてのツールが今後 1 つの出口だけになる、ということを覚えれば十分です。**

**インストール前は、今の状態が次のようになります：**

```
Claude Code  →  Anthropic 公式サイト  →  手元の Claude サブスクリプション
Codex        →  OpenAI 公式サイト     →  手元の ChatGPT サブスクリプション
Cline        →  DeepSeek 公式サイト   →  手元の DeepSeek キー
OpenClaw     →  Kimi 公式サイト       →  手元の Kimi キー
```

**インストール後はこうなります：**

```
Claude Code ─┐
Codex       ─┼→  Magpie ローカルゲートウェイ  →  { Anthropic, OpenAI, DeepSeek, Kimi, ... }
Cline       ─┤
OpenClaw    ─┘
```

**中核的なメリット：モデルを変えても設定ファイルを変更しなくてよく、一度の変更で全体に反映されます。あるベンダーの枠を使い切ると自動的に次のひとつに切り替わり、AI ツールが社長の前でエラーを出すこともありません。**

**二、初心者のための事前チェック（5 分）**

インストールする前に、まず 3 つのことを確認します。

**1 番目：自分のシステムは何ですか。**
Mac（メニューバーにアイコンが出るタイプ）、Windows（画面右下のトレイ）、Linux（デスクトップ版または純ターミナル版）。分からなくて構いません。このチュートリアルは 3 つとも対応しています。

**2 番目：モデル供給元を 1 つ以上持っている。**
サブスクリプション（Claude / ChatGPT / Copilot のいずれか）があれば最適です。持っていなければ、DeepSeek や Kimi の公式サイトで API Key を作っても構いません。国内の支払いはスムーズで、数百円で動かせます。**注意：Magpie 自体は無料オープンソースですが、モデルそのものは提供されません。** モデル供給元がないのは、ルーターを買ったのに光契約を敷いていないのと同じです。

**3 番目：すでに AI ツールを 1 つ以上導入している。**
まだ AI コーディングツールを何も導入していない場合、Magpie の Agents ページは空になります。まず Claude Code か Cursor を 1 つ入れ、戻ってきてください。

**1 行のチェックリスト：**
- [ ] 導入済みで普通に対話できる AI ツールが 1 つある
- [ ] 手元に API Key かサブスクリプションのアカウントがある
- [ ] 自分のシステムが Mac / Windows / Linux のどれか分かっている

**三、第一歩：インストール**

**3.1 最も楽な方法（初心者にはこれを推奨）**

ブラウザを開いて `usemagpie.ai` にアクセスし、自分のシステムに対応するインストーラーをダウンロードしてダブルクリックでインストールします。Mac 用のパッケージは署名済みで、Apple の公証も通っています。Windows と Linux 用のパッケージにも GitHub Actions のビルド来歴の証明があります。

**なぜこれを推奨するのか？** ターミナル上で起こりうるすべてのエラーを回避できるからです。ダウンロードしたファイルが本当に公式ビルドによるものであることを確認したいなら、ターミナルで次を実行できます（GitHub CLI のインストールが前提です）：

```bash
gh attestation verify magpie-darwin-arm64.dmg -R yetone/magpie-releases
```

ビルドしたワークフローと実行番号が表示され、公式ビルドでないファイルなら失敗します。

**3.2 ターミナルでの 1 コマンドインストール**

コマンドラインに慣れているなら（Mac と Linux のユーザーに推奨）：

```bash
curl -fsSL https://usemagpie.ai/install.sh | sh
```

この 1 行で 3 つの処理がまとめて行われます。システムに合うビルドのダウンロード、インストール、そして `magpie` コマンドを PATH に追加します。

**3.3 中国国内ネットワークではプロキシが必要**

公式サイトや GitHub にアクセスできないネットワークなら、引数を付けます：

```bash
curl -fsSL https://usemagpie.ai/install.sh | sh -s -- --proxy http://127.0.0.1:7890
```

`7890` は自分のプロキシソフトのポートに置き換えてください。HTTP、HTTPS、SOCKS5、SOCKS5H の 4 つのプロトコルに対応しています。GitHub のダウンロードミラーを使っているなら、`--mirror https://あなたのミラー接頭辞/` をさらに追加できます。**安心してください：どの経路を選んでも、ダウンロードファイルの SHA-256 チェック値は常に公式サイトから取得され、ミラーがファイルを書き換えていれば直接拒否されます。**

**3.4 Linux ユーザー向けの補足**

Linux ではインストールスクリプトが自分で判定します。

- GUI デスクトップがあり、WebKitGTK 4.1 が既に導入済み → **デスクトップ版**をインストール（ウィンドウがあり、トレイアイコンもあります）
- GUI デスクトップはあるが WebKitGTK 4.1 が無い → スクリプトがパッケージマネージャで導入し（`sudo` パスワードの入力が必要）、デスクトップ版を入れます
- デスクトップが無い（純サーバー）あるいは `sudo` を使うのが怖い → **ターミナル版**をインストール、コマンドライン UI のみ

バージョンを自分で指定する場合：

```bash
curl -fsSL https://usemagpie.ai/install.sh | sh -s -- --gui    # デスクトップ版を強制
curl -fsSL https://usemagpie.ai/install.sh | sh -s -- --tui    # ターミナル版を強制
```

**3.5 インストール成功の確認**

ターミナルを開いて（Mac なら「ターミナル」アプリ、Windows なら PowerShell）、次を入力します：

```bash
magpie --version
```

バージョン番号が出力されれば、インストールは成功です。

もう 1 つ入力すると、マシン上のすべての AI ツールと現在の設定が一覧表示されます：

```bash
magpie ls
```

**この表が見えたら、インストールは成功です。** この表が今後の日々確認するダッシュボードになります。

**四、第二歩：モデル供給元を追加する**

Magpie を開きます。Mac は右上のメニューバーアイコンから、Windows は右下のトレイから、右クリックして `Open magpie` を選択します。

**4.1 API Key のベンダーを追加する（最も多いケース）**

1. 画面上部の **Providers**（モデル供給元）タブをクリックします。
2. **`＋ Add provider`**（モデル供給元を追加）をクリックします。
3. 表示されるパネルにはベンダーのアイコンが並んでいます。キーを買ったベンダーを探してください（DeepSeek、Kimi、Zhipu、MiniMax、Alibaba Bailian、Volcano Ark、Tencent Hunyuan、SiliconFlow、OpenRouter、`xAI`、OpenAI、Anthropic、Gemini などが揃っています）。
4. クリックして、キーを入力欄に貼り付けて保存します。

**各社のキーはどこで取得しますか？** 各ベンダーの隣に **`Get a key ↗`** という小さな矢印があり、クリックすればそのベンダーのキー管理ページに直接ジャンプします。**サードパーティののページからキーを買わないでください。必ずベンダーの公式サイトから取得してください。**

**4.2 サブスクリプションのアカウントでログインする（最も安い使い方）**

同じ `Add provider` パネルで、**Claude**、**ChatGPT**、**GitHub Copilot**、**Gemini Code Assist** といったサブスクリプションのカードをクリックすると、Magpie が自動的にベンダーの公式ログインページを開いて認証ログインさせてくれます。**ログイン後、そのサブスクリプションが 1 つの Provider になり、その中のモデルをどのツールからでも使えます。**

ここには非常に重要な仕組みがあります。**1 つのサブスクリプションに複数のアカウントを追加できます。** 例えば Claude のアカウントが 2 つ、ChatGPT のアカウントが 1 つあるなら、Claude カードをもう一度クリックすると 2 つ目のアカウントを追加できます。Magpie はその候補集合の中で自動的に配分し、1 つ使い切ると次に切り替えるため、「枠を使い切りました」というエラーを見ることはありません。

**重要なお知らせ（公式が明言しています）：** Claude サブスクリプションのリクエストはローカルにインストールされた Claude Code を経由して転送されるため、Claude Code は必ずマシンに残しておいてください。Google も、アカウントが Antigravity 以外で使われていることをリスク管理の対象にされる可能性があるため、**実験には Antigravity のアカウントを使い、主力のアカウントは使わないでください。**

**4.3 ローカルモデル**

Ollama や LM Studio を導入済みなら、`Add provider` パネルで **Ollama** または **LM Studio** を選び、キーは不要でポート番号を入れるだけです（Ollama のデフォルトは 11434）。**コスト面に注意：ローカルモデルは無料ですが、遅いのです。** 日々のフォールバックとして使い、主力にはしないのがコツです。

**4.4 あらゆる互換 API（万能の選択肢）**

他のサービスを使っていて、OpenAI または Anthropic 形式に互換なら、**Custom** を選び、3 つの項目を入れます。名前、ベース URL（OpenAI 互換の場合は `/v1` で終わり、Anthropic 互換の場合はルートアドレス）、そしてキーです。Magpie は各 API に対し、それがネイティブに対応できる形式を割り当て、必要な形式をそのまま使い、もう一方は Magpie が翻訳します。

**4.5 既存設定のインポート（手間の節約手段）**

`Add provider` パネルの上部に **`Import…`** ボタンがあり、クリックすると Claude Code の `settings.json`、Codex の `config.toml`、CC Switch、Alma 内の設定を読み取り、中のモデル供給元をそのまま Magpie へ取り込めます。**読み取るだけで変更はしません。元のファイルはそのままです。** すでに大量のキーを設定済みなら、このステップで 30 分は節約できます。

**4.6 重要なセキュリティ上の注意**

**Magpie のキーは `~/.config/magpie/providers.json` に保存され、読めるのは自分だけです。** シェル環境変数からキーを読み取ることは**ありません**。追加したものをそのまま使い、`export` した他のキーを勝手に再利用することもありません。この設計は非常に抑制的で、信頼に値します。

---

**五、第三歩：ツールごとにモデルを選ぶ**

**5.1 GUI での操作**

1. 上部の **Agents**（ツール）タブをクリックします。
2. ページの上の行が 1 つで、1 つの AI ツールを表します。右の列には現在使っているモデルが書かれています。
3. **そのモデル名をクリックすると**、検索可能なリストがポップアップします。3 つのグループに分かれます。ツール固有のモデル、あなたのルーティンググループ、そして追加したすべての Provider 配下のすべてのモデルです。
4. 欲しいモデルを直接クリックするか、キーワードで絞り込みます。

**クリックした瞬間に、Magpie がそのツールの設定ファイルを書き換えます。** 変更されるのは必要なキーだけで、コメント、順序、インデントはすべてそのまま保持され、書き込みはアトミックです（途中で電源が落ちても半分のファイルは残りません）。

**5.2 具体的にどのファイルが変わるのか**

この表は社長が一度目を通す価値があります。「Magpie はものを壊さない」ことの証拠だからです。

| ツール | 変更される設定ファイル |
|------|------------------|
| Claude Code | `~/.claude/settings.json`：ANTHROPIC_BASE_URL、ANTHROPIC_AUTH_TOKEN とモデル項目を書き込む |
| Codex | `~/.codex/config.toml`：`[model_providers.magpie]` セクションとモデル設定を追加 |
| Gemini CLI | `~/.gemini/settings.json` と `~/.gemini/.env` |
| OpenCode | `~/.config/opencode/opencode.json(c)` |
| Cursor CLI | `~/.cursor/cli-config.json` |
| Cline / Roo / OpenClaw など | それぞれの既定の設定ファイル |
| VS Code Chat、Zed、JetBrains | エディタ自身の設定ファイル |

**すべて「キーが 1 つだけ変更」であって、「ファイル全体を書き直し」ではありません。**

**5.3 コマンドラインでの操作（より速い）**

```bash
magpie claude deepseek/deepseek-v4-pro      # Claude Code を DeepSeek にする
magpie codex moonshot/kimi-k2.5             # Codex を Kimi にする
magpie opencode anthropic/claude-sonnet-5   # OpenCode を Claude にする
magpie codex effort high                    # 推論強度も高めにしておく
```

**モデル名の形式は `ベンダー/モデル名`** です。例えば `deepseek/deepseek-chat`、`moonshot/kimi-k2.5` となります。`magpie models` で現在のすべての Agent が選べるモデルを一覧表示できます。

**5.4 最も重要な 1 ステップ：新しいセッションを開く**

**ここに 90% の人が最初に詰まるところがあります：** すでに開いているセッションではモデルが変わりません。Agent はすべて起動時に設定ファイルを読んでいるからです。

したがって、**モデルを選んだら、現在のセッションを終了して、新しく開き直してください。** Codex の利用者はさらに Codex アプリごと完全に終了して起動し直す必要があります（モデルリストは起動時に生成されます）。

**5.5 実際に反映されたかの確認**

```bash
magpie ls
```

そのツールの行に書かれたモデルが変わったかを見てください。変わっていれば正解です。

**あるいは使用量ページを見ます**：Magpie には Usage（使用量）タブがあり、ツールごと、モデルごとに何 token を使い、どれだけコストがかかったか、どの Provider を通ったかを表示します。**このページが、今後のコスト振り返りの根拠になります。**

---

**六、第四歩（任意ですが強く推奨）：ルーティンググループで枠を自動的にリレーさせる**

モデル供給元が 1 つより多い場合（サブスクリプションが 2 つ、あるいはサブスクリプションと API Key の組み合わせ）、ツールに 1 つのモデルしか認識させるべきではありません。**枠を使い切ると自動的に次へ切り替わる機能は、Magpie が持つ事業上の価値として最も高い機能です。**

**6.1 1 つのモデルに複数の供給元があるケース**

Claude サブスクリプションと Copilot、そして Anthropic の API Key を 1 つずつ持っているとします。いずれも Opus 系を提供します。Magpie はこれらを自動的に 1 つのグループにまとめ、`auto/claude-opus-4.6` という名前をつけます。Agent の中でこのグループを選べば、リクエストは自動的にこれらの供給元のあいだで配分されます。

**6.2 手動でグループを作る**

コマンドラインではこう書きます：

```bash
magpie group add "Opus anywhere" models=claude/claude-opus-5-5,copilot/claude-opus-5.5 routing=smart
magpie claude group/opus-anywhere
```

**6.3 配分戦略は 9 種類、どれを選ぶ？**

| 戦略 | 挙動 | どんな場面で使うか |
|------|------|-----------|
| **`smart`（賢い、デフォルト）** | 「そろそろリセットされるけどまだ使いきっていない」サブスクリプションを優先し、無駄に期限切れにするのを避ける | 日常業務、**デフォルトはこれ** |
| `order`（順序） | 1 番目を限界まで使い、次へ移る | 特に優先して使いたい主力モデルがあるとき |
| `rotate`（ローテーション） | リクエストごとに供給元を切り替える | 各アカウントの枠を均等に消化したいとき |
| `usage`（使用量が少ない順） | 残っている量が多い方を使う | アカウント間の枠の差が大きいとき |
| `pace`（期限が近い順） | 今週で期限が切れるもの、損失が大きいものから使う | サブスクリプションを月末に無駄にしたくないとき |
| `weight`（重み付け） | 設定した比率でトラフィックを振り分ける | 安いモデルに多くのトラフィックを配りたいとき |
| `fast`（速度優先） | 最近応答が速かった方を使う | 応答速度に敏感な場面 |
| **`cheap`（最安優先、グループでのみ利用可能）** | 一番安い方を使う | **純粋なコスト最適化、社長はこれを最も使うべき** |

**社長への率直なアドバイス：日常は `smart`、バッチ処理や無人実行タスクは `cheap` を使ってください。** 安いモデルに雑用を任せ、高価なモデルを判断が必要な作業に残す、これが AI によるコスト削減の真の目玉です。

**6.4 枠のダッシュボード**

```bash
magpie quota
```

このコマンドは、各サブスクリプションと各キーが残りいくら、いつリセットされるかを教えてくれます。**週に 1 回は確認することを勧めます。** サブスクリプションの枠は何もせず消えていくものです。ひと目見るだけで、モデルを替えるべきかどうかが分かります。

**七、第五歩（任意）：設定プロファイルで作業モードを一括切り替え**

**こんな場面はありませんか**：日中は安いモデルで日常業務、夜は最強モデルで複雑なアーキテクチャを直す。または「自分の Claude サブスクリプション」と「会社の API Key」の切り替え。設定を手で書き換えるのは面倒です。

Agents ページの下にある **`＋ Save current`** をクリックすると、現在のすべてのツール設定をプロファイルとして保存できます。たとえば「節約モード」と「攻略モード」みたいな名前を付けられます。あとはプロファイルを 1 回クリックするだけで、すべてのツールが同時に切り替わります。

```bash
magpie save work      # 現在のすべての設定をプロファイル work として保存
magpie use work       # work に戻す
magpie profiles      # どのプロファイルがあるか表示
```

**この機能の社長にとっての本当の価値：「AI の使用量」を管理可能なアクションに変えることにあります。** チームの誰がどのモデルを使いいくらかかっているかを把握し、プロファイルを切り替えるだけで管理できます。

**八、第六歩（強く推奨）：プライバシーマスキング**

**この節は、私が考える限り記事全体の中で最も価値のある部分です。必ず読んでください。**

**問題は何ですか？** AI ツールは、あなたが読み込んだ内容をプロンプトに詰めて送信します。これにはプロジェクトの `.env` ファイル、設定ファイル、ログの中のトークンが含まれます。プロンプトにうっかり API Key、パスワード、顧客のメールアドレスが混ざると、そのままモデル提供者に送信されます。

**Magpie のアプローチ（最初から使える、ローカルで完結）：**

1. **Settings → Privacy** でマスキングを有効にします（デフォルトではオフなので、**手動でオンにするのを忘れずに**）。
2. Magpie は**あなたのマシン上で**キー、パスワード、メールアドレスなどの値をプレースホルダーに置き換えます。たとえば `{{API_KEY_k3v9x2mq}}` のような形です。
3. 送信されるのはプレースホルダーなので、**ベンダーがあなたの本物のキーを見ることは決してありません**。
4. モデルの応答にプレースホルダーが含まれて戻ってきたら、Magpie がローカルで実値に戻すので、ツールはこれまでどおり使えます。

**設計の細部を見ると、丁寧に作り込まれていることが分かります：**

- 同じ値は毎回**同じプレースホルダー**に置き換わるので、会話の文脈、プロンプトのキャッシュ、思考署名が失効しません。
- 値は**メモリ上にしか存在せず**、ディスクには「種類、長さ、先頭の何文字か」しか記録しません。値そのものは書きません。
- マスキングが有効なのに機能しない場合、リクエストは**保留されて送信されません**（503 が返る）。原文をそのまま送ることはありません。
- 内蔵ルールは API Key、秘密鍵、トークン、メールアドレス、チェックサム一致のカード番号や身分証番号をカバーします。独自のキーワードや正規表現も追加できます。
- 書き換えられたリクエストは **Insights → Masking** で 1 件ずつ確認できます。何が書き換わり、ベンダーが実際に何を見たのかを照合できます。

**代償は明確に：** モデルが見るのは `{{API_KEY_xxx}}` で本物のキーではないため、「このトークンがなぜ拒否されたのか」といった質問には答えません。この種の値は `Never mask` リストに入れてください。**あらゆるセキュリティ施策の宿命なので、把握しておけば十分です。**

**社長の視点で一言：これは「会社が本物の業務データを AI に渡してもよい」と判断できるスイッチです。オンにしなければ、開発部の同僚が迟早本番環境の鍵をモデル提供者に送ってしまいます。**

**九、よくある問題の切り分け（そのままでよいです）**

**問題 1：Agent が 502 を返す、または接続できず、Magpie の Routing ページが空です。**

**これは国内で最も多い落とし穴で、90% はプロキシソフトが原因です。** `Surge` / `Clash` / `mihomo` がシステムプロキシや TUN モードを有効にしていると、`127.0.0.1:3425` 宛のリクエストまでプロキシされてしまい、Magpie に届きません。

**対処：ローカルアドレスに直行ルールを追加し、ほかのルールの一番前に置きます。**

Surge：
```
IP-CIDR,127.0.0.0/8,DIRECT,no-resolve
IP-CIDR6,::1/128,DIRECT,no-resolve
```

Clash / `mihomo`（`rules:` の下に置き、各行の先頭に `-` を付けます）：
```yaml
- IP-CIDR,127.0.0.0/8,DIRECT,no-resolve
- IP-CIDR6,::1/128,DIRECT,no-resolve
```

設定したら Agent に新しいリクエストを 1 回送ってください。**この対処は覚えておいてください。2 時間を節約できます。**

**問題 2：モデルを替えたのに、Agent がまだ古いままです。**

理由は 3 つあります。① セッションを開き直していない。② Codex のアプリを再起動していない。③ ツールの設定ファイルを変更したが、そのツールが読んでいるのは別の環境変数だった。

順番に試します：現在のセッションを閉じる → 新しいセッションを開く → それでもだめなら Codex アプリを完全に終了して起動し直す。

**問題 3：Magpie の設定を変更したら、手動で入れた設定が消えますか？**

消えません。Magpie は毎回ファイルを読み直し、自分が扱うキーだけを変更します。手書きのコメント、ほかの設定項目、インデントはすべて保持されます。

**問題 4：あるツールを元の状態に戻すには？**

```bash
magpie claude default
```

書き込んだ内容を取り消し、もとの `ANTHROPIC_BASE_URL` などの値を復元します。GUI の中でそのツール自身のモデルを選ぶのと同じ効果です。

**問題 5：Magpie は起動しっぱなしで必要ですか？**

**Magpie のモデルを使うなら、起動していなければなりません。** ゲートウェイはアプリと一緒に動くからです。

常駐させる方法は 3 つあります：

```bash
magpie tray              # メニューバー/トレイアイコンだけ残す（自動起動に登録）
magpie serve             # ゲートウェイだけを動かし、ウィンドウは開かない
magpie daemon install    # システムサービスとして登録。Linux は systemd、Mac は launchd で、起動時に自動開始
```

`magpie daemon install --web` なら Web 版の画面も一緒に立ち上がります。**社長への提案：`magpie daemon install` でサービスとして登録して、アイコンを手でクリックすることを当てにしないでください。**

**問題 6：Linux でインストールしたのにターミナル画面だけです。デスクトップ版に切り替えたい。**

表示された指示どおり WebKitGTK 4.1 を導入します：

```bash
sudo apt install libwebkit2gtk-4.1-0     # Debian / Ubuntu
sudo dnf install webkit2gtk4.1            # Fedora
sudo pacman -S --needed --noconfirm webkit2gtk-4.1   # Arch
sudo zypper install libwebkit2gtk-4_1-0   # openSUSE
```

導入後にもう一度インストールスクリプトを実行します。

**問題 7：完全にアンインストールして、ツールを元の状態に戻すには？**

```bash
curl -fsSL https://usemagpie.ai/install.sh | sh -s -- --uninstall
```

まずすべての Agent の接続を解除して元の設定に戻し、その後インストールしたものを削除します。**設定と Provider は `~/.config/magpie` に残ります。`--purge` を付けて初めて一緒に削除されます。**

**問題 8：パソコンを替えたときは？**

```bash
magpie backup                       # バックアップ（パスワードを 2 回設定する）
magpie restore magpie.magpie-backup # 新しいパソコンで復元
```

設定画面から WebDAV、S3、暗号化された GitHub リポジトリに同期することもできます。**バックアップファイルにはデフォルトで API Key は含まれません。** キーごと持ち運ぼうとするなら、パスフレーズを設定してください。

**十一、Magpie はデータを送り出すのか？（社長必読のセクション）**

**結論：あなたのプロンプト、応答、キー、アカウントは、自分で選んだモデル提供者にだけ送られます。Magpie 自身は間に立つサーバーを立てていません。** ただのローカル中継装置です。

**デフォルトでは毎日 1 回、使用統計を報告します。** 内容は次のとおりです。ランダムに生成された ID（手元のマシンで生成）、バージョン番号、システム情報、どの `agent` / `provider` / モデルを使ったか（Magpie 自身の ID を使い、自分で追加したものは custom とだけ記す）、どのプラグインを入れ、どの市場の MCP を使ったか。**名前、URL、アカウント、キー、プロンプト、使用量の明細は一切含みません。**

**停止する方法**（3 つのいずれか）：
- 設定 → Privacy で項目ごとにオフにする。
- 環境変数に `DO_NOT_TRACK=1` を設定する。
- 環境変数に `MAGPIE_NO_STATS=1` を設定する。

**ほかに 2 つだけ知っておいてください：**

- ローカルにログイン済みの Claude Code と Codex のログイン情報（キーチェーン内）を読み取ります。読ませたくない場合は、**設定 → Privacy → サブスクリプションアカウント**をオフにするか、`magpie accounts discovery off` を実行してください。**API Key タイプの供給元には影響せず、そのまま使えます。**
- 公式ドキュメントの `/docs/privacy` に、報告される内容がすべて記載されています。

**社長の判断基準：もし会社が「データの海外移転」に法的要件があるなら、そのページを読んでください。** 同类产品のほとんどより細かく書かれていて、プラグインのアイコンが Cloudflare のプロキシを通る、クリック数だけを数えて ID は残さないといった細部まで載っています。**これは減点要素ではなく加点要素です。**

**十二、最後：この仕組みは社長にとって何を意味するか**

技術は終えたので、現実の話をしましょう。

**第 1 層、費用。**
いま AI のサブスクリプションをいくつ持っていますか？ 毎月のコストは明細と合っていますか？ Magpie の Usage ページは、ツールごと、モデルごと、キーごとの支出を一覧で見せてくれます。ルーティンググループの `smart` と `cheap` 戦略を併用すれば、**同じ作業でも 30% から 60% 節約できるのが普通です。** 以往は 1 つのモデルですべての仕事を賄っていたのが、任務の難度に応じて分流できるからです。

**第 2 層、人（チーム）。**
新しく入ったエンジニアが「キーはどこ、ベース URL はどう書く」と聞く必要がなくなります。コマンド 1 行 `magpie claude deepseek/deepseek-chat` で終わりです。**これは「新人が 2 日かけて環境を整える」コストを削ったことになります。**

**第 3 層、資産。**
あなたのモデル供給元（サブスクリプション、キー、設定）の一覧は、バックアップも引き継ぎもできるリストになりました。`magpie backup` 1 行のコマンドで持ち運べます。パソコンを替えても、人が替わっても、「キーの場所を知っているのはある特定の担当者だけ」という状況になりません。

**第 4 層、リスク。**
プライバシーマスキングによって、開発担当者が本番環境の鍵をモデル提供者に送ってしまうというほぼ必然的に起きること、を社内で処理できるようになりました。**この 1 項目は、前の 3 項目の合計に匹敵する価値があると考える。**

**第 5 層、そして最も重要な層：あなたはロックインされません。**
今日は OpenAI が値下げ、明日は Anthropic が値上げ、後日はさらに強い新しいモデルが出てくる。Magpie を入れれば、ベンダーの切り替えはクリック 1 回で済み、全社で設定を書き換える技術プロジェクトにはなりません。**これは「AI ツール」を固定資産から可変コストに変える能力です。**

**十三、導入の進め方（一度に全部やらないでください）**

**1 日目**：Magpie をインストールし、API Key を 1 つ追加して、ツールを 1 つだけ（たとえば Cline）変更し、1 日試運転します。動くことを確認してから次へ進みます。

**2 日目**：手元の他のサブスクリプションもログインさせ、ルーティンググループを 2 つ作ります。日常は `cheap`、攻めの作業は `smart` です。`magpie quota` と Usage ページの使い方を覚えてください。

**3 日目**：プライバシーマスキングをオンにします。すべてのツールにプロファイル（節約 / 攻め）を 1 つずつ設定します。`magpie ls` を 1 回実行して保存し、チームの標準設定の基準にしてください。

**2 週目**：チームが 3 人を超えるなら、LAN 共有と、クライアントごとの独立キーおよび支出上限を有効にします。この 1 歩を踏み出せば、AI 支出に対する完全な管理能力が獲得できます。

**やってはいけないこと：** 最初から 20 個のツールの設定を全部変えて、複数をまとめて開き直さないこと。何かあったときに切り分けできません。1 つずつ変えて、1 回ごとに検証してください。

**最後のまとめ**

Magpie が 40000 以上のスターを得たのは、より強いモデルを使えるようにしたからではなく、誰もがうるさかった一件事を解決したからです：**モデルとツールの組み合わせの獄。**

その仕事を社長の言葉で言い換えると 4 つに尽きます。

**第一に、散らばったモデル供給元を 1 つのリストにまとめること。第二に、「モデルを替える」を設定書き換えからクリック 1 回に変えること。第三に、枠を使い切ると自動的に次へリレーさせ、ツールが目の前でエラーを出さないこと。第四に、データが外に出る前に、自分のマシン上で先に鍵を置き換えること。**

最初の 3 つは効率、最後の 1 つは安全です。**この 4 つが揃ってこそ、午後の数時間を使ってまで導入する価値があると思う理由です。**
