# AI Knowledge Graph：非構造化ドキュメントからインタラクティブな知識グラフへ

情報爆発の時代、私たちは毎日大量の非構造化テキストに触れています。研究論文、技術文書、企業レポート、無数の書籍——これらのコンテンツには貴重な知識が眠っていますが、パズルの断片のように散らばっていて、全容を把握することが難しいものです。非構造化テキストから価値ある情報を抽出し、概念間の関係を直感的に提示するにはどうすればいいでしょうか？**AI Knowledge Graph Generator**プロジェクトが私たちにエレガントな解决方案を提供します。

## プロジェクト概要

**AI Knowledge Graph Generator**は、開発者[robert-mcdermott](https://github.com/robert-mcdermott)によって作成されたオープンソースプロジェクトで、現在GitHubで**2.8k Stars**と**388 Forks**を獲得しており、**Apache-2.0**オープンソースライセンスを採用しています。

このプロジェクトのコア機能は、任意の非構造化テキストドキュメントを**インタラクティブな知識グラフ**に変換し、ユーザーがドキュメント内のエンティティ、概念、およびその関係性を視覚的に探索できるようにすることです。

### 主な特徴

- **広範な互換性**：Ollama、LM Studio、OpenAI、vLLM、LiteLLMを含む任意のOpenAI互換APIエンドポイントをサポート
- **インテリジェントなテキストチャンキング**：大きなドキュメントをLLMコンテキスト処理に適した重複チャンクに自動的に分割
- **SPOトリプル抽出**：各テキストチャンクから主語-述語-目的語トリプルを抽出
- **エンティティ標準化**：ドキュメントチャンク全体でエンティティ命名の一貫性を確保
- **関係推論**：切断されたコンポーネント間の推移関係を自動的に発見
- **インタラクティブな可視化**：PyVisライブラリを使用した美しいインタラクティブなHTML可視化を生成

## コアデザイン哲学

### なぜ知識グラフなのか？

従来のテキスト読書は、いくつかのコアな課題に直面しています：

1. **情報の断片化**：長いドキュメント内の重要な情報はあちこちに散らばっていて、グローバルな把握が難しい
2. **暗黙の関係**：テキスト内のエンティティ間の関係は文内に隠されていることが多く、直感的には発見しにくい
3. **知識のサイロ**：異なるドキュメント間の関連性は往々にして見落とされる

知識グラフはテキストを**エンティティ（Entity）**と**関係（Relation）**に分解し、グラフ構造で保存することで、以下を可能にします：

- ドキュメントのコア内容をを一目で確認
- 異なる概念間の接続を素早く識別
- グラフのトラバーサル 통해隠された接続を発見

### SPOトリプル：知識の原子表現

SPO（Subject-Predicate-Object）トリプルは知識表現の基盤です。あらゆる知識は主語、述語、目的語に分解できます。

例えば、テキスト「*PythonはGuido van Rossumによって作成されたプログラミング言語です*」から、以下を抽出できます：

- **主語（Subject）**：Python
- **述語（Predicate）**：によって作成された
- **目的語（Object）**：Guido van Rossum

この表現形式は简洁でありながら強力で、自然言語の豊かな表現を機械処理可能な知識ユニットに変換し、その後の推論とクエリの基盤を築きます。

## ワークフロー詳細解説

AI Knowledge Graph Generatorの処理フローは5つのコアステージで構成されています：

### 第1ステージ：ドキュメントチャンキング（Text Chunking）

長いドキュメントは、LLMコンテキストウィンドウサイズに適した重複チャンクに分割されます。

```
元のドキュメント → 重複チャンク1 → 重複チャンク2 → 重複チャンク3 → ...
```

チャンキング戦略の重要なパラメータ：
- **チャンクサイズ**：各チャンクに含まれるトークン数
- **オーバーラップ**：隣接チャンク間の重複率

この重複設計により、境界にあるエンティティと関係が切断されることがなく、知識抽出の完全性が保証されます。

### 第2ステージ：SPOトリプル抽出

各テキストチャンクに対して、システムはLLMを呼び出してSPOトリプルを識別・抽出します。

```
入力：「AppleがiPhone 15を発表、A16チップを採用」

出力：
- (Apple, 发表した, iPhone 15)
- (iPhone 15, 采用した, A16チップ)
```

このステージはプロセス全体の中核であり、LLMのプロンプト設計が抽出品質に直接影響します。

### 第3ステージ：エンティティ標準化（Entity Canonicalization）

チャンキング処理により、同一のエンティティがifferentチャンクで異なる表現形式出現する可能性があります。

例えば：
- 「Python」vs「Pythonプログラミング言語」
- 「Guido van Rossum」vs「Guido」

エンティティ標準化ステージでは、LLM支援による**エンティティアライメントと解決**を使用して、同一のエンティティが統一された命名を使用することを保証し、知識グラフ内の冗長性と曖昧さを避けます。

### 第4ステージ：関係推論（Relation Inference）

抽出されたトリプルに基づいて、システムは切断されたコンポーネント間の推移関係を自動的に推測します。

例えば：
- 已知：(A, 位于, B) と (B, 位于, C) → 推論：(A, 位于, C)
- 已知：(X, 是, Y) と (Y, 包含, Z) → 推論：(X, 包含, Z)

この推移推論により、知識グラフの接続性が 크게強化され、暗黙の知識が表面に浮かび上がります。

### 第5ステージ：インタラクティブな可視化

最終的な知識グラフは、**PyVis**ライブラリを使用してインタラクティブなHTML可視化を生成します。

PyVisは、vis.jsベースのPythonライブラリで、ネットワークグラフ可視化の生成に特化しています。生成されたHTMLファイルは任意のモダンブラウザで開くことができ、豊富なインタラクティブ機能をサポートしています。

## 可視化の特徴

生成されたインタラクティブな知識グラフには、以下の視覚的特性があります：

### コミュニティ検出とカラーコーディング

**Louvain法**を使用してコミュニティ検出を行い、緊密に 연결된ノードは同じコミュニティに分類され、同じ色でマークされます。

これにより、知識グラフ内の主要なトピッククラスターを一目で識別できます。

### ノードサイズと重要度

ノードサイズは複数の重要度指標に基づいています：
- **次数中心性（Degree Centrality）**：そのノードと直接相连するエッジ数が越多越大
- **媒介中心性（Betweenness Centrality）**：そのノードが他のノードを接続するブリッジとして機能する頻度
- **固有ベクトル中心性（Eigenvector Centrality）**：隣接ノードの重要度を考慮した総合指標

### エッジの視覚的区別

- **実線**：テキストから直接抽出された元の関係
- **破線**：システムにより自動的に推測された推移関係

この区別により、ユーザーは「確実な事実」と「推論された結論」を区別できます。

### インタラクティブ制御

可視化インターフェースは以下の完全なインタラクティブ操作をサポートしています：

| 操作 | 機能 |
|------|------|
| ズーム | マウスホイールまたはトラックパッドでビューをズーム |
| パン | キャンバスをドラッグしてビューを移動 |
| ホバー | マウスをホバーするとノード/エッジの詳細情報を表示 |
| フィルター | タイプ、重みなどの条件に応じて表示をフィルター |
| 物理制御 | ノード間の引力・反発力を調整 |

### テーマサポート

**ライト**と**ダーク**の2つのテーマを提供し、異なる使用環境と個人の好みに適応します。

## 詳細なインストール設定教程

### 環境要件

- Python 3.8以上
- OpenAI互換API（ローカルまたはクラウド）

### インストール手順

```bash
# 1. リポジトリをクローン
git clone https://github.com/robert-mcdermott/ai-knowledge-graph
cd ai-knowledge-graph

# 2. 依存関係をインストール
pip install -r requirements.txt

# 3. APIエンドポイントを設定
export OPENAI_API_BASE="http://localhost:11434/v1"  # Ollamaの例
export OPENAI_API_KEY="your-api-key"  # ローカルOllamaでは任意の値を設定可能
```

### Ollamaローカルモデル設定（推奨）

ローカルで実行したい場合は、Ollamaの使用をお勧めします：

```bash
# Ollamaをインストール
# macOS/Linux: https://ollama.ai
# Windows: WSLまたはDocker経由

# モデルをダウンロード
ollama pull llama3.2

# Ollamaサービスを起動（デフォルトポート11434）
ollama serve

# 環境変数を設定
export OPENAI_API_BASE="http://localhost:11434/v1"
export OPENAI_API_KEY="ollama"  # Ollamaは実際のキーを必要としない
```

### クイックスタート

```bash
# 基本的な使用方法
python generate-graph.py --input your_text_file.txt --output knowledge_graph.html

# ローカルモデルを使用
python generate-graph.py \
    --input research_paper.txt \
    --output knowledge_graph.html \
    --api-base http://localhost:11434/v1 \
    --model llama3.2

# チャンキングパラメータを指定
python generate-graph.py \
    --input large_document.txt \
    --output knowledge_graph.html \
    --chunk-size 1000 \
    --overlap 200
```

## 使用例とベストプラクティス

### 例1：研究論文の分析

```bash
# arXiv論文をダウンロードして知識グラフを抽出
curl -s https://arxiv.org/pdf/2301.XXXXX.pdf | pdftotext - | \
python generate-graph.py \
    --input /dev/stdin \
    --output paper_graph.html \
    --chunk-size 800
```

### 例2：技術ドキュメントの分析

```bash
# プロジェクトのREADMEを分析
python generate-graph.py \
    --input /path/to/project/README.md \
    --output readme_graph.html

# 複数のドキュメントを分析（マージ経由）
cat doc1.md doc2.md doc3.md > combined.txt
python generate-graph.py \
    --input combined.txt \
    --output combined_graph.html
```

### ベストプラクティス

1. **適切なモデルの選択**
   - ローカルデプロイメント：Llama 3.2、Qwen 2.5（速度と品質のバランス）
   - クラウドAPI：GPT-4o、Claude 3.5（より高い精度）

2. **チャンクサイズの調整**
   - 学術論文：600-1000トークン（完全な文を維持）
   - 技術ドキュメント：800-1200トークン
   - 会話記録：200-400トークン

3. **ポスト処理の最適化**
   - Neo4jなどのグラフデータベースに生成されたJSONをインポート
   - Gephiを使用してより高度なグラフ分析を実施

4. **反復的な改善**
   - まず小サンプルでテストして抽出品質を確認
   - 結果に基づいてプロンプトまたはチャンキングパラメータを調整
