# Loop Engineering 実践ガイド：自己改善する AI Agent ループシステムの構築法

> 核心思想：**もう AI にプロンプトする必要はない。AI に自動でプロンプトするシステムを設計すべきだ。** @elune0x のバイラル X ポスト（373K 閲覧、318 ブックマーク）は 2026 年 AI Agent 開発のパラダイムシフトを明らかにする：「人間がプロンプト → AI が実行」から「人間がループを設計 → ループが自動プロンプト → AI が自律実行 → ループが自動検証」へ。Loop Engineering の核心は **4 つのループタイプ**（Heartbeat/Cron/Hook/Goal）+ **5 つのコアコンポーネント**（Worktrees/Skills/Connectors/Subagents/State）、モデルルーティングによるコスト 60-80% 削減を組み合わせ、AI エージェントを「人間のプロンプトが必要」から「自律稼働・自己改善するシステム」に変換する。

### 1.3 何を解決するか？

2026 年 AI Agent 開発の最大の転換は新しいモデルではなく、**モデルの新しい使い方**だ。従来：人間がプロンプト → AI が実行 → 人間が確認 → 人間が再びプロンプト。このループは人間の継続的な関与が必要で、非効率だ。Loop Engineering の答え：**ループシステムを設計する**——cadence、停止条件、ステート永続化、分離実行を定義し、AI エージェントが設計したループに沿って自律稼働し、実行中に自己改善する。

## 2. 核心思想

### 2.1 「プロンプトエンジニアリング」から「ループエンジニアリング」へ

従来：人間がプロンプト → AI が実行 → 人間が確認 → 人間が再びプロンプト。Loop Engineering：人間がループを設計 → ループが自動プロンプト → AI が自律実行 → ループが自動検証 → ループが自動記録。**人間は「プロンプター」から「システムデザイナー」に変化する。**

### 2.2 なぜ今才実用的か？

2026 年に 3 つの能力が収束：

- **モデルが長タスクを処理**：METR ベンチマーク顯示 Claude Opus 4.6 が 12 時間必要なタスクの 50% を完了可能。1 年前は Opus 4 の上限が 1 時間 40 分。天井が 6 倍に。
- **ループが組み込み**：Claude Code が `/loop`、cron スケジューリング、動的ワークフローを提供。Codex が Automations タブで定期スケジュールとサブエージェント生成を提供。カスタムインフラは不要に。
- **サブエージェントが劣化を防止**：メインループが分離されたサブエージェントを新鲜なコンテキストウィンドウで生成。各サブエージェントがフォーカスされた作業を行い報告。メインループコントローラは自分のコンテキストを消費しない。

### 2.3 4 つのループタイプ

- **Heartbeat ループ**：短い間隔で継続実行（秒〜分）。監視用：ログ確認、サービスヘルスチェック、ドリフトスキャン。
- **Cron ループ**：特定時刻にスケジュール。バッチ作業用：毎日のコードレビュー、週次依存関係審計、朝会サマリー。
- **Hook ループ**：外部イベントでトリガー。PR プッシュ、CI 失敗、Slack メッセージ到着。トリガーごとに 1 回実行。
- **Goal ループ**：成功条件を満たすまで迭代、その後停止。リファクタリング、バグハント、または範囲が事前に不明な移行タスク用。

### 2.4 5 つのコアコンポーネント

- **Worktrees**：各迭代が分離された git ワークツリーで実行。エージェントが壊すのはコピーであり、メインブランチではない。
- **Skills**：ループが呼び出せる再利用可能な指令セット。スケジュールに大量の指示を貼り付けるのではなく、スキルファイルを参照。
- **Connectors（MCP）**：Model Context Protocol でループが外部ツールにアクセス：データベース、課題追跡器、デプロイシステム、監控ダッシュボード。
- **Subagents**：ループコントローラが作業を分解し、専門のサブエージェントに委任。各サブエージェントが独自のコンテキストウィンドウとツール権限を持つ。
- **State Tracking**：ループは自分が何をしたかを知る必要がある。ファイルベースのステート（JSON チェックポイント）、git 履歴、または外部データベースが迭代間の重複作業を防止。

## 3. 設計哲学

### 3.1 「システムを設計し、プロンプトを書くな」

プロンプトの専門家である必要はない——システムデザイナーである必要がある。ループは再利用可能、バージョン管理可能、監査可能——プロンプトは使い捨てだ。

### 3.2 「サブエージェントは信頼の境界だ」

メインループは作業を直接実行せず、サブエージェントに委任する。各サブエージェントが独立したコンテキストウィンドウとツール権限を持つ。サブエージェントが失敗しても、メインループは健全のまま。これが安全な自律の基盤だ。

### 3.3 「コストは現実的な制約だ」

Agent ループの API 呼び出し回数はチャットボットの 10-100 倍。コスト最適化なしではループが金を燃やす。モデルルーティングでコストを 60-80% 削減可能。

### 3.4 「停止条件は開始条件よりも重要だ」

停止条件のないループは無限に実行し、予算を燃やす。Goal ループには明確な成功条件が必要。Heartbeat ループには `max_iterations` 上限が必要。**ループを開始するのは容易——安全に停止するのがエンジニアリングだ。**

### 3.5 「ステートは記憶の脊柱だ」

ステートトラッキングのないループは各迭代でゼロから始まる。ファイルベースのステート（JSON チェックポイント、git 履歴）がループに迭代をまたぐ永続的なメモリを与える。

## 4. フルチュートリアル

### 4.1 4 つのループタイプの YAML 設定

**Heartbeat ループ**：
```yaml
schedule: "*/5 * * * *"  # 5 分ごと
prompt: "ステージング環境のエラーログを確認。エラー率 > 1% なら issue を開く。"
stop_condition: never  # 無限実行
```

**Cron ループ**：
```yaml
schedule: "0 10 * * 1-5"  # 平日 10am
prompt: "3 日以上経過したすべての PR をレビュー。各 PR のブロッカーを要約し、著者に ping。"
model: gpt-5.5
subagents: true
```

**Hook ループ**：
```yaml
trigger: "post-push"
prompt: "テストスイートを実行。テストが失敗したら修正を試行。修正が通ればコミット。通らなければ失敗詳細付きで issue を開く。"
```

**Goal ループ**：
```yaml
prompt: "古い API パターンを使用している次のファイルを見つける。新しいパターンに移行。テストを実行。"
stop_condition: "古いパターンに一致するファイルなし"
max_iterations: 200
```

### 4.2 実践：毎日の PR レビュアーを構築

**Claude Code 版**：
```bash
claude code --schedule "15 10 * * 1-5" \
  --skill pr-review \
  --prompt "このリポジトリで 3 日以上経過した open PR をすべて見つける。各 PR について、サブエージェントを生成して diff をレビューし、ブロッカーの要約を作成。要約を PR コメントとして投稿し、著者をタグ。"
```

### 4.3 モデルルーティング：コスト 60-80% 削減

- **ファイルスキャン＆分類**：Nano → $0.10-$0.30/1M tokens
- **要約＆起草**：Mid-tier → $1-$3/1M tokens
- **最終レビュー＆決定**：Frontier → $10-$15/1M tokens

prompt caching と組み合わせると、$50/日 のループが $8-$12/日 に。

### 4.4 よくある失敗モードと対策

- **トークン暴走**：`max_iterations` のない Goal ループは 1 時間に $500 燃やすabilir。必ず上限を設定、50 から開始。
- **コンテキスト腐敗**：長時間稼働ループが同じコンテキストウィンドウに追加し続け、品質が劣化。対策：各迭代で新鲜なコンテキストのサブエージェント。
- **過信终止**：エージェントがコードベースの半分しか確認していないのに「完了」を宣言。検証ステップを追加。
- **ステート失憶**：ループが処理したことを忘れる。各迭代後にステートをファイル/データベースに書き込み。

## 5. まとめ（考察と結論）

1. **「ループを書く」は「プロンプトを書く」よりもレバレッジが大きい。** プロンプトは使い捨て——ループは再利用可能、バージョン管理可能、監査可能なシステム。2026 年の AI エンジニアの価値はプロンプターからシステムデザイナーへ。

2. **4 つのループタイプが全シナリオをカバー。** Heartbeat は監視、Cron はバッチ作業、Hook はイベントドリブン、Goal はオープンエンドタスク用。正しいループタイプの選択が第一步。

3. **サブエージェントがコンテキスト劣化を防止する鍵。** メインループは新鲜なコンテキストのサブエージェントに委任。これがコンテキスト腐敗を防ぐ唯一の確実な方法。

4. **モデルルーティングがコスト最適化の核心。** すべてのステップに最強モデルは不要。prompt caching と組み合わせ、コストを 60-80% 削減。

5. **停止条件は開始条件よりも重要。** 必ず `max_iterations` と明確な成功条件を設定。

6. **ゲートウェイレイヤーが信頼性の基盤。** フェイルオーバー、コスト追跡、キャッシュ、レート制限——すべてゲートウェイレイヤーが処理。
