> **Cloudflare OS** は、ソフトウェアの配信と使用方法を再定義するCloudflareのオープンソースAI生産性環境です。本包括的分析では、プロジェクトのアーキテクチャ、設計哲学、実践的チュートリアル、そしてAI時代のコアインサイトを網羅します。

## 1. プロジェクト概要

### 1.1 Cloudflare OS とは？

Cloudflare OSは、Cloudflare社内での使用を目的として開発されたAI生産性環境です。Cloudflareの従業員の大部分——エンジニアリングから営業まで——が毎日Cloudflare OSを使用して業務を遂行しています。

これは従来のコンピュータオペレーティングシステムではありません。「オペレーティングシステム」という言葉は2つの意味で使用されます：

- 会社がAIを安全に生産的に使用するためのオペレーティングシステム
- 従来のOSがコンピュートワークロードを管理するのと同様に、AIワークロードを管理するオペレーティングシステム

Cloudflare OSは3つのコア能力を提供：

1. **Agent チャットUI** — エージェントにタスクを依頼し、会社の運営知識を事前ロード
2. **サンドボックスアプリ開発** — AIで「Gadgets」（小型パーソナルアプリ）を構築し、安全に共有
3. **セキュリティフレームワーク（Gatekeepers）** — 非技術者でも安全に「思いきって使える」ガードレール

### 1.2 コア機能

| 機能 | 詳細 |
|------|------|
| **Gadgetサンドボックス** | 各アプリが隔離されたDynamic Workerで実行、デフォルトでインターネットアクセスなし |
| **能力ベースセキュリティ** | Agent/Gadgetはデフォルトで何もアクセス不可；ユーザーが明示的にリソースを紹介する必要あり |
| **非同期ヒューマンインザループ** | Agentは動作を継続し、ユーザーは後で一括承認 |
| **リアルタイムマルチプレイ** | Durable Objectsによるコラボレーション編集が標準搭載 |
| **AgentフレンドリーAPI** | 全Gadgetが自動的にAgent呼び出し可能なCap'n Web RPC APIを公開 |
| **Blueprint共有** | ホストサービスではなく、アプリコードをテンプレートとして共有 |
| **BYOK AIモデル** | 多くのLLMプロバイダーに対応；ユーザーが独自に利用料金を支払い |

### 1.3 コアコンセプト

#### Gadgets — ソフトウェアへの新しい考え方

Cloudflare OSは単なるコネクター付きチャットボックスではありません。システムは、各ユーザーが自分の生産性アプリのコピーを実行するという新しいアプローチを中心に展開します。

Cloudflare OSでスライドデッキを作成する際、クラウドで実行されているSaaSソフトウェアを呼び出すのではありません。システムは*プライベートインスタンス*を*あなた専用*に作成します。これを「Gadget」と呼びます。このインスタンスは他の人のスライドデッキとは別々のサンドボックスで実行されます。

これには2つの深い効果があります：

1. **セキュリティ** — スライドデッキアプリにセキュリティバグがあり、攻撃者にスライドが漏洩することは不可能です。Cloudflare OSサンドボックスがプライベートインスタンスへのすべてのアクセスを制御します。
2. **変更可能性** — 必要であれば、コードを自由に変更できます。スライドデッキアプリに必要な機能が足りない場合は、エージェントに追加を依頼するだけです。そしてポイント1のおかげで、这样做は完全に安全です。

これは過去25年のクラウドアーキテクチャと「ソフトウェアとしてのサービス」から大きく逸脱していますが、AIが方程式を変えた我们认为します。あらゆるユーザーがエージェントに必要な機能を追加するプロンプトをできる時代では、集中型ソフトウェアモデルは意味を失います。

#### Gatekeepers — 能力ベースセキュリティレイヤー

Gatekeepersは強化版MCPサーバーのようなものです。

エージェントやGadgetを外部リソースに紹介する際、Gatekeeperが作成されてそのアクセスを管理します。Gatekeeperは各外部サービス固有のソフトウェアで、Gadgetのそのサービスへの接続を仲介します。それは：

- サービスへのクリーンなCap'n Web APIを提供（サービスがネイティブに提供するAPIをラップ）
- 認証を処理（OAuth経由など）
- ユーザーが意図した特定のリソースのみへの狭いアクセスを強制
- Gadget（またはエージェント）が実行するすべてのアクションをログに記録
- 副作用のあるアクションについては、人類ユーザーにアクションの承認または拒否の機会を提供（「ヒューマンインザループ」）

**非同期ヒューマンインザループ**はGatekeeperの重要な革新です。従来のヒューマンインザループ設定では、人間がアクションを*同期的*に承認する必要があります。エージェントが何かを実行したい場合、*停止*して承認を待つ必要があります。これは面倒です：エージェントにタスクを与え、コーヒーを飲みに行くと、エージェントが最初のステップで承認に引っかかって進歩がないことに気づきます。結果として、人々は often 妥協し、エージェントを「自動承認」または `--dangerously-skip-permissions` に設定しますが、これは明らかに安全ではありません。

Gatekeepersはより良い方法を提供します：エージェント（またはGadget）が承認が必要なアクションを実行すると、Gatekeeperは結果をローカルに*シミュレート*し、エージェントが動作を継続してさらに多くのアクションをキューイングできるようにします。Gatekeeperはエージェントにアクションが完了したと伝え、エージェントが結果を読み戻そうとすると、Gatekeeperはシミュレートされた結果を返します。エージェントが完了すると、ユーザーはアクションを一括または個別に承認または拒否できますが、いずれにしても後で便利な時にできます。

#### Blueprints — コードを共有する

他の人にとって有用なGadgetを作成したが、Gadget自体を共有したくない場合は、Blueprintを共有することで、他の人がGadgetのコピーを作成できます。Blueprintは本質的にコードのコピーです。

Blueprintはクラウドソフトウェアの伝統からの重大な変化です。従来、他のユーザーと共有したいWebアプリを作成した場合、サーバーにアプリをホストし、ユーザーはそこに接続します。Blueprintはモバイルアプリや従来のPCアプリに much more like です：各ユーザーがソフトウェアのコピーを実行します。

AI時代にこの変化は重要です。一方、AIは個々の開発者に以往にない構築力を与えますが、個々の開発者がオンラインサービスを維持することは依然として困難です；これはその必要性を排除します。他方——さらに重要的是——各ユーザーが自分のソフトウェアコピーを実行できるようにすることで、ユーザーはAIを使用してソフトウェアを*変更*し、ニーズを満たすことができます。機能リクエストを送る必要も、開発者に優先順位を頼む必要もありません。エンドユーザーが自分の問題を解決できます。

## 2. 詳細チュートリアル

### 2.1 クイックスタート：ローカル実行

Cloudflare OSを使用する最も速い方法は、ローカルで実行することです。

**前提条件**：
- [pnpm](https://pnpm.io/) をインストール

```bash
# pnpmをインストール（まだの場合）
npm install -g pnpm

# リポジトリをクローン
git clone https://github.com/cloudflare/cloudflare-os.git
cd cloudflare-os

# フルスタックを実行
pnpm run-local
```

次にアクセス：http://localhost:8787

これは`wrangler`（Workers開発ツールCLI）を使用してローカルでCloudflare OSを実行します。これは本番サーバーでOSを実行する適切な方法ではありませんが、ローカルマシンで試すには十分です。

データは`.wrangler`という名前のサブディレクトリに保存されます。

### 2.2 開発モード

開発時、フロントエンドとバックエンドを2つのターミナルで別々のコマンドとして実行します：

```bash
# ターミナル1：バックエンド
pnpm dev-server

# ターミナル2：フロントエンド
pnpm dev-client
```

次にアクセス：http://localhost:3000

### 2.3 Cloudflareアカウントにデプロイ

#### ワンクリックデプロイ

Cloudflareは自分のCloudflareアカウントにデプロイするオンラインフローを構築しました：

アクセス https://os.cloudflare.app/deploy

#### 高度なデプロイ

より高度なデプロイについては、gatekeeperやコード変更を含むデプロイメントスターターリポジトリを確認：

アクセス https://github.com/cloudflare/cloudflare-os-starter

### 2.4 これらのプロンプトを試してみてください

ローカルで実行した後、これらのプロンプトを試してください：

- 「今度の顧客会議用のスライドを作成してください。」（組み込みスライドブループリントを使用）
- 「コラボレーションホワイトボードアプリを作成してください。」（ゼロから新しいアプリを作成）
- 「三目並べゲームを作成してください。」→「私はX、あなたはO。最初の手を打ちました。あなたの番です。」
- 「このGitHubリポジトリのissueダッシュボードを作成してください。」（リポジトリを添付；GitHub統合が必要）
- 「このGoogleドキュメントのタイプミスを修正してください。」（ドキュメントを添付；Google統合が必要）

### 2.5 外部サービスの設定

多くのGatekeeperはサードパーティサービスに接続するための設定が必要です。各サービスのOAuthクライアント資格情報を取得する必要があります。

Cloudflare OSは2つの認証モードをサポート：

2. **Cloudflare Accessモード** — `VITE_CF_ACCESS_MODE=true` を設定

## 3. コアアーキテクチャの深層解析

### 3.1 オペレーティングシステムアナロジー

Cloudflare OSは技術レベルで実際にオペレーティングシステムに類似：

| 従来のOS | Cloudflare OS |
|----------|---------------|
| カーネル | `packages/workshop-backend` |
| ドライバー | `packages/gatekeeper-*` |
| シェル | `packages/workshop-frontend` |
| プロセス | gadgets |
| 実行可能ファイル | blueprints |
| ユーザー | users |
| ACLs | 共有権限 |
| （欠落） | **agents** |

「カーネル」は`workshop-backend`パッケージにあります。バックエンドは実際に本物のOSカーネルと多くのことを似ています：ユーザーをプログラムやデバイス（GadgetsとGatekeepers）に接続し、アプリケーションのサンドボックス化とアクセス制御の強制によりセキュリティを実装します。

このアナロジーでは、Gatekeepers——ユーザーとエージェントを外部サービスに接続する——はドライバー——ユーザーとプログラムを外部デバイスに接続する——に似ています。

従来のOSが今日本当に管理していないが、Cloudflare OSが管理するもの：**AIエージェント**。考えてみると、これは従来のOSの欠落した機能です。AIエージェントは単にユーザーとして扱われるべきではない我们认为します。彼らは人間のユーザーに説明責任を負いながら、同時に独自の制限された権限を持つ必要があります。エージェントはコードスニペットを書き、その場で実行することで仕事をします。これらすべての理想的なセキュリティモデルは、アクセス制御リストではなく、能力ベースセキュリティです。

### 3.2 技術スタック

- **ランタイム**：Cloudflare Workers（Durable Objects、Dynamic Workers、Facets）
- **ローカル開発**：`workerd`（オープンソースWorkersランタイム）
- **フロントエンド**：Viteベースの開発サーバー
- **主要ライブラリ**：
  - [Pi](https://pi.dev/) — LLMプロバイダー抽象化
  - [Monaco Editor](https://microsoft.github.io/monaco-editor/) — コードエディター
  - [Yjs](https://yjs.dev/) — リアルタイムコラボレーション
  - [Cap'n Web RPC](https://github.com/cloudflare/capnweb) — 低ボイラープレートRPC

### 3.4 サンドボックスセキュリティモデル

各Gadgetは、明示的な同意なしにインターネットと通信することを防ぐセキュリティサンドボックスで実行されます：

- **サーバーサイド**：インターネットアクセスが無効にされたDynamic Workerで実行。Workers Bindingsを介して明示的に指定した特定の外部リソースのみと通信可能。
- **クライアントサイド**：サンドボックス化されたiframeで実行。親フレームから提供される`postMessage()`経由のCap'n Web RPCセッションを介してサーバーと通信可能。iframeはそれ以外インターネットへのアクセスがブロック（`Content-Security-Policy`とiframeサンドボックス設定により、ブラウザが許容する最大限）。

### 3.5 能力ベースアクセス制御

各エージェントと各Gadgetは、デフォルトで何のアクセスもありません。Gadget Workshopに外部アカウントへのアクセスを設定しても、エージェントやGadgetは自動的にそれらを使用する権限を得ません。

代わりに、アクセスしたい特定のリソースに各エージェント（またはGadget）を*紹介*する必要があります。例えば、リンクを貼り付けるか、「リソースを追加」をクリックしてUI経由でGitHubリポジトリを紹介できます。エージェントも必要だと思うリソースへの紹介をリクエストでき、その後提供または拒否できます。

これはほとんどのエージェントハーネスとは異なり、 Those MCPサーバーは事前に設定され、すべてのチャットでエージェントにすべてのサービスへの広いアクセスが環境的に利用可能になります。能力ベースの紹介は、各エージェントを実際の作業に必要なアクセスのみに制限します。

## 4. 総括：コアインサイトと知見

### 4.1 SaaSの終焉：ホストからローカルコピーへ

Cloudflare OSはソフトウェア配信の根本的な転換を体現：

**従来のモデル**：Webアプリを作成し、サーバーにホストし、ユーザーはそこに接続。

**新しいモデル**：コード（Blueprint）を共有し、各ユーザーが自分のコピーを実行。

この転換の理由：

1. **AIが個人をエンパワーメント** — AIは個々の開発者に以往にない構築力を与える
2. **メンテナンス負担** — 個々の開発者がオンラインサービスを維持することは依然として困難
3. **カスタマイズニーズ** — ユーザーはAIを使用して自分のコピーを変更可能
4. **リクエスト不要** — 機能リクエスト不要、ユーザーが自分の問題を解決

**インサイト**：ソフトウェアの未来は「ソフトウェアとしてのサービス」ではなく「コードとしてのサービス」かもしれません。

### 4.2 能力ベースセキュリティ：アクセス制御リストを超えて

従来のアクセス制御リスト（ACLs）はユーザー/ロールに固定権限を割り当てます。能力ベースセキュリティは各操作に最小権限を割り当てます。

**従来のACLs**：
```yaml
user: admin
permissions:
  - read
  - write
  - delete
```

**能力ベースセキュリティ**：
```yaml
agent: code-reviewer
task: review-pr-123
capabilities:
  - read:repo/my-project
  - read:pr/123
  # write、deleteなどの他の権限なし
```

**インサイト**：AI Agent時代では、能力ベースセキュリティはACLsよりも適切です：
- エージェントのタスクは動的
- 権限はタスクとともに変化すべき
- 最小権限原則がより容易に実装可能

### 4.3 非同期ヒューマンインザループ：エージェントのスタール問題を解決

従来のヒューマンインザループ設定では同期承認が必要で、エージェントが頻繁にスタールします。

**従来のアプローチ**：
```
エージェントがアクションを試行 → ユーザーの承認を待つ → ユーザーがコーヒーを飲みに行く → エージェントがスタール → ユーザーが戻る → エージェントが継続
```

**Cloudflare OSのアプローチ**：
```
エージェントがアクションを試行 → Gatekeeperが結果をシミュレート → エージェントが継続 → ユーザーが後で一括承認
```

**利点**：
- エージェントがスタールしない
- ユーザーが便利な時に一括処理可能
- 「自動承認」の誘惑を減少
- セキュリティを維持しながら効率を向上

**インサイト**：非同期ヒューマンインザループはAIツールに不可欠な機能です。

### 4.4 オペレーティングシステムアナロジー：AI時代のプラットフォーム思考

Cloudflare OSのオペレーティングシステムへのアナロジーは単なるマーケティングではありません：

| コンポーネント | 機能 |
|----------------|------|
| **カーネル** | リソース、プロセス、セキュリティを管理 |
| **ドライバー** | 外部デバイス/サービスを接続 |
| **シェル** | ユーザーインターフェース |
| **プロセス** | 実行中のアプリケーション |
| **Agent** | 新しいタイプの「プロセス」、制限された権限を持つ |

従来のオペレーティングシステムはコンピュートリソースを管理します。Cloudflare OSはAIワークロードを管理します。

**インサイト**：AI Agentにはユーザーレベルの権限ではなく、オペレーティングシステムレベルの管理が必要です。

### 4.5 オープンソースの戦略的価値

CloudflareがCloudflare OSをオープンソース化する理由：

1. **エコシステム構築** — コミュニティに新しいGatekeepersとBlueprintsの作成を奨励
2. **標準化** — AI生産性ツールの標準化を推進
3. **信頼構築** — オープンソースコードが透明性と信頼を向上
4. **フィードバックループ** — コミュニティの使用フィードバックが製品改善に貢献
5. **人材獲得** — オープンソースプロジェクトが優秀な開発者を引き付ける

**インサイト**：オープンソースはAIツールエコシステムを構築する効果的な戦略です。

## 5. 従来のソリューションとの比較

### 5.1 Cloudflare OS vs 従来のSaaS

| 次元 | 従来のSaaS | Cloudflare OS |
|------|-----------|---------------|
| **データストレージ** | ベンダーサーバー | あなたのCloudflareアカウント |
| **コード管理** | ベンダーが管理 | あなたが管理 |
| **カスタマイズ** | 限定されたAPI | 完全なコード変更 |
| **セキュリティモデル** | ベンダーを信頼 | サンドボックス隔離 |
| **価格設定** | サブスクリプション | BYOK（独自キー持参） |
| **AI統合** | 後から追加されることが多い | ネイティブデザイン |

### 5.2 Cloudflare OS vs 他のAgentフレームワーク

| 次元 | 汎用Agentフレームワーク | Cloudflare OS |
|------|------------------------|---------------|
| **セキュリティモデル** | MCPサーバーが事前設定 | 能力ベースの紹介 |
| **アプリ隔離** | なし | 各Gadgetが隔離サンドボックス |
| **ヒューマンインザループ** | 同期承認 | 非同期シミュレーション+一括承認 |
| **アプリ配信** | 共有インスタンス | Blueprints（コードコピー） |
| **ランタイム** | ローカル/セルフホスト | Cloudflare Workers |

## 6. ロードマップと今後の計画

### 6.1 現在のステータス

- **バージョン**：v2（2026年8月 アーリーアクセス）
- **ステータス**：積極的に開発中、v1からの完全書き直し

- **workerdセルフホスト**：オープンソース`workerd`ランタイム上で完全に実行するためのドキュメントとツール
- **さらに多くのGatekeepers**：新しいサービス統合の継続的な追加
- **コミュニティ貢献**：プロジェクトの成熟に応じて、より多くの貢献機会が開かれる可能性

### 6.3 貢献ポリシー

> 現在、外部からの貢献は求めていません。外部PRは「容易な部分（コード作成）」を「寄付」し、より多くの作業（レビュー）を生み出しています。小さな、簡単に検証可能なPR（≤12行）のみ受け付けます。大きなアイデア → ディスカッション。

## 7. まとめ

Cloudflare OSは単なるAI生産性ツールではありません——それはソフトウェアがどのように配信され使用されるかのパラダイム転換を体現しています。各アプリをユーザーが所有するプライベートインスタンス（Gadget）に変えることで、能力ベースセキュリティフレームワーク（Gatekeeper）を実装することで、非同期ヒューマンインザループメカニズムを可能にすることで、Cloudflare OSはAI時代の生産性に新しい基準を設定します。

**コアバリュー**：
1. **セキュリティ** — サンドボックス隔離 + 能力ベースセキュリティ
2. **コントロール** — ユーザーがコードとデータを所有
3. **カスタマイズ可能** — AIが任意のアプリを変更可能
4. **効率的** — 非同期ヒューマンインザループ
5. **オープン** — Apache-2.0オープンソース

**適用シナリオ**：
- 安全なAI使用が必要な企業
- ユーザーカスタマイズ可能なアプリを望む組織
- データプライバシーとコントロールを重視するチーム
- AIネイティブ生産性ツールを構築したい開発者

Cloudflare OSはAI時代の生産性ソフトウェアに新しいベンチマークを設定しました。その設計哲学と実践的経験は、すべてのAIツール開発者にとって学び参考にする価値があります。
