# Macro：統一チームワークスペース——メール、チャット、ドキュメント、AIエージェントを融合した All-in-One プラットフォーム

## プロジェクト背景とコア問題

### ツール断片化のジレンマ

現代のチームは何度もツールを切り替える必要があります：

| ツールタイプ | 常用ソフトウェア | 問題点 |
|-----------|----------------|---------|
| メール | Gmail、Outlook | チャットやドキュメントと分断 |
| IM | Slack、Discord | 履歴が探しにくい |
| ドキュメント | Notion、Confluence | タスクやメールにリンクなし |
| タスク管理 | Linear、Jira | コンテキストと分離 |
| CRM | Salesforce、HubSpot | 日常作業と分断 |
| AIアシスタント | ChatGPT、Claude | チームコンテキストがない |

**核心的矛盾**：各ツール单独见れば优秀ですが、組み合わせると情報孤島を形成します。

### Macroの誕生

Macroのチームは多年的なツール断片化に不満を持った後、大胆な决定を下しました：

> **「ゼロから рабо 软件全体を统一されたシステムとして再設計しよう。」**

这就是 Macro —— メール、チャット、ドキュメント、タスク、AIエージェント、電話、CRMを融为一体、统一されたチームワークスペースです。

## プロジェクト概要

### Macroとは？

Macroは**All-in-Oneチームワークスペース**で、以下の特点があります：

```
Macro ワークスペース：

    📧 メール    💬 チャット    📝 ドキュメント   📋 タスク
       │              │              │              │
       └──────────────┴──────────────┴──────────────┘
                           │
                   ┌───────┴───────┐
                   │  双方向 @リンク │
                   │     グラフ     │
                   └───────┬───────┘
                           │
           ┌───────────────┼───────────────┐
           ▼               ▼               ▼
       🤖 AIエージェント  📊 CRM        📞 電話
```

### 核心機能一览

| 機能モジュール | 核心的特性 |
|-------------|-----------|
| 📧 **メール** | マルチアカウント受信箱、キーボードショートカット、共有受信箱、Gmail統合、AI支援 |
| 💬 **チームチャット** | スレッド折りたたみ、技術的議論に专注于、双方向グラフ |
| 📋 **タスク** | チャンネル/DMと密結合、どこでも作成可能 |
| 📝 **ドキュメント** | CRDTリアルタイム協調編集、オフライン編集、版履歴 |
| 🎨 **キャンバス** | 2D 白板、タスク/ファイル/メールへの@リンク |
| 🤖 **AIエージェント** | チームレベルメモリ（毎晚更新）、MCP統合 |
| 📊 **CRM** | ネイティブ客户/連絡先オブジェクト、カンバンボード |
| 📞 **電話** | 録音と文字起こし、チームメモリに自動記録 |

## 技術アーキテクチャ

### 技術スタック選択

Macroは**SolidJS + Rust**という非常に珍しい組み合わせ选择しています：

```
Macroアーキテクチャ：

フロントエンド (SolidJS)           バックエンド (Rust)
┌──────────────────────┐         ┌──────────────────────┐
│ apps/web (ブラウザ)   │◄────────►│ 42 マイクロサービス  │
│ apps/web (Tauri)     │  HTTP   │ - メール、チャット    │
│ apps/web (モバイル)   │  gRPC   │ - ドキュメント        │
│ apps/docs            │         │ - タスク、AI           │
└──────────────────────┘         └──────────────────────┘
```

### _hexagonal Architecture

各サービスは_hexagonal architecture（ポートとアダプタ）を採用：

```
サービス内部アーキテクチャ：

┌──────────────────────────────────────────┐
│           Inbound Adapters (着信アダプタ)   │
│    HTTP Handler │ gRPC Handler │ Events  │
└────────────────────────┬─────────────────┘
                         │
                         ▼
┌──────────────────────────────────────────┐
│              Domain Core (ドメインコア)      │
│         Ports (インターフェース)            │
│         ビジネスロジック                    │
└────────────────────────┬─────────────────┘
                         │
                         ▼
┌──────────────────────────────────────────┐
│          Outbound Adapters (発信アダプタ)    │
│   Database Client │ External APIs │ Cache │
└──────────────────────────────────────────┘
```

## 核心機能详解

### 1. メール：分断ではなく統一

Macroのメールシステムは単なるGmailクライアントではありません——**メールとワークフローの深い統合**です。

```javascript
// Macroのキーボードショートカット
const shortcuts = {
  'j': '次のメール',
  'k': '前のメール',
  'o': 'メールを開く',
  'r': '返信',
  'a': '全員返信',
  'f': '転送',
  'c': '新規作成',
  'c t': 'メールからタスク作成',  // 重要なショートカット！
};
```

#### メールからタスク作成

```
1. メール查看
   📧 差出人: client@company.com
   件名: 「ランディングページ修正が必要」

2. 'c t'を押してタスク作成
   タイトル: ランディングページを修正
   説明: [自動入力]
   優先度: 高

3. タスクは自動的にメールにリンク
   📧 ←→ 📋 双方向リンク！
```

### 2. AIエージェント：チームレベルメモリ

これがMacroの最も差別化された機能——**チームメモリを持つAIエージェント**：

```
AIエージェントアーキテクチャ：

                    │  (毎晚更新)      │
                    └────────┬────────┘
                             │
                             ▼
┌──────────────────────────────────────────────┐
│                AIエージェントレイヤー              │
│    OpenAI GPT-4 │ Google Gemini │ Anthropic  │
└──────────────────────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────┐
│              MCPツールインターフェース              │
│   メール │ チャット │ タスク │ ドキュメント     │
└──────────────────────────────────────────────┘
```

## 設計哲学

### 哲学1：双方向@リンク = 双方向到達可能性

```
Notion の問題：
  ページAがページBを参照
  → ページBは参照されたことを知らない
  → 一方向リンクのみ

Macro の解決策：
  📧 メール ←──── @link ────→ 📋 タスク
       │                          │
       │      双方向              │
       └────────── @link ─────────┘
```

### 哲学2：チャンネル = 権限

```
伝統的：
  ドキュメント作成 → 権限を設定
  メール送信 → 宛先を選択
  タスク作成 → 担当者を選択

Macro：
  チャンネルで共有 → メンバーが自動的にアクセス
  権限はコンテンツに応じて自然に流動
```

### 哲学3：統一受信箱 = 重要なものを見逃さない

```
Macro 受信箱の哲学：

┌───────────────────────────────────────┐
│            統一受信箱                   │
├───────────────┬───────────────────────┤
│   📢 重要     │      🔔 ノイズ        │
├───────────────┼───────────────────────┤
│ • @メンション │ • ニュースレター         │
│ • ダイレクト  │ • システム通知          │
│ • タスク担当  │ • チャンネル活動        │
│ • 重要メール  │ • グループメッセージ     │
└───────────────┴───────────────────────┘
```

### 哲学4：AIはメモリであり、ツールではない

```
ChatGPT の問題：
  「昨日ChatGPTに何を聞きましたか？」
  → 每次新しい会話、メモリがない

Macro AI：
  「先週チームで何を議論しましたか？」
  → メモリはチーム全体のもの、追跡可能
```

## クイックスタート

### 方法1：ホスト版（新手推奨）

**ステップ1：登録**

1. [macro.com/app](https://macro.com/app)を訪問
2. Google またはメールアドレスでログイン
3. Gmail または Google Workspace を接続

**ステップ2：Gmailを接続**

```
Gmailアカウントを接続：

1. 左サイドバーの「設定」をクリック
2. 「メールアカウント」を選択
3. 「アカウントを追加」をクリック
4. Gmail または Google Workspace を選択
5. Macro のアクセスを承認
6. 同期するラベル/フォルダを選択
```

### 方法2：ローカル開発

```bash
git clone https://github.com/macro-inc/macro
cd macro

# 環境変数テンプレートをコピー
cp .env.example .env
# .env を編集してAPIキーを入力

# インフラを起動
docker compose up -d

# フロントエンド依存関係をインストール
cd apps/web && npm install

# 開発サーバーを起動
npm run dev
```

**アクセス先：**
- フロントエンド: http://localhost:3000
- API: http://localhost:4000

## 設計哲学まとめ

### 1. 統合より統一

```
統合モード (Slack + Notion + Linear + Gmail)：
  → Zapier が必要
  → 遅延、维护コスト、データ不整合

統一モード (Macro)：
  全てのモジュール ──→ 共有DB ──→ 自然整合
```

### 2. 機能よりコンテキスト

```
伝統的优先级：              Macroの优先级：
1. 機能が完全か？           1. コンテキストを辿れるか？
2. 性能がいいか？           2. 情報が繋がっているか？
3. UIが美しいか？          3. 機能がコンテキストに奉仕するか？
```

## 結論

Macroは作業ツールの発展における重要な方向性を代表しています：**ツールの集合から統一されたシステムへ**。双向@リンク、チームレベルAIメモリ、统一されたワークスペースは同一个目標を指しています——**チーム作業をコンテキスト的に接続された状態に保つ**。

ツール爆発的时代において、Macroは私たちに思い出させます：**必要なのはより多くのより良いツールではなく、全てを统一できるシステムかもしれない**と。

AGPLv3ライセンスはMacroがベンダーロックインのないツールであることを意味します——それは本当にチームに属するツールです。これが最も重要な価値提案かもしれません。
