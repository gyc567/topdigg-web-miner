# Harnessの深掘り：AI Agentの"登山の命綱"——登山の比喩からオープンソースの自律性まで

> 核心のアイデア：**"Agent = Model + Harness"**——AIモデルはエンジンであり、Harnessはエンジンが安全に稼働し、あなたのために働くための外壳である。Harnessはモデルの従属物ではなく、ユーザーが実際に所有し管理すべきレイヤーである。HarnessはAIの行動パターン、使用するツール、作業リズムを決定し、そして最も重要なこととして——ユーザーが最終的な制御権を保持するかどうかを決定する。

## 序論：誤解されている"Harness"

AI情報のサークルに長く身を置いているなら、"Agent"这个词は无数次聞こえてくるだろう。しかし"Agent Harness"はどうだろうか？

おそらく多くの人の第一反応は：また一つのかなりの業界用語だろう、というものだろう。

Earendilチームは一篇の非常に明確な記事 [What is a Harness?](https://earendil.com/posts/what-is-a-harness/) を書いている。その目的はまさにこのコンセプトに附着した神秘的なオーラを剥がすことにある。彼らのアプローチは非常に賢い——**登山用ハーネスから始める**のだ。この比喩は理解しやすいだけでなく、正確でもある：因为、安全帯の核心ロジック——"接続、保護、あなたにより危険なことを르게する"——はまさしくAgent HarnessがAIの世界で果たす役割だからである。

この記事はEarendilの原文を中心に、Agent Harnessが何であるか、どう働くか、なぜ重要か、そしてオープンソースコミュニティがどのようにしてそれをAI実験室の権力集中に対抗するユーザーの手に渡そうとしているかを体系的に解析する。

## 一、プロジェクトの背景：この文章を書いたのは誰か

EarendilはAIインフラストラクチャチームであり旗下には複数のAgent/Harness関連オープンソースプロジェクトがある：

- **Pi** (`pi.dev`)：個人ユーザー向けの最小限のオープンソースAgent Harness、ローカルノートパソコン上で完全に動作
- **Lefos**：メールシナリオ向けのAgent Harness、コアなインタラクション媒介はEmail
- **OpenClaw`：もう一つの人気オープンソースAgent Harness、iMessage、Emailなど複数のインターフェースをサポート

この記事はEarendilチームがPiのために書いたプロダクト哲学の解説であると同時に、一般向けのAI Agent 科学普及記事でもある—— читательがAgent Harnessを全く知らないことを前提に、最も直截な言葉でこのコンセプトを説明する。

## 二、核心的比喩：登山用ハーネス

### 2.1 現実におけるハーネス

Cambridge DictionaryによるHarnessの定義：

> **名詞.** 人、動物または物を制御または固定するために使用されるベルトとハーネスを備えた一套の機器
> **動詞.** 通常はその力を利用するために何かを制御する

登山用ハーネスの実際の機能を語る時、以下のことが言える：

1. **サポートと保護**——クイックドローとロopeに接続することで、登山者の転落損傷から保護し、下降速度を制御し、登攀ルートをガイドする
2. **ツールの取り付けが可能**——雰囲袋、岩钉ツール、クイックドローフックはすべてハーネスに取り付け可能
3. **移植可能**——山が変わる、登り方が変わる場合でも、ハーネス自体は持っていける，只需調整して掛ける装備を変更するだけ
4. **カスタマイズ可能**——曲芸師とツリークライマーは異なるハーネスを使用し、同一のハーネスを完全に異なる用途に調整することも可能

### 2.2 物理的世界からAIの世界へ

Earendilは2種類のHarness間の構造と機能の対応関係を示した：

| 登山用ハーネス | Agent Harness |
|-------------|---------------|
| ボディとロopeを接続 | AIモデルとツール、環境を接続 |
| 登山者の転落から保護 | ユーザーのAI誤った意思決定から保護 |
| 雰囲袋、ツールを搭載 | 検索、コード、メールなどのツールセットを搭載 |
| 移植可能、カスタマイズ可能 | 跨モデル、跨タスク、カスタマイズ可能 |
| 登攀リズムとルートを決定 | Agent行動リズムと実行パスを決定 |

この比喩の核心的な洞察：**安全帯は登山者本身ではないが、登山者がより高い場所を安全に探検できるための前提条件である。** 同様に、HarnessはAIモデル本身ではないが、AIモデルがユーザーに信頼できるサービスを提供するための前提条件である。

## 三、Agent Harnessとは（核心定義）

### 3.1 基本定義

> **Agent Harnessとは、AIモデルに実行環境を提供するソフトウェアのことである。**

ほとんどのAIモデルとは異なり（AIモデルを"所有する"ことはできない）、**自分のAgent Harnessを所有することができる**。これがHarnessをモデル本身と区別する最も根本的な特徴である。

ユーザーとHarnessのやり取りの方法は多様である：
- ソフトウェアエンジニアはターミナルで直接Piを使用できる
- OpenClawはiMessage、Chat AppまたはEmail 통해ューザーとインタラクションできる
- Lefosは主にEmailを通じて動作

インターフェースに関係なく、Harnessは一般的に4つのことを行う：

```
┌─────────────────────────────────────────────────────┐
│                  Agent Harness                      │
│                                                     │
│  ┌─────────────┐  ┌─────────────┐                   │
│  │ System      │  │   Tools     │                   │
│  │ Prompt      │  │ (ツールセット)│                   │
│  └─────────────┘  └─────────────┘                   │
│                                                     │
│  ┌─────────────┐  ┌─────────────┐                   │
│  │ Agentic     │  │ Translation │                   │
│  │ Loop        │  │ Layer       │                   │
│  │ (エージェント│  │ (翻訳레이어) │                   │
│  │   ループ)   │  │             │                   │
│  └─────────────┘  └─────────────┘                   │
└─────────────────────────────────────────────────────┘
```

## 四、4つのコア構成の詳解

### 4.1 System Prompt（システムプロンプト）

**比喩**：新入社員初日に受け取るオペレーションマニュアル。

ほとんどのAIモデルは訓練 과정에서一連の内在するルールとガイドラインを形成する——最も有名な例は、Claude Opus 4.5那份広く伝播された [Soul Document](https://gist.github.com/Richard-Weiss/efe157692991535403bd7e7fb20b6695) であり、AIモデルに"私は誰か、私がどのように行動すべきか"を説明する。

Harness内のSystem Promptはこれに類似するが、2つの重要な違いがある：

1. **モデル内部のものではなく**、各対話に注入される外部コマンドである
2. **本能よりも作業手册に近い**——モデルはこれらの指示に従うべきであることを知っているが、これらの指示はモデルが"天生的にできる"ことではない

System Promptの役割は**AIモデルが特定のHarnessの文脈で適切に行動することを確保する**ことである。異なるHarnessは完全に異なるSystem Promptを使用して、同一のモデルに截然異なる"性格"と能力の重みを見せることができる。

**例**：OpenClawのSystem Promptは"あなたはフレンドリーで有帮助なホームアシスタントです"かもしれない；PiのSystem Promptはよりミニマリストで、ユーザーが自分で形作れるクリーンなキャンバスのように設計されているかもしれない。

### 4.2 Tools（ツールセット）

**定義**：Toolsとは、Harnessがモデルに"呼び出し"を提供する一連のコード能力のことである。

Harnessは単にツールの機能何もかを説明するだけでなく、ツール本身的コード実装も提供する。代表的なツールには以下が含まれる：

| ツール種別 | 機能説明 |
|---------|---------|
| WebSearch | モデルにネットワーク検索させて最新情報を取得 |
| WriteCode | モデルにコードを記述・実行させる |
| ComposeEmail | モデルにメールを作成・送信させる |
| FileSystem | モデルにローカルファイルの読み書きをさせる |
| Browser | モデルにブラウザを制御させて操作を実行 |

**鍵となる設計原則**：Harnessは通常、モデルがいつどのようにツールを使用するかを**規定しない**。単に：
1. ツールが何であるかを明確に説明する
2. ツールの呼び出し可能なインターフェースを提供する
3. "いつ呼び出すか、どれを呼び出すか"という決定権をAIモデル本身に完全に委譲する

これは微量だが重要な設計選択である——Harnessを**環境提供側**にし、**決定者**にはしない。

### 4.3 Agentic Loop（エージェントループ）

これはHarness最も核心的なコンセプトであり、AI Agentが"本当にどのように動くか"を理解するための鍵である。

#### 4.3.1 Agentic Loopとは何か

Agentic Loopとは、AIモデルがHarness環境内で**自律的意思決定によってループ的に実行する**フレームワークである。モデルは一度回答を返して終わるのではなく：

1. **リクエストを理解する**（ユーザーのpromptを理解する）
2. **行動を計画する**（どのツールを呼び出す必要があるかを決定する）
3. **ツールを実行する**（実際にツールを呼び出す）
4. **結果を評価する**（ツールが返した結果がニーズを満たすかどうかを確認する）
5. **継続するかを決定する**（結果が不十分なら、ツールを続けたり別のツールに変えたりする）
6. **最終結果を产出する**（満足したら最終出荷ツールを呼び出す）

#### 4.3.2 具体的な例：学区調査

Earendilは非常に説明的な例を提供した——Agentに地元の小学校のランキングと試験結果を比較させてアドバイスを得るタスク。

HarnessにWebSearch、WriteCode、ComposeEmailの3つのツールが組み込まれているとし、インタラクションメディアはEmailとする。ユーザーがメールを送り："A学区とB学区の実驗小学のランキングと試験点を比較して、学校選択のアドバイスをお願いします。"

Agentのワークフローは以下の通り：

```
第1歩：リクエストを理解する
────────────────────────────
モデルは"実験小学"、"A学区/B学区"、"ランキングと試験点"という概念を理解する

第2歩：情報を検索する
────────────────────────────
モデルは検索クエリを構成し、ネットワークから最新の学校ランキングと試験データを抓起す
　↓
第3歩：検索結果の評価
────────────────────────────
モデルはHarness環境で検索結果をレビューする
データが完全でないか関連性が低いことを発見
→ 自律的に再度検索することを決定

第4歩：データ分析
────────────────────────────
モデルはWriteCodeツールを呼び出す（コードを書く）
スプレッドシート生成、データを処理し、結果をフォーマットする
　↓
第5歩：中間結果の評価
────────────────────────────
スプレッドシートを元のリクエストと比較する
データがまだニーズを満たさないなら、検索を続けたり分析を修正したり продолжать
→ 必要なら第2歩に"ループバック"する

第6歩：レポート作成
────────────────────────────
モデルはComposeEmailツールを呼び出す
メール本文にアドバイスを書き込み、スプレッドシートを添付
　↓
第7歩：最終確認
────────────────────────────
モデルは自分が書いたメールと添付ファイルをレビューする
確認後送信

第8歩：ユーザーがメールを受信
────────────────────────────
数秒後、ユーザーは分析結果のサマリーを含むメールを受信する
本文は分析結論、添付ファイルは詳細なスプレッドシート
```

これが完全なAgentic Loopである——モデルはHarness環境内で**自律的にループし、自己判断でタスクが完了するまで続ける**。

#### 4.3.3 Loopの意味

Agentic Loopの存在は意味している：**AI Agentは">Q&Aマシーン"ではなく、"タスク実行者"である。**：
- 自律的に更多信息が必要かどうかを判断する
- 自律的にどのツールを使用するか選択する
- 自律的にいつ反復し、いつ終了するかを決定する

これは従来のAI対話（あなたが一句我问え一句我答え一句）とは本质的な違いがある。Agentic Loopにより、AIは複雑なマルチステップタスクを完了できるようになり、単に質問に答えるだけではない。

### 4.4 Translation Layer（翻訳レイヤー）

#### 4.4.1 翻訳レイヤーとは何か

Translation Layer（翻訳レイヤー）は、Harnessが異なるAIモデルと协调して動作できるようにする关键コンポーネントである。

 обязанности：
1. Harnessの標準インターフェースを特定のモデルのAPIフォーマットに翻訳する
2. 特定のモデルの出力をHarnessの標準フォーマットに翻訳し返す
3. 同一のAgentic Loop内でタスクのニーズに応じて**動的に異なるモデルを切り替える**ことを許可する

#### 4.4.2 なぜ翻訳レイヤーは如此重要なのか

**権力の移転**：翻訳レイヤーは、力をAI実験室からエンドユーザーの手に移す关键的なメカニズムである。

翻訳レイヤーがなければ：
- Anthropicのアプリケーションを使えば、Claudeしか使えない
- OpenAIのアプリケーションを使えば、GPTしか使えない
- あなたはAI実験室の"ユーザー"であり、本当の意味での主人ではない

翻訳レイヤーがあれば：
- 自分のHarnessをAnthropic、OpenAI、または任意のオープンソースモデルに接続できる
- 同一タスク内でClaudeに推理を処理させ、GPTに生成を処理させ、オープンソースモデルに単純なタスクを処理させることが可能
- 異なるモデルの結果をコストと効果で比較できる

**ユーザー主権の実現パス**：翻訳レイヤーは、ユーザーが"どのモデルを使用するか"を選択できることを意味し某个AI実験室のアプリケーションに束縛されるのではない。Harnessはユーザーが所有するものであり、モデルは外部から呼び出す——この主従関係はHarness哲学の核心である。

#### 4.4.3 具体的なシナリオ

先の学区調査の例に戻る。ユーザーは同一のHarnessに以下をさせることができる：
- OpenAIモデル、Anthropicモデル、オープンソースモデルに同時に同一のリクエストを送信する
- 3つの異なる返信を受け取る
- 同一のメールボックス内で3つのバージョンの結果、成本、質を比較する
- 3つのAppを別々に開き、別々にログインし、別々に記録を保存するのではなく

これがHarnessがもたらす自由である：**ツールとデータはあなたのもの、選択権はあなたのもの**。

## 五、オープンソースとユーザー自律権：Harnessの政治学

### 5.1 なぜHarnessはオープンソースでなければならないのか

EarendilはAIインフラストラクチャの重要な矛盾を指摘した：

> 最初期の流行的Agent HarnessはClaude Codeだったが、それは"モデルに依存しない翻訳レイヤー"を提供するために設計されたものではなかった——それは自分のパソコンでClaudeモデルを使ってコードを書くためのアプリケーションであった。

Claude Codeの問題：それはユーザーをClaudeモデルとAnthropicのエコシステムに束縛してしまう。モデルを簡単に切换ことも、仕事を他のHarnessに簡単に移行することもできない。

Harnessの"ユーザー自律権"の価値を真に実現するための前提は：**オープンソース + 中立**である。

### 5.2 Piの実践：ユーザーに自分のHarnessを真に"所有"させる

Earendilは記事の詳細にPiの設計哲学を述べた：

- **最小限化**：PiのSystem Promptは非常に短く、ツールセットは非常に精简されている。箱から出してすぐ使え、できる限り邪魔しない
- **拡張可能**：ユーザーはSystem Promptを修正でき、拡張パック（Extensions）を設計でき、ツールセットを調整できる
- **コミュニティ共建**：Piユーザーは既に5,000を超える拡張パックを共有している
- **完全ローカル**：Piは自分のノートパソコン上で動作し任何のクラウドサービスに依存しない
- **オープンソース**：ユーザーはコードをレビューし、コードを修正し、コードを再配布できる

これは以下のことを意味する：
- Piはユーザーが**所有する**ツールであり、ユーザーが**レンタルする**サービスではない
- ユーザーの"AI能力"は某个会社のビジネス上の決定に依存しない
- ユーザーの全会話履歴はローカルに保存され、AI実験室のサーバー上にはない

### 5.3 より大きな絵：AIの権力に対抗するツール

Earendilは以下の深いビジョンを記事结尾で述べた：

> ますます大きくなり、ますます強大なAI企業に懸念を抱く人は多い。一部の人々は完全にAIを回避することを選ぶかもしれない。
>
> 私たちEarendilは、**精巧に作られたソフトウェアと開放されたプロトコルによって人間の主体性を強化できる**と信じている。分歧和无知跨越し、持続的な喜びと理解を培養する。
>
> 私たちは今日のtechnologyが存在することを無視することでこれを実現するのではなく，而是**清醒な頭脑と揺るぎない支配でそれらを操る**ことで：私たちハンマーを振るう，而不是锤子在挥舞我们。

この言葉の潜在的な意味：**AIを放弃するより、AIの梯を手に入れる**。Harnessはその梯である。

## 六、設計哲学：ユーザー自律権の载体としてのHarness

Earendilの原文とPiプロジェクトの実践を综合すると、Harnessの設計哲学は以下の核心原則に归纳できる：

### 6.1 ツール中立（Tool Agnosticism）

良いHarnessはモデルに対して中立であるべきである。どのモデルを使用するかはユーザーの権利であり、Harnessはその選択を提供するだけであり、ユーザーに代って決定すべきではない。PiがOpenAI、Anthropic、各種オープンソースモデルの接続をサポートするのは正是この原則の反映である。

### 6.2 ユーザー主権（User Sovereignty）

ユーザーはAI実験室が提供するサービスをレンタルするのではなく、自分のHarnessを所有し管理すべきである，这意味着：
- ローカルで実行し、データはユーザー端末から離れない
- オープンソースコードで、ユーザーはレビュー・修正できる
- 会話履歴はユーザーのローカルに保存され、クラウドに保存されない

### 6.3 開放的拡張（Open Extensibility）

Harnessのツールセットとシステムプロンプトはユーザーが自由に拡張できるべきである。Piの5,000を超える拡張パックは証明している：**ユーザーにツールを拡張する権限が与えられると、エコシステムの豊かさはプラットフォーム側の期待を遥かに超える**。

### 6.4 人在回路（Human in the Loop）

Agentic Loopはモデルに自律的なループを許可하지만、Harnessの設計は常に**人在回路**を保証すべきである：
- モデルの全てのツール呼び出しはユーザーが見えるコンテキスト内で発生する
- ユーザーはいつでも介入、変更、またはAgentの行動を終了できる
- 最終的な成果物（メール、ファイル、コード）はユーザーが使用するかどうかを決定する

### 6.5 最小限のデフォルト（Minimal Default）

PiのSystem Promptは非常に短く、ツールセットは非常に精简されている。これは**意識的な抑制**である：デフォルト設定が少ないほど、ユーザーが再形成する空間が大きい。"Less is More"はHarness設計において美学の選択ではなく философская選択である。

## 七、观点のまとめと示唆

### 观点1：HarnessはAI Agentの"オペレーティングシステムレイヤー"である

モデルは計算リソースであり、Harnessはこれらのリソースをスケジュールし使用するオペレーティングシステム的なコンポーネントである。Linuxがどんなアプリが走るかに关心しないのと同様に（インターフェースに従う限り）、良いHarnessもどのモデルを使用かに关心しない（Translation Layerを通じて接続する限り）。

### 观点2：ユーザーは"ワークベンチ"を所有すべきであり"ツール"を租用すべきではない

現在のほとんどのAIプロダクト（Claude App、ChatGPT、Cursor）は本质的に**アプリケーション**である——ユーザーはAI実験室が構築したプロダクトを使用している。Harnessの理念：ユーザーは自分の**ワークベンチ**を所有すべきであり、その上でどのモデルが走るかは選択可能である。アプリケーションは時代遅れになることがあり、ワークベンチは常にあなたのものある。

### 观点3：開放プロトコル > クローズドプラットフォーム

すべてのAI実験室が自分のクローズドAgentだけを提供한다면、ユーザーはロックインされる。オープンソース、中立、相互運用可能なHarnessプロトコルは、AIの権力集中を防ぐ技術的基盤である。Earendil、OpenClaw、OpenCodeなどのプロジェクト的这种開放プロトコルのインフラストラクチャを構築している。

### 观点4：Agentic LoopはAIが"質問に答える"から"タスクを完了する"への分岐点である

従来のAI対話の限界は"あなたが一句我问え一句我答え一句"である。Agentic Loopにより、AIは自律的に計画し、自律的に反復し、自律的に成果物を納品できるようになった——これはAIが"インテリigent Q&Aエンジン"から"自律的エージェント"への核心的な飛躍である。

### 观点5：ローカルファーストはユーザーのデータ主権的唯一の実直な保障である

クラウドに保存されたAIの会話記録は商業的に持続可能ではない（AI実験室はいつでもアクセス、削除、または货币化できる）、政治的にも信頼できない（会社のポリシーと国家規制に依存する）。プレーンテキストファイルのローカル保存は、ユーザーがAI会話に対して完全な主権を持つ唯一の技術的基盤である。

### 观点6：翻訳レイヤーの競争がAIエコシステムの権力構造を決定する

誰が翻訳レイヤーを制御しているか誰がユーザーの選択権を制御している。翻訳レイヤーがオープンソースで中立なら、力はユーザーの手にある；翻訳レイヤーがクローズドソースで商用なら、力はプラットフォームの手にある。これはまだ広く認識されていない戦略的高地である。

### 观点7：オープンソースコミュニティはAI民主化の希望である

Claude CodeはAgent Harnessの時代を開いた，但它选择了封闭和绑定。Pi、OpenClaw、OpenCodeなどのオープンソースプロジェクトはこの権をユーザーに返すことを正在している。5,000を超える拡張パックの大規模エコシステムが証明している：**ユーザーに真の制御権が与えられると、彼らがにできることはプラットフォーム側の想像を遥かに超える**。

## 九、結語：ハーネスを握る

Earendilは以下の言葉を記事结尾で書いている：

> 私たちは今日のtechnologyが存在することを無視することで（人間の主体性を強化するこれを）実現するのではなく，而是**清醒な頭脑と揺るぎない支配でそれらを操る**ことで：私たちハンマーを振るう，而不是锤子在挥舞我们。

この言葉はすべてのAI時代の参加者が真面目に考える価値がある。

私たちは急速にあるAIがどこにでも存在する世界に入り込んでいる。この世界には2つの選択がある：

1. **AIのユーザーになる**——AI実験室が構築したアプリケーション内で"AI能力"をレンタルし、ロックイン、データ収集、選択権の剥奪を受け入れる
2. **AIの操縦者になる**——自分のHarnessを所有し、自分のツールとデータを掌控し、清醒な頭脑でいつどのようにAIを使用するかを決定する

Harnessはそのハーネスである。AI本身ではないが、AIを誰が制御するか、どう制御するか、誰のために服務するかを決定する。

それを握れ。
