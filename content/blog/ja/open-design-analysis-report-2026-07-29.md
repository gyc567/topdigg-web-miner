> **Open Design (OD)** はオープンソース、ローカルファーストのClaude Design代替で、あなたのCLIをデザインエンジンに変えます。本包括的分析はプロジェクトのアーキテクチャ、設計哲学、実用チュートリアル、そしてAgent時代の核心洞察をカバーします。

## 1. プロジェクト説明

### 1.1 Open Designとは何か？

Open DesignはオープンソースのClaude Design代替です。2026年4月、AnthropicはClaude Designを発表しました — LLMがもはや文章を書かず、デザイン成果物を直接届けるようになったのは初めてのことでした。それは急速に広まりましたが、常にクローズドソース、有料のみ、クラウド限定で、Anthropicのモデル、スキル、表面にロックインされていました。Checkout機能はなく、セルフホストはできず、Vercelデプロイもできず、自分のAgentに交換することもできませんでした。

Open Designはあらゆるロックインを打破します：

- **🌐 オープンソース（Apache-2.0）**：完全透明、サブスクリプションなし、ベンダーロックインなし
- **🖥️ ローカルファースト**：macOS（Apple Silicon + Intel）とWindows（x64）のネイティブデスクトップアプリ、Linux AppImageはオプション
- **🤖 Agent原生**：25+のローカルCLI実行ファイル上で動作 — Claude Code、Codex、Cursor、Copilot、OpenCode、Qwen、Hermes、Kimi、Antigravityなど — またはBYOK経由で任意のOpenAI互換エンドポイントに接続
- **🔒 プライバシー優先**：すべてはデータが存在する場所で実行される — あなたのノートPC、あなたのチームサーバー、あなたのVercelプロジェクト

### 1.2 中核機能

| 機能 | 詳細 |
|------|------|
| **プロトタイプ** | Web、デスクトップ、モバイル単一ページHTML成果物、サンドボックスiframeプレビュー付き |
| **リアルタイムダッシュボード** | 編集可能なKPI大画面、リアルタイム調整パネル |
| **プレゼンテーション** | 15セットのDeckテンプレート × 36テーマ、HTML/PDF/PPTXにエクスポート |
| **画像** | 93個の再現可能なプロンプトテンプレート、gpt-image-2、ImageRouter、カスタムAPIに対応 |
| **動画/HyperFrames** | HeyGen HyperFramesフレームワークによるHTML→MP4モーショングラフィック、11テンプレート + 39 Seedanceプロンプト |
| **デザインシステム** | DESIGN.mdを中心とした151個のブランドレベルデザインシステムパッケージ |
| **プラグイン** | 277個の公式プラグイン + 183個のミックス可能リファレンス例 |

## 2. 詳細チュートリアル

### 2.1 クイックスタート：デスクトップアプリをダウンロード（ゼロ設定）

Open Designを使用する最速の方法はデスクトップアプリです。Node、pnpm、またはリポジトリのクローンは不要です。

1. [open-design.ai](https://open-design.ai/) または[GitHub Releases](https://github.com/nexu-io/open-design/releases) にアクセス
2. macOS（Apple Silicon / Intel x64）またはWindows（x64）版をダウンロード
3. インストールして開く — アプリがPATH上のすべてのコーディングAgent CLIを自動検出
4. スキルを選択し、デザインシステムを選択し、要求を入力して送信をクリック

### 2.2 コーディングAgentへのインストール（ヘッドレス）

CLI Agent内で直接作業したい場合は：

```bash
# ワンコマンドインストール（16+ CLIサポート）：
od mcp install <agent>
# <agent> = claude | codex | cursor | copilot | opencode | kimi | hermes | ...

# その後Agent内で：
> Use open-design to generate a landing page with the Linear design system
```

> **macOSユーザーへの注意**：`/usr/bin/od`（Appleの8進ダンプツール）がOpen Design CLIを上書きする場合は、デスクトップアプリの「設定 → MCPサーバー」コードスニペットを使用してください。

### 2.3 完全ワークフロー：要求から成果物まで

完全なデザインフローは、`DESIGN.md`をブランド契約として駆動する5つのステップに従います：

```
要求 → プラグイン → 方向 → デザインシステム → 成果物 → 配信 → 記憶
```

**ステップ 1 — PMが要求を提出**：プラグインセレクターがランディングページ、ピッチDeck、ダッシュボード、ソーシャルメディア投稿、PM仕様、OKRスコアカードなどを提供。

**ステップ 2 — 方向を確定**：ブランドがない？ 5つのキュレート方向から選択。ブランドがある？ スクリーンショットまたはURLを投入 — AgentがGitHubに接続、figmaをインポート、再利用可能な`DESIGN.md`を編纂。

**ステップ 3 — 最初の成果物を作成**：Agentがプラグイン + 機能スキル + デザインテンプレート + `DESIGN.md`を組み合わせ、仕様プロジェクトファイルに書き込み。プレビューが即座に更新。

**ステップ 4 — エンジニアリングチームに配信**：成果物は実際のHTML/CSS — Cursor、Codex、Claude Codeに入れてコード開発を継続、またはPPTX/PDF/MP4に直接エクスポートしてマーケティングチームに引き渡し。

**ステップ 5 — ODは使うほど賢くなる**：スクリーンショット、フォント、カラーパレット、確認された成果物が次回のセッションのデフォルトとして蓄積。繰り返しの作業が減り、ずれが減る。

### 2.4 Dockerセットアップ（貢献者向け）

```bash
git clone https://github.com/nexu-io/open-design.git
cd open-design/deploy
cp .env.example .env
echo "OD_API_TOKEN=$(openssl rand -hex 32)" >> .env
docker compose up -d
# http://localhost:7456を開く
```

### 2.5 ソースから実行（開発モード）

```bash
git clone https://github.com/nexu-io/open-design.git
cd open-design
corepack enable && pnpm install
pnpm tools-dev run web
```

> **要件**：Node ~24、pnpm 10.33.x。WSL2ユーザーはまず[WSL2設定ガイド](docs/wsl-setup.md)を参照してください。

## 3. 要約された見解

### 見解一：Agent原生設計はパラダイムシフト

Open Designは独自のAgentを発行しない — あなたの既存のCLIをデザインエンジンに変えます。これはFigma（キャンバスツール）やLovable/v0/Bolt（クラウドAgent）と根本的に異なります：

- **ローカル実行でクラウドラウンドトリップなし** — すべてがあなたのマシンで発生
- **ワンクリックでAgent切り替え** — Claude Code、Codex、Cursor、または25のサポートされているCLIのいずれか
- **Agentの優位性が設計の優位性になる** — コード生成、繰り返し速度、コンテキスト認識
- **ファイルシステムが唯一の真実の源** — Agentはキャンバス状態ではなく実際のファイルを読み書き

これは哲学的転換を表しています：設計はキャンバス上でピクセルをプッシュすることではなく、命令を構成し、Agentが実際のコードと実際のデータで実行することです。

### 見解二：DESIGN.mdをブランド契約とする発想は天才

`DESIGN.md`ファイルはOpen Designのブランドレベルアプローチの中核です。各レンダリングは現在のパッケージの`DESIGN.md`を中核ブランド契約として読み取ります。これが驚異的なのは：

- **標準フォーマット** — 各チームはすでにMarkdownを使用しており、採用の摩擦はゼロ
- **組み合わせ可能** — DESIGN.mdはmanifest.json、tokens.css、コンポーネント、資産、出所情報を運べる
- **バージョン管理可能** — ファイルであるため、コードと一緒にGitに住む
- **リフレッシュ可能** — Gitリポジトリ + DESIGN.mdをAgentに渡すと、ブランド仕様に合わせて実際のコンポーネントを再構築

リポジトリには151個のデザインシステムパッケージが付属しており、AppleからStripe、NotionからFerrariまで全てをカバー。ディレクトリはリソースであると同時に概念実証です。

### 見解三：ローカルファーストはプライバシーファーストを意味する

クラウドデザインツールが第三者サーバーへのデータアップロードを要求する時代において、Open Designのローカルファーストアーキテクチャは急進的な選択であり、深遠な意味を持ちます：

- **デフォルトでデータはノートPCから出ない**
- **すべてのレイヤーがBYOK** — あなたのAPIキー、あなたのモデル、あなたの認証情報はサーバーに保存されない
- **デーモンエッジにSSRF防御** — 内部ネットワークIP、リンクローカル、CGNATが自動ブロック
- **分析データはオプトイン** — 製品テレメトリはオプションで、サニタイズされたセーフデータのみ収集

これは単にプライバシー機能ではなく、ビジネスモデルの革新です。BYOKは、Open Designに最低請求階層、プロプライエタリモデルコスト、推論ベンダーロックインがないことを意味します。ユーザーは選択したプロバイダーのAPI呼び出しの費用のみを支払います。

### 見解四：4つの平面での組み合わせ可能性は注目すべきアーキテクチャ

Open Designの組み合わせ可能なアーキテクチャは4つの異なる平面で動作します：

1. **プラグイン** — 実行可能なワークフロー（マイグレーション、コード生成、データ抽出）を運ぶ
2. **機能スキル** — Agentの動作を運ぶ（デザインタスクの段階的命令）
3. **デザインテンプレート** — レンダリングブループリントを運ぶ（プロトタイプ、Deck、画像、動画パターン）
4. **デザインシステム** — ブランドを運ぶ（DESIGN.md + tokens.css + コンポーネント + 資産）

4つすべてがポータブル、バージョン管理可能なディレクトリを使用し、誰でも作成・公開できます。この四面体モデルは、Figmaのプラグインストア、Lovableのテンプレート、またはClaude Designの閉鎖されたスキルよりも豊かです。「デザインツール」、「コードジェネレータ」、「テンプレートライブラリ」、「ブランドシステム」の境界が曖昧になるエコシステムを作り出します。

### 見解五：HyperFramesは動的デザインをAgent原生にする

HyperFrames（HeyGenのオープンソースAgent原生動画フレームワーク）をファーストクラス市民として統合することは重要な差別化機能です。AgentがHTML + CSS + GSAPを記述し、HyperFramesがヘッドレスChrome + FFmpegで決定論的MP4にレンダリングします。これは次のような意味を持ちます：

- **新しいツールを学ぶ必要なし** — Agentがすでに知っているコードを書く
- **決定論的出力** — 同じ入力 = 同じMP4、いつでも
- **他のメディアと組み合わせ可能** — Seedance 2.0を動画生成に、Suno v5をオーディオに組み合わせ
- **すぐに使える** — 11テンプレート + 39プロンプト

これはデザインループの最後のギャップを埋めます：動的要素。プロトタイプはすでにAgent原生だったが、今では動画とアニメーションもそうなった。

## 4. 設計哲学

### 哲学一：利便性より開放性

> 「Open Designは、Agent原生のループが閉鎖されるのを止めたときに生まれた産物です。」

Open Designの創立時の決定は、Claude Designの閉鎖されたエコシステムを拒否することでした — 精巧なワンストップ製品の利便性を受け入れる代わりに、開放性、透明性、コミュニティ所有を選択。これはシリコンバレーの壁に囲まれた庭園モデルとは逆です。結果として：

- **セルフホスト可能** — あなたのサーバー、あなたのVercelプロジェクトで実行
- **任意のモデルを使用可能** — GPT、Claude、Gemini、DeepSeek、または任意のOpenAI互換エンドポイント
- **誰でも拡張可能** — 100+機能スキル、277プラグイン、151デザインシステム、すべてコミュニティが作成可能
- **最低請求なし** — BYOKはコストを完全にコントロールできることを意味する

### 哲学二：CLIがインターフェース

従来のデザインツールはGUIを使用：ピクセルをドラッグし、レイヤーを配置し、ボタンをクリック。Open DesignはインターフェースをCLIとして再想像します。あなたの入力AgentがUIです — 命令を読み、ファイルを書き込み、ファイルシステム操作を通じて繰り返し。これはAgent時代にとって深い意味を持ちます：

- **LLMは構造化テキストの読み書きが最も得意** — JSON、YAML、Markdown、CSS、HTML
- **ファイルシステムは最も普遍的なAPI** — 各AgentはファイルI/Oを理解する
- **バージョン管理（Git）がデザインのバージョン管理になる** — 各繰り返しは1つのコミット
- **組み合わせ可能性は自然に生まれる** — 1つのAgentの出力を別のAgentにパイプできる

### 哲学三：デザインシステムは設定ではなくコード

Open Designはデザインシステムを、JSON設定ファイルやビジュアルテーマエディタではなく、コードとして扱います。デザインシステムはGitに住む`DESIGN.md`ファイルであり、出所情報があり、他のデザイン要素と組み合わせ可能です。この哲学は：

- **Figmaのプロプライエタリフォーマットを拒否** — デザイントークンはベンダー固有フォーマットではなくCSS変数
- **既存のツールチェーンを採用** — Markdown、CSS、Git、npm
- **デザインシステムをプログラム可能に** — Agentはコードを扱うようにデザイントークンを読み、修正、推論できる
- **チームコラボレーションをサポート** — デザインシステムの変更は他のコード変更と同様にPR

### 哲学四：Agentはツールだけでなくユーザーでもある

ほとんどのデザインツールは人間のために構築されています。Open DesignはAgentのために構築され、同時に人間はループ内に留まります。この反転はアーキテクチャに深い意味を持ちます：

- **MCPが主要プロトコル** — REST APIやWebhookではなく、stdioベースのモデルコンテキストプロトコル、直接ファイルシステムアクセス用
- **スキルは行動単位** — アクションやマクロではなく、Agentが連鎖できるポータブルな命令パッケージ
- **プレビューは副作用** — 主要出力はディスク上のファイル；サンドボックスiframeは人間のレビュー専用
- **エクスポートは多くの出力の1つにすぎない** — HTML、PDF、PPTX、MP4、Markdown、ZIP — すべて同じソースのファイルシリアライゼーションにすぎない

### 哲学五：コミュニティがエンジン

> 「Open Designが前進し続けているのは貢献者のおかげです — デザイナー、エンジニア、プロンプト作成者が絶え間なく現れています。」

プロジェクトは最も人気のあるコンポーネントの多くを明確に外部貢献者に帰属しています。Open Design Fellowプログラム（$1,000/MR、無料LLMクレジット、成長インセンティブ）はコミュニティ貢献を一流の活動として正式化します。プラグインマーケット、デザインシステムディレクトリ、スキルライブラリはすべて「オープン標準で収束、実装で発散」モデルを採用しており、成功したオープンソースエコシステムを模倣しています。

## 6. 結論

### Open Designが正しくやったこと

1. **実際のロックイン問題を解決** — Claude Designの閉鎖エコシステムはセルフホスト、モデル交換、Vercelデプロイ、コミュニティ拡張がないことを意味する。Open Designはあらゆる制約を除去。

2. **DESIGN.mdをブランド契約とする発想はゲームチェンジャー** — それは最もシンプルで実用的な解決策：Git内のMarkdownファイル、どのAgentも読める、どの人間も編集できる、どのツールも生成できる。

3. **四面体の組み合わせ可能性モデル**（プラグイン × スキル × テンプレート × デザインシステム）は、単一ベンダーのデザインツールよりも豊かなエコシステムを作り出した。

4. **ローカルファースト + BYOK** は、プロプライエタリブランド資産や未発表製品を含む専門的なデザイン作業にとって唯一合理的なアーキテクチャ。

### まだ証明すべきこと

1. **コミュニティスケーラビリティ** — 277プラグインと151デザインシステムは若いプロジェクトとして印象的だが、スケールでの品質維持には強力なガバナンスと貢献ガイドラインが必要。

2. **Agentの信頼性** — 出力品質は完全に基盤となるCLI Agent次第。Agent能力の進化（良くも悪くも）とともに、Open Designの出力品質も変動する。

3. **UXギャップ** — CLIファーストモデルは哲学的には合理的だが、Figmaを開くよりも依然として多くの技術スキルを必要とする。デスクトップアプリは助けになるが、学習曲線はクリック式ツールより急峻。

4. **従来の巨人からの競争** — AnthropicはClaude Designを反復してオープンエコシステムに進入するかもしれず、Figmaは既存のAgentプラグインを買収済み。オープンソースの優位性はコミュニティにあり、技術だけではなく。
