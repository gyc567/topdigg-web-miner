## はじめに

AIプログラミングアシスタントが日益に普及する今日、これらのツールにプロジェクトの理解とチームルール遵守をさせることは、開発効率を向上させる鍵となっています。AGENTS.mdは、Cursor、Copilot、Codex、Claude Codeなどの主要AIプログラミングツールに広くサポートされているオープン標準です。本記事では、AGENTS.mdの設計哲学とベストプラクティスを深く掘り下げます。

## AGENTS.mdがなぜ重要か

### 大規模設定ファイルの困境

 сучасні великі мовні моделі (LLM) は能力が向上続けているものの黎明の命令 followingには天生の制限があります。研究によると、最先端のLLMでも約**150〜200個**の命令しか一貫してフォローできないことが示されています。AGENTS.mdファイルが肥大化すると、次のような問題が発生します：

- **トークンの無駄**：すべてのトークンはリクエストごとにロードされ、冗長なコンテンツは直接コストを増加させます
- **遵守率の低下**：命令が多いほど、モデルが重要なルールを無視または誤解する可能性が高くなります
- **レスポンスの遅延**：コンテキストが長いほど、最初のリスポンス時間が遅くなります

### 肥大化したファイルの実際のコスト

典型的な失敗例は、何千行もの「ベストプラクティス」を含むAGENTS.mdファイルです Such files:
- 決して実行されない 수많은命令を含みます
- 異なるシナリオの競合するルールを混在させます
- 維持と更新が困難です
- 新しいチームメンバーの理解障壁となります

## AGENTS.md vs CLAUDE.md：主な違い

名前が似ていても，这两个文件有不同的定位：

| 機能 | AGENTS.md | CLAUDE.md |
|------|-----------|-----------|
| **標準** | クロスプラットフォームオープン標準 | Claude Code専用設定 |
| **サポートツール** | Cursor、Copilot、Codex、Claude Codeなど | Claude Codeのみ |
| **設計目標** | 汎用プロジェクトガイダンス | Claude固有の最適化 |
| **エコシステム** | オープン標準コミュニティ駆動型 | ベンダーロックイン（Anthropic） |

**コアポイント**：複数のAIプログラミングツールでプロジェクト設定を使用できるようにしたい場合は、AGENTS.mdが最適な選択です。Claude Codeの体験を最適化することに集中したい場合は、CLAUDE.mdがより精细な制御を提供します。

## ルートファイルのコアコンテンツ

効率的なルートAGENTS.mdファイルは簡潔に保ち、最も重要な情報のみを含める必要があります。

### 3つの必須要素

#### 1. 一文プロジェクトの説明

```markdown
# プロジェクト名

Rustで構築された高性能暗号通貨取引ボット
```

これにより、AIアシスタントはプロジェクトに初めて接触する際に正しいコンテキストを確立できます。

#### 2. パッケージマネージャーの指定

```markdown
## パッケージマネージャー

- Python依存関係の管理に`poetry`を使用
- Rust依存関係の管理に`cargo`を使用
```

プロジェクトが標準以外のツールチェーンを使用する場合、これは特に重要です。

#### 3. 非標準ビルドコマンド

```markdown
## ビルドコマンド

- 型チェック：`pytest --type-check`
- ビルド：`make build TARGET=release`
- テストカバレッジ：`make coverage`
```

AIがビルドコマンドを推測したり、誤ったコマンドを使用したりすることを避けます。

### 含めるべきではない内容

**ルートファイルに含めないもの：**
- 詳細なコードスタイルガイドライン（別ファイルに移動）
- 特定のフレームワークの使用ガイド（プロジェクトの中核でない限り）
- 完全なディレクトリ構造の説明（この情報はすぐに時代遅れになります）

## プログレッシブディスクロージャーの原則

「プログレッシブディスクロージャー」（段階的開示）は、効果的なAGENTS.md設計の核となる哲学です。コアアイデアは：**関連するルールを必要な時にのみロードする**です。

### ディレクトリ構造の例

```
project/
├── AGENTS.md              # ルート：グローバルルール + リンク
├── docs/
│   ├── TYPESCRIPT.md      # TypeScript固有のルール
│   ├── TESTING.md         # テスト規則
│   ├── API.md             # API設計ガイドライン
│   └── DEPLOYMENT.md      # デプロイメントプロセス
└── packages/
    ├── core/
    │   └── AGENTS.md      # コアモジュール専用ルール
    └── cli/
        └── AGENTS.md      # CLIツール専用ルール
```

### サブファイルのリンク方法

ルートのAGENTS.mdで明確なリンクを使用します：

```markdown
## 詳細なドキュメント

- [TypeScriptガイドライン](docs/TYPESCRIPT.md)
- [テストガイド](docs/TESTING.md)
- [API設計](docs/API.md)
```

### プログレッシブディスクロージャーの利点

1. **認知的負荷の軽減**：AIと人間の両方が現在のタスクに関連するルールにのみ焦点を当てる必要があります
2. **遵守率の向上**：命令が少ないほど、执行精度が高くなります
3. **メンテナンスの簡素化**：独立したファイルは他のルールに影響を与えずに個別に更新できます
4. **より良い分離**：ルール間の競合と依存関係减少了

## モノレポサポート

AGENTS.mdの別の強力な機能は、複数レベル設定のサポートです。

### マージルール

異なるディレクトリにAGENTS.mdファイルが存在する場合、AIアシスタントは自動的にそれらをマージします：

- **ルートAGENTS.md**：グローバルルール、共有ツール、共通規則
- **サブディレクトリAGENTS.md**：特定のパッケージガイダンス

### 実践例

次のような構造のモノレポがあるとします：

```
monorepo/
├── AGENTS.md              # プロジェクト全体の説明
├── packages/
│   ├── shared/
│   │   └── AGENTS.md      # 共有ライブラリルール
│   └── app/
│       ├── AGENTS.md      # アプリケーション固有のルール
│       └── docs/
│           └── FEATURES.md
```

サブディレクトリのルールはルートのルールを継承して拡張し、完全なコンテキストを形成します。

## ベストプラクティスと一般的な落とし穴

### ベストプラクティス

#### 1. 遵守率向上のための強調詞の使用

```markdown
IMPORTANT: すべてのAPI応答にはエラーコードを含める必要があります
MUST: コミット前にテストを実行します
NEVER: mainブランチに直接コミットしないでください
```

研究により、强烈的指示語（IMPORTANT、MUST、NEVERなど）がモデルの遵守率を著しく向上させることが示されています。

#### 2. 簡潔さを保ち、優先順位を強調

良いAGENTS.md：
- 各ルールは1文
- 優先順位順に並んでいる
- プロジェクト固有の用語を使用

#### 3. チーム vs 個人の好み

| タイプ | 場所 | 例 |
|------|------|------|
| チームルール | メインAGENTS.md | コードレビュー流程、Git規則 |
| 個人的な好み | ローカルオーバーライドファイル | エディタ設定、ショートカット |

#### 4. 定期的なレビューと清理

四半期ごとにAGENTS.mdをレビューし、以下を削除します：
- もう適用されないルール
- 決して遵守されなかった指示
- 実際の実践と矛盾する規定

### 一般的な落とし穴

#### 落とし穴1：過度の文書化

** 잘못된 예**:
```markdown
## コードスタイル

- クラス名はPascalCaseを使用
- メソッド名はcamelCaseを使用
- 変数名はsnake_caseを使用
- 定数はすべて大文字
- プライベートメソッドは_で始まる
- ...
（200行続く）
```

**正しいアプローチ**：リンティング設定またはスタイルガイドドキュメントにリンクします。

#### 落とし穴2：ファイル構造の文書化

** 잘못된 예**:
```markdown
## ディレクトリ構造

src/
├── controllers/
│   ├── AuthController.php
│   └── UserController.php
├── models/
│   └── User.php
└── services/
    └── AuthService.php
```

**正しいアプローチ**：特定の paths ではなく、プロジェクトの形態と能力を記述します。

#### 落とし穴3：時代遅れ情報の 포함

ファイル paths、依存関係バージョン、ツール設定はすぐに時代遅れになります。AGENTS.mdを高レベルかつ原則的に保ち、具体的な技術的詳細を避けます。

## 重要なポイントまとめ

1. **簡潔に保つ**：ルートAGENTS.mdは150〜200行以内にし、コアレンジラクのみを含める
2. **プログレッシブディスクロージャー**：詳細なルールは別ファイルに移動し、必要に応じてロード
3. **能力而非構造を記述**：プロジェクトが何をするかを説明し、ファイルがどこにあるかではない
4. **強調詞を使用**：IMPORTANT、MUST、NEVERは遵守率を向上させます
5. **クロスプラットフォームの考慮**：複数ツールのサポートが必要な場合は、专用設定よりAGENTS.mdを優先
6. **定期的なメンテナンス**：時代遅れのルールを継続的に清理し、ファイルの鮮度を保つ

## 結論

AGENTS.mdは単なる設定ファイルではなく、AI時代におけるプロジェクトの自己記述言語です。「小さく美しい」という設計原則に従うことで、AIプログラミングアシスタントがプロジェクトをより効率的に理解し、私たちの規則従い、最終的には真に価値のある開発パートナーとなることができます。

正しいAGENTS.md戦略は以下を可能にします：
- AIの誤解とミスを減少
- 開発速度の向上
- コードの一貫性改善
- 新メンバーの参入障壁降低

今すぐプロジェクトのAGENTS.mdを見直し、簡素化の旅を始めましょう。
