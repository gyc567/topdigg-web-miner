# ToolJet：オープンソース低コードプラットフォームで内部ツールを構築する完全ガイド

## プロジェクト背景とコア問題

### 内部ツール開発の困境

現代の企業デジタルトランスフォーメーションにおいて、**内部ツール開発**は見過ごされがちなながらも極めて重要な問題です。すべての企業に多くの内部ニーズがあります：CRMシステム、データダッシュボード、工数管理システム、承認ワークフローなど。しかし、従来の開発アプローチは多くの課題に直面しています：

| 痛点 | 従来開発 | 低コードプラットフォーム |
|------|---------|----------------------|
| **開発期間** | 数週間甚至は数ヶ月 | 数時間から数日 |
| **技術障壁** | 專業開発者が必要 | 業務担当者でも利用可能 |
| **維持コスト** | 高額な保守費用 | ビジュアル保守 |
| **反復速度** | 遅い、開発スケジュールに依存 | 速い、即時反映 |
| **コスト** | 人件費が高い | 大幅に低減 |

ToolJetはこれらの問題を解決するために作られました。2021年にリリースされ、オープンソース低コードプラットフォーム分野で明星プロジェクト迅速にになりました：

## プロジェクト概要

### ToolJetとは？

ToolJetは**オープンソース低コードプラットフォーム**で、内部ツール、ビジネスアプリケーション、データダッシュボードを迅速に構築・デプロイするために設計されています。コアPhilosophyは：

> **"開発チームが最小限の時間と労力で強力な内部ツールを構築できるようにし、車輪の再開発を避ける。"**

### 主要機能一覧

| 機能 | 説明 |
|------|------|
| 🎨 **ビジュアルビルダー** | ドラッグ＆ドロップUIビルダー、60+レスポンシブコンポーネント |
| 🔗 **データソース統合** | データベース、API、SaaSサービスを含む80+データソースに接続 |
| 📊 **組み込みデータベース** | ToolJet Database — コード不要データベースソリューション |
| 🔄 **マルチページアプリ** | 複雑なマルチページアプリケーションとルーティングをサポート |
| 👥 **コラボレーション編集** | リアルタイムコラボレーション、複数ユーザーが同時に編集 |
| 💻 **コード実行** | ネイティブJavaScriptとPython実行をサポート |
| 🔌 **プラグインシステム** | CLIによるカスタムプラグイン拡張 |
| 🛡️ **セキュリティ機能** | AES-256-GCM暗号化、SSO、ロールベースアクセス制御 |
| ☁️ **柔軟なデプロイメント** | Docker、Kubernetes、クラウドプロバイダー一括デプロイメント |

## 設計Philosophy

### コアPrinciple

ToolJetの設計Philosophyは以下のコア原則を中心にしています：

#### 1. 開発民主化（Democratizing Development）

> **"非技術者もプロフェッショナルな内部ツールを構築できるようにする。"**

ToolJetはビジュアルインターフェースを通じて開発障壁を下げると同時にディープなカスタマイズが必要な場合に技術チームのためにコード拡張能力を保持しています。

#### 2. セキュリティファースト（Security First）

すべてのデータ操作はバックエンドプロキシを通じて行われ、フロントエンドが直接データベースに接続することは決してありません：

```
┌─────────────────────────────────────────────────────────────┐
│                    セキュアデータフロー                       │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│   フロントエンドコンポーネント  ───▶  ToolJet API  ───▶  データソース  │
│                                  │                           │
│                                  ▼                           │
│                           ┌──────────────┐                  │
│                           │ セキュリティ  │  • 認証検証      │
│                           │ チェック     │  • 認可検査      │
│                           │ データマスキング│  • SQLインジェクション防止  │
│                           └──────────────┘  • 機微データフィルタリング  │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

#### 3. オープン＆拡張可能（Open & Extensible）

- **完全オープンソース**：コードは透明で監査可能
- **プラグインエコシステム**：誰でもプラグインを作成して共有可能
- **カスタムコンポーネント**：ディープなUIと動作のカスタマイズをサポート

#### 4. パフォーマンス指向（Performance Oriented）

- **コンポーネント遅延読み込み**：表示されているコンポーネントのみを読み込む
- **クエリキャッシュ**：重複リクエストを削減
- **仮想スクロール**：大規模データリスト高效レンンダリング
- **接続プール**：データベース接続の再利用

## クイックスタートチュートリアル

### 環境要件

開始する前に、システムが以下の要件を満たしていることを確認してください：

| コンポーネント | 最小要件 | 推奨構成 |
|---------------|---------|---------|
| **メモリ** | 4 GB | 8 GB以上 |
| **ディスク** | 10 GB | 20 GB以上 |
| **Docker** | 20.x以上 | 最新バージョン |
| **Node.js** | 18.x以上 | 20.x LTS |

### 方法1：Dockerクイックデプロイメント（推奨）

これが最もシンプルな開始方法です：

```bash
# 1. ToolJetイメージをプル
docker pull tooljet/try:ee-lts-latest

# 2. コンテナを実行
docker run -d \
  --name tooljet \
  -p 8082:80 \
  -v tooljet_data:/var/lib/postgresql/13/main \
  --restart unless-stopped \
  tooljet/try:ee-lts-latest

# 3. アプリケーションにアクセス
# ブラウザで http://localhost:8082 を開く
```

**注意**：初回起動はデータベース初期化に数分かかります。

### 方法2：ローカル開発環境セットアップ

ディープな理解とカスタマイズしたいユーザー向け：

```bash
# 1. リポジトリをクローン
git clone https://github.com/ToolJet/ToolJet.git
cd ToolJet

# 2. 依存関係をインストール
npm install

# 3. 環境設定をコピー
cp .env.example .env

# 4. データベースサービスを起動
docker-compose up -d postgres redis

# 5. データベースマイグレーションを実行
npm run db:migrate

# 6. シードデータ（オプション）
npm run db:seed

# 7. 開発サーバーを起動
npm run dev

# 8. http://localhost:8082 にアクセス
```

## ハンズオン教程：タスク追跡アプリケーションの構築

### ステップ1：新規アプリケーションを作成

1. ToolJet Dashboardにログイン
2. **Create new app**をクリック
3. アプリケーション名を入力：`Task Tracker`
4. 空のキャンバスまたはテンプレートを選択

### ステップ2：データソースを設定

1. 左パネルの**Data Sources**をクリック
2. **ToolJet Database**を選択
3. タスクテーブルを作成：

```sql
CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  status VARCHAR(50) DEFAULT 'pending',
  priority VARCHAR(50) DEFAULT 'medium',
  assignee VARCHAR(100),
  due_date DATE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### ステップ3：UIインターフェースを構築

左パネルのコンポーネントをキャンバスにドラッグ：

| コンポーネント | プロパティ | 設定 |
|---------------|----------|------|
| **Text Input（タイトル）** | variableName | `taskTitle` |
| **Text Area（説明）** | variableName | `taskDescription` |
| **Dropdown（優先度）** | options | `[{label: '高', value: 'high'}, {label: '中', value: 'medium'}, {label: '低', value: 'low'}]` |
| **Button** | text | `タスクを追加` |
| **Table** | data | `{{queries.tasks.data}}` |

### ステップ4：データクエリを作成

1. **Queries**パネルのクリック
2. 新規クエリを追加：`tasks`
3. データソースを選択：`ToolJet Database`
4. SQLを入力：

```sql
SELECT * FROM tasks ORDER BY created_at DESC;
```

### ステップ5：イベントハンドラを設定

ボタンにクリックイベントを追加：

| イベント | アクション | 設定 |
|---------|----------|------|
| `onClick` | Run Query | `queries.createTask` |

`createTask`クエリを作成：

```sql
INSERT INTO tasks (title, description, priority)
VALUES ('{{components.taskTitle.value}}',
        '{{components.taskDescription.value}}',
        '{{components.priorityDropdown.value}}');
```

### ステップ6：プレビューと公開

1. 右上隅の**Preview**をクリックして効果をプレビュー
2. 追加、編集、削除機能をテスト
3. 準備ができたら**Publish**をクリック

## まとめと結論

### コア洞察

#### 1. 低コードのコア価値

低コードプラットフォームのコア価値は「コードの排除」ではなく：

> **"反復的な作業を自動化し、プロフェッショナルにプロフェッショナルな仕事をさせる。"**

#### 2. オープンソースの戦略的意义

オープンソース低コードプラットフォームを選択することは以下を意味します：

| ディメンション | 優位性 |
|--------------|--------|
| **データ主権** | データは完全に自分のコントロール下にある |
| **コスト管理** | ベンダーロックインなし、需要に応じて拡張 |
| **カスタマイズの自由** | 特定のニーズを満たすために自由に変更可能 |
| **長期的実行可能性** | 単一ベンダーの存続に依存しない |

#### 3. アーキテクチャ設計の示唆

ToolJetのアーキテクチャ設計は優れた参考を提供します：

- **フロントエンド・バックエンド分離**：独立した拡張と保守が容易
- **プラグイン設計**：高度に拡張可能
- **セキュリティファースト**：すべてのデータがバックエンドプロキシを通過
- **パフォーマンス指向**：大数据量シナリオを考慮

### ユースケース

✅ **ToolJetを強く推奨**：

- 内部ツールを迅速に構築する必要がある中小企業
- 高速プロトタイプ検証が必要な開発チーム
- プライベートデプロイメントを必要とするデータ機密アプリケーション
- 既存システムとの深い統合が必要なシナリオ
