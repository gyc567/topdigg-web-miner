## 1. プロジェクト概要

### 1.1 Prime Agentとは？

Prime Agentは、汎用および長時間実行ワークロード向けに設計されたオープンソースのコーディングおよび研究エージェントです。2つのコア抽象化を中心に構築されています：

1. **再帰言語モデル（RLM）**：コンテキストを変数として扱い（*プロンプト-as-a-変数*）、ツール/再帰サブエージェントを関数呼び出しとして扱います（*プログラマティックツール/サブエージェント呼び出し*）、永続REPL内で動作します
2. **継続的ハーネス**：補足プロンプト、メモリ、スキル説明、再利用可能なサブエージェント仕様を耐久性のある状態として保存し、Prime Agentが小規模な、エビデンスに基づいた更新で改善できます

これは別のチャットインターフェースやコード補完ツールではありません。Prime Agentは永続的なPython制御環境で動作し、継続的改善メカニズムを通じて学習・適応する真のプログラミングエージェントです。

### 1.2 コア機能

| 機能 | 詳細 |
|------|------|
| **永続IPython制御環境** | モデルがターン間で状態を保持する耐久性のあるPythonカーネル内で動作 |
| **再帰サブエージェント** | `rlm(...)` が並列/バックグラウンド作業用に子エージェントを生成し、プログラマティックにハンドルを返す |
| **自己改善ハーネス** | `/refine` が軌跡をレビューし、エビデンスに基づいた更新を補足状態に適用 |
| **実行可能スキル** | インポート可能なPythonパッケージ、組み込みスキル作成機能 |
| **バックグラウンドセッション** | デーモンバックエージェントがターミナル切断時も実行を維持 |
| **エージェント間通信** | 実行中のエージェントがメッセージを交換し、相互にオーケストレーション可能 |
| **自律モード** | 設定可能な品質ゲートを持つ有界継続 |
| **長時間実行サポート** | 自動圧縮、永続目標、ハートビート、スケジュール |

### 1.3 重要な概念

#### RLMプログラミングモデル — 新しいAIプログラミングパラダイム

Prime Agentはツール付きの別のチャットインターフェースではありません。再帰言語モデル（RLM）という新しいプログラミングパラダイムを中心に構築されています。これはコンテキストを変数として扱い、サブエージェントを関数呼び出しとして扱います。

従来のAIプログラミングエージェントは各タスクに別個のツール呼び出しを使用します。Prime Agentは異なります—永続的なPythonカーネル全体をコアツールとして使用します。ファイル操作、コマンド実行、ツール使用、サブエージェント、コンテキスト管理はすべてコードを通じて行われます。

これには2つの深い影響があります：

1. **プログラマティック能力**：モデルは別個のツール定義なしにPythonカーネル内で anything を実行できます。这意味着运行时可以创建新工具、修改行为，并适应任何编程任务
2. **再帰サブエージェント**：`rlm(...)` は別個のツール呼び出しではなく、真の子エージェントを生成します。サブエージェントはハンドルを返し、結果は明示的なメッセージパッシングを通じて取得され、複雑な並列およびバックグラウンドワークフローをサポートします

#### 継続的ハーネス — 学習と適応

継続的ハーネスはPrime Agentの最も重要な革新です。補足プロンプト、メモリ、スキル説明、サブエージェント仕様を耐久性のある状態として保存し、小規模な、エビデンスに基づいた更新で改善できます。

`/refine` コマンドは現在の軌跡をレビューし、補足ハーネス状態に小規模な、エビデンスに基づいた更新を適用できます。不変のベースシステムプロンプトを書き換えることはなく、記録されたスナップショットによるロールバックをサポートします。

これは従来のプロンプトエンジニアリングとは根本的に異なります。従来のアプローチでは、プロンプトは静的で手動調整が必要です。Prime Agentは経験から自動的に学習し、異なるプログラミングタスクやコードベースに適応できます。

#### スキルシステム — 再利用可能なプログラミング能力

スキルはオンデマンドでロードできる自己完結型の能力パッケージです。MarkdownスキルとPython対応スキルの両方をサポートします。

組み込みスキル：
- `prime-intellect`：Prime Intellect製品とワークフロー
- `skill-creator`：新しいスキルの作成（MarkdownまたはPython対応）
- `websearch`：Serper API経由のGoogle検索

スキルのインストール場所：
- `~/.prime/agent/skills/`（グローバル）
- `.prime/agent/skills/`（プロジェクトレベル）
- `~/.agents/skills/`（共有）

## 2. 設計哲学

### 2.1 すべてはプログラマティック

Prime Agentの設計哲学は**すべてはプログラマティック**です。永続IPythonは組み込みモデルツールです。ファイル操作、シェルコマンド、ツール使用、サブエージェント、コンテキスト管理はすべてコードを通じて行われます。

これは偶然の設計选择ではなく、意図的なアーキテクチャ决定です：

1. **柔軟性**：プログラマティック能力意味着エージェントは事前定義されたツールなしに任何のプログラミングタスクに適応できます
2. **合成可能性**：Pythonコードは組み合わせ、変更、拡張でき、複雑なプログラミングワークフローをサポート
3. **デバッグ可能性**：すべての操作はコードであり、検査、変更、再現が可能

### 2.2 サブエージェントは再帰呼び出し

Prime Agentでは、サブエージェントは別個のツールではなく、真の再帰呼び出しです。`rlm(...)` は答えではなくハンドルを返す独立した子エージェントを生成します。結果は明示的な `agent_message` を通じて取得されます。

この設計は以下をサポート：
- **並列作業**：複数のサブエージェントが異なるタスクを同時処理
- **バックグラウンド処理**：サブエージェントがメインフローをブロックせずにバックグラウンドで実行
- **モジュラープログラミング**：複雑なタスクをより小さい、管理可能なサブエージェントに分解

### 2.3 静的プロンプトではなく継続的改善

従来のAIエージェントは手動調整が必要な静的プロンプトを使用します。Prime Agentは継続的改善メカニズムを通じて自動的に学習・適応します。

`/refine` コマンドは：
- 現在の軌跡をレビュー
- 効果的なパターンと戦略を特定
- この知識を耐久性のある状態として保存
- 将来のセッションで再利用

このアプローチにより、エージェントは時間とともに改善し、異なるプログラミングスタイル、コードベース、タスクタイプに適応できます。

```bash
# 保存されたセッションを再開
prime-agent --resume <path|id>
```

### 3.4 RLMプログラミング例

Prime Agentでは、RLMモデルを使用して複雑なプログラミングタスクを実行できます：

```python
# 並列レビュー用にサブエージェントを生成
api_review = await rlm("パブリックAPIをレビュー", name="api-reviewer")
test_review = await rlm("テストカバレッジをレビュー", name="test-reviewer")

# サブエージェントはagent_messageで返信
# await agent_message.send(message, receiver_role="parent")

# 保持されたサブエージェントとフォローアップ
await agent_message.send(
    "新しく追加された回帰テストをチェック",
    receiver_role="child",
    receiver_name=api_review.name,
)

# サブエージェントを一覧・管理
children = await rlm.list_subagents()
await rlm.delete_subagent(children[0])
```

### 3.6 自律モード

```bash
# 自律モードを有効化
prime-agent -p \
  --autonomous \
  --autonomous-gate "npm run check" \
  --autonomous-gate-retries 2 \
  --autonomous-max-turns 12 \
  --autonomous-max-tokens 80000 \
  --autonomous-timeout-ms 1800000 \
  "失敗したチェックを修正し、検証された結果を報告して。"
```

自律モード設定：

| フラグ | デフォルト | 説明 |
|--------|------------|------|
| `--autonomous` | 無効 | 自律継続を有効化 |
| `--autonomous-gate <cmd>` | なし | 完了前にパスする必要のあるシェルコマンド |
| `--autonomous-max-continuations` | 3 | 最大フォローアップメッセージ数 |
| `--autonomous-max-turns` | 12 | 最大アシスタント応答数 |
| `--autonomous-max-tokens` | 80000 | 最大累積トークン数 |
| `--autonomous-timeout-ms` | 1800000 | 最大経過時間（30分） |


セッション内コマンド：

- `/goal <objective>` - 永続目標を設定
- `/heartbeat` - 定期的な指示を設定
- `/autonomous` - 有界自律モードを有効化

## 4. コアアーキテクチャの深層解析

### 4.1 マルチプロセス設計

Prime Agentはライフサイクル分離と回復のためにマルチプロセスアーキテクチャを採用しています：

```
クライアント（TUI/CLI）
    ↓ ローカルデーモンプロトコル
スーパーバイザ（ルーティング、回復）
    ↓
セッションワーカー
    ├── AgentSession（プロバイダー呼び出し、セッション状態）
    ├── IPythonカーネル（永続Python制御環境）
    └── RLM子プロセス（独立コンテキストのサブエージェント）
```

**コンポーネントの責任**：

| コンポーネント | 責任 |
|----------------|------|
| **TUI/クライアント** | レンダリングとキーボード入力を所有、実行は担当しない |
| **スーパーバイザ** | 発見、ルーティング、ワーカーの健全性、クロスエージェントメッセージ配信を所有 |
| **セッションワーカー** | ルートランタイム、スケジューラ、IPythonカーネル、子エージェントを所有 |
| **IPythonカーネル** | プログラマティック実行のためのモデル面向制御環境 |

### 4.2 実行フロー

1. **ユーザープロンプト** → AgentConnection → スーパーバイザ → セッションワーカー
2. **セッション** → モデルプロバイダー（テキストまたはIPythonツール呼び出しをストリーム）
3. **IPythonツール呼び出し** → Pythonを実行 → 型付きホスト要求または結果
4. **トランスクリプトとアーティファクト** → セッションストレージに永続化

### 4.3 永続化メカニズム

- **セッションストレージ**：すべての会話履歴、ツール呼び出し、結果
- **IPythonカーネル状態**：変数、インポート、実行コンテキスト
- **サブエージェントレジストリ**：サブエージェントハンドルと状態
- **継続的改善状態**：学習パターンと戦略

### 4.4 セキュリティモデル

- **プロセス分離**：ワーカーとカーネルはライフサイクル分離のためプロセス分離される（セキュリティサンドボックスではない）
- **有界自律**：設定可能なターン、トークン、時間予算
- **品質ゲート**：ユーザー定義の検証チェック
- **スナップショットサポート**：継続的改善状態はロールバック可能

## 5. 洞察のまとめ

### 5.1 Prime Agentが重要な理由

Prime AgentはAIプログラミングエージェントの重要な進化を代表します。これはコード補完ツールではなく、永続的なPython制御環境で動作し、継続的改善メカニズムを通じて学習・適応する真のプログラミングエージェントです。

**3つのコア洞察**：

1. **プログラマティック優先**：すべてはプログラマティックであり、永続IPythonカーネルがコアツールとなり、無限の柔軟性と合成可能性をサポート
2. **再帰サブエージェント**：サブエージェントは真の再帰呼び出しであり、複雑な並列およびバックグラウンドワークフローをサポート
3. **継続的学習**：エージェントは経験から学習し、異なるプログラミングタスクやコードベースに適応可能

### 5.2 他のツールとの比較

| **サブエージェント** | ✅ 再帰 | ❌ | ❌ | ✅ ツール |

| **オープンソース** | ✅ MIT | ❌ | ❌ | ❌ |

### 5.3 ユースケース

**最適**：
- 長時間実行プログラミングタスク
- 複雑なコードベースの理解とリファクタリング

**あまり適さない**：
- シンプルなコード補完（Copilotを使用）

### 5.4 設計哲学のまとめ

Prime Agentの設計哲学は以下のように要約できます：

1. **プログラマティック優先**：すべてはコードであり、無限の柔軟性をサポート
2. **再帰能力**：サブエージェントは真の再帰呼び出しであり、複雑なワークフローをサポート
3. **継続的学習**：エージェントは経験から学習・適応可能
4. **長時間実行**：デーモンがバックグラウンド実行と回復をサポート
5. **オープンで透明**：MITライセンス、完全オープンソース
