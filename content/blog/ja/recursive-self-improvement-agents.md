# コーディングAgentの再帰的自己改善：一つのプロンプトからSOTA結果までの完全な実践

## 概要 / Summary

本記事では、Clineチームが**再帰的自己改善（Recursive Self-Improvement, RSI）**技術を通じて、たった1つのプロンプトでコーディングAgentを17時間連続実行させ、Terminal-Bench 2.1ベンチマークで88.8%のSOTAスコアを達成し、コストはわずか$49.8で、Fable 5の$552やGPT-5.6 Terraの$400を大幅に下回った方法を深く分析します。完全なプロジェクト背景、ステップバイステップチュートリアル、中核見解の要約、設計哲学の分析を含む。

**キーワード**：再帰的自己改善、コーディングAgent、Cline、Terminal-Bench、AI Agent、自己最適化、SOTA

---

## 一、プロジェクト説明 / Project Description

### 1.1 再帰的自己改善とは？

再帰的自己改善（Recursive Self-Improvement）とは、AIモデルが反復的に自己を改良し、能力の特異点（Singularity）を解放する能力を指します。Clineチームはこの分野でブレークスルーを達成しました — Kimi K3モデルにClineのharnessを組み合わせ、ワンタイムの再帰的自己改善プロンプトを通じて、Terminal-Bench 2.1で88.8%のSOTAスコアを達成しました。

### 1.2 中核データハイライト

| 指標 | 数値 |
|------|------|
| 最終スコア | 88.8%（79/89） |
| 単一実行コスト | $49.8 |
| Fable 5とのコスト比較 | $552（Clineはその1/11） |
| GPT-5.6 Terraとのコスト比較 | $400 |
| 実行時間 | 17時間連続実行 |
| 総トークン消費 | 10億（4億はAgent消費、6億は反復評価消費） |
| 人間の介入度 | 極めて低い（数時間に1回確認するだけでよい） |
| リーダーモデル | GPT-5.6-Sol |
| 対象モデル | Kimi K3（OpenRouter経由） |

### 1.3 Clineとは？

ClineはオープンソースのAIプログラミングアシスタントで、IDEプラグイン、CLIツール、SDKを提供します。複数のモデル呼び出しをサポートし、自動評価（evals）とhill climbing（坂登り最適化）を実行するための完全なharnessシステムを備えています。ClinePassはサブスクリプション制の推論サービスを提供し、月額$9.99でKimi K3、DeepSeek、GLM、MiniMax、Qwenなどのオープンソースモデルの優先アクセスを利用できます。

## 二、詳細チュートリアル / Detailed Tutorial

### ステップ 1：ベースラインの確立（Baseline）

まず、対象モデルに対してTerminal-Bench 2.1の完全実行を1回行い、初期スコアを記録します。

```
ベースライン実行：Kimi K3 → Cline Harness → OpenRouter
結果：69/89（77.5%）、コスト $79
```

**目的**：以降のすべての改善の比較基準となる、定量化可能な開始スコアを取得する。

### ステップ 2：AI支援によるプロンプト作成

手動でHill Climbingプロンプトを書かないでください。代わりに、GPT-5.6に再帰的自己改善プロンプトを作成させます：

1. GPT-5.6に、通常どのようにhill climbingを行っているかを説明
2. 対象ベンチマーク（Terminal-Bench 2.1）の構造と評価方法を説明
3. GPT-5.6に、手動プロセスを自動化された再帰的自己改善プロンプトに変換させる

**重要なテクニック**：初版は通常すでに十分に包括的です。あなたが行うべきことは：
- エッジケース（edge cases）を補足
- 明確な終了条件（well-defined end state）を指定
- 報酬ハッキング（reward hacking）を禁止

### ステップ 3：再帰的自己改善プロンプトの設定

プロンプトの中核構造には以下を含めるべき：

1. **目標定義**：Terminal-Bench 2.1で最高スコアを獲得する
2. **実験記録メカニズム**：大きなファイルを維持し、Agentが各実験後に完了した作業を記録し、ループの繰り返しを避ける
3. **反復実験フレームワーク**：各実験は1つの具体的な改善点に焦点を当てる
4. **検証プロセス**：各変更後に完全なテストセットを再実行して効果を確認
5. **自己制限**：検証器の改変禁止、不合理なタイムアウト膨張禁止、チート的reward hacking禁止

### ステップ 4：実験ループの開始

プロンプトを送信すると、Agentは自動的に以下のフローを実行します：

```
for each experiment:
    1. 現在の失敗パターンを分析
    2. 根本原因を特定
    3. 修復を実施
    4. 完全評価を実行
    5. 結果を実験ログに記録
    6. 改善した場合 → コミットを提出し継続
       改善しなかった場合 → 無効な実験として記録し、次へ
```

### ステップ 5：監視と介入

人間の介入は最小限に抑えるべき：
- 2〜3時間ごとにAgentの状態を確認
- Agentが予期せず停止したら「continue」を押す
- 中断しないようにクラウドVM上で実行
- 最終的に人間がPRをレビューしてからマージ

## 三、実験詳細 / Experiment Breakdown

### 実験 0：最大推論設定の修正

**問題**：Cline harnessがKimi K3の`max`推論effortを正しくマップせず、Agentレイヤーがそれを暗黙的に`high`にダウングレードしていた。

**修正**：abstractionレイヤーを修正し、harnessが`max`推論設定を正しく渡すようにする。

**結果**：スコア変化はないが、下流実験の障害を取り除く重要な正確性修正。

```
Commit: d1bc440
```

### 実験 1：429レート制限リトライメカニズム

**問題**：5つのベースライン失敗ケースがすべて同じパターン — OpenRouterが429エラーを返した後、Clineが直接あきらめていた。当時、Kimi K3を提供するプロバイダーは1つだけで、容量が逼迫していた。

**修正**：リトライ回数 + 指数バックオフ戦略を追加。

**結果**：診断スライス内の5つの失敗ケースすべてが合格に転換。

```
Commit: cabfa9e
```

### 実験 2：スマートループ検出（出力感知型）

**問題**：Clineのループ検出器が、長時間実行されるバックグラウンドタスクを合法的にポーリングしているAgentを誤って終了させていた。同じコマンドの出力が変化していることは、本当の進捗であってループではないことを示していた。

**修正**：ループ検出器を出力感知型にする — 出力が変化していれば、コマンドが同じでも有効な進捗と判定する。

**結果**：以前は死亡していた2つのタスクがすべて合格。

```
Commit: dbcdba8
```

### 実験 3：7.6秒ゴースト失敗の修正

**問題**：あるタスクが7.6秒後に終了し、ゼロトークン、ゼロセッション。根本原因：`@a`-styleトークンを含むプロンプトが、未参照の非同期workerのファイル言及検索をトリガーし、プロセスがモデル呼び出し前に合法的に終了していた。

**修正**：1行のliveness修正により、非同期workerがプロセス終了前に完了するようにする。

**結果**：決定的フリップ（deterministic flip）。

```
Commit: 289cb82
```

### 実験 4：タスクの自己破壊を阻止

**問題**：2つのタスクが失敗 — Agentが`pkill -f`を実行する際に、自身のharnessコマンドラインに一致するパターンを使い、タスクの途中で自己終了させていた。

**修正**：広範なパターンマッチによるプロセス終了を廃止し、PID追跡方式に変更。

**結果**：2つのタスクがすべて転換。

```
Commit: 23d5970
```

## 四、最終結果と検証 / Final Results

### 組み合わせ候補結果

```
77/89 (86.5%) at $65 → ベースラインより8タスク向上
```

### 確認実行（Confirmation Run）

```
79/89 (88.8%) at $49.8
```

### 重要な検証ポイント

- すべての修正は汎用harnessの改善であり、ベンチマーク特定のhackではない
- 検証器（verifier）の改変なし
- タスク名検出（task-name detection）を使用していない
- タイムアウト膨張（timeout inflation）なし
- モデルが帰属保護を自己記録し、無効な実行を除外
- 最終的に人間がPRをレビューしてからマージ

## 五、要約された中核見解 / Key Viewpoints

### 見解一：ボトルネックはモデルではなく人間

> 「ここまでで非常に明確：**ボトルネックはモデルではなく、モデルを使う人間である。**」

6ヶ月のhill climbing経験が、手動でトレースを読み、仮説を形成し、修正をテストすることから、1つのプロンプト + 17時間の自動実行へと進化した。これはAIエンジニアリングのパラダイムの根本的転換を示しています — 人間は「実行者」から「設計者」へと変わった。

### 見解二：再帰的自己改善はSFから現実に

Clineチームの実験は、再帰的自己改善がもはや理論的構想ではないことを証明しました。1つのプロンプトだけで、システムを数時間内に自律的にバグを発見・修正し、設定を最適化し、パフォーマンスを向上させることができます。これはAI Agentの自律的進化へのまったく新しい道を切り開きました。

### 見解三：低コストでSOTA達成は可能

$49.8のコストで88.8%のSOTAスコアを達成、Fable 5のコストのわずか9%。これは以下を示しています：
- 正しい方法論はブルートフォースの計算力よりも重要
- 精心に設計されたプロンプト + 自動化実験ループ = 極めて高いROI
- 最先端モデルの推論コストは、特定のタスクでは投資する価値が十分にある

### 見解四：報酬ハッキングは設計的に回避可能

実験設計者は以下のメカニズムで報酬ハッキングを防止しました：
- プロンプトでチート行為を明示的に禁止
- 検証器を改変しない
- タスク名検出を使用しない
- タイムアウトを膨張させない
- モデルが自己監査し無効な実行を除外
- 人間の最終レビューを最後の防衛線として

### 見解五：汎用harnessの改善はベンチマーク特定hackより優れている

5つの修正はすべて汎用harnessの改善であり、特定のベンチマークをターゲットにしていない。この「直交改善」戦略は以下のことを意味します：
- 改善は汎化能力を持ち、異なるベンチマークで再現可能
- 特定のベンチマークをhackすることで、他のタスクでのモデル能力を損なわない
- 長期的には、汎用改善の方が持続可能

### 見解六：AI評価自体もAIによる最適化が必要

従来の人間主導のeval + hill climbingフローは数週間の人的労働を必要とします。再帰的自己改善はこの時間を17時間の自動実行に圧縮します。これはAI評価インフラ自体もAI Agentによる最適化・保守が必要であることを予示しています。

### 見解七：ClineはKimi K3最適化のための最良harness

ClineはMoonshotの公式Kimi harnessのSOTAスコアに匹敵します。ClinePassを使用すれば、補助推論（$9.99/月）も利用でき、標準APIレート制限の2〜5倍を得られます。

## 六、設計哲学 / Design Philosophy

### 6.1 「人間監督 + 機械実行」の協調パラダイム

RSIの設計哲学の中核は、人間と機械の分業を再定義することにあります：
- **人間の役割**：プロンプトの設計、境界条件の定義、ガードレール（guardrails）の設定、最終レビュー
- **Agentの役割**：実験の実行、失敗の分析、根本原因の特定、修復の実施、成果の記録

これは「AIに完全自律を与える」ことではなく、**人間が目標を設計し、機械が自律的に探索する**ハイブリッドシステムを構築することです。

### 6.2 ガードレール優先（Guardrails First）

システムは設計当初から、チート防止メカニズムを最も優先度の高い設計制約としています：
- 報酬ハッキングを明示的に禁止
- 検証器の改変を禁止
- タスク名検出を禁止
- タイムアウト膨張を禁止
- モデル自己監査メカニズム

この「設計によるチート回避」（avoid cheating by design）の理念は、事後検出よりも効果的です。

### 6.3 直交改善（Orthogonal Improvement）

各実験の修正は、特定のベンチマークhackではなく、汎用harnessの改善に専念します。この直交設計により以下が保証されます：
- 改善の**可搬性**：修正はより広範なシナリオに適用可能
- システムの**保守性**：特定のベンチマークと結合した脆弱なコードを導入しない
- パフォーマンスの**持続可能性**：hackによりモデルの他の次元でのパフォーマンスを損なわない

### 6.4 記録が知能（Recording is Intelligence）

Agentは巨大なファイルを保守して各実験の成果を記録し、繰り返しの労働とループを防ぎます。この一見シンプルな設計は、実際には再帰的自己改善システムの重要なインフラです：
- 繰り返しの失敗を避ける
- 経験知識を蓄積
- 意思決定のコンテキストを提供
- Agentに長期記憶能力を付与

### 6.5 段階的検証（Progressive Verification）

システムは多層検証メカニズムを採用しています：
1. 実験レベル検証：各変更後にすぐに対象テストを実行
2. 組み合わせレベル検証：すべての実験を組み合わせた後に再実行
3. 確認レベル検証：独立した確認実行（confirmation run）
4. 人間の最終レビュー：人間がPRをレビューしてからマージ

この段階的検証により、各改善が信頼できるものであり、偶然の幸運ではないことが保証されます。

### 6.6 コスト効率最適化

システムはコスト制御を中核設計目標の1つとしています：
- doomed retries（無駄な再試行）にトークンを浪費しない
- 自己破壊バグの修正により不要な再実行を減らす
- 最低コストで最高スコアを達成
- 各実験に明確なコスト-収益分析がある

### 6.7 オープン透明性（Open by Design）

Clineはオープンソースプロジェクトで、すべての実験のプロンプト、トレース、コスト内訳はGitHub Gistを通じてコミュニティに公開・透明に共有されています。この開放性は：
- コミュニティの信頼を構築
- 知識共有を促進
- 他者が結果を再現・検証できる
- 業界全体の進歩を推進

## 七、未来展望 / What's Next

1. **RSIが標準フローに**：Clineチームは再帰的自己改善を新しいモデルリリースの標準フローに組み込みました — まずベースライン実行を行い、次にRSIスタイルのプロンプトでモデルの最高パフォーマンスを引き出します。

2. **長時間タスクの継続的推進**：チームはコミュニティにより多く、より長いタスクでモデルの能力境界を押し広げることを奨励しています。

3. **再帰的自己改善はSF実験ではない**：最先端モデルの能力は、この精密で時間を要するAI評価を可能にしました。私たちは転換点にいます — AI AgentはAI Agentの評価インフラを自律的に改善できます。

4. **評価から本番環境へ**：RSI技術はベンチマークスコアの最適化だけでなく、本番環境の継続的最適化にも適用でき、真の「自己改善閉ループ」を形成します。

## 八、開発者への実践的アドバイス / Practical Advice

### 推奨ツールチェーン

1. **Cline**：オープンソースAIプログラミングアシスタント、GitHub 65k+ stars
2. **ClinePass**：$9.99/月、Kimi K3、DeepSeek、GLM、MiniMax、Qwenなどのモデルにアクセス
3. **OpenRouter**：統一モデルAPIゲートウェイ
4. **Terminal-Bench 2.1**：コーディングAgent能力を評価する標準ベンチマーク

### 入門アドバイス

1. シンプルなベンチマークから始める（Terminal-Benchサブセットなど）
2. まず手動で1回hill climbingを完了してフローを理解
3. 次にAI支援で自動化プロンプトを作成
4. クラウドVM上で長時間実験を実行
5. 定期的に監視し、各実験の結果を記録

### コスト制御アドバイス

- OpenRouterのKimi K3ルートを使用してコストパフォーマンス向上
- ClinePassで補助推論とより高いレート制限を取得
- doomed retries（無駄な再試行）にトークンを浪費しない
- 実験数に合理的な上限を設定し、無制限に実行しない
