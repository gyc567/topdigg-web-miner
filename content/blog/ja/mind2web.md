# Mind2Web：世界初の実在Webエージェントベンチマークデータセット—任意のページで複雑なタスクを完了するAIの訓練

## プロジェクトの背景と核心的な問題

### なぜWebエージェントが必要なのか

今日のインターネット時代、ユーザーは毎日無数のウェブサイトで様々な複雑なタスクを完了する必要があります—フライトの予約、情報の検索、フォームへの入力、ソーシャルメディアの管理など。一見単純なこれらの操作でも、人間は各新しいウェブサイトに適応するために多くの時間を費やす必要があります。

**重要な問題**：人間のと同じように自然言語の指示を理解し、任意のページで自律的にナビゲートして操作し、複雑な 장기 タスクを完了できるAIエージェントを訓練ことはできないでしょうか？

これがまさにMind2Webが解決しようとする核心的な問題です。

### 既存のデータセットの限界

Mind2Webが登場する前は、Webエージェント研究は2つの大きな困難に直面していました：

| データセットタイプ | 問題 | 代表的数据集 |
|-----------------|------|------------|
| シミュレーション環境 | 単純化しすぎで実在するウェブサイトの複雑さを再現できない | MiniWoB, WebShop |
| 限定的なウェブサイトカバー | 泛化能力を評価できず、モデルは「暗記」する可能性がある | ALFWorld, WebArena |

これらのデータセットは、人工的に構築された単純化された環境を使用するか、あるいは少数のウェブサイトとタスクのみをカバーしており、真のAIエージェントの реальная 世界の泛化能力を評価することができません。

### Mind2Webの誕生

> **「私たちはMind2Webを紹介します。言語の指示に従って任意のページで複雑なタスクを完了できる、Web用の汎用エージェントを開発・評価するための最初の大規模データセットです。」**
> — Mind2Web論文

Mind2Webは，俄亥俄州立大学NLP研究グループ（OSU-NLP-Group）によって開発され、NeurIPS 2023でSpotlight表彰を受け、Webエージェント研究における重要なマイルストーンとなりました。

## プロジェクトの概要とコア統計

### Mind2Webとは？

Mind2Webは**実在するウェブサイトに基づく世界初のLLM Webエージェントベンチマークデータセット**であり、以下のコアの特徴を持ちます：

- 🌍 **実在するウェブサイト環境**：シミュレーションではなく、実際のインターネットウェブサイトを使用
- 📊 **大規模データセット**：2000以上のオープンエンドタスク
- 🌐 **広範なドメインカバー**：31のドメインにわたる137の実在するウェブサイト
- 🎯 **3つの泛化評価**：タスク間、ウェブサイト間、ドメイン間の泛化能力テストをサポート

### コアデータ統計

| 指標 | 数値 |
|------|------|
| タスク総数 | 2,350 |
| カバーブロット | 137 |
| カバードメイン | 31 |
| 平均タスク長 | 7.3の操作ステップ |
| 平均ページ要素 | 1,135のDOM要素/ページ |
| 訓練セットサイズ | 1,009インスタンス |
| テストセットサイズ | 1,341インスタンス |

## データセット設計の哲学

### コア原則：リアル、オープン、实用

Mind2Webの設計哲学は3つのコア原則に基づいています：

#### 1. 現実世界優先

> **「既存のWebエージェントデータセットは、シミュレーションされたウェブサイトを使用するか、限られたウェブサイトとタスクのみをカバーしているため、汎用Webエージェントには適していません。」**

Mind2Webは実際のウェブサイトを使用することを主張し、以下をもたらします：
- **真正性**：実際のウェブサイトの複雑さを反映（様々なレイアウト、广告、ポップアップなど）
- **多様性**：異なるウェブサイトは完全に異なる設計言語と相互作用パターンを持つ
- **挑戦性**：実際のウェブサイトの不規則性と動態性は、シミュレーション環境で再現できない

#### 2. オープンドメイント丽莎設計

タスクは事前設定された固定テンプレートではなく、**Crowdworkerによって実際に提案・完了**されたものです：

```
3フェーズデータ収集：
┌─────────────────────────────────────────────────────┐
│  フェーズ1：タスク提案 (Task Proposal)                │
│  ワーカーが指定されたウェブサイトに対して可行なタスクを提案│
└─────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────┐
│  フェーズ2：タスクデモ (Task Demonstration)           │
│  ワーカーがPlaywrightを使用してタスク完了をデモ        │
└─────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────┐
│  フェーズ3：タスク検証 (Task Verification)             │
│  作者がすべてのアクションの清潔性と正確性を検証        │
└─────────────────────────────────────────────────────┘
```

#### 3. 階層的泛化評価

 Mind2Webは、エージェントの泛化能力を包括的に評価するために、**3つの難易度が上がるテスト分割**を設計しました：

| 分割タイプ | 訓練データ | テストデータ | 難易度 | 評価重点 |
|-----------|-----------|-------------|--------|---------|
| **Cross Task** | 同ウェブサイトタスク | 同ウェブサイトの新タスク | ⭐⭐ | タスクレベルの泛化 |
| **Cross Website** | 同ドメインウェブサイト | 同ドメインの新ウェブサイト | ⭐⭐⭐ | ウェブサイトレベルの泛化 |
| **Cross Domain** | 特定ドメイン�タスク | 全新技術ドメイン | ⭐⭐⭐⭐⭐ | ドメインレベルの泛化 |

## 技術アーキテクチャの詳細

### 2段階Pipeline設計

Mind2Webの技術ソリューションは**2段階Pipeline**を採用し、これはその核心的な创新点です：

```
                    ┌─────────────────────────────────────┐
                    │         ユーザーの自然言語指示        │
                    │   「NYCからLAへの片道フライトを検索」  │
                    └─────────────────────────────────────┘
                                    ↓
                    ┌─────────────────────────────────────┐
                    │    ステージ1：候補要素生成            │
                    │         DeBERTa-v3-baseエンコーダ     │
                    │    クエリ-候補要素ペアをスコアリング    │
                    │         Recall@50 ≈ 85%              │
                    └─────────────────────────────────────┘
                                    ↓
                    ┌─────────────────────────────────────┐
                    │    ステージ2：アクション予測           │
                    │         Flan-T5 シーケンスモデル       │
                    │   タスク記述 + HTMLコンテキスト + 候補   │
                    │         出力：CLICK / TYPE / SELECT    │
                    └─────────────────────────────────────┘
                                    ↓
                    ┌─────────────────────────────────────┐
                    │            アクション系列を実行          │
                    │      ユーザーが指定した複雑なタスクを完了│
                    └─────────────────────────────────────┘
```

### ステージ1：候補要素生成

#### なぜ候補生成が必要なの？

実際のウェブページは 많은 要素を含みます（Mind2Webは平均1,135のDOM要素/ページ）。これらをすべてLLMに入力するのは **非効率** で **コスト高昂** です。

#### 解決策

**DeBERTa-v3-baseエンコーダモデル**を使用して候補要素をスコアリングとフィルタリングします：

```python
# 候補生成の例
model = AutoModel.from_pretrained("osunlp/MindAct_CandidateGeneration_deberta-v3-base")

# 入力：クエリ-候補要素ペア
scores = model.score(query, candidate_elements)

# 出力：Top-50候補要素
top_candidates = select_top_k(scores, k=50)
```

**パフォーマンス**：Recall@50 ≈ 85%、Top-50候補に正しい要素の85%が含まれます。

### ステージ2：アクション予測

#### モデル選択

Mind2Webは複数のアクション予測モデルをサポートします：

| モデルタイプ | モデルサイズ | 特徴 |
|------------|------------|------|
| Flan-T5 | Base / Large / XL | オープンソース、ローカル展開可能 |
| GPT-3.5/GPT-4 | API呼び出し | パフォーマンス向上、成本も増加 |

#### 複数選択QAフォーマット

LLM（GPTシリーズなど）のために、Mind2Webは**複数選択QAフォーマッティング**を採用しています：

```python
# アクション予測のQAフォーマッティング
prompt = f"""
タスク: {task_description}

現在のページには以下のインタラクティブ要素が含まれています：
{formatted_candidates}

どの要素にどのような操作を実行すべきですか？

A) [ボタン：「フライトを検索」をクリック]
B) [入力：「から」に「ニューヨーク」を入力]
C) [選択：「旅程タイプ」から「片道」を選択]
...
"""
```

#### アクションタイプ

Mind2Webは3つの基本的なアクションタイプを定義しています：

| アクション | 説明 | 例 |
|----------|------|------|
| **CLICK** | 要素をクリック | ボタン、リンクをクリック |
| **TYPE** | テキストを入力 | 入力フィールドにテキストを入力 |
| **SELECT** | オプションを選択 | ドロップダウンメニューから選択 |

## タスクタイプと例

### 多様な実世界のタスク

Mind2Webは、ユーザーの毎日のオンライン生活のあらゆる側面をカバーする、豊かで多様なタスクタイプが含まれています：

#### 1. 旅行と交通
```
タスク：ExpediaでNYCからLAへの片道フライトを検索
- アクション：出発都市を入力 → 目的地を入力 → 日付を選択 → 検索をクリック
- 難易度：複数ステップのフォーム入力と動的コンテンツ読み込みを伴う
```

#### 2. ヘルスケア
```
タスク：ある薬与其他薬の相互作用を検索
- アクション：医薬品ウェブサイトにアクセス → 薬名を入力 → 相互作用情報を表示
- 難易度：専門家のドメтерerminologyを理解する必要がある
```

#### 3. 金融サービス
```
タスク：通信料金プラン付きで電話を申請
- アクション：電話モデルを選択 → プランを選択 → 個人情報を入力 → 申請をサブミット
- 難易度：複数ページの流れと複雑なフォームロジックを伴う
```

#### 4. ソーシャルメディア
```
タスク：Twitterで技術ブロガーを見つけフォロー
- アクション：ユーザー名を検索 → プロファイルにアクセス → フォロー tuşをクリック
- 難易度：ソーシャルメディアの相互作用パターンを理解する必要がある
```

#### 5. コンテンツの発見
```
タスク：Netflixで2020年公開のサスペンス映画を見つける
- アクション：Netflixにアクセス → カテゴリを選択 → 年でフィルタリング → 結果を閲覧
- 難易度：多次元のフィルタリングとコンテンツ発見を伴う
```

## 評価指標と実験結果

### 評価指標体系

Mind2Webは多次元の評価指標を提供します：

#### 1. 正確率指標

| 指標 | 計算方法 | 最適な使用場面 |
|------|---------|--------------|
| **Macro平均正確率** | すべてのタスクの等加重計算 | 論文比較（推奨） |
| **Micro平均正確率** | タスクインスタンス数で加重 | タスクの多いウェブサイトにバイアスする可能性がある |

#### 2. 候補リコール

- **Recall@K**：正しい要素がTop-K候補に 나타나는 割合
- 候補生成段階の品質を評価

### ベースラインモデルのパフォーマンス

| モデル | Cross Task | Cross Website | Cross Domain |
|-------|-----------|--------------|--------------|
| MindAct (Flan-T5-base) | 40.2% | 28.1% | 16.4% |
| MindAct (Flan-T5-large) | 47.5% | 32.7% | 19.5% |
| MindAct (Flan-T5-xl) | 52.1% | 38.9% | 24.3% |
| GPT-3.5 (3-shot) | 48.2% | 33.5% | 20.8% |
| GPT-4 (3-shot) | 57.6% | 42.3% | 28.9% |

### 重要な発見

#### 発見1：LLMは初期の泛化能力を示す

> **「私たちのソリューションは、モデルが一度も見たことのないウェブサイトやentire ドメインでもまあまあのレベルのパフォーマンスを示しています。」**

LLMベースのWebエージェントが初期のクロスドメイン泛化能力を持つことを証明しています。

#### 発見2：候補フィルタリングは重要

生のHTMLを直接LLMに入力するのはパフォーマンスが悪いですが、**小さなLM（DeBERTa）でまず候補要素をフィルタリングする**と、LLMの効果と効率が大幅に向上します。

#### 発見3：まだ大きな改善の余地がある

> **「しかし、真に泛化可能なエージェントを実現するためには、まだ大きな改善の余地があります。」**

最新のGPT-4でも、Cross Domain設定での正確率はわずか28.9%であり、現在のテクノロジーが真に汎用的なWebエージェントを実現するにはまだ長い道路要走であることを示しています。

## 設計哲学のまとめ

### 1. 現実世界優先の原則

Mind2Webの最も重要な設計的意思決定は**実際のウェブサイトを使用することの主張**です。これによりデータセットは реальный インターネットの複雑さを反映できますが、ウェブサイトが変わりうる、内容が無効になりうるなどの課題も生じます。チームはDOMスナップショットとMHTMLフォーマットを提供することでデータの永続的な利用可能性を確保しました。

### 2. タスク指向の評価

従来の入力-出力マッチング評価とは異なり、Mind2Webは**タスク完了率**をコアの評価指標として採用しています。これは、エージェントが複数の操作ステップ全体で正しい方向を維持し、最終的に整个タスクを完了する必要があることを意味します。

### 3. 階層的泛化

Cross Task、Cross Website、Cross Domainの3つの難易度が上がるテスト分割を通じて、Mind2Webは**階層的な泛化評価体系**を確立し、研究者が泛化のボトルネックを正確に特定するのを助けます。

### 4. 小モデルが大なモデルを支援

2段階Pipelineの設計は**分業と協力**の哲学を体現しています：小さな効率的なモデル（DeBERTa）が情報フィルタリングを担当し、大きなモデル（Flan-T5/GPT）が複雑な推論を担当します。この設計はパフォーマンスを維持しながら計算コストを大幅に削減します。

### 5. オープンソースと開放性

Mind2Webは**データセット、コード、モデルのオープンソース化**を主張し、コミュニティに以下を提供します：
- 完全なデータセット（HuggingFace）
- 訓練されたモデル（HuggingFace）
- 完全な評価フレームワーク
- 詳細なドキュメントと例

## 核心的な洞察と結論のまとめ

### 核心的な洞察

#### 洞察1：実環境テストはWebエージェント研究にとって重要

現在のほとんどのWebエージェント研究はシミュレーション環境で実施されており、評価には便利ですが、真の複雜かつ変化に富む реальный インターネットでのエージェントのパフォーマンスを真に反映できません。Mind2Webは実際のウェブサイトに基づく最初の大規模ベンチマークを提供することでこの空白を埋めました。

#### 洞察2：候補フィルタリングは長いHTMLを処理するLLMにとって重要

実際のウェブページには多くのDOM要素があり、すべてをLLMに入力するのは実用的でも効率的でもありません。Mind2Webは**小さなLM（DeBERTa）でまず候補要素をフィルタリングする**と、効率と効果が大幅に向上することを証明しました。このパラダイムは後続の研究で広く採用されています。

#### 洞察3：クロスドメイン泛化は核心的な課題

実験結果は、最も先进的なGPT-4でもCross Domain設定での正確率はわずか28.9%であることを示しています。これは**ドメイン泛化**が現在のWebエージェントテクノロジーの核心的なボトルネックであり、より多くの研究关注が必要であることを示しています。

#### 洞察4：2段階Pipelineは効果的なアーキテクチャ

候補生成 + アクション予測の2段階設計は、パフォーマンスと効率の間で良好なバランスを達成しています。このアーキテクチャの設計は、後続の複数のWebエージェント作品によって参照・拡張されてきました。

#### 洞察5：マルチモーダルは未来の方向性

Mind2Webチームのフォローアップ作品（SeeAct、Multimodal-Mind2Web）は、**視覚情報を組み合わせる**とWebエージェントの性能がさらに向上することを示しており、マルチモーダルはWebエージェント研究の重要な発展方向です。

### 方法論的な貢献

| 貢献タイプ | 具体的な内容 |
|----------|-------------|
| **データセットの貢献** | 最初の実際のWebエージェントベンチマーク、137ウェブサイト/31ドメイン/2,350タスク |
| **評価フレームワークの貢献** | 3層泛化評価体系、多次元評価指標 |
| **モデルの貢献** | MindActモデルと訓練/推論コードの完全な提供 |
| **実践的な貢献** | 2段階Pipeline設計、再現可能なベースライン |

### 限界

1. **ウェブサイトの動態**：実際のウェブサイトは常に変化し、データのタイムリー性に影響を与える可能性があります
2. **オフライン評価の限界**：現在の評価はオフラインであり、オンライン相互作用の複雑さを反映できません
3. **単一の相互作用モダリティ**：主にCLICK/TYPE/SELECTをサポートし、より複雑な相互作用のサポートは限定的
4. **コスト上の考慮事項**：GPT-4などの大腿モデルを使用した評価はコスト高昂

| **より複雑なタスク** | より長い推論、マルチターン対話、およびより複雑な相互作用パターン |

## 結語

Mind2WebはWebエージェント研究における重要なマイルストーンです。これは最初の実際のウェブサイトに基づく大規模ベンチマークデータセットを提供するだけでなく、完全な評価フレームワークと技術的ソリューションを確立しました。その2段階Pipeline設計と3層泛化評価体系は、後続の研究に重要な参照を提供します。

しかし、実験結果も、現在のWebエージェントテクノロジーが任意のページで自律的に動作できる真の汎用的なAIアシスタントを実現するにはまだ長い道路要走であることを明確に示しています。28.9%のCross Domain正確率は、**ドメイン泛化**がAIエージェントが直面する核心的な課題であることを私たちに思い出させます。

マルチモーダル技術、オンライン学習方法、およびより強力な基盤モデルの継続的な発展により、真に汎用的なWebエージェントが不遠の将来実現可能になるであろうと信じる理由があります。Mind2Webはこの目標にとって重要な研究基礎を築きました。
