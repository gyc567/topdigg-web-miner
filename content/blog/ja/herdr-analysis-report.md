# Herdr — AIコーディングエージェントの「住処」、AIエージェントを不掉線に保つ

> **一行で説明**：Herdrはバックグラウンドのターミナルサーバーであり、Claude Code、Codex、CursorなどのAIコーディングエージェントを継続的に動作させます。ノートPCを閉じても、ネットワークが切れても、PCを再起動しても、エージェントは仕事を続け、你はいつでも再接続できます。

## 🎯 どんな問題を解決するの？

このようなシナリオを想像してください：

AIコーディングエージェント（例：Claude Code）にスターバックスの注文システムを書いてもらうよう頼みました。プログラムは大規模で、3時間かかるそうです。

**Herdrがない場合：**
- PCの電源を入れっぱなしにしなきゃいけない、画面を閉じられない
- ネットワークが切れた？→ プログラムが止まる
- エージェントが質問したいのに、あなたは今外出中？→ おしまい
- PCを再起動？→ 最初からやり直し

**Herdrがある場合：**
- エージェントはあなたの「デジタル牧場」で走り続けている
- ノートPCを閉じる → エージェントは走り続ける
- ネットワークが切れる → エージェントは走り続ける
- PCを再起動 → Herdrが自動回復、エージェントは継続
- エージェントが質問したい → Herdrが「どのエージェントが待っているか」 알려줌

## 🏗️ コアコンセプト（小学生でもわかるように）

Herdrにはいくつかの基本概念があり、現実世界に例えて説明します：

### 1. ワークスペース（Workspace）= 大きなオフィス

ワークスペースはプロジェクトの最上位コンテナです。「スターバックス注文システム」と「出前配送システム」を同時に開発している場合、2つのワークスペースを開いて、干渉なく作業できます。

### 2. タブ（Tab）= オフィスの違うホワイトボード

ワークスペースには複数のタブを持てます：
- `agents` タブ → AIエージェントを入れる
- `logs` タブ → ログを入れる
- `review` タブ → コードレビューを入れる

### 3. ペイン（Pane）= 各エージェントの「仕事机」

各ペインは本当にターミナルであり、AIエージェントが動作しています。左右または上下に分割できます。

### 4. エージェント（Agent）= 雇ったプログラマー

Herdrは以下AIコーディングエージェントを自動認識します：

| エージェント | 説明 |
|------------|------|
| Claude Code | Anthropic製 |
| Codex | OpenAI製 |
| Cursor Agent | Cursor IDEのAIモード |
| Pi / OMP | コーディングエージェント |
| OpenCode | オープンソースエージェント |
| Grok CLI | xAI製 |
| GitHub Copilot CLI | GitHub製 |
| Kimi Code CLI | 月の暗面製 |
| …… | 他也有很多 |

### 5. エージェントの状態 — 何をしているの？

Herdrは各エージェントの状態を自動判断します：

| 状態 | 意味 |
|------|------|
| `working` 🔵 | コードを必死に書いている |
| `blocked` 🟡 | 問題に出会い、あなたの回答を待っている |
| `done` ✅ | 完了し、結果を見るのを待っている |
| `idle` ⚪ | <minimax:tool_call>，或者在等什么 |
| `unknown` ❓ | 判断できない |

> 💡 **これがHerdrの一番賢いところです**：ウィンドウを一つ一つ調べてどのエージェントが止まっているかを探す必要がありません。サイドバーが直接「プロジェクトAのエージェントがあなたの回答を待っています」と教えてくれます。

## 🚀 詳細なインストール教程

### 方法1：一括インストール（一番簡単）

**macOS / Linux：**
```bash
curl -fsSL https://herdr.dev/install.sh | sh
```

**Windows（ベータ版）：**
```powershell
powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"
```

### 方法2：Homebrewでインストール

```bash
brew install herdr
```

### 方法3：miseでインストール

```bash
mise use -g herdr
```

### 方法4：Nixでインストール

```bash
nix run github:herdrdev/herdr/v0.x.y
```

### 方法5：手動ダウンロード

[GitHub Releases](https://github.com/herdrdev/herdr/releases)からバイナリをダウンロード：

| OS | ファイル |
|------|---------|
| Linux x86_64 | `herdr-linux-x86_64` |
| Linux ARM64 | `herdr-linux-aarch64` |
| macOS Intel | `herdr-macos-x86_64` |
| macOS Apple Silicon | `herdr-macos-aarch64` |

ダウンロード後：
```bash
chmod +x herdr-linux-x86_64
mv herdr-linux-x86_64 ~/.local/bin/herdr
```

### ✅ インストール確認

```bash
herdr
```

Herdrのインターフェースが表示されればインストール成功です！

## 📖 クイックスタート教程

### ステップ1：Herdrを起動

任意のディレクトリで：
```bash
herdr
```

Herdrは自動的に以前のバックグラウンドセッションに接続または起動します。

### ステップ2：ワークスペースを作成

Herdrは初めて起動した時自動的にワークスペースを1つ作成します。`ctrl+b c`で新しいタブを作成できます。

### ステップ3：AIエージェントを起動

ペインで好きなエージェントコマンドを入力：

```bash
claude
```

または：
```bash
codex
```

または：
```bash
pi
```

Herdrは自動的にAIエージェントとして認識し、サイドバーに状態を表示します。

### ステップ4：マウス操作（完全に任意）

Herdrはマウスネイティブです：
- **クリック** ペイン/タブ/ワークスペースを切り替え
- **ドラッグ** 分割線を引いてサイズ調整
- **右クリック** 新規ペインまたはタブを作成
- **テキスト選択** 直接コピー（Ctrl+C不要）

### ステップ5：キーボード操作

| 操作 | キー |
|------|------|
| コマンドモードに入る | `ctrl+b` |
| 新規タブ | `ctrl+b c` |
| 左右分割 | `ctrl+b v` |
| 上下分割 | `ctrl+b -` |
| ペイン移動 | `ctrl+b h/j/k/l` または矢印キー |
| 次の/前のタブ | `ctrl+b n` / `ctrl+b p` |
| ワークスペース移動 | `ctrl+b w` |
| 切断（エージェント継続） | `ctrl+b q` |

> 💡 `ctrl+b ?`ですべてのショートカットを確認できます。

### ステップ6：切断と回復

**切断**（エージェント継続）：
- `ctrl+b q`を押す
- またはターミナルウィンドウを閉じる

**回復**：
```bash
herdr
```

Herdrは自動的に以前のセッションを復元し、すべてのエージェントが元の状態にあります。

### 完全停止

```bash
herdr server stop
```

すべてのエージェントとペインが停止します。

## 🧠 デザイン哲学

Herdrのデザイン哲学は明確にまとめると以下の通りです：

### 1. 「エージェントネイティブ」（Agent-Native）

Herdrは単なる「ターミナルマルチプレクサー」ではなく、**AIエージェントのために設計**されています。

- HerdrのCLIとSocket APIは同じインターフェースであり、エージェントはこれを使ってペインを作成し、他のエージェントを起動し、他のエージェントが本当にブロックされるまで待つことができます
- これはtmuxにはできません—tmuxはただのターミナルマルチプレクサーであり、AIエージェントを理解しません

> 簡単に言えば：HerdrはAIエージェント専用の「家」であり、tmuxはただの普通の「マンション」です。

### 2. 「侵襲しない」（Non-Invasive）

Herdrはあなたが既に使っているエージェントツールを**包装したり置き換えたりしません**：

- Claude CodeはそのままClaude Code
- CodexはそのままCodex
- Herdrはただ它们的终端"拥有"下来，让它们可以一直运行

これを **"Ownership without Replacement"**（所有但不替代）と呼びます。

### 3. 「真のターミナル」（Real Terminals）

Herdrの各ペインはすべて**本当のターミナル**です：

- シミュレートされたものではなく、偽物でもありません
- エージェントが直接ターミナルを動かした時と同じものが見えます
- すべてのターミナル機能に対応：ANSIカラー、カーソル制御、OSCシーケンスなど

### 4. 「Electron不要」（No Electron）

HerdrはRustで書かれ、単一バイナリにコンパイルされます：

- Electron、Node.js依存なし
- サイズが小さく、起動が速く、メモリ使用量が少ない
- 既存のターミナルで動作（iTerm2、Kitty、Alacritty、Windows Terminal……）

### 5. 「常にオンライン」（Always Running）

Herdrは**バックグラウンドサーバー**です：

- クライアントはいつでも切断、再接続可能
- サーバーとエージェントは継続的に動作
- ノートPCの蓋を閉じる → エージェントは継続動作
- これを **"Sessions Survive"**（セッション永生）と呼びます

### 6. 「状態の集約」（State Rollup）

Herdrは状態を上に集約します：

- `blocked`のエージェントは、そのペイン、タブ、ワークスペースすべてを`blocked`として表示
- ウィンドウを一つ一つ調べてどのエージェントが止まっているかを探す必要がありません
- サイドバーが「プロジェクトAはあなたの回答が必要です」と一秒で教えてくれます

### 7. 「リモートファースト」（Remote-First）

Herdrはリモート接続に対応：

- SSHでリモートマシンのHerdrに接続
- SSH経由でスマホからエージェント状態を確認
- `herdr --remote user@host`で一コマンド

### 8. 「オープンソースで無料」（Open Source & Free）

- 完全オープンソース（Apache 2.0）
- 常に無料（有料壁なし）
- コミュニティプラグインエコシステム：[herdr.dev/plugins](https://herdr.dev/plugins/)

## 🔌 上級機能

### 1. Socket API（エージェント用インターフェース）

HerdrはSocket APIを提供し、エージェントは以下を行えます：
- 新規ペインを作成
- 他のペインに入力を送信
- ペインが本当にブロックされるまで待つ（盲目的に待たない）
- エージェント状態をクエリ

これはHerdrだけの独自の機能で、他のターミナルマルチプレクサーにはありません。

### 2. プラグインシステム

Herdrはプラグイン拡張に対応：
- コミュニティプラグインをインストール
- ペインとワークフローをカスタマイズ
- プラグイン市場：[herdr.dev/plugins](https://herdr.dev/plugins/)

### 3. Gitワークツリー統合

HerdrはGitワークツリーと深く統合：
- サイドバーから直接Gitワークツリーを作成
- ワークツリーを独立したワークスペースとして管理
- 手動でディレクトリを切り替える必要がない

### 4. リモートワークフロー

**方法1：SSHリモート接続**
```bash
herdr --remote user@your-server.com
```

**方法2：まずSSHでサーバーに入り、然后运行Herdr**
```bash
ssh user@your-server.com
herdr
```

**方法3：SSH経由でスマホから状態を確認**（参照のみ）

### 5. 設定管理

Herdr設定ファイル：
- **Linux/macOS**：`~/.config/herdr/config.toml`
- **Windows**：`%APPDATA%\herdr\config.toml`

設定可能項目：
- ショートカットキー（prefixキー、ペイン切り替えなど）
- テーマカラー
- 通知設定
- SSH接続パラメータ
- プラグイン設定

デフォルト設定を確認：
```bash
herdr --default-config
```

## 🗺️ 適用シーン

### ✅ ぴったりのシーン

1. **長時間実行されるコードタスク**
   - 大きなモデルのトレーニング、データ処理、バッチリファクタリング
   - エージェントをバックグラウンドで走らせ、別のことをする

2. **マルチエージェント並列作業**
   - 3つのエージェントを同時に走らせ、3つの機能を開発
   - サイドバーがすぐにどのエージェントが待っているかを示す

3. **リモートサーバー開発**
   - サーバー上でエージェントを走らせ、ローカルでSSH 통해 확인
   - 会社のPCでエージェントを走らせ、帰宅后将笔记本放在一边

4. **中断/再開ワークフロー**
   - エージェントが質問が必要だが、あなたは外出する予定
   - ノートPCを閉じ、エージェントは考え続ける、戻ってきたら継続

### ❌ あまり向かないシーン

1. **GUIが必要なタスク**（エージェントがブラウザでUIを操作する必要がある）
2. **非常に短いタスク**（数秒で終わるタスクにはHerdrは不要）
3. **Windowsユーザー**（Windows版はまだBeta版で不安定な場合がある）

## 💡 主な观点と結論

### 观点1：HerdrはAIコーディングエージェントの「OS」

AIエージェントを「就打者」に例えるなら、Herdrは「工作站管理系统」です：
- 就打者（エージェント）は工作站（ペイン）で仕事をしている
- 管理系统（Herdr）は就打者（あなた）が離れても工作站的管理系统が止まらないようにする
- 就打者が問題に出会った時、管理系统はあなたに着信を知らせる

### 观点2：Herdrはtmuxの代替品ではなく進化

tmuxが解決したのは「ターミナル永続化」の問題です。Herdrはその基础上，增加了「AIエージェント管理」の能力を持っています。

ターミナルマルチプレクサーとしてだけtmuxを使うなら、Herdrでもっと使いやすくできます。
AIコーディングエージェントを使うなら、Herdrは唯一の選択です。

### 观点3：状態の可視性がHerdrのコアバリュー

5つのエージェントが同時に走っているプロジェクトで、一番面倒なことは「どのエージェントが止まっているかわからない」ことです。

Herdrは状态的集約（blocked → pane → tab → workspace）によってこの問題を完全に解決します。

### 观点4：「Agent-Native」が主要な差別化ポイント

HerdrのSocket APIはエージェント間の通信と相互待機を可能にします。他のツールにはこの能力がありません。

マルチエージェント協調が主流になると、Herdrの価値はさらに明らかになります。

### 观点5：Rustは正しい選択

- Electron依存なし → サイズが小さく、起動が速い
- 単一バイナリ → インストールがシンプル
- 性能がいい → 大量ターミナル出力を処理できる

サーバーサイドツールとしては最も現実的な選択です。

## 📝 小まとめ

HerdrはAIコーディングエージェント専用のターミナル工作站管理器です。そのコアバリューは：

1. **エージェントを不掉線に保つ** — あなたがいてもいなくても、エージェントは走り続ける
2. **エージェントの状態を一目でわかる** — サイドバーが直接誰が何をしているかを示す
3. **マルチエージェント協調を可能にする** — Socket APIがエージェント間通信をサポート
4. **学習コストゼロ** — 既存のワークフローを変えない

> **Claude Code、Codex、CursorなどのAIコーディングエージェントを使っているなら、Herdrは手放せないツールです。** これはAIエージェントを「あなたが見ている必要がある」から「委任できる」に変えます。
