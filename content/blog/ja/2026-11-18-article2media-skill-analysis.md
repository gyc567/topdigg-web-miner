# スター435のarticle2media：価値があるのはAIが記事を書くことではなく、「何かが変だ」を機械が止められる指標に翻訳すること

**結論から：** GitHubには、スター435、フォーク65のオープンソースプロジェクトとしてarticle2mediaがあります。記事1本または動画1本を、一発で、そのまま公開できるXiaohongshuの画像投稿、マガジン調のロングイメージ、WeChat公式アカウントのレイアウト、そしてAIナレーション動画へ変換するものです。

10個の機能、12種類のテーマ、すべての成果物に対する自動検収（acceptance testing）、npm依存ゼロ。必要なのはNode 22とChromeだけです。

しかし、これを「また一つAIライティングツール」とだけ見れば、肝心な点を見失います。

**経営者が最もまねする価値があるのはその10個の機能ではなく、検収規律（acceptance discipline）です。「急ぎすぎ」「ずっと点滅している」「このテーマはよくない」といった曖昧なフィードバックを、4.5字/秒、点滅0箇所、版面エラー0件といった、機械が止められる指標に翻訳するところにあります。**

これはそのまま、自分のコンテンツチームに、AIツールチェーンに、クライアントに納品するSOPへ持ち込めます。内側から分解して説明します。

---

## 1、プロジェクト説明：そもそも何なのか

article2mediaはオープンソースのClaude Code / Codexスキルの集合であり、同時にClaude Codeプラグインでもあります。

作者はLeiLiu（GitHub: threerocks）、MITライセンス、リポジトリの作成は2026年11月8日で、一週間でスター435に到達しています。リポジトリはJavaScriptで、.mjsファイル77個、コードは約12400行です。

入力は次の2つです。

- 記事: X（Twitter）の長いポスト、スレッド、任意のウェブページ、WeChat公式アカウントの記事、ローカルのMarkdown、あるいは直接貼り付けた本文;
- 動画: Douyin、YouTube、Bilibiliのリンク、ローカルの動画または音声、`.srt` / `.vtt`の字幕。

動画はまず逐語起こしの記事へ変換され、その後は記事とまったく同じ工程をたどります。

出力は12形態あります。

| 成果物 | 仕様 | 公開に向いている場所 |
|---|---|---|
| 要約ロングイメージ | 幅1080のシングルカラムのモバイル版、1から4ページ。`--wide`を付けると幅1200の2カラムマガジン版 | WeChat、WeChatモーメント、Weibo |
| カードセット | Xiaohongshu用3:4（1080×1440）、ほかに4:5、1:1、9:16も。表紙レイアウトは6種で、全面引用、大数字、全面の画像を差し挟められる | Xiaohongshu、Instagram、Douyinの画像投稿 |
| 表紙複数版 | 同じ記事から、レイアウトやフックを変えた表紙を数版 | 表紙を選んで個別に公開し、効果を比べる |
| 軽量版 | 1ページで読める版、引用カード、質問形式カード | 高頻度の更新、カードセット全体への導線 |
| WeChat公式アカウント用レイアウト | インラインスタイル、画像の埋込み、エディタにそのまま貼り付け可能。ほかに2.35:1のヘッダー画像と1:1の表紙 | WeChat公式アカウント |
| ナレーション動画 | 1080×1920の縦型、逐語同期のアニメーション、ローカルAI音声合成と字幕 | Douyin、WeChatチャンネル、Xiaohongshu動画 |
| 原文ロングイメージ | 一文字も変えず、レイアウトだけ | 原文をそのまま残す |
| 原文カード | 全文を順番にページ分割してカード化 | 全文をXiaohongshuに公開 |
| 全文翻訳 | 外国語の本文を段落ごとに日本語へ翻訳し、構造をブロック単位で対応 | 外国語の転載 |
| ホワイトボード論証 | 縦1本の推論の背骨: 問題、前提、証拠、矛盾、転回、結論 | 作者が結論へどう到達したかを見る |
| 漫画 | 白黒のコマ割りで、キャラクターが前後とも一貫 | 仕組みを物語で説明する |

**鍵となる設計は「機能は独立、組み合わせは自由」です。** 10個の機能はそれぞれ独立したスキルで、作業ディレクトリ内のファイルだけで受け渡します。`article.md`（原文）、`article.zh.md`（翻訳）、`content.json`（書き換え稿）、`rewrite.md`（書き換え稿の記事版）です。

つまり取得だけ、翻訳だけ、レイアウトだけでも構いません。ロングイメージ、Xiaohongshu、WeChat公式アカウントを一度に作り切ることもできます。

## 2、詳細チュートリアル：ゼロから最初の成果物を作り上げる

### ステップ1: インストール

おすすめはClaude Codeプラグインです。11個のスキルが一度に入ります。

```bash
claude plugin marketplace add threerocks/article2media
claude plugin install article2media@article2media
```

skills CLIを使えば、Claude CodeとCodexの両方に入れることもできます。

```bash
npx skills add threerocks/article2media -g -a claude-code -a codex -y
```

`-g`は全体インストール（Claude Codeは`~/.claude/skills/`、Codexは`~/.agents/skills/`にインストール）。`-g`を付けない場合は現在のプロジェクトにだけ入ります。`-y`は確認を飛ばし、`-l`は一覧を表示するだけでインストールしません。

手動インストールで気をつけるのは1点だけです。**リポジトリのルートディレクトリはスキルディレクトリではありません。`skills/`ディレクトリ全体を同期してください。**

```bash
git clone --depth 1 https://github.com/threerocks/article2media.git ~/code/article2media
rsync -a ~/code/article2media/skills/ ~/.claude/skills/
rsync -a ~/code/article2media/skills/ ~/.agents/skills/
```

隣の`article2media`がない状態で単一の機能だけコピーすると、スクリプトは共有エンジンが見つからないとすぐ報告します。すべての機能のスクリプトは`article2media/engine/`にあるからです。環境変数`ARTICLE2MEDIA_ENGINE=/path/to/skills/article2media/engine`で指すこともできます。

### ステップ2: 環境の確認

```bash
bash scripts/install.sh
```

このスクリプトは、何が足りないか、どう入れればよいかだけを知らせます。**それ自体で何かをダウンロードすることはありません。**

確認する項目は、Node 22以上と任意のChrome / Chromium（必須）、ffmpeg（ナレーション動画用）、Codex CLIのログインまたはOpenAI / Geminiのキー（AIイラストと漫画用）、Apple Siliconとmlx-audioとVoxCPM2（ローカル音声合成）、mlx-whisper（逐語同期と字幕なし動画の文字起こし）、yt-dlp（YouTubeとBilibiliの字幕）です。

中国大陸のネットワーク環境では、テーマのフォントは既定でGoogle FontsとjsDelivrから読み込むため、取得に失敗することがよくあります。そのときは次を1度実行します。

```bash
node skills/article2media/scripts/fonts.mjs
```

およそ 65 MBです。テーマのフォントをローカルのキャッシュにミラーし、以降の画像生成ではネットワークに出ません。描画そのものは何もダウンロードしません。

### ステップ3: Claude Codeからの呼び出し

一括での組み合わせはメインの入口を使います。

```
/article2media https://x.com/thedankoe/status/2117664712532123680
/article2media https://example.com/post xiaohongshu
/article2media ./my-essay.md wechat
/article2media https://x.com/… 日本語に翻訳してwechatに公開
/article2media https://x.com/… ロングイメージ、xiaohongshu、wechatをすべて
/article2media https://www.bilibili.com/video/BV… xiaohongshu
/article2media links.txt 一括、xiaohongshuとロングイメージを各記事へ
```

単一の機能を直接呼ぶこともできます（プラグイン内では名前に`article2media:`の接頭辞が付きます）。

```
/article2media:wechat-layout ./my-essay.md
/article2media:image-cards ./my-essay.md 原文カード
/article2media:video-transcript https://www.bilibili.com/video/BV…
/article2media:article-translate article2media-out/x-…/article.md
```

出力はカレントディレクトリの`article2media-out/<slug>/`配下に出ます。

### ステップ4: Claudeを介さずスクリプトを直接動かす

どの機能にも独自のスクリプト入口があり、Claudeなしでも動きます。

```bash
K=skills
node $K/article-fetch/scripts/fetch.mjs "https://x.com/…/status/…"
node $K/video-transcript/scripts/transcribe.mjs "https://www.bilibili.com/video/BV…"
node $K/article-rewrite/scripts/check.mjs <slug>/content.json
node $K/article-rewrite/scripts/export.mjs <slug>/content.json
node $K/long-image/scripts/long.mjs <slug>/content.json --theme all
node $K/image-cards/scripts/cards.mjs <slug>/content.json --ratio 3:4
node $K/image-cards/scripts/cards.mjs <slug>/content.json --covers
node $K/wechat-layout/scripts/wechat.mjs <slug>/article.md --theme quiet
node $K/explainer-video/scripts/video.mjs make <slug>/video/video.json
node $K/logic-whiteboard/scripts/whiteboard.mjs <slug>/article.md
node $K/article-comic/scripts/comic.mjs make <slug>/comic.json
```

ロングイメージとカードには`--out <ディレクトリ>`、`--page 1,3`、`--scale 2`、`--format jpeg --quality 90`、`--max-height 7600`、`--brand brand.json`、`--issue 13`、`--html-only`も指定できます。WeChat公式アカウント用レイアウトには`--title`、`--digest`、`--cover-title`、`--kicker`、`--hero`があります。

### ステップ5: 一括処理と公開のループ

一括モードでは、リンクをテキストファイルに書き出します。

```bash
node $K/article2media/scripts/batch.mjs init links.txt --name 今週 --spec "cards:3:4,long,wechat"
node $K/article2media/scripts/batch.mjs next 今週
node $K/article2media/scripts/batch.mjs checklist 今週
```

`batch.mjs init`は取得とボードの作成を担当します。Claudeは`next`に従って1件ずつ進め、1本が終わってから次へ進みます。取得に失敗した記事、本文が短すぎる記事、有料壁の疑いがある記事は、一覧に分けて確認待ちとなり、まとめて処理を止めません。

1本ごとに公開チェックリスト`publish.md`が残ります。アップロード順、代替タイトル、本文コピー、タグ、プラットフォームの制限チェックです（Xiaohongshuはタイトル20文字以内、本文1000文字以内、画像18枚まで。WeChat公式アカウントはタイトル64文字以内、要約120文字以内）。

公開後はデータを入力します。

```bash
node $K/article2media/scripts/stats.mjs add <slug> --platform xhs --views 1200 --likes 80 --saves 150
node $K/article2media/scripts/stats.mjs report
```

レポートは、プラットフォームごとにテーマ別、表紙レイアウト別の保存率とエンゲージメント率を比較します。**サンプルが5件に満たないグループは「サンプル不足、参考のみ」と明示されます。** 2、3本の投稿の違いから結論を誘導することはありません。

### ステップ6: セルフテスト（ローカルでコードを直す場合）

```bash
node tests/run-all.mjs --quick
node tests/run-all.mjs
node tests/unit.mjs
node tests/visual.mjs
node tests/eval-score.mjs <ディレクトリ> --ref <ディレクトリ>
```

`run-all.mjs`はセルフテストの行列です。サンプル記事4本に7種のレイアウトと12種類の主要テーマを組み合わせ、合計504回の描画を行い、どれも版面エラー0件を要求します。`visual.mjs`はピクセル単位の視覚回帰、`eval-score.mjs`はモデル差し替え時の品質スコアです。

## 3、3本の経路: 原文、要約、翻訳

これがプロジェクト全体の最も重要な設計判断であり、経営者が最もまねしやすい1点です。

多くのツールには「AI要約」ボタンが1つあるだけで、原文が欲しいと思っても対処できません。article2mediaはこれを明示的な振り分けルールにしています。

| あなたが言ったこと | どちらの経路を通るか |
|---|---|
| レイアウト、原文、全文、一文字も変えない、そのまま、`-f` | 原文経路: 直接に表現機能へ渡す |
| 要約、抽出、書き換え、要点、実用的な情報 | 書き換え経路: まず`article-rewrite`、その後で表現 |
| 翻訳、日本語に、外国語の転載 | 翻訳経路: まず全文を翻訳し、その後原文経路で表現 |
| 何も指定せず、ロングイメージかカードが欲しい | 既定は書き換え |
| 何も指定せず、WeChat公式アカウントが欲しい | 既定は原文レイアウト |
| 原文経路なのに原文の言語と目標の言語が違う | 先に翻訳してから原文レイアウト |

**ここには逆説的な既定値があります。WeChat公式アカウントは要約しません。**

つまり、他人の記事を投入して「WeChatに公開」と指示すると、返ってくるのは一文字も変えない原文レイアウトです。明確に「要約」と指示したときだけ書き換えます。

**経営者がにとっての意味:** コンテンツを作るチームでいちばん起きやすい事故は、レイアウトの粗さではなく、「AIに要約してもらって」という1文です。要約するたび作者の意図が1層はがれ、3層はがれると成功学の空語になります。既定を「要約しない」にすることは、最初から越権しない扉をチームに取り付けることに等しくなります。

## 4、設計哲学：6つの硬い規則

### 1. コンテンツとスタイルの分離

テーマはCSS変数とわずかな構造の上書きだけ。テーマを変えるには再描画するだけで、コンテンツは書き換えません。

これは、同じ`content.json`を12種類の主要テーマのどれにでも描画でき、ロングイメージ、カード、WeChat公式アカウントを同時に作り出せることを意味します。

### 2. npm依存ゼロ

Node 22に組み込まれたWebSocketとfetchだけを使い、手元にあるChromeを直接駆動します。puppeteerもplaywrightも、ブラウザのダウンロードが必要なパッケージも使いません。

### 3. 画像の中に文字を入れない

これがプロジェクト全体でいちばん賢い決定です。

AI生成画像のいちばんの問題の一つは、中国語の文字が誤って描かれることです。article2mediaの手法はこうです。**生成する画像には文字を一切含めません。** タイトル、グラフのラベル、漫画のセリフ、動画の字幕など、すべての文字をHTMLでレイアウトし、ヘッドレスのChromeでスクリーンショットを撮ります。

結果として2つのことが起きます。文字が化けることはなく、いつでも差し替えられます。より重要なのは、**プログラムが描画された文字を読み戻して検査できる**ことです。

### 4. 機能の検出で、強制しない

画像生成（Codex CLIからOpenAI、Geminiまで）、ローカル音声合成（VoxCPM2からedge-tts、システム音声まで）、逐語同期、動画の文字起こし。いずれもまず検出してから採用します。欠けている場合は縮退するか、何が足りないかを明示します。**決して自動でダウンロードもインストールもしません。**

### 5. 判断はモデル、計測はスクリプト

Claudeは理解と執筆を担当します。構成の計画、タイトルの書き換え、どの節に棒グラフを置くか、どの節にフローチャートを置くか、数値の照合。成果物はスタイルを一切含まない`content.json`だけです。

レイアウト、スクリーンショット、音声合成、整列、ミックス、検収はすべてスクリプトに任せます。

### 6. コンプライアンスを先に

同梱の音声6種は、すべて記述による説明だけで設計されており、実際の人物を真似たものは1つもありません。クローンした音声はローカルの個人音声ライブラリに留まり、利用時のレビューで権利確認を促します。完成動画の冒頭フレームとMP4のメタデータにはAI生成の表示が付きます。画像にはすべて原典を出典として記載します。

音声について、プロジェクトの結論は冷静です。**クローンした声をAIでさらに合成し直しても、新しい声にはなりません。** 根拠は民法典1023条第2項（自然人の声の保護に関する規定は、肖像権の保護に関する規定を準用する）と、2024年4月の北京市インターネット裁判所の判断です（一般の聞き手がAI合成の声から誰かを見分けられるなら、その声も同じように保護される）。そこで音声ライブラリは著作権で2層に分けています。公開音声はプロジェクトに同梱し、ローカルの個人音声ライブラリは本人だけが使います。

## 5、自動検収：すべての成果物に検査器がある

ここが「AIにそのまま画像を作らせる」こととの決定的な違いです。

AI生成の成果物でいちばん叫人恐怖なのは「だいたいそれらしく見える」ことです。そこで成果物ごとに検収を持ち、不合格なら人が目で見つけるのではなく、エラーを報告して終了します。

| 成果物 | 検査項目 |
|---|---|
| 書き換え稿（原文との比較） | 原文に見つからない数値、他人の記事を一人称で書いていないか、原文の図が1枚も使われていないか、原文の具体的な数値や固有名詞やツール名の使用量、中国語に一般的な英単語が混ざっていないか、本文が薄い、データパネルや全面カードが少ない、大数値とタイトルが一致しない、同じ文の重複、「避けるべきこと」が行うべきこととして書かれている、フッターに制作過程が書かれている、代替タイトルがない |
| 要約ロングイメージ、カード、表紙 | 文字のはみ出し、途中で切れる、要素の重複、1文字だけの行、ページが高すぎる、画像の読み込み失敗、フォントファミリー単位の検査、カードのあふれ、グラフが小さすぎる、自動省略が発生していないか |
| 原文ロングイメージ、原文カード、WeChat公式アカウント用レイアウト | 原文ブロック台帳とのブロック単位比較（カード跨ぎの接合を含む）、解析の網羅率、出典のSHA-256固定、実際のフォント、カードのあふれ、ページ数の上限、WeChat側に残るスタイル、タイトルの長さ |
| 全文翻訳 | ブロック数と構造のブロック単位対応、コードと画像の原形のまま、未翻訳または脱落の疑い、数値の欠落がないか |
| ホワイトボード論証 | 論証台帳: 原文のどの段落もいずれかの工程に入るか、あるいは省略理由が明記されていること |
| 漫画 | セリフ、ナレーション、効果音の文字がコマの外にはみ出していないか |
| ナレーション動画 | セーフエリア、最初の文が5秒以内、冒頭の画面が2.5秒以内、静止画が5秒以内、ナレーションの話速、字幕の保持時間と点滅、完成動画での1フレーム単位の字幕落ち、文ごとの音声合成の品質検査、音量 |
| 公開チェックリスト | Xiaohongshuはタイトル20文字以内、本文1000文字以内、画像18枚まで。WeChat公式アカウントはタイトル64文字以内、要約120文字以内 |

## 6、まとめ: 8つの見解と、それが経営者に意味すること

### 見解1: このプロジェクトの本質は「生成システム」ではなく「検収システム」です。

10個の機能は皮で、検収が骨です。生成能力は誰でもモデルをつなげれば実現できます。検収規律には数千回の反復が必要です。

**経営者がにとって:** あらゆるAIツールを評価するとき、まず「どうやれば自分は間違いだと気づくのか」を確認してください。答えられないツールは、成果物の品質がすべて自分の肉眼に依存し、1日3件しか作れません。

### 見解2: 「何かが変だ」を指標に翻訳することが、高い品質のコンテンツを大規模化できる唯一の手段です。

プロジェクトの作者はこういうフィードバックを残しました。「解説全体の話速が急ぎすぎてはいけない。これは大忌だ」。コードを直しただけで終わらせず、参照音声の話速を測定し、標準をおよそ4.5字/秒と定め、1節が5.2字/秒を超えると速いと判定し、速いと判定された文は乱数シードを変えて再生成し、それでも速ければ音高を保ったまま遅くしました。修正後、同じ動画のナレーションは毎秒5.97字から4.27字に下がりました。

**このルールは現在、レビュー用のスクリプトに書き込まれています。次に誰かがコードを直しても、機械がその人の代わりに「急ぎすぎ」を覚えていてくれます。**

**経営者がにとって:** チームの「ここが上品でない」「この感じがおかしい」というフィードバックが数値にならない限り、ずっと玄学で、ずっと誰か1人の監視に依存します。1つずつ量にすることこそ、コンテンツ工業化のいちばん安い一歩です。

### 見解3: 機械の検査は必須ですが、人目も省けません。

プロジェクトが新中華風テーマを作る際、見栄えのよい見出しフォントを選び、版面検査は全部通りました。しかし人が成品を見ると、「回」の文字がすべて黒く塗りつぶされていました。フォントファイル自体が壊れており、プログラムでは検出できませんでした。

それ以降、新しいフォントは毎回「回図国円品器噩」の数文字で試します。

**経営者がにとって:** 品質管理の流れには、自動検査と人目の抜き取り検査の両方が必要です。自動検査だけだと「技術的には合格だが人間には見にくい」分類を漏らします。人目だけだと生産性が上がりません。

### 見解4: 機能を作れることと、做るべきことは別です。

背景音楽は3回試しました。オンラインの著作権フリー曲集、プログラムで合成したコードの土台、ローカルのAI作曲（モデルだけで 11 GB）。結局どれも残しませんでした。

理由は単純です。重すぎる。そもそも、プラットフォームのアプリにBGMを入れるのは数秒で済むからです。

**経営者がにとって:** これはこのプロジェクト全体で見た中で最も価値のある取舍でした。チームがAIツールチェーンを作る時に犯しやすい誤り（mistake）は、「作れる機能は全部載せる」ことです。機能を1つ足すたびに、保守コスト、障害点、ユーザーが使い方を分からない入口が1つ増えます。**引算は足し算より難しい。足し算には称賛が来ますが、引算の受益者は自分だけだからです。**

### 見解5: コンプライアンスは初日に正しくなければならず、後から直すコストは最初から正しく書くコストのはるかに上回ります。

**経営者がにとって:** AIツールチェーンが顧客データ、著作物の著作権、声や肖像の権利を扱うなら、事後対策の代償は最初にルールを正しく書いたときの10倍です。クライアントに納品するすべてのAIソリューションに当てはまります。

### 見解6: モデルの差し替えは、推測ではなく測定です。

プロジェクトはモデル差し替えのリグレッションテストを同梱しています。3本の記事でHaikuとOpusの「Xiaohongshuカードへの書き換え」を比較しました。

結果は、ルール面（客観スコア）ではHaikuはOpusの70%から95%まで上がり、ルールは守れる状態に到達しました。読者面（誰が作ったか分からない盲検評価、3回の入れ替え）ではHaikuはOpusの85%から91%、平均で約88%でした。差の主な原因は理解です。原文の中核の方法を落とし、近い2つの数値を混ぜ、画像を別の節に置きました。

**経営者がにとって:** これが「小さいモデルが書き、大きいモデルがレビューする」の現実的な天井で、88%です。安いモデルに替えれば節約になると思わず、気になっている軸をまず測定してください。

### 見解7: 既定を「要約しない」にすることは、既定を「より賢くする」より重要な設計です。

**経営者がにとって:** クライアントにAIワークフローを納品するとき、最初にすべきことは既定の挙動をもっとも保守的なものにすることです。ユーザーが明示的に求めたものを、出します。

### 見解8: 機能がうまく作られているかの印は、ループが閉じているかどうかです。

画像生成は半分です。「公開して効果が出る」という範囲にわたって、プロジェクトは一式つくりました。表紙の複数版、ブランドキット、軽量版、一括処理、公開チェックリスト、公開後のデータ記録と比較レポート。データは自分のマシンにだけ置き、サンプルがたまれば、テーマ選択ガイドは2つの同じ選択肢の間の判断材料としてそれを使います。

**経営者がにとって:** これがコンテンツと配信の間の断絶した鎖です。绝大多数のコンテンツチームはコンテンツを作って公開ツールに放り出し、データを見に戻りません。だから、どのやり方が効くのかが永久に分かりません。**ループを閉じるのに大系統は不要です。10件データを記録すれば十分です。**

## 7、明確にしておくべき境界

- **ローカル音声合成**: VoxCPM2は現在Apple Siliconでのみ動作します。それ以外の環境ではedge-ttsかシステム音声を使います。
- **画像生成**: AIイラストと漫画には画像生成機能が必要です。Codex CLIのログイン（ChatGPTアカウントで十分）か、OpenAI、Geminiの有料キー。
- **背景音楽**: 動画にまだBGMはありません。プラットフォームのアプリで自分で追加してください。
- **Xの取得**: FxTwitterに依存します。利用できない場合は本文を手動で貼り付けます。
- **動画入力**: ローカルの音声認識にはApple Siliconが必要です。YouTubeはネットワークによってはログイン確認を求め、Douyinはブラウザのcookieを求めることがあります。いずれかの方法としてブラウザの状態を再利用（`--cookies-from-browser chrome`）するか、動画をローカルに保存してファイルを渡します。
- **聴きやすさ**: 音色と話速の最終判断は、やはり人の耳に委ねられます。
- **Codexサンドボックス**: 既定ではChromeの起動が許可されず、画像生成で「Chromeが予期せず終了しました」と表示されます。このステップを許可する必要があります。

もう1つ覚えておく価値のある詳細があります。動画を文字起こしするとき、**機械翻訳された字幕トラックとBilibiliの弾幕はどちらも使えません。** 前者は話者の言葉ではなく、後者は視聴者のコメントです。文字情報の信頼性の順序はこうです。人間の字幕、プラットフォームが原言語で生成した自動字幕、ローカルのWhisper認識。
