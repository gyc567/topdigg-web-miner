# holaOS 徹底解説：あなたとあなたのエージェントのためのコンピュータ——オープンソースのオールインワン AI エージェントワークスペース

> コア思想：**「The Computer for You and Your Agent」（あなたとあなたのエージェントのためのコンピュータ）**。holaOS の創業者は、エージェント時代の真の主役はチャットウィンドウの羅列ではなく、**エージェントと一緒に使えるコンピュータ**だと考えました。そのビジョンをオープンソースのオールインワン AI エージェントワークスペースとして具現化：ローカルファーストの単一ワークスペースで**任意の**エージェント（Claude Code、Codex、内蔵の holaOS エージェント）を実行し、同じメモリ・同じツール・同じブラウザ・同じアプリエコシステムを共有します。「仕事に最適なエージェントを、毎回セットアップし直すことなく使う」。より深い判断はこうです：**モデルは急速にコモディティ化しており（その価値はゼロに向かっている）、真に価値を捕捉するのはエージェントの上の「ワークスペース層」**——共有メモリ、実アプリケーションの UI、エージェントが操作できる完全なワークステーションです。

## 背景とプロジェクト紹介

2026 年、AI エージェント分野の競争は激化の一途をたどっています：Claude Code、OpenAI Codex、Cursor、Windsurf……どのエージェントも開発者の唯一の入り口になろうとしています。しかし holaboss-ai のチームは異なる視点を提示します：**なぜエージェントの間で択一を迫られるのか？**

holaOS の答え——個々のエージェントに賭けるのではなく、**すべてのエージェントを載せる「コンピュータ」に賭ける**。ブラウザを変えてもファイル・ブックマーク・履歴を失わないのと同じように、エージェントを変えてもメモリ・ツール・スキルを失うべきではありません。holaOS はこの「エージェント時代のオペレーティングシステム」なのです：オープンソースで、ローカルファーストで、特定のエージェントに依存しない**ワークスペース層**。

### 一言での位置づけ

holaOS は**オープンソース・ローカルファーストのオールインワン AI エージェントワークスペース**です：Claude Code、Codex、または内蔵の holaOS エージェント——任意のエージェントを単一ワークスペースで実行し、同じメモリ・同じツール・同じアプリエコシステムを共有。モデルは内蔵か BYOK（キー持ち込み）のどちらでも。

## コア思想：なぜ「コンピュータ」なのか、「チャットボックス」ではないのか

holaOS プロジェクト全体の魂は、次の 4 つの段階的判断に分解できます：

### 1. エージェント時代の主役は「コンピュータ」であり、「チャット」ではない

ほとんどの AI 製品はインタラクションをチャットボックスとして設計します：メッセージを送り、AI がテキストで返す。holaOS の創業者はこれを誤ったメタファーだと考えます。本当のパラダイムは**コンピュータ**です——あなたとエージェントが 1 台のマシン・1 セットのファイル・1 つのブラウザ・1 組のアプリを共有します。エージェントが生むのは「会話のログ」ではなく、**実際に成果物として着地したもの**：本物の `.xlsx` レポート、本物の `.pptx` スライド、本物の `.docx` ドキュメント、実際に操作されたアプリの UI です。

### 2. モデルはコモディティ化し、価値はワークスペース層にある

Kimi K3・GLM 5.2（日常のコスパ用）を内蔵し、GPT 5.6・Claude Opus 5・Fable 5（難問用）をトップ層に据え、OpenAI/Anthropic や互換エンドポイントへの BYOK もサポート——この背後にある判断：**モデルそのものはもはや差別化要因ではない**。差別化はモデルの上の層、つまりメモリ・ツール・スキル・アプリ・ワークフローの**オーケストレーションと共有**にあります。

### 3. ロックインなし：エージェントは挿し替え可能、ワークスペースは永続的

holaOS は「No lock-in」（ロックインなし）を明示します：すでに信頼しているエージェントを持ち込めばいい。エージェントを変え、アプリを閉じ、1 週間後に戻っても——前回の続きを覚えています。**すべてを共有**（1 つのコンテキスト、1 セットのツール、1 つのワークスペース）+ **一貫した結果**（誰が駆動しても、スキルとインテグレーションは常に同じ）。

### 4. 一度教えたら、どこでも再利用（Teach once, reuse everywhere）

holaOS では、あるエージェント向けに設定した Skills（スキル）、Integrations（統合）、MCP サーバー、Combos（組み合わせパック）を**すべてのエージェントが自動的に継承**します。これにより「エージェントを乗り換えるコスト」をゼロにまで押し下げます——まさにこれがロックインなしの約束を成立させる技術的基盤です。

## プロジェクト説明：holaOS とは

### 6 大コア機能

#### 🔀 任意のエージェントを実行、1 つのワークスペース

Claude Code、Codex、内蔵 holaOS エージェント——並べて実行、切り替え不要。どれを実行しても、同じメモリ・ツール・スキル・アプリを共有します。

#### 🧠 1 つのメモリを、すべてのエージェントで共有

コンテキスト、好み、プロジェクト履歴は**単一の共有メモリ**に保存——**ローカルのプレーンテキストファイル**として保存され、あなたは直接読んで編集できます。エージェントを切り替え、アプリを閉じ、1 週間後に戻る：前回の続きをすでに知っています。

- **ゼロから始めることはない**——セッションをまたぎ、エージェントをまたぐ永続メモリ
- **ローカルファーストで、あなたのもの**——あなたのマシン上にあり、可視で編集可能、他人のクラウドに閉じ込められない
- **本当に呼び出せる**——構造化・埋め込みされた保存により、必要なときに正しいコンテキストが戻ってくる

#### 💸 モデルはあなた次第——内蔵か、キー持ち込みか

1 つのアカウントで全モデル——キー不要、セットアップ不要、プロバイダ間の切り替え不要。最先端モデルが**内蔵**：コスパの **Kimi K3** と **GLM 5.2** が日常のボリュームを、トップの **GPT 5.6**・**Claude Opus 5**・**Fable 5** が難問を担当。自分のプロバイダがいい？OpenAI、Anthropic、または互換エンドポイントへ**キー持ち込み（BYOK）**——それらはあなたのアカウントで動き、holaOS のプランでは動きません。

#### 🪟 HolaApps——アプリとエージェントを並べて

ワークスペース内のマーケットプレイスからアプリをインストールすると、**エージェントのすぐ隣に本物のインタラクティブな UI** として開きます。アプリの中でエージェントが働く様子を見て、いつでも介入でき、結果はその場に着地します——チャットのテキストの壁ではなく、**実際のアプリ**が、エージェントに駆動され、エージェントの隣にあります。

- **チャットではなく実 UI**——すべてのアプリは生きた UI（Notion、ブラウザ、あなた自身のアプリ）
- **並べるのが設計**——アプリとエージェントが画面を共有
- **ワンクリックインストール**——マーケットプレイスを閲覧して即開く
- **自分で持ち込む**——任意の URL と MCP サーバーを HolaApp に向ける

#### 🧩 Skills、Integrations、MCP——一度教えたらどこでも再利用

- **Integrations**——Gmail、Notion、Slack、GitHub、Linear など 50+ アプリにワンクリック OAuth で接続。エージェントはツールをまたいで直接読み書き、グルーコード不要
- **MCP**——任意の Model Context Protocol サーバーを接続、またはコミュニティの MCP サーバーをワンクリックインストール
- **Skills**——ワークフローを一度パッケージ化し、任意のエージェントがオンデマンド実行
- **Combos**——スキルと統合を 1 つのワンクリックインストールにバンドル

#### 🛠️ ワークステーション全体をエージェントが操作可能に

- **🌐 エージェントが駆動する本物のブラウザ**——サインイン済みブラウザをエージェントが操作して閲覧・クリック・抽出、すべてあなたのコントロール下
- **🎨 最先端の生成を内蔵**——最新の画像・動画・音声モデルがすべてのエージェントの中に
- **📄 本物の成果物**——レポート・表計算・スライドが本物の `.xlsx`・`.pptx`・`.docx` ファイルとして保存
- **💬 あらゆるチャット導線からアクセス**——飛書（Feishu）、WeChat、Slack、Telegram
- **⏰ 自動化**——スケジュールやトリガーで実行

### 技術アーキテクチャ：Electron デスクトップ + プロセス内ランタイム

holaOS は bun + turbo の monorepo で、**デスクトップアプリ**と**プロセス内ランタイム**の分離が核心です：

```text
holaOS/
├── apps/                     # アプリケーション
│   ├── desktop/              # Electron デスクトップアプリ（Vite renderer + electron main/preload）
│   └── docs/                 # ドキュメントサイト
├── runtime/                  # プロセス内ランタイム（核心）
│   ├── api-server/           # ランタイム API サーバー
│   ├── channel-gateway/      # チャネルゲートウェイ
│   ├── harness-host/         # ランタイムホスト（pi/Hola ブレインはここで実行）
│   ├── harnesses/            # 各種ハーネス（pi ブレイン含む）
│   └── state-store/          # 状態ストア（better-sqlite3）
├── packages/                 # 共有パッケージ（例：@holaboss/app-sdk）
├── shared/                   # 共有コード
├── scripts/                  # install.sh、hola.mts など
└── patches/                  # 依存パッチ
```

デスクトップは Electron + React 19 + TypeScript + Vite + Tailwind CSS の 3 ペインレイアウト（ファイルエクスプローラー / アプリ内ブラウザパネル / AI チャットアシスタント）で、安全な preload ブリッジ（`contextIsolation: true`、`nodeIntegration: false`、`webviewTag: true`）を通じてローカルファイルシステムと内蔵ブラウザにアクセスします。

ランタイムは**自己完結バンドル**です：ランタイム API、同梱の Node/npm、同梱の Python をパッケージ化。デスクトップアプリは `apps/desktop/out/runtime-<platform>` にランタイムをステージングし、環境の決定性と移植性を保証します。

## 詳細チュートリアル：holaOS をゼロからインストール

### 方法 1：ワンラインインストール（推奨）

macOS、Linux、WSL の新しいマシンで：

```bash
curl -fsSL https://raw.githubusercontent.com/holaboss-ai/holaOS/refs/heads/main/scripts/install.sh | bash -s -- --launch
```

このスクリプトはデフォルトで：
1. git がなければインストール
2. Node.js 24 + npm がなければインストール
3. リポジトリを `~/holaboss-ai` にクローン
4. 必要に応じて `apps/desktop/.env.example` から `apps/desktop/.env` を作成
5. `npm run desktop:install` を実行
6. `npm run desktop:prepare-runtime:local` を実行
7. `npm run desktop:typecheck` を実行
8. Electron を起動する前に停止（`--launch` を渡さない限り）

オプションフラグ：
- `--dir <path>` クローン先ディレクトリを指定
- `--ref <git-ref>` / `--branch <git-ref>` `main` 以外のブランチやタグからインストール
- `--launch` 検証後に `npm run desktop:dev` へ続行

すでにローカルチェックアウト内にいる場合、同じラッパーを直接再利用できます：

```bash
bash scripts/install.sh --dir "$PWD"
```

### 方法 2：手動インストール（各ステップを制御）

まず前提条件を確認：

```bash
git --version
node --version    # 24 以上であること
npm --version
```

そして順番に実行：

```bash
# 1. リポジトリをクローン
git clone https://github.com/holaboss-ai/holaOS.git holaboss-ai
cd holaboss-ai

# 2. デスクトップ依存関係をインストール
npm run desktop:install

# 3. ローカル環境ファイルを作成
cp apps/desktop/.env.example apps/desktop/.env

# 4. ローカルランタイムバンドルを準備
npm run desktop:prepare-runtime:local

# 5. 起動前の非対話クイック検証
npm run desktop:typecheck

# 6. 開発モードを起動
npm run desktop:dev
```

`npm run desktop:dev` の `predev` フックは環境の検証・ネイティブモジュールの再ビルド・ランタイムバンドルのステージング確認を自動で行うため、通常の開発パスでは手動の prepare は不要です。

### ランタイムバンドルの 2 つのソース

```bash
# ローカルソースからランタイムをビルドしてステージング
npm run desktop:prepare-runtime:local

# GitHub Releases から現在のプラットフォーム向け最新公開ランタイムを取得
npm run desktop:prepare-runtime
```

ローカルソースパスはランタイムコードを変更しているときに使い、公開バンドルは既知のリリース成果物に対するデスクトップの検証に使います。

### ランタイム検証（オプション、新規クローン向け）

```bash
npm run runtime:state-store:install
npm run runtime:state-store:build
npm run runtime:harness-host:install
npm run runtime:harness-host:build
npm run runtime:api-server:install
npm run runtime:test
```

### 上級：hola CLI で pi ブレインをデバッグ

`scripts/hola.mts` は**デスクトップ UI を開かずに**、ソースからプロセス内で **pi（Hola）ブレイン**を実行してデバッグできます：`runtime/harness-host/src/pi.ts` にブレークポイントを置き、ビルド/ステージングのループなしで編集・再実行、複数インスタンスも起動可能。

```bash
# 先にこのチェックアウトのデスクトップを閉じる（書き込み競合回避）。その後：
npm --prefix runtime/api-server run hola -- -p "list the files in this repo and summarize it"
```

これはランタイムの本物の `executeTsRunnerRequest` パイプラインを呼び、`runHarnessHost` 依存だけをプロセス内 `runPi()` に置き換えます（`harness-host run-pi` を spawn する代わりに）。つまり MCP、sidecar、skills、ツール、`model_client`、注入コンテキストなどすべてのビルド段階が**デスクトップ実行に忠実**で、ハーネスのサブプロセスのみが差し替わります。イベントは本物の relay を通るため（`harness_session_id` が永続化され、resume が機能）。

主なフラグ：`-p/--prompt`、`--cwd`、`-m/--model`、`-s/--session <path>`（特定セッションを再開）、`--fresh`（新規セッション）、`--no-runtime`（HTTP バックエンドツールをスキップ）、`--keep`（起動したランタイムを残す）、`--force`（稼働中のデスクトップが使う root を開く）、`--print-request`（ビルド+印刷のみ、モデル呼び出しなし）、`--debug`（生イベント）、`--port`。

### パッケージングとリリース（上級）

```bash
# macOS（ローカル ad-hoc 署名）
npm run dist:mac
npm run dist:mac:dmg

# Windows（NSIS インストーラー）
npm run dist:win
```

- `dist:mac` は未署名のローカル `.app` を生成（`runtime-macos` を `Contents/Resources/` に同梱）
- `dist:mac:dmg` はローカル使用の `.dmg` インストーラーを生成
- 本番の署名と公証は GitHub Actions で実施（Apple シークレット設定後）
- デスクトップリリースのバージョンは安定 semver `YYYY.MDD.R`（例：`2026.410.1`、`2026.1113.1`）。GitHub リリースタグは `holaOS-YYYY.MDD.R`

### セキュリティモデル

- レンダラー：`contextIsolation: true`、`nodeIntegration: false`、`webviewTag: true`（内蔵ブラウザパネルのため意図的に有効化）
- preload ブリッジはランタイム情報と制約付きファイルシステム API のみを公開
- セキュリティ問題（認証情報漏えい、RCE、サンドボックス脱出、認証バイパス、安全でないデフォルト設定）は**非公開**で `admin@holaboss.ai` へ報告し、公開 issue にしない

## 設計哲学：holaOS の 9 原則

### 1. ローカルファーストとデータ所有権（Local-first & data ownership）

メモリはあなたのマシン上のプレーンテキストファイル——可視、編集可能、移行可能。「Not locked in someone else's cloud」（他人のクラウドに閉じ込めない）——これは SaaS 系 AI 製品の「メモリのブラックボックス」への正面回答です。ユーザーのデータ主権こそが製品の信頼の基盤です。

### 2. エージェント非依存（Agent-agnostic）

単一エージェントに賭けず、ワークスペース層をエージェントから切り離します。Claude Code、Codex、内蔵エージェントは**挿し替え可能な実行器**であり、ワークスペース（メモリ/ツール/スキル/アプリ）は**永続的な資産**です。これはユーザーへの約束（ロックインなし）であると同時に、ポジショニングの選択（どちらにも与しない）でもあります。

### 3. サイロより共有コンテキスト

各エージェントが独自のメモリとツールを持つのは、大きな無駄であり断片化です。holaOS の核心的主張：**コンテキスト、好み、プロジェクト履歴は単一の共有資産であるべき**で、どのエージェントが駆動していても同じ。これは「一貫した結果」（Consistent results）の約束の源泉でもあります。

### 4. チャットではなく実 UI（Real surfaces, not chat）

エージェントの成果は**実アプリケーションの UI と実ファイル**であるべきで、チャットの記録の壁であってはなりません。HolaApps はアプリとエージェントを並べます——「app and agent share the screen, so you always see what's happening and can take over」（アプリとエージェントが画面を共有し、何が起きているかを常に見て、いつでも引き継げる）。**ヒューマン・イン・ザ・ループ**は事後のパッチではなく、設計に組み込まれています。

### 5. 一度教えたら、どこでも再利用（Teach once, reuse everywhere）

スキル、統合、MCP、Combos は**エージェント非依存の資産**です。これにより知識再利用の単位を「単一エージェント」から「ワークスペース全体」へ引き上げ、エージェント乗り換えのコストをゼロに近づけます——ロックインなしの約束が信頼に足るものになる理由です。

### 6. ゼロセットアップデフォルト + BYOK の柔軟性

内蔵モデルは「1 アカウント、全 SOTA モデル、API キー管理不要」というゼロセットアップデフォルトを意味します。BYOK は「あなたのキー、あなたのプロバイダ、あなたのレート」を意味します。これは「使いやすさ」と「自律性」の両立——デフォルトの道は摩擦ゼロ、上級の道は閉じ込めません。

### 7. 自己完結ランタイム（Self-contained runtime）

ランタイム API・Node/npm・Python をすべてランタイムバンドルに同梱し、デスクトップアプリがステージングして実行します。これにより**環境の決定性**（ホストの Node/Python バージョンに依存しない）、移植性、再現性が保証されます——AI ワークスペースは「ユーザーのマシン環境がたまたま正しい」という前提の上に築けません。

### 8. セキュリティ最優先（Security-first）

`contextIsolation` + 制約付き preload ブリッジ + 明確な非公開脆弱性報告フロー + エンタープライズ監査ログ。エージェントがあなたのブラウザやファイルを操作できる以上、セキュリティはファーストクラス市民でなければなりません。セキュリティポリシーは 5 クラスの機微問題（認証情報漏えい、RCE、サンドボックス脱出/権限昇格、認証バイパス、ローカルランタイムを露出する安全でないデフォルト設定）を明示し、「エージェント権限」へのチームの真剣さを示しています。

### 9. エージェント向けの決定的ドキュメント（Deterministic docs for agents）

INSTALL.md は明確に「新しいマシンから作業するエージェントのための決定的セットアップ runbook」として書かれています——Codex/Claude Code に直接インストールを実行させる 1 文のハンドオフまで用意。AGENTS.md はアイコンを `@/components/ui/icons` ラッパー層経由にすること、コミットを詳細な Conventional Commits 形式にすることを規定。**このリポジトリ自体が「エージェントフレンドリーなコードベース」のデモンストレーション**——ドキュメントは人間が読むためだけでなく、エージェントが実行するために書かれています。

## 重要な論点まとめ

### 論点 1：Agent OS が次のプラットフォーム層

モデル層はコモディティ化が進み（SOTA の差は縮まり、互いに追いかけ合う）、アプリ層は巨人が握っています。本当の空白は**エージェントを載せる OS 層**——メモリ・ツール・スキル・アプリのオーケストレーション層です。holaOS が賭けているのはまさにこの位置。「The Computer for You and Your Agent」はマーケティングスローガンではなく、プラットフォーム判断です。

### 論点 2：メモリが堀（モート）である

セッションをまたぎ、エージェントをまたぐ永続共有メモリこそ、holaOS の最も深い差別化です。すべてのエージェントがモデルとツールを呼べるようになったとき、**「覚えていること」こそが希少**になります。そして「プレーンテキストファイルとして保存する」という選択は極めて賢明です：ローカルファーストの約束を果たすと同時に、メモリを監査可能・移行可能・信頼可能にします。

### 論点 3：モデル商品化後、ワークスペース層が価値を捕捉する

最先端モデル内蔵 + BYOK という姿勢が示すのは：holaOS はモデルでは儲けない（そこはコモディティ化された層）——**オーケストレーション、メモリ、アプリエコシステム、エンタープライズセキュリティ**で儲ける。これは「モデル＝堀」という物語への明確な反論です——堀はモデルの上にあります。

### 論点 4：オープンソース + ホステッド + エンタープライズの 3 軸

デスクトップ App（無料開始）→ オープンソースのセルフホスト（BYOK）→ エンタープライズ（SSO/監査/プライベート展開）。これは成長ファネル（オープンソースが導線、エンタープライズが収益化）であると同時に、信頼戦略でもあります（セルフホスト選択肢が「自分のデータがあなたのクラウドにある」という懸念を除去）。

### 論点 5：エージェントには「見えて、引き継げる」操作 UI が必要

HolaApps の並列設計は、エージェント安全性の核心的問いに答えます：**ユーザーに「エージェントが実アプリを操作すること」をどう信頼させるか？** 答え——操作を完全に見える化し（side-by-side）、引き継ぎを常に可能にする（step in whenever）。信頼は権限システムで積み上げるのではなく、**透明性**で積み上げるのです。

### 論点 6：自己完結ランタイムは AI ワークスペースの現実解

Node/npm/Python をバンドルするランタイムバンドルは、サイズを犠牲にして決定性と移植性を手に入れます。AI ワークスペースにとっては、**軽量さより再現性が重要**——エージェントが実行するツールチェーンは安定していなければなりません。この選択は類似製品への直接的な示唆になります。

### 論点 7：「会話型 AI」から「ワークスペース型 AI」へのパラダイムシフト

holaOS は形作られつつあるコンセンサスを代表しています：**AI の究極のインタラクションはダイアログボックスではなく、共有された作業環境**。エージェントはあなたのブラウザの中で、アプリの中で、ファイルシステムの中で働き、本物の成果物を生み、あらゆるチャット導線から到達でき、スケジュールで自動実行されます——「チャット」は数あるヒューマンインターフェースの 1 つであり、もはや製品のすべてではありません。

## 結び

holaOS は 2026 年のエージェント基盤競争において、最も代表的な「ワークスペース派」プロジェクトの 1 つです。どのエージェントが勝つかに賭けるのではなく、より根本的な層——**エージェント時代のコンピュータ**に賭けています。7.4k Stars と 642 Forks は、この判断が広く共感を得ていることを示しています。

その核心的教訓は 1 文に凝縮できます：**モデルがもはや希少でなくなったとき、「エージェントと共有する永続的なワークスペース」こそが希少になる。** ローカルファーストの共有メモリ設計、チャットでなく実 UI の HolaApps パラダイム、一度教えたらどこでも再利用のスキル体系、そしてエージェント向けの決定的ドキュメントまで、holaOS は同じ問いに答えています：**「どんなエージェントでもどんな仕事でも」を、コンピュータを使うように自然で、信頼でき、引き継げるものにするにはどうすればいいか。**

AI 製品を構築している人にとって、holaOS は多くの点で解剖する価値があります：monorepo 構造、自己完結ランタイム方式、HolaApps の並列インタラクションパラダイム、「メモリ＝堀」のプロダクト判断。エンドユーザーにとっては、稀有な約束を提供します：**エージェントを変えても、もうゼロから始める必要はない。**
