# Pluely：一款「无感」的AI助手，让AI真正融入你的每一次对话

## 引言

你有没有过这样的经历：

开会时对方问了一个尖锐的问题，你脑子一片空白；面试时突然被要求举例，手忙脚乱地回忆；销售电话里客户抛出一个技术问题，你不确定自己说的是否准确。

大多数AI助手需要你切换窗口、打开标签页、粘贴上下文——这一步的延迟，往往就让你错过了最佳回答时机。

**Pluely** 解决的就是这个问题。它不是一个聊天机器人，而是一个「悬浮在你所有工作之上的AI overlay」——一个始终漂浮在屏幕最前端的透明小窗口，让你在任何场景下都能即时获得AI的帮助，而且不会被屏幕共享暴露，在通话中也没有任何机器人加入。

这就是它名字的含义：**Pluely = Plugin + Truly = 真正无感的插件**。

---

## 一、项目概述

### 1.1 核心定位

Pluely 是一款跨平台（macOS / Windows / Linux）的桌面应用，定位为「隐形的AI伴侣」：

> **One overlay, no tab, no trace.**
> （一个悬浮层，无需切换标签页，不留任何痕迹。）

它的核心特性是「始终可用、从不打断」——悬浮层永远漂浮在你正在使用的应用之上，但不会抢占焦点（macOS上尤其明显）。

### 1.2 两个核心模式

**Ask 模式（提问模式）**：在悬浮层中输入问题，可附加全屏/区域截图、图片、文件（PDF，支持OCR）、语音输入。答案以Markdown流式返回，所有对话自动保存在本地。

**Listen 模式（聆听模式）**：实时转录麦克风音频和系统音频（对方的声音），显示带说话人标签的转录文本，并可自动生成回答建议、实时翻译、记录会议纪要。

### 1.3 技术架构

```
┌─────────────────────────────────────────────────┐
│                   Pluely v1                     │
├─────────────────────────────────────────────────┤
│  Frontend: React + shadcn/ui                    │
│  Runtime:  Tauri (Rust)                         │
│  Platform: macOS native panel (tauri-nspanel)   │
│  Storage:  Local SQLite                         │
│  Audio:    System audio + mic, echo cancellation │
│  AI:       200+ hosted models / 自带 key / CLI  │
└─────────────────────────────────────────────────┘
```

- **Tauri 替代 Electron**：安装包仅9-16MB，比动辄100MB+的Electron轻量得多
- **本地SQLite存储**：所有数据不上云
- **tauri-nspanel**：macOS原生panel集成，真正系统悬浮面板

## 二、详细功能解析

### 2.1 Ask 模式：让AI看到你在看什么

截图捕获方式：
1. **Capture** — 全屏或拖拽区域截图
2. **Attach image** — 附加已有图片
3. **Attach file** — 附加PDF等文档（内置OCR）
4. **Use image** — 每次消息自动附上新鲜截图

你可以：
- 看到报错信息？截图问「这是什么问题」
- 看到PDF合同条款？截图问「这句话的法律含义」
- 看到架构图？截图问「这个流程有什么问题」

### 2.2 Listen 模式：实时转录 + 主动建议

转录能力：
- 同时捕获麦克风 + 系统音频（对方的声音）
- 自动区分说话人（Speaker 1, Speaker 2...）
- 回声消除，不重复转录
- 支持数十种语言及多语言混合模式

**自动回复触发方式：**

| 触发方式 | 说明 |
|---------|------|
| 有人提问时 | 检测到疑问句后自动生成回答 |
| 每段对话间隙 | 每次说话暂停后生成回应 |
| 手动 Suggest | 按需生成，不自动触发 |

**内置提示词模板：** Interview Assistant、Meeting Assistant、Translator、Coding Discussion、自定义模板。你还可以给提示词附加知识文件（简历、产品规格书、定价表）作为回答的参考依据。

**场景自动检测：** Pluely会分析对话内容，自动切换到对应的模式标签（面试/会议/编程）。

**隐私保护：** 5分钟完全静默后自动停止，每小时询问「是否继续」，月度时间用完时在自然停顿处优雅结束。

### 2.3 模型选择

```
优先级 1: 你的 CLI（Claude Code / Gemini CLI / Ollama 等）
优先级 2: Pluely 托管模型（200+ 模型，无需 API key）
优先级 3: 自带 Provider Key（任意 OpenAI 兼容 endpoint）
```

顶部两个特殊入口：**Web Search** 和 **Perplexity Search**，用于需要实时信息的场景。

## 三、设计哲学：为什么「无感」是关键

### 3.1 「第二大脑」的产品哲学

传统AI助手的交互范式：**用户主动打开应用 → 粘贴上下文 → 提问 → 获得回答**。当处于高压场景（面试、谈判、会议）时，你根本没有时间去切换窗口。

Pluely把这个流程反过来：**AI始终在场，随时待命，按需响应**。

### 3.2 隐私优先架构

- **本地SQLite**：所有内容存储在本地数据库，不上云
- **凭证加密**：API Key本地加密存储，不以明文出现在磁盘
- **Stealth模式**：屏幕共享时不抢占焦点，Windows有专属隐藏触发模式

### 3.3 「不抢占焦点」的设计

macOS上，Pluely的悬浮层是「非 activating」的——点击它不会把当前应用推到后台。你可以一边在IDE里写代码，一边直接在当前窗口中给Pluely打字，代码窗口纹丝不动。

### 3.4 从开源转向闭源的决策

Pluely早期完全开源（MIT → GPL-3），但代码被不断拿去重新打包成商业产品销售，license投诉毫无作用。v1转向「签名二进制分发」策略，但旧版GPL-3代码仍保留在GitHub历史中，免费计划保持免费，release依然公开发布。

**护城河不在代码里，而在产品体验、品牌信任和持续迭代里。**

## 四、实战教程：5分钟上手 Pluely

### 4.1 安装

访问 [pluely.com/download](https://pluely.com/download) 下载对应平台安装包（9-16MB）。首次启动后授予屏幕录制和麦克风权限即可。

### 4.2 基础提问（Ask模式）

```
Step 1: 打开悬浮层（全局快捷键，默认 Cmd+Shift+Space）
Step 2: 确保在「Ask」标签下
Step 3: 输入问题，按 Enter
Step 4: （可选）点击 Capture 截取屏幕内容
```

### 4.3 会议记录（Listen模式）

```
Step 1: 切换到「Listen」标签
Step 2: 选择提示词模式（Interview / Meeting / Translate / 自定义）
Step 3: 配置自动回复触发方式
Step 4: 点击「Start listening」
Step 5: 查看「Compact View」小窗模式转录
Step 6: 点击「Stop」，自动保存为会议记录
```

### 4.4 配置自己的模型

```
Dashboard → Dev Space → Connect a CLI 或 Provider
CLI：填写命令模板（如 claude-code --print "%s"）
Provider：填入 endpoint URL + API Key
保存后出现在悬浮层模型选择器中
```

### 4.5 自定义 Listen 模式提示词

```
Dashboard → System Prompts → 创建/编辑提示词
编写系统提示词内容，可附加知识文件
提示词菜单中选择「Make Listen mode」
该提示词出现在Listen模式标签栏中
```

## 五、核心观点归纳

### 5.1 「无感」是下一代AI应用的核心竞争力

AI的价值在高压场景下最高，但高压场景恰恰是用户最没有时间去「找AI」的时候。Pluely的核心洞察：解决方案不是让AI更快，而是让AI始终在场。

### 5.2 本地化是隐私的最好保障

将数据存储在本地SQLite而不是上传云端，是隐私保护的最彻底方式。Pluely处理的只是「请求」本身，而非「数据内容」。

### 5.3 场景感知比功能堆砌更重要

Pluely没有试图做全功能AI助手，而是专注于「Ask」和「Listen」两个场景，并通过场景检测自动切换提示词模式。「少即是多」的设计让产品更加聚焦。

### 5.4 开源与商业的边界正在被重新定义

当代码可以被轻易复制和分发时，护城河究竟在哪里？Pluely的答案是：护城河不在代码里，而在产品体验、品牌信任和持续迭代里。

---

## 六、总结

Pluely的核心创新不是某个具体的AI模型或功能，而是一种**交互范式的转变**——从「用户找AI」到「AI始终在场」。

它解决了一个真实的痛点：**在关键时刻（面试、销售、谈判、会议），人们需要AI的帮助，但恰恰没有时间去切换窗口、复制粘贴**。Pluely把这个成本降到了零。

**无感化、场景化、隐私优先**，这三个关键词可能是下一代AI应用的核心方向。
