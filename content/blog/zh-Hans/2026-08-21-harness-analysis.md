# 深度解析 Harness：AI Agent 的"攀岩绳索"——从攀岩隐喻到开源自主权

> 核心思想：**"Agent = Model + Harness"**——AI 模型是发动机，Harness 是让发动机安全运转并为你服务的外壳。Harness 不是模型的附庸，而是用户真正应该拥有和掌控的层。它决定了 AI 如何行为、使用什么工具、以什么节奏工作，以及——最重要的是——用户是否保有最终的控制权。

## 引言：被误解的"Harness"

如果你长期浸润在 AI 资讯圈，你大概已经听过"Agent"这个词无数次了。但"Agent Harness"呢？

恐怕多数人听到这个词的第一反应是：又一个行业黑话。

Earendil 团队写了一篇异常清晰的文章 [What is a Harness?](https://earendil.com/posts/what-is-a-harness/)，目的就是给这个概念祛魅。他们的方法很聪明——**从攀岩安全带说起**。这个隐喻不仅好懂，而且精准：因为安全带的核心逻辑——"连接、保护、让你能去做更危险的事"——恰好就是 Agent Harness 在 AI 世界里做的事。

这篇文章将围绕 Earendil 的原文，系统性地解析 Agent Harness 是什么、怎么工作、为什么重要，以及开源社区正在如何把它变成用户手中对抗 AI 实验室权力集中的工具。

## 一、项目背景：谁写了这篇文章

Earendil 是一个 AI 基础设施团队，旗下有多个与 Agent/Harness 相关的开源项目：

- **Pi** (`pi.dev`)：最小化的开源 Agent Harness，面向个人用户，完全运行在本地笔记本电脑上
- **Lefos**：面向电子邮件场景的 Agent Harness，核心交互媒介是 Email
- **OpenClaw**：另一个流行的开源 Agent Harness，支持 iMessage、Email 等多种界面

这篇文章是 Earendil 团队为 Pi 所写的产品哲学阐释，同时也是一篇面向大众的 AI Agent 科普文章——它假设读者完全不了解 Agent Harness，用最直白的语言解释了这个概念。

## 二、核心隐喻：攀岩安全带

### 2.1 现实中的安全带

Cambridge Dictionary 对 Harness 的定义是：

> **Noun.** 一套带有绑带和安全带的设备，用于控制或固定一个人、动物或物体
> **Verb.** 控制某样东西，通常是为了利用它的力量

当我们谈论攀岩安全带时，它的实际功能是：

1. **支撑与保护**——通过连接快挂和绳索，保护攀岩者免受坠落伤害、控制下降速度、引导攀登路线
2. **可挂载工具**——粉袋、岩钉工具、快挂挂环都可以挂在安全带上
3. **可迁移**——换一座山、换一种攀登方式，安全带本身可以带走，只需调整挂在上面的装备
4. **可个性化**——杂技演员和树艺师用不同的安全带，同一个安全带可以被调整成完全不同的用途

### 2.2 从物理世界到 AI 世界

Earendil 指出了两种 Harnesses 之间的结构与功能对应关系：

| 攀岩安全带 | Agent Harness |
|-----------|---------------|
| 连接身体与绳索 | 连接 AI 模型与工具、环境 |
| 保护攀岩者免受坠落 | 保护用户免受 AI 错误决策的伤害 |
| 承载粉袋、工具 | 承载工具集（搜索、代码、邮件等） |
| 可迁移、可个性化 | 跨模型、跨任务、可自定义 |
| 决定攀登节奏与路线 | 决定 Agent 行为节奏与执行路径 |

这个隐喻的核心洞见在于：**安全带不是攀岩者本身，但它是让攀岩者能安全探索更高处的前提条件。** 同样，Harness 不是 AI 模型本身，但它是让 AI 模型能可靠为用户服务的前提条件。

## 三、什么是 Agent Harness（核心定义）

### 3.1 基本定义

> **Agent Harness 是一种软件，它为 AI 模型提供一个运行环境。**

与大多数 AI 模型不同（你无法"拥有"一个 AI 模型），**你可以拥有自己的 Agent Harness**。这是 Harness 区别于模型本身最根本的特点。

用户与 Harness 的交互方式多种多样：
- 软件工程师可以直接在终端里使用 Pi
- OpenClaw 可以通过 iMessage、Chat App 或 Email 与用户交互
- Lefos 主要通过 Email 运行

无论界面如何，Harness 一般做四件事：

```
┌─────────────────────────────────────────────────────┐
│                  Agent Harness                      │
│                                                     │
│  ┌─────────────┐  ┌─────────────┐                   │
│  │ System      │  │   Tools     │                   │
│  │ Prompt      │  │  (工具集)   │                   │
│  └─────────────┘  └─────────────┘                   │
│                                                     │
│  ┌─────────────┐  ┌─────────────┐                   │
│  │ Agentic     │  │ Translation │                   │
│  │ Loop        │  │ Layer       │                   │
│  │ (代理循环)  │  │ (翻译层)    │                   │
│  └─────────────┘  └─────────────┘                   │
└─────────────────────────────────────────────────────┘
```

## 四、四大核心构成详解

### 4.1 System Prompt（系统提示词）

**类比**：新员工入职第一天拿到的操作手册。

大多数 AI 模型在训练过程中形成了一套内嵌的规则和指南——最著名的例子是 Claude Opus 4.5 那份被广泛传播的 [Soul Document](https://gist.github.com/Richard-Weiss/efe157692991535403bd7e7fb20b6695)，它向 AI 模型解释"我是谁、我应该如何行动"。

Harness 中的 System Prompt 与此类似，但有两个关键区别：

1. **它不是模型内部的东西**，而是注入到每次对话中的外部指令
2. **它更像工作手册而非本能**——模型知道应该遵循这些指令，但这些指令不是模型"天生就会的"

System Prompt 的作用是**确保 AI 模型在特定 Harness 的语境下行为得当**。不同的 Harness 可以用完全不同的 System Prompt 让同一个模型展现出截然不同的"性格"和能力侧重。

**举例**：OpenClaw 的 System Prompt 可能是"你是一个友好、有帮助的家庭助手"；Pi 的 System Prompt 则可能更极简、更像一个干净的空白画布让用户自己塑造。

### 4.2 Tools（工具集）

**定义**：Tools 是 Harness 提供给模型"调用"的一系列代码能力。

Harness 不仅描述工具有什么功能，还提供工具本身的代码实现。常见工具包括：

| 工具类型 | 功能描述 |
|---------|---------|
| WebSearch | 让模型搜索网络获取最新信息 |
| WriteCode | 让模型编写并执行代码 |
| ComposeEmail | 让模型撰写并发送邮件 |
| FileSystem | 让模型读写本地文件 |
| Browser | 让模型控制浏览器执行操作 |

**关键设计原则**：Harness 通常**不规定**模型何时以及如何使用工具。它只是：
1. 清晰地描述工具是什么
2. 提供工具的可调用接口
3. 把"何时调用、调用哪个"的决定权完全交给 AI 模型本身

这是一个微妙但重要的设计选择——它让 Harness 成为**环境提供方**，而不是**决策者**。

### 4.3 Agentic Loop（代理循环）

这是 Harness 最核心的概念，也是理解 AI Agent 如何"真正工作"的关键。

#### 4.3.1 什么是 Agentic Loop

Agentic Loop 是 AI 模型在 Harness 环境中**自主决策循环执行**的框架。模型不是一次性给出答案就结束，而是：

1. **理解请求**（理解用户的 prompt）
2. **规划行动**（决定需要调用什么工具）
3. **执行工具**（实际调用工具）
4. **评估结果**（检查工具返回的结果是否满足需求）
5. **决定是否继续**（如果结果不够，继续调用工具或换工具）
6. **产出最终结果**（满意后调用最终交付工具）

#### 4.3.2 具体例子：学校排名调研

Earendil 给出了一个极具说明性的例子——让 Agent 比较本地小学的排名和考试成绩并给出建议。

假设 Harness 内置了三个工具：WebSearch、WriteCode、ComposeEmail，交互媒介是 Email。用户发邮件说："帮我比较 A 片区和 B 片区的实验小学排名和考试分数，给出选校建议。"

Agent 的工作流程如下：

```
第1步：理解请求
────────────────
模型理解"实验小学"、"A片区/B片区"、"排名和考试分数"这些概念

第2步：搜索信息
────────────────
模型构造搜索查询，从网上抓取最新的学校排名和考试数据
　↓
第3步：评估搜索结果
────────────────
模型在 Harness 环境中review搜索结果
发现数据不够完整或不相关
→ 自主决定再次搜索

第4步：数据分析
────────────────
模型调用 WriteCode 工具（写代码）
生成电子表格，处理数据，格式化结果
　↓
第5步：评估中间结果
────────────────
将电子表格与原始请求对比
如果数据仍不满足，继续搜索或修正分析
→ 必要时"循环"回第2步

第6步：撰写报告
────────────────
模型调用 ComposeEmail 工具
将建议写入邮件正文，附上电子表格附件
　↓
第7步：最终确认
────────────────
模型review自己写好的邮件和附件
确认无误后发送

第8步：用户收到邮件
────────────────
几秒内，用户收到一封包含建议摘要的邮件
正文是分析结论，附件是详细的电子表格
```

这就是一个完整的 Agentic Loop——模型在 Harness 环境中**自主循环、直到自我判断任务完成**。

#### 4.3.3 Loop 的意义

Agentic Loop 的存在意味着：**AI Agent 不是"问答机"，而是"任务执行者"**。它会：
- 自主判断是否需要更多信息
- 自主选择使用哪个工具
- 自主决定何时迭代、何时收尾

这与传统 AI 对话（你问一句我答一句）有本质区别。Agentic Loop 让 AI 可以完成复杂的多步骤任务，而不仅仅是回答问题。

### 4.4 Translation Layer（翻译层）

#### 4.4.1 什么是翻译层

Translation Layer（翻译层）是让 Harness 能够与**不同 AI 模型**配合工作的关键组件。

它负责：
1. 将 Harness 的标准接口翻译成特定模型的 API 格式
2. 将特定模型的输出翻译回 Harness 的标准格式
3. 允许在同一个 Agentic Loop 中根据任务需求**动态切换不同模型**

#### 4.4.2 为什么翻译层如此重要

**权力转移**：翻译层是把力量从 AI 实验室转移到终端用户手里的关键机制。

如果没有翻译层：
- 你用 Anthropic 的应用，就只能用 Claude
- 你用 OpenAI 的应用，就只能用 GPT
- 你是 AI 实验室的"用户"，不是真正的主人

有了翻译层：
- 你可以把自己的 Harness 接到 Anthropic、OpenAI 或任何开源模型上
- 你可以在同一个任务里让 Claude 处理推理、GPT 处理生成、开源模型处理简单任务
- 你可以用不同模型的结果对比成本和效果

**用户主权的实现路径**：翻译层意味着用户可以选择"用哪个模型"，而不是被绑定在某个 AI 实验室的应用里。Harness 是用户拥有的，模型是从外部调用的——这个主从关系是 Harness 哲学的核心。

#### 4.4.3 一个具体场景

回到前面的学校调研例子。用户可以让同一个 Harness：
- 同时向 OpenAI 模型、Anthropic 模型、开源模型发送同样的请求
- 收到三个不同的回复
- 在同一个邮箱里比较三个版本的结果、成本和质量
- 而不是分别打开三个 App，分别登录，分别保存记录

这正是 Harness 带来的自由：**工具和数据属于你，选择权属于你**。

## 五、开源与用户自主权：Harness 的政治学

### 5.1 为什么 Harness 必须是开源的

Earendil 指出了 AI 基础设施的一个关键矛盾：

> 第一个流行的 Agent Harness 是 Claude Code，但它并不是为了提供"模型无关的翻译层"而设计的——它是为了让你在自己的电脑上用 Claude 模型写代码而构建的一个应用程序。

Claude Code 的问题是：它把用户绑定在了 Claude 模型和 Anthropic 的生态里。你无法轻易换模型，无法轻易把工作迁移到其他 Harness。

真正让 Harness 发挥"用户自主权"价值的前提是：**开源 + 中立**。

### 5.2 Pi 的实践：让用户真正"拥有"自己的 Harness

Earendil 在文章中详细描述了 Pi 的设计哲学：

- **最小化**：Pi 的 System Prompt 非常短，工具集非常精简，开箱即用、尽量不挡路
- **可扩展**：用户可以修改 System Prompt、设计扩展包（Extensions）、调整工具集
- **社群共建**：Pi 用户已经共享了超过 **5,000 个扩展包**
- **完全本地**：Pi 运行在你自己的笔记本电脑上，不依赖任何云服务
- **开源**：用户可以审查代码、修改代码、重新分发代码

这意味着：
- Pi 是一个用户**拥有**的工具，不是一个用户**租用**的服务
- 用户的"AI 能力"不依赖于某个公司的商业决策
- 用户的所有对话历史都保存在本地，不在 AI 实验室的服务器上

### 5.3 更大的图景：对抗 AI 权力的工具

Earendil 在文章结尾说出了更深层的愿景：

> 许多人对越来越大、越来越强势的 AI 公司感到担忧。一些人可能会选择完全回避 AI。
>
> 我们 Earendil 相信，我们可以**通过精心制作软件和开放协议来增强人类的主体性**，跨越分歧和无知，培养持久的快乐和理解。
>
> 我们不会通过忽视今天存在的技术来实现这一点，而是**以清醒的头脑和坚定的掌控来驾驭它们**：确保我们挥舞锤子，而不是锤子挥舞我们。

这段话的潜台词是：**与其放弃 AI，不如掌握 AI 的缰绳**。Harness 就是那根缰绳。

## 六、设计哲学：Harness 作为用户自主权的载体

综合 Earendil 的原文和 Pi 项目的实践，Harness 的设计哲学可以归纳为以下几个核心原则：

### 6.1 工具中立（Tool Agnosticism）

好的 Harness 应该对模型保持中立。用户选择用哪个模型是用户的权利，Harness 应该提供这个选择，而不是替用户做决定。Pi 支持 OpenAI、Anthropic 以及各种开源模型的接入，正是这一原则的体现。

### 6.2 用户主权（User Sovereignty）

用户应该拥有并控制自己的 Harness，而不是租用 AI 实验室提供的服务。这意味着：
- 本地运行，数据不离开用户设备
- 开源代码，用户可审查、可修改
- 会话记录保存在用户本地，而非云端

### 6.3 开放扩展（Open Extensibility）

Harness 的工具集和系统提示词应该可以被用户自由扩展。Pi 的 5,000+ 扩展包证明了：当用户被允许扩展工具时，生态的丰富程度远超平台方的预期。

### 6.4 人在回路（Human in the Loop）

虽然 Agentic Loop 允许模型自主循环，但 Harness 设计应该始终保证**人在回路**：
- 模型的所有工具调用都在用户可见的上下文里发生
- 用户可以随时干预、修改或终止 Agent 的行为
- 最终交付物（邮件、文件、代码）由用户决定是否使用

### 6.5 最小化默认（Minimal Default）

Pi 的 System Prompt 非常短，工具集非常精简。这是一种**有意识的克制**：默认配置越少，用户重新塑造的空间越大。"少即是多"在 Harness 设计中不是美学选择，而是哲学选择。

## 七、观点总结与启示

### 观点 1：Harness 是 AI Agent 的"操作系统层"

模型是计算资源，Harness 是调度和使用这些资源的操作系统类组件。就像 Linux 不关心你跑什么应用（只要你遵循接口），好的 Harness 不关心你用什么模型（只要你通过 Translation Layer 接入）。

### 观点 2：用户应该拥有"工作台"而不是"工具"

当前大多数 AI 产品（Claude App、ChatGPT、Cursor）本质上是**应用**——用户在使用 AI 实验室构建的产品。Harness 的理念是：用户应该拥有自己的**工作台**，工作台上面跑什么模型是可选的。应用会过时，工作台永远是你的。

### 观点 3：开放协议 > 封闭平台

如果每个 AI 实验室都只提供自己的封闭 Agent，用户就会被锁定。开源、中立、可互操作的 Harness 协议，是防止 AI 权力集中的技术基础。Earendil、OpenClaw、OpenCode 等项目正在建立这种开放协议的基础设施。

### 观点 4：Agentic Loop 是 AI 从"回答问题"到"完成任务"的分水岭

传统 AI 对话的局限在于"你问一句我答一句"。Agentic Loop 让 AI 能够自主规划、自主迭代、自主交付——这是 AI 从"智能问答引擎"到"自主代理"的核心跨越。

### 观点 5：本地优先是用户数据主权的唯一可靠保障

云端存储的 AI 会话记录在商业上不可持续（AI 实验室可以随时访问、删除或变现），在政治上不可靠（取决于公司政策和国家法规）。纯文本文件的本地存储，是用户对 AI 会话拥有完整主权的唯一技术基础。

### 观点 6：翻译层的竞争将决定 AI 生态的权力格局

谁控制了翻译层，谁就控制了用户的选择权。如果翻译层是开源的、中立的，权力在用户手里；如果翻译层是闭源的、商业的，权力在平台手里。这是一个尚未被广泛认识的战略高地。

### 观点 7：开源社区是 AI 民主化的希望

Claude Code 开启了 Agent Harness 的时代，但它选择了封闭和绑定。Pi、OpenClaw、OpenCode 等开源项目正在重新把这个权力还给用户。5,000+ 扩展包的社群生态证明：**当用户被赋予真正的控制权，他们能做的事情远超平台方的想象。**

## 八、项目速览：Pi

Pi 的核心设计理念是：**给你一个干净的空白画布，让你按照自己的意志塑造 AI 的行为**。默认情况下它什么都不做，但你可以把它塑造成任何你想要的样子。

## 九、结语：握住缰绳

Earendil 在文章结尾写道：

> 我们不会通过忽视今天存在的技术来实现（增强人类主体性），而是通过**以清醒的头脑和坚定的掌控来驾驭它们**：确保我们挥舞锤子，而不是锤子挥舞我们。

这句话值得每个 AI 时代的参与者认真思考。

我们正在快速进入一个 AI 无处不在的世界。在这个世界里，有两种选择：

1. **成为 AI 的用户**——在 AI 实验室建造的应用里租用自己的"AI 能力"，接受锁定、数据被收集、选择权被剥夺
2. **成为 AI 的驾驭者**——拥有自己的 Harness，掌控自己的工具和数据，以清醒的头脑决定何时、如何使用 AI

Harness 就是那根缰绳。它不是 AI 本身，但它决定了谁能控制 AI、如何控制 AI、为谁服务。

握住它。
