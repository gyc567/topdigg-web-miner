# 435 星的 article2media：真正值錢的不是 AI 會寫稿，是它把「感覺不對」翻譯成腳本能攔的指標

**結論先行：** GitHub 上有個 435 星、65 個 fork 的開源專案叫 article2media，做的是把一篇文章或一條影片，一鍵變成能直接發的小紅書圖文、雜誌長圖、公眾號排版和 AI 配音的口播影片。

它有 10 個能力、12 套主題、每種產出自動驗收（acceptance），零 npm 依賴，只要 Node 22 和一個 Chrome。

但如果你只把它當成「又一個 AI 寫作工具」，你會看錯它的重點。

**這個專案最值得老闆抄走的，不是那 10 個能力，是它的驗收紀律：把「太急了」「一直在閃」「這個主題不好」這種模糊回饋，翻譯成 4.5 字/秒、0 處閃斷、版面 0 個錯誤這種機器能卡的指標。**

這套東西可以直接搬進你自己的內容團隊、你的 AI 工具鏈、你交付給客戶的 SOP。我把它拆給你看。

---

## 一、專案說明：它到底是什麼

article2media 是一組開源的 Claude Code / Codex Skill，同時也是一個 Claude Code 外掛。

作者是 LeiLiu（GitHub：threerocks），MIT 授權，2026 年 11 月 8 日建倉，一週內衝到 435 星。倉庫是 JavaScript，77 個 .mjs 檔案，約 12400 行程式碼。

它的輸入是：

- 文章：X（Twitter）長文貼文、討論串、任意網頁、微信公眾號文章、本地 Markdown，或者你直接貼上的正文；
- 影片：抖音、YouTube、B 站連結，本地影片或音訊，`.srt` / `.vtt` 字幕。

影片先被轉成逐字稿文章，後面走的流程和文章完全一樣。

它的輸出是十二種形態：

| 產出 | 規格 | 適合發在哪 |
|---|---|---|
| 總結長圖 | 1080 寬單欄手機版，1 到 4 頁；加 `--wide` 出 1200 寬雙欄雜誌版 | 微信、朋友圈、微博 |
| 卡片組 | 小紅書 3:4（1080×1440），另有 4:5、1:1、9:16；6 種封面版式，可穿插整頁金句、大數字、整頁圖 | 小紅書、IG、抖音圖文 |
| 封面多版本 | 同一篇出幾版封面，不同版式或不同鉤子 | 挑封面、分開發布比效果 |
| 輕量形態 | 一頁看完、金句圖、問答卡 | 高頻更新、給整組卡片引流 |
| 公眾號排版 | 內嵌樣式、圖片內嵌，可直接貼進編輯器；另出 2.35:1 頭圖和 1:1 封面 | 公眾號 |
| 口播影片 | 1080×1920 直屏，逐字同步動畫，本地 AI 配音加字幕 | 抖音、影片號、小紅書影片 |
| 原文長圖 | 一字不改，只做排版 | 完整保留原文 |
| 原文卡片 | 全文按順序分頁成卡片 | 全文發小紅書 |
| 全文譯文 | 外文逐段譯成中文，結構逐塊對應 | 外文搬運 |
| 白板論證 | 一條縱向推理主幹：問題、前提、證據、矛盾、轉折、結論 | 看清作者怎麼得出結論 |
| 漫畫 | 黑白分鏡，角色前後一致 | 用故事講清一個機制 |

**關鍵設計是「能力獨立，組合自由」。** 十個能力每一個都是一個獨立的 skill，只靠工作目錄裡的檔案交接：`article.md`（原文）、`article.zh.md`（譯文）、`content.json`（改寫稿）、`rewrite.md`（改寫稿的文章形態）。

所以你可以只抓取、只翻譯、只排版，也可以把長圖、小紅書、公眾號一次做完。

## 二、詳細教學：從零跑通第一個產出

### 第 1 步：安裝

推薦用 Claude Code 外掛，一次裝好全部 11 個 skill：

```bash
claude plugin marketplace add threerocks/article2media
claude plugin install article2media@article2media
```

也可以用 skills CLI，同時裝給 Claude Code 和 Codex：

```bash
npx skills add threerocks/article2media -g -a claude-code -a codex -y
```

`-g` 是全域安裝（Claude Code 裝到 `~/.claude/skills/`，Codex 裝到 `~/.agents/skills/`），不加 `-g` 就只裝進當前專案。`-y` 跳過確認，`-l` 只列出不安裝。

手動安裝的話注意：**倉庫根目錄不是 skill 目錄，要同步整個 `skills/` 目錄**。

```bash
git clone --depth 1 https://github.com/threerocks/article2media.git ~/code/article2media
rsync -a ~/code/article2media/skills/ ~/.claude/skills/
rsync -a ~/code/article2media/skills/ ~/.agents/skills/
```

只拷單個能力而旁邊沒有 `article2media` 時，腳本會直接報「找不到共享引擎」，因為所有能力的腳本都在 `article2media/engine/` 裡。也可以用環境變數 `ARTICLE2MEDIA_ENGINE=/path/to/skills/article2media/engine` 指過去。

### 第 2 步：檢查環境

```bash
bash scripts/install.sh
```

這個腳本只告訴你缺什麼、怎麼裝，**它自己一個東西都不會下載**。

它會檢查：Node 22+ 和任意 Chrome / Chromium（必需）、ffmpeg（口播影片要）、Codex CLI 登入或 OpenAI / Gemini 的 key（AI 插畫和漫畫要）、Apple Silicon 加 mlx-audio 加 VoxCPM2（本地配音）、mlx-whisper（逐字對齊和無字幕影片轉寫）、yt-dlp（YouTube 和 B 站字幕）。

在中國大陸網路下，主題字型預設從 Google Fonts 和 jsDelivr 載入，經常拉不動。這時候跑一次：

```bash
node skills/article2media/scripts/fonts.mjs
```

約 65 MB，把主題字型鏡像到本地快取，之後所有出圖不再連網。渲染過程本身從不下載任何東西。

### 第 3 步：在 Claude Code 裡呼叫

一鍵組合用總入口：

```
/article2media https://x.com/thedankoe/status/2117664712532123680
/article2media https://example.com/post 小紅書
/article2media ./my-essay.md 公眾號
/article2media https://x.com/… 翻譯成中文發公眾號
/article2media https://x.com/… 長圖、小紅書、公眾號都要
/article2media https://www.bilibili.com/video/BV… 小紅書
/article2media links.txt 批次，每篇出小紅書和長圖
```

也可以直接用單個能力（外掛裡名字帶 `article2media:` 前綴）：

```
/article2media:wechat-layout ./my-essay.md
/article2media:image-cards ./my-essay.md 原文卡片
/article2media:video-transcript https://www.bilibili.com/video/BV…
/article2media:article-translate article2media-out/x-…/article.md
```

產出寫在當前目錄的 `article2media-out/<slug>/` 下。

### 第 4 步：不經過 Claude，直接跑腳本

每個能力都有自己的腳本入口，不依賴 Claude 也能跑：

```bash
K=skills
node $K/article-fetch/scripts/fetch.mjs "https://x.com/…/status/…"
node $K/video-transcript/scripts/transcribe.mjs "https://www.bilibili.com/video/BV…"
node $K/article-rewrite/scripts/check.mjs <slug>/content.json
node $K/article-rewrite/scripts/export.mjs <slug>/content.json
node $K/long-image/scripts/long.mjs <slug>/content.json --theme all
node $K/image-cards/scripts/cards.mjs <slug>/content.json --ratio 3:4
node $K/image-cards/scripts/cards.mjs <slug>/content.json --covers
node $K/wechat-layout/scripts/wechat.mjs <slug>/article.md --theme quiet
node $K/explainer-video/scripts/video.mjs make <slug>/video/video.json
node $K/logic-whiteboard/scripts/whiteboard.mjs <slug>/article.md
node $K/article-comic/scripts/comic.mjs make <slug>/comic.json
```

長圖和卡片還支援 `--out 目錄`、`--page 1,3`、`--scale 2`、`--format jpeg --quality 90`、`--max-height 7600`、`--brand brand.json`、`--issue 13`、`--html-only`。公眾號另有 `--title`、`--digest`、`--cover-title`、`--kicker`、`--hero`。

### 第 5 步：批次處理和發布閉環

批次模式下，把連結寫進一個文字檔：

```bash
node $K/article2media/scripts/batch.mjs init links.txt --name 本週 --spec "cards:3:4,long,wechat"
node $K/article2media/scripts/batch.mjs next 本週
node $K/article2media/scripts/batch.mjs checklist 本週
```

`batch.mjs init` 負責抓取和建看板，Claude 按 `next` 一條條做，做完一篇再做下一篇。抓取失敗、正文太短、疑似付費牆的會被單獨列出來等你確認，不會卡住整批。

做完每篇有一份發布清單 `publish.md`：上傳順序、備選標題、正文文案、標籤、平台硬性限制檢查（小紅書標題不超過 20 字、正文不超過 1000 字、圖不超過 18 張；公眾號標題不超過 64 字、摘要不超過 120 字）。

發布之後把資料告訴它：

```bash
node $K/article2media/scripts/stats.mjs add <slug> --platform xhs --views 1200 --likes 80 --saves 150
node $K/article2media/scripts/stats.mjs report
```

報告會按平台對比各主題、各封面版式的收藏率和互動率。**樣本不足 5 條的組會明確標註「樣本不足，僅供參考」**，不會讓你憑兩三篇貼文的差別下結論。

### 第 6 步：自測（如果你在本地改程式碼）

```bash
node tests/run-all.mjs --quick
node tests/run-all.mjs
node tests/unit.mjs
node tests/visual.mjs
node tests/eval-score.mjs <目錄> --ref <目錄>
```

`run-all.mjs` 是自測矩陣：4 篇範例文章乘 7 種版式乘 12 套主推主題，一共 504 次渲染，每次都要求 0 個版面錯誤。`visual.mjs` 是像素級視覺回歸，`eval-score.mjs` 是換模型時的品質評分。

## 三、三條路徑：原文、總結、翻譯

這是整個專案最關鍵的設計決策，也是老闆最容易抄走的一條。

很多工具只有一個「AI 總結」按鈕，你想要原文它也沒轍。article2media 把這件事做成了一個明確的分流規則。

| 你說的 | 走哪條路 |
|---|---|
| 排版、原文、全文、一字不改、原樣、`-f` | 原文路徑：直接交給呈現能力 |
| 總結、提煉、改寫、重點、乾貨 | 改寫路徑：先 `article-rewrite`，再呈現 |
| 翻譯、譯成中文、搬運外文 | 翻譯路徑：先全文翻譯，再按原文路徑呈現 |
| 都沒說，要長圖或卡片 | 預設改寫 |
| 都沒說，要公眾號 | 預設原文排版 |
| 走原文路徑，但原文語言和目標語言不同 | 先翻譯，再原文排版 |

**這裡有個很反直覺的預設值：公眾號預設不總結。**

也就是說，你把別人的文章丟給它說「發公眾號」，它給你的是一字不改的原文排版。只有你明確說「總結」，它才改寫。

**對老闆的意義：** 團隊裡做內容，最容易出的事故不是排版醜，是「AI 幫我總結一下」這句話。總結一次，作者的原意就掉一層，掉到第三層就變成了成功學的空話。把預設設成「不總結」，等於給團隊裝了一道預設不越權的門。

## 四、設計哲學：六條硬規矩

### 1. 內容與風格分離

主題只是一組 CSS 變數加少量結構覆寫。換主題只需重新渲染，不重寫內容。

這意味著同一份 `content.json` 可以渲染成 12 套主推主題中的任何一套，也可以同時出長圖、卡片和公眾號。

### 2. 零 npm 依賴

只用 Node 22 內建的 WebSocket 和 fetch，直接驅動本機已有的 Chrome。不用 puppeteer，不用 playwright，不用任何需要下載瀏覽器的套件。

### 3. 圖裡不放字

這是整個專案最聰明的一個決定。

AI 畫圖最大的問題之一是中文字會畫錯。article2media 的做法是：**生成的圖片裡不含任何文字**，所有文字，包括標題、圖表標籤、漫畫對白、影片字幕，都用 HTML 排版，再由無頭 Chrome 截圖。

這帶來兩個後果：字永遠不會亂碼，隨時能改；更重要的是，**程式能把渲染出來的文字讀回來檢查**。

### 4. 能力探測，不強求

出圖（Codex CLI 到 OpenAI 到 Gemini）、本地配音（VoxCPM2 到 edge-tts 到系統語音）、逐字對齊、影片轉寫，全部都是先探測再選用。缺了就降級或者明確告訴你缺什麼，**從不自動下載或安裝任何東西**。

### 5. 模型做判斷，腳本做測量

Claude 負責理解和寫作：規劃結構、改寫標題、決定哪一節配柱狀圖、哪一節配流程圖、核對數字。它產出的是一份只有內容、沒有任何樣式的 `content.json`。

排版、截圖、配音、對齊、混音、驗收，全部交給腳本。

### 6. 合規前置

6 款隨包音色全部只憑文字描述設計，不模仿任何真人。複製音色只留在本機個人音色庫，使用時審片會提醒確認授權。成片首幀和 MP4 中繼資料都帶 AI 生成標識，每張圖都署原文出處。

關於聲音，專案的結論很清醒：**用 AI 把複製來的聲音再合成一遍，不算新聲音。** 依據是《民法典》第 1023 條第二款（對自然人聲音的保護參照適用肖像權保護的有關規定），以及 2024 年 4 月北京互聯網法院的判例（一般聽眾能從 AI 合成聲音裡認出是誰，這個聲音就同樣受保護）。所以音色庫按版權分成兩層：公開音色隨專案分發，本機個人音色庫只供本人製作。

## 五、自動驗收：每種產出都有自己的檢查器

這是這個專案和「讓 AI 直接出圖」最本質的差別。

AI 生成的東西最怕「看起來差不多」。所以每種產出都有自己的驗收，不合格直接報錯退出，而不是交給人用眼睛去找。

| 產出 | 檢查項 |
|---|---|
| 改寫稿（和原文比對） | 原文裡找不到的數字、別人的文章寫成第一人稱、原文配圖一張沒用、原文的具體數字和人名工具名用上了多少、中文裡夾雜英文普通詞；正文太薄、資料面板和整頁卡偏少、大數字和標題對不上、同一句話重複、「該避開什麼」寫成了該做的事、頁尾寫了製作過程、沒寫備選標題 |
| 總結長圖、卡片、封面 | 文字溢出、截斷、元素重疊、單字成行、頁面過高、圖片載入失敗、字型按家族檢查、卡片溢出、圖表過小、自動省略了什麼 |
| 原文長圖、原文卡片、公眾號排版 | 原文塊帳本逐塊比對（卡片跨卡拼接）、解析覆蓋、來源 SHA-256 鎖定、實際字型、卡片溢出、張數上限、公眾號殘留樣式、標題長度 |
| 全文翻譯 | 塊數與結構逐塊對應、程式碼與圖片原樣、疑似未翻譯或漏譯、數字是否遺失 |
| 白板論證 | 論證帳本：每段原文都要進入某一步，或寫明省略理由 |
| 漫畫 | 對白、旁白和音效字不越出分格 |
| 口播影片 | 安全區、首句不超過 5 秒、首個畫面不超過 2.5 秒、畫面靜止不超過 5 秒、旁白語速、字幕停留與閃斷、成片逐幀字幕丟幀、逐句配音品檢、響度 |
| 發布清單 | 小紅書標題不超過 20 字、正文不超過 1000 字、圖不超過 18 張；公眾號標題不超過 64 字、摘要不超過 120 字 |

每個腳本都以 `✓ / ⚠ / ✗` 逐行報告，最後彙整成「版面檢查：N 個錯誤，M 個提示」。**只要有錯誤，腳本就以非零碼退出。**

其中「原文塊帳本」是最狠的一道：每個可見文字塊都登記進帳本，渲染後在瀏覽器裡逐塊讀回比對。**改一個字、調一次順序、漏一塊或重複一塊，都會失敗。**

## 六、歸納總結：8 條觀點，以及它們對老闆的含義

### 觀點 1：這個專案的本質是「驗收系統」，不是「生成系統」。

十個能力只是皮，驗收才是骨。生成能力誰都能接模型，驗收紀律需要幾千次迭代。

**對老闆：** 評估任何 AI 工具，先看它「怎麼知道自己做錯了」。答不出來的，產出品質全靠你肉眼兜底，一個團隊一天只能產三條。

### 觀點 2：把「感覺不對」翻譯成指標，是唯一能規模化的高品質手段。

專案的作者記下過一句回饋：「做解說整體語速都不能太急，這個是大忌。」他們沒有只改程式碼，而是測了參考音檔的語速，定下標準約 4.5 字/秒，單段超過 5.2 字/秒判為偏快，偏快的句子換種子重新生成，還快就在保持音高的前提下放慢。改完同一條影片的旁白從每秒 5.97 字降到 4.27 字。

**這條規則現在寫進了審片腳本。下次誰再改程式碼，機器會替他們記住那句「太急了」。**

**對老闆：** 你團隊裡那些「這裡不夠高級」「這個感覺怪」的回饋，如果不能變成數字，就永遠是玄學，永遠靠某個人在盯。把它們一條條量化，是內容工業化裡最便宜的一步。

### 觀點 3：機器檢查必須有，人眼也省不掉。

專案做新中式主題時選了一款好看的標題字型，版面檢查全部通過，可人一看成品，所有的「回」字都是一個實心黑塊。字型檔案本身就是壞的，程式偵測不出來。

從那以後每款新字型都要先用「回圖國圓品器噩」這幾個字試一遍。

**對老闆：** 你的品檢流程要同時有自動檢查和人眼抽檢。只做自動檢查，會漏掉「技術上合格但人類看著難受」的那一類；只做人眼檢查，產能上不去。

### 觀點 4：功能能做，不代表應該做。

背景音樂試了三次：線上免版權曲庫、程式合成的和弦鋪底、本地 AI 作曲（光模型就 11 GB）。最後一個都沒留。

原因很簡單：太重了，而且平台 App 裡加背景音樂只要幾秒鐘。

**對老闆：** 這是我在這整個專案裡看到的最值錢的一條取捨。團隊做 AI 工具鏈最容易犯的錯，是「能加的功能都加上」。每加一個功能，你就多一份維護成本、多一個失敗點、多一個使用者不知道怎麼用的入口。**減法比加法難，因為加法有人誇，減法只有你受益。**

### 觀點 5：合規必須在第一天就做對，事後補的成本遠高於一開始就做對。

**對老闆：** 你的 AI 工具鏈如果涉及客戶資料、素材版權、聲音肖像權，事後整改的代價是當初寫對規則的十倍。這條適用於你給客戶交付的所有 AI 方案。

### 觀點 6：換模型這件事，要測，不要猜。

專案自帶換模型回歸測試：用 3 篇文章對比 Haiku 和 Opus 的「改寫到小紅書卡片」。

結果是：規則層面（客觀分）Haiku 從 Opus 的 70% 到 95% 提到 100% 以上，規則都能守住；讀者層面（盲評，不知道哪組是誰做的，三輪換位）Haiku 是 Opus 的 85% 到 91%，平均約 88%。差距主要在理解：漏掉原文的核心方法、把兩個相近的數字混為一談、配圖放錯節。

**對老闆：** 這就是「小模型寫稿 + 大模型審一遍」的現實天花板，88%。別指望換個便宜模型就省錢，得先測你在乎的那個維度。

### 觀點 7：預設「不總結」，是比預設「更聰明」更重要的設計。

**對老闆：** 你給客戶交付 AI 工作流時，第一件事應該是把預設行為調成最保守的那個。使用者主動要什麼再給什麼。

### 觀點 8：一個功能做得好的標誌，是它有閉環。

出圖只是一半。圍繞「發出去並且有效」，專案做了一整套：封面多版本、品牌包、輕量形態、批次、發布清單、發布資料記錄與對比報告。資料只存在你本機，攢夠樣本後，選主題指南會把它當作兩個同樣合適的選項之間的裁決依據。

**對老闆：** 這是內容和投放之間那條斷鏈。絕大多數內容團隊做了內容就扔進發布器，再也沒有回頭看資料，所以你永遠不知道哪種做法有效。**閉環不需要大系統，先記 10 條資料就夠開始。**

## 七、幾個必須說清楚的邊界

- **本地配音**：VoxCPM2 目前只在 Apple Silicon 上執行，其他機器用 edge-tts 或系統語音。
- **出圖**：AI 插畫和漫畫需要出圖能力，Codex CLI 登入（ChatGPT 帳號就行）或者 OpenAI、Gemini 的付費 key。
- **背景音樂**：影片目前沒有背景音樂，得自己在平台 App 裡加。
- **X 抓取**：依賴 FxTwitter，它不可用時需要手動貼上正文。
- **影片輸入**：本地語音辨識需要 Apple Silicon。YouTube 在有的網路下要求登入確認，抖音有時要瀏覽器 cookie，這時候要嘛同意複用瀏覽器狀態（`--cookies-from-browser chrome`），要嘛把影片存到本地再傳檔案。
- **聽感**：音色和語速的最終判斷仍然要靠人耳。
- **Codex 沙箱**：預設不允許啟動 Chrome，出圖會報「Chrome 意外結束」，需要給這一步放行。

還有一個細節值得記：影片轉文字時，**機器翻譯的字幕軌和 B 站彈幕都不能用**。前者不是說話人的原話，後者是觀眾評論。文字來源按可信度排序是：人工字幕、平台按原語言產生的自動字幕、本地 Whisper 辨識。

## 八、如果你只抄三件事

### 第一抄：給每一個 AI 產出配一個「不通過就非零退出」的檢查器。

哪怕只有五條規則，也比全靠人眼強。

### 第二抄：把團隊口頭回饋裡最常出現的那 3 到 5 條感覺，變成可測量的數字。

「太急了」變成 4.5 字/秒，「一直在閃」變成 0 處閃斷，「太長了」變成 15 秒。

### 第三抄：預設行為調保守。

不總結、不潤色、不腦補。使用者主動要才給。

這三條不需要你先裝 Node 22、不需要你先有 MacBook Pro、不需要你先把 Codex 登入好。**今天下午就能在你自己的內容流水線裡試第一條。**

這個專案本身，我把它理解為一次誠實的實驗：它證明了一件事，**AI 內容生產真正稀缺的不是產能，是判斷力**。十個能力誰都能做，把判斷力寫成規則並且讓機器替你盯著，才是護城河。
