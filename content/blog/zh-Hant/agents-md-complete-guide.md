## 引言

在 AI 編程助手日益普及的今天，如何讓這些工具真正理解你的專案、遵循你的團隊規範，成為提升開發效率的關鍵。AGENTS.md 作為一種開放標準，正在被 Cursor、Copilot、Codex、Claude Code 等主流 AI 編程工具廣泛支持。本文將深入探討 AGENTS.md 的設計哲學與最佳實踐。

## 為什麼 AGENTS.md 至關重要

### 大型設定檔案的困境

現代大型語言模型（LLM）雖然在能力上不斷突破，但在遵循指令方面存在固有限制。研究表明，即使是前沿的 LLM，也只能一致地遵循約 **150-200 條**指令。當 AGENTS.md 檔案過於臃腫時，會出現以下問題：

- **token 浪費**：每個 token 都會在每次請求時加載，冗餘內容直接增加成本
- **遵循度下降**：指令越多，模型越容易忽略或誤解重要規則
- **響應變慢**：更長的上下文意味著更慢的首次響應時間

### 臃腫檔案的真實代價

一個典型的反面案例是包含數千行「最佳實踐」的 AGENTS.md 檔案。這樣的檔案：
- 包含大量從未被執行的指令
- 混合了不同場景的衝突規則
- 難以維護和更新
- 成為新團隊成員的理解障礙

## AGENTS.md vs CLAUDE.md：關鍵區別

雖然名稱相似，但這兩個檔案有不同的定位：

| 特性 | AGENTS.md | CLAUDE.md |
|------|-----------|-----------|
| **標準** | 跨平台開放標準 | Claude Code 專用配置 |
| **支持工具** | Cursor、Copilot、Codex、Claude Code 等 | 僅 Claude Code |
| **設計目標** | 通用專案指導 | Claude 特定優化 |
| **生態定位** | 開放標準，社群驅動 | 廠商鎖定（Anthropic） |

**核心要點**：如果你希望專案配置能被多種 AI 編程工具使用，AGENTS.md 是更好的選擇；如果你專注於優化 Claude Code 的體驗，CLAUDE.md 提供更精細的控制。

## 根檔案核心內容

一個高效的根 AGENTS.md 檔案應該保持精簡，僅包含最重要的資訊。

### 必須包含的三大要素

#### 1. 一句話專案描述

```markdown
# 專案名稱

一個高性能的加密貨幣交易機器人，採用 Rust 建構
```

這讓 AI 助手在首次接觸專案時就能建立正確的上下文。

#### 2. 套件管理器指示

```markdown
## 套件管理器

- 使用 `poetry` 管理 Python 依賴
- 使用 `cargo` 管理 Rust 依賴
```

如果專案使用非標準工具鏈，這一點尤為重要。

#### 3. 非標準建構命令

```markdown
## 建構命令

- 類型檢查：`pytest --type-check`
- 建構：`make build TARGET=release`
- 測試覆蓋率：`make coverage`
```

避免讓 AI 猜測或使用錯誤的建構命令。

### 應該避免的內容

**不要在根檔案中包含：**
- 詳細的程式碼風格規範（移到單獨檔案）
- 特定框架的使用指南（除非是專案核心）
- 完整的目錄結構說明（這些資訊會快速過時）

## 漸進式披露原則

「漸進式披露」（Progressive Disclosure）是設計高效 AGENTS.md 的核心原則。其核心思想是：**只在需要時加載相關規則**。

### 目錄結構示例

```
project/
├── AGENTS.md              # 根檔案：全域規則 + 連結
├── docs/
│   ├── TYPESCRIPT.md      # TypeScript 特定規則
│   ├── TESTING.md         # 測試規範
│   ├── API.md             # API 設計指南
│   └── DEPLOYMENT.md      # 部署流程
└── packages/
    ├── core/
    │   └── AGENTS.md      # 核心模組專用規則
    └── cli/
        └── AGENTS.md      # CLI 工具專用規則
```

### 如何連結子檔案

在根 AGENTS.md 中使用清晰的連結：

```markdown
## 詳細文檔

- [TypeScript 規範](docs/TYPESCRIPT.md)
- [測試指南](docs/TESTING.md)
- [API 設計](docs/API.md)
```

### 漸進式披露的優勢

1. **降低認知負擔**：AI 和人類都只需要關注當前任務相關的規則
2. **提高遵循度**：更少的指令意味著更高的執行準確率
3. **易於維護**：獨立檔案可以獨立更新，不影響其他規則
4. **更好的隔離**：減少規則之間的衝突和依賴

## Monorepo 支持

AGENTS.md 的另一個強大特性是支援多層級配置。

### 合併規則

當不同目錄中存在 AGENTS.md 檔案時，AI 助手會自動合併它們：

- **根目錄 AGENTS.md**：全域規則、共享工具、通用規範
- **子目錄 AGENTS.md**：特定包的專門指導

### 實踐示例

假設你有以下結構的 monorepo：

```
monorepo/
├── AGENTS.md              # 專案總體說明
├── packages/
│   ├── shared/
│   │   └── AGENTS.md      # 共享庫規則
│   └── app/
│       ├── AGENTS.md      # 應用特定規則
│       └── docs/
│           └── FEATURES.md
```

子目錄的規則會繼承並擴展根目錄的規則，形成完整的上下文。

## 最佳實踐與常見陷阱

### 最佳實踐

#### 1. 使用強調詞提高遵循度

```markdown
IMPORTANT: 所有 API 響應必須包含錯誤碼
MUST: 提交前執行測試
NEVER: 不要直接提交到 main 分支
```

研究顯示，強烈的指令詞（如 IMPORTANT、MUST、NEVER）能顯著提高模型的遵循率。

#### 2. 保持精簡，突出重點

好的 AGENTS.md：
- 每個規則一句話
- 按優先順序排序
- 使用專案特有的術語

#### 3. 團隊 vs 個人偏好

| 類型 | 位置 | 示例 |
|------|------|------|
| 團隊規則 | 主 AGENTS.md | 程式碼審查流程、Git 規範 |
| 個人偏好 | 本地覆蓋檔案 | 編輯器設定、快捷鍵 |

#### 4. 定期審查和清理

每季度審查一次 AGENTS.md，移除：
- 不再適用的規則
- 從未被遵循的指令
- 與實際實踐衝突的規定

### 常見陷阱

#### 陷阱 1：過度文檔化

**錯誤示範**：
```markdown
## 程式碼風格

- 類名使用 PascalCase
- 方法名使用 camelCase
- 變數名使用 snake_case
- 常量全部大寫
- 私有方法以 _ 開頭
- ...
（持續 200 行）
```

**正確做法**：連結到 linter 配置或風格指南文檔。

#### 陷阱 2：記錄檔案結構

**錯誤示範**：
```markdown
## 目錄結構

src/
├── controllers/
│   ├── AuthController.php
│   └── UserController.php
├── models/
│   └── User.php
└── services/
    └── AuthService.php
```

**正確做法**：描述專案形態和能力，而非具體路徑。

#### 陷阱 3：包含過時資訊

檔案路徑、依賴版本、工具配置等資訊會快速過時。保持 AGENTS.md 高層次和原則性，避免具體的技術細節。

## 關鍵觀點總結

1. **保持精簡**：根 AGENTS.md 應在 150-200 行以內，包含核心指令
2. **漸進式披露**：將詳細規則移到單獨檔案，按需加載
3. **描述能力，而非結構**：說明專案能做什麼，而非檔案在哪裡
4. **使用強調詞**：IMPORTANT、MUST、NEVER 等詞提高遵循度
5. **跨平台考慮**：如需多工具支持，優先使用 AGENTS.md 而非專有配置
6. **定期維護**：持續清理過時的規則，保持檔案的生命力

## 結語

AGENTS.md 不僅僅是一個設定檔案，它是 AI 時代專案自我描述的語言。通過遵循「小而美」的設計原則，我們可以讓 AI 編程助手更高效地理解我們的專案，遵循我們的規範，最終成為真正得力的開發夥伴。

正確的 AGENTS.md 策略能夠：
- 減少 AI 的誤解和錯誤
- 加快開發速度
- 提高程式碼一致性
- 降低新成員的上手門檻
