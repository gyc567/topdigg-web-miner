# Tev 深度解析：用「潜在世界」造資料，用稠密獎勵訓長程智能體

> 論文：*Tev: Scaling Long-Horizon Agentic Environments with Dense Progress Rewards*
> 作者：Wenbo Hu、Shraman Pramanick、Krishna Kumar Singh、Nanyun Peng、Kai-Wei Chang、Yong Jae Lee（Adobe Research + UCLA）
> 論文主頁：https://arxiv.org/abs/2610.18868 ｜ HTML 版：https://arxiv.org/html/2610.18868v1
> 專案主頁：https://tev-agent.github.io/
> 模型權重：https://huggingface.co/gordonhu/Tev-27B ｜ https://huggingface.co/gordonhu/Tev-320B

## 引子：一個被資料卡死的領域

過去兩年，AI Agent 的能力曲線幾乎完全由「任務有多長」劃定。

短任務和中等任務是甜蜜區。SWE-Smith 有 5 萬個環境，TMAX-15K 有 1.46 萬個，CLI-Gym、SETA、Endless Terminals 各有幾千到上萬不等。這些資料集足夠大，訓練流水線足夠成熟，模型確實在進步。

但當你把任務時間尺度拉長到「數小時到數天」——真正的開放式數學問題、自動化機器學習研究、生產事故根因分析——整個領域撞上了一堵牆。

這堵牆由兩個缺口構成。

**第一個缺口是資料。** 長跨度任務只以人工編寫的評測集形式存在。Agents' Last Exam（ALE）和 Terminal-Bench（TB）裡的每一個實例，都需要專家投入數週時間。ALE-CM 全集只有幾十到幾百個題目，而且它們只能被用來評測，不能被用來訓練。這造成了一個極其尷尬的結構性矛盾：

> 智能體訓練語料很多，但都很短；長任務確實存在，但只是少量人工評測集。

中間那塊「大規模長跨度訓練資料」，是徹底空白的。

**第二個缺口是獎勵。** 就算你想造資料，長任務的獎勵是稀疏的。終局獎勵只在任務完成時才出現，而長任務上模型的通過率往往只有 5% 甚至更低。這意味著在 GRPO 這類組內相對的強化學習演算法裡，絕大多數採樣組全部失敗，優勢值處處為零，對梯度的貢獻完全是零。

論文用了一個非常具體的數字來說明這件事：如果任務通過機率 $p=0.05$、每組 $G=8$ 條 rollout，那麼 **66% 的採樣組被完全浪費**；當 $p=0.01$ 時，浪費率高達 **92%**。而這恰恰是訓練早期、策略最弱、最需要訊號的階段。

Tev 這篇論文做的事情，一句話概括就是：

> **從「已知正確答案的世界」反向造出任務，再用這個世界的真值給訓練的每一步打分。**

下面我們把它的核心思想、方法結構、實驗結論和可復現教程完整拆開。

## 一、核心思想：潛在世界優先（Latent-World-First）

### 1.1 與傳統流水線的根本分歧

目前主流的合成資料流水線大致是這樣的：讓語言模型生成一個任務描述，再生成對應的輸入檔案，再生成驗證器或測試用例。整個鏈條沒有任何一處存在「正確答案」——只有看起來合理的東西。

這種做法有三個眾所周知的問題：

1. **驗證器不可靠。** 生成的測試用例可能本身就寫錯了。
2. **任務與驗證器可能對不上。** 這是最致命的。論文稱之為**製品漂移（artifact drift）**：環境、任務、驗證器被分別生成，各自單看都成立，合起來卻在描述兩個不同的問題。
3. **沒有中間狀態。** 只有終局是非黑即白的，你不知道 agent 到底做對了哪一步、離目標還有多遠。

Tev 的做法是把整個鏈條倒過來。

**先構造一個潛在世界（latent world）$W$**：它是這個任務領域完整且正確的狀態。比如一個零售倉庫的客戶、產品、交易記錄；一個分布式 checkpoint 的張量分片和拓撲；一個 Kubernetes 叢集的資源清單。

在這個世界裡，**正確答案天然存在**。因為世界本身就是「一切正常時的樣子」。

然後，把這個世界**渲染（render）**成 agent 實際會看到的輸入檔案，再施加**受控的、可逆的損壞**，得到 agent 拿到的初始工作區 $s_0$。

關鍵在於：**潛在世界 $W$ 同時充當了任務提示、輸入檔案、驗證器、進度打分器四者的共同來源。**

論文把這個關係寫成了一個簡潔的式子：

$$E=(x,\;s_{0},\;\operatorname{ver}_{W},\;\Phi_{W}),\tag{1}$$

一個環境 $E$ 的四個組成部分，全部是同一個 $W$ 的函數：

- $x$：任務提示（agent 能看到的唯一描述）
- $s_0$：輸入目錄樹（agent 的初始工作區）
- $\operatorname{ver}_{W}$：嚴格的通過/不通過驗證器，依據 $W$ 檢查 agent 的輸出檔案
- $\Phi_{W}$：進度勢能，第 3 節詳述

這一個錨點，從根上杜絕了製品漂移。因為真值在構造上就是正確的，因為渲染可以往返還原（round-trip），因為損壞是已聲明且可逆的，所以 **agent 的初始工作區 $s_0$ 完全決定了 $W$**——正確答案可由 agent 實際看到的內容計算得出，不需要執行求解器。

### 1.2 三個推論

這個設計的漂亮之處在於，它順手解決了三個別的方案要靠額外東西才能解決的問題。

**推論一：難度是可控的旋鈕，不是碰運氣。**

因為 $W$ 是先造出來的，所以「變大一點」是純程式碼操作，不需要重新讓模型生成任何東西。規模檔位（scale tier，預設 unit / small / full）控制 $|W|$，工作流 DAG 的依賴深度控制「必須完成多少階段才能拿到正確輸出」。兩個旋鈕互相獨立。

**推論二：中間狀態免費。**

因為每個正確中間態都是 $W$ 的渲染，所以打分不需要人工標註步驟、不需要訓練一個 process reward model、不需要語言模型當裁判。$\Phi$ 是確定性的、可復現的、零模型呼叫的。

**推論三：邊際成本極低。**

生成一個環境（含跑兩個參考求解器、封存隱藏測試套件、預覽進度勢能）中位數只需 **30 秒 CPU 時間**（90 分位 82 秒），**零模型呼叫**。這是對比手工編寫的專家工時（數小時/題）的量級差異。而一次性的生成器編寫成本，可以被它所有種子和規模檔位攤薄。

更狠的是：論文指出 Tev-Gym 可以被進一步規模化——讓 coding agent 去寫生成器，生成器跨種子、跨規模檔位批次產出新環境，**全程不需要再呼叫任何模型**。

## 二、方法拆解：六階段環境合成流水線

第 2.1 節把環境合成拆成六個階段。整個流水線**沒有一個語言模型參與**。

### 階段 0：任務來源

針對 ALE-CM 的七個計算與數學子域（對應 Tev-Gym 的七大領域），每個領域先建立一個**真實任務規格池**：

| 子域 | 名稱 | 覆蓋範圍 |
|------|------|----------|
| 9.1 | Software Engineering | 功能實作、除錯、重構、測試撰寫 |
| 9.2 | Data & Analytics Engineering | ETL/ELT 流水線、推薦排序系統、特徵工程 |
| 9.3 | AI Engineering, Safety & CS Research | 模型訓練評測流水線、論文復現、checkpoint 管理、對齊實驗 |
| 9.4 | Mathematical & Operations Research | 組合最佳化、博奕均衡、應用數學與數論、機率估計與濾波 |
| 9.5 | Cybersecurity & Digital Forensics | 反向工程、惡意程式設定擷取、網路封包分析、事件取證 |
| 9.6 | Infrastructure Engineering & Cloud Operations | K8s 遷移與設定、生產事故根因分析、OS 強化、IaC |
| 9.7 | Quantum Computing | 量子線路建構與模擬、糾錯碼分析、雜訊模擬 |

規格池的來源包括：從網際網路挖掘的規格、MLE-bench 的 82 個 Kaggle 競賽，以及量子計算域（沒有任何 benchmark 覆蓋）使用的公開參考資料（MQT Bench 線路套件、Qiskit Experiments 手冊、TeNPy 的 DMRG 範例）。

從池中隨機抽樣規格，然後**圍繞每條規格自己寫一個生成器**。注意這裡的邊界：生成器參考規格的結構和難度，**絕不複製**它的 prompt、輸入、答案或評分文字。

三道過濾：
- **可行性過濾**：只保留「真值在構造上可知」且「純 CPU 可批次執行」的規格，排除依賴線上服務、音影片、重型工具鏈、GPU kernel、開放式「優化一下」類任務。
- **相似度閘門**：新生成器的程式碼、規格、生成資料與所有已註冊生成器比對，拒絕近似重複。
- **對抗評審**：攻擊每個通過前兩關的規格，尋找隱藏捷徑、過短跨度、偽裝來源。

### 階段 1：世界建構

每個生成器都是一個**帶種子的程式**。給定 `(seed, scale_tier)`，它程式化生成潛在世界 $W$，並做兩件事：

1. **校驗不變量**：唯一標識、合法連線、有限度量。
2. **抽取缺陷計劃（defect plan）**：精確指明 $W$ 中哪些記錄、分片、欄位將被損壞，以及由哪個已聲明的算子損壞。

這個缺陷計劃是「種子衍生」的，所以同一個生成器在兩個不同種子下，必然產出兩個可證明不同的世界。

### 階段 2：工作流圖

把環境的工作流編譯成**有向無環圖（DAG）**，帶顯式依賴、允許並行性、每階段語義工作量估算。例如零售倉庫 ETL 場景：

```
profile-sources → reconcile-facts / normalize-dimensions → load-facts
                → aggregate-validate → package-sidecars
```

**這個 DAG 由程式碼依據 $W$ 的規模生成，過程中沒有模型參與。**

DAG 的兩個關鍵性質：

- **關鍵路徑**（最長的依賴階段鏈）定義任務的**跨度（horizon）**。
- **各個階段構成進度勢能的骨架**（第 3 節）。

注意論文這裡的一個方法論選擇：**用 DAG 關鍵路徑而不是實際 rollout 長度 $T$ 來度量跨度**，因為 $T$ 會隨著 agent 的繞路而虛高。DAG 深度是結構性的、可控的。

### 階段 3：製品渲染

把 $W$ 投影到環境宣告的公共介面上，物化成目標線格式：

- CSV / TSV 分區
- JSON 記錄
- SQLite 資料庫
- safetensors 分片
- 去除符號的二進位檔案
- 基礎設施清單

**渲染是 $W$ 的純函數。** 並且在繼續之前，流水線會**斷言它能往返還原**——即從渲染後的檔案裡能精確恢復出 $W$。

### 階段 4：受控損壞

把階段 1 的缺陷計劃施加到渲染後的檔案上，注入模式漂移（schema drift）、重複與缺失記錄、類別漂移、打亂的分片索引、過期快取等。

被損壞的樹 $s_0$ 就是 agent 收到的任務，未被改動的 $W$ 就是真值。

### 階段 5 與階段 6：公開規格與隱藏測試套件

**階段 5** 輸出公開契約 $x$：輸入角色、所需輸出製品及其模式、有序的需求、權威優先級規則、允許的工具鏈。這是 agent 能看到的**唯一**描述。

**階段 6** 在 agent 視野之外封存隱藏套件，用於驗證階段：
- **變形變換（metamorphic transform）**：保持語義的重寫，**不得**改變評分。
- **陳舊輸出反事實（stale-output counterfactual）**：貌似合理但錯誤的狀態，**必須**判為不通過。

這一層的作用是防止驗證器過窄，以及防止「提交一個陳舊但看起來合理的結果」蒙混過關。

### 2.2 覆蓋度、校準與八道準入門檻

**多樣性。** 每個環境在 **19 條覆蓋軸**上被標註：子領域、規模、四條跨度軸、工作流階段、工具能力、制品角色、關係類型、損壞類別等。

論文特別強調「行為性軸」的價值：改變某個軸的取值，會改變 agent **必須修復什麼**（損壞類別）、**如何修復**（工作流階段、工具能力）、**透過哪些檔案修復**（制品角色、關係類型）。

**可控難度。** 兩個控制項：規模檔位（unit / small / full）拉長操作跨度；DAG 依賴深度 + 損壞類別數量決定「必須完成多少階段、必須按什麼順序」。

一個具體的數字感受：對於在三個規模檔位都實例化的生成器，輸入樹中位數從 **17 個檔案 / 51 KB（unit）** 成長到 **20 個檔案 / 168 KB（small）**，再到 **28 個檔案 / 586 KB（full）**，而**工作流 DAG 保持不變**。

**八道準入門檻。** 一個合成環境只有在通過全部八道與基準無關的門檻後才被接納，每道門檻在生成時自動檢查，並對應一個具名的失敗類別：

| 門檻 | 強制要求 | 針對的失敗類別 |
|------|----------|--------------|
| 獎勵因果性 | 每個獎勵分量在因果被變異時必須掉分 | 獎勵了錯誤的結果 |
| 抗利用性 | 全部 **14 個作弊探針**必須得 0 分 | 驗證器漏洞、抄近路被接受 |
| 角色獨立性 | 參考求解器 / 替代求解器 / 嚴格驗證器 / 進度打分器**程式碼閉包互不相交** | 求解器與打分器共享偏差 |
| 求解器一致性 | 兩個獨立編寫的求解器必須在每個種子上產出完全相同的輸出樹 | 僅驗證器通過、規格未解決 |
| 進度有效性 | 部分正確狀態上 $0<\Phi<1$；沿參考軌跡單調升到 1；倒退時產生負增量 | 無效的過程訊號 |
| 變形不變性 | 保義重寫不改變評分；陳舊輸出必須失敗 | 驗證器過窄、陳舊狀態被接受 |
| 六種子多樣性 | 至少 6 個種子產出不同的世界身分 / 公共樹雜湊 / 任務 ID | 退化環境、範本重複 |
| 公開契約衛生 | prompt 和公共樹中不得出現任何私有權威、參考答案或驗證器程式碼 | 答案外洩 |

關於**作弊探針（gaming probe）**，論文列了 14 種作弊策略，包括：空輸出、最小但 schema 合法的輸出、複製輸入、單種子硬編碼、路徑穿越、私有查詢等。每一種都必須在嚴格驗證器和進度打分器下同時得 0 分。

關於**角色獨立性**，這一條值得單獨強調。它要求：

$$\operatorname{ver}_W(\pi^{\mathrm{ref}}(s_0))=\Phi_W(\pi^{\mathrm{ref}}(s_0))=1,\quad \pi^{\mathrm{ref}}(s_0)=\pi^{\mathrm{alt}}(s_0)$$

參考求解器 $\pi^{\mathrm{ref}}$（分數恰好 1.0）和**獨立編寫**的替代求解器 $\pi^{\mathrm{alt}}$ 必須在每個種子上產出完全相同的輸出樹。**一旦不一致，就視為規格未解決，直接拒絕該環境。**

論文解釋了這個設計的意義：求解器稽核獨立於驗證器——兩個求解器都不 import 驗證器程式碼，所以它們的一致性是關於**規格本身**的證據，而不是關於**打分器**的證據。

## 三、稠密獎勵：從進度勢能到 PPRS

### 3.1 為什麼終止獎勵會「餓死」組內相對 RL

先看 GRPO 的組內相對優勢值：

$$\hat{A}_i=\frac{R_i-\operatorname{mean}(R_{1:G})}{\operatorname{std}(R_{1:G})+\epsilon}\tag{2}$$

其中 $R_i=\mathds{1}[\tau_i\ \text{passes}]$，即只有 rollout 提交且嚴格驗證器 $\operatorname{ver}_W$ 接受時才為 1。

**核心問題**：如果一組 $G$ 條 rollout 全部失敗，那麼 $R_1=\cdots=R_G=0$，於是所有 $\hat{A}_i=0$。這個任務對梯度的貢獻是零，這 $G$ 條 rollout 全部作廢。

浪費比例是 $(1-p)^G$：

| 通過率 $p$ | $G=8$ 時的浪費組比例 |
|------------|---------------------|
| 0.05 | 66% |
| 0.01 | 92% |

論文還點出了一個更隱蔽的問題：**即使一組裡只有一條成功，也好不了多少。** 那一條正樣本面對的是 $G-1$ 條負樣本，所有負樣本拿到相同的負優勢值，梯度**無法區分「差一點點」和「完全沒進展」**。

在長跨度任務上，未訓練開源模型的 $p$ 大約在十分之一甚至更低。所以「丟掉全失敗組」或「重新抽樣」這類做法，在長任務上直接扔掉了大部分 batch。

### 3.2 進度勢能：來自潛在世界的確定性刻度

每個 Tev-Gym 環境都提供一份**進度契約**：一個節點集合 $V$，每個節點是輸出工作區的一個可檢查狀態，派生自階段 2 的工作流 DAG。節點帶權重 $w_v>0$，$\sum_v w_v=1$，以及前置依賴集合 $\mathrm{pre}(v)$。

部分打分器 $c_v(s)\in[0,1]$ 直接對著潛在世界給 agent 當前的工作區 $s$ 打分。

**信用是前置依賴門控的（prerequisite-gated）**：$\tilde{c}_v(s)$ 取 $v$ 及其所有直接和間接前置節點中最小的部分分數。

於是進度勢能為：

$$\Phi(s)=\sum_{v\in V}w_v\,\tilde{c}_v(s)\in[0,1]\tag{3}$$

這個設計帶來三個由門檻強制保證的性質：

- **錨定（抗利用性）**：未改動的公共樹和每一個作弊探針都嚴格得 $\Phi=0$；嚴格驗證器接受時嚴格得 $\Phi=1$。
- **單調（進度有效性）**：隨節點完成而上升，隨已完成工作被破壞而下降。
- **獨立（角色獨立性）**：打分器程式碼閉包與驗證器、參考求解器**互不相交**，一個打分器的缺陷不會被另一個繼承。而且這些打分程式碼**不隨公共樹發布**。

論文特別強調「可擴展的獎勵設計」：因為潛在世界在任務生成之前就定義了，每個正確的中間狀態都能被直接渲染出來並被 $c_v$ 評估。這提供了**精確、確定性**的進度回饋，**不需要**人工步驟標籤、不需要訓練獎勵模型、不需要語言模型裁判。

這是與主流方案最本質的分野。

### 3.3 PPRS：進度勢能獎勵整形

設一條 rollout 的工作區狀態為 $s_0,\dots,s_T$，其中 $s_0$ 是未改動的公共樹，故 $\Phi(s_0)=0$。

參照基於勢能的獎勵整形（PBRS，Ng et al. 1999），每步的整形獎勵是勢能的變化量：

$$r_t=\Phi(s_t)-\Phi(s_{t-1})$$

rollout 總獎勵為：

$$R(\tau)=\mathds{1}[\tau\ \text{passes}]+\lambda\sum_{t=1}^{T}r_t=\mathds{1}[\tau\ \text{passes}]+\lambda\,\Phi(s_T),\tag{4}$$

其中 **$\lambda=0.25$，所有實驗執行均使用此值**。

這裡有四個設計細節，每一個都值得單獨拎出來。

**細節一：PPRS 故意不保持最優策略不變。**

標準 PBRS 會把終止勢能歸零，從而保證最優策略不變。PPRS 保留了 $\lambda\Phi(s_T)$，**故意改變了最佳化目標**。這是一個明確的、承擔了風險的偏離，論文在附錄中坦誠地討論了「什麼被保留了、什麼沒有被保留」。

**細節二：提交是動作，不是狀態。**

$\Phi$ 打分的是工作區，終局項打分的是策略**提交**的工作區。一條耗盡了回合或 token 預算但沒提交的 rollout，**不會被終局打分**，只拿 $\lambda\Phi(s_T)$。這正是圖 4 裡那條「完整建構但未提交」的 rollout 能夠達到 $\Phi=1$ 而終局獎勵為 0 的原因。

**細節三：獎勵只依賴最終狀態。**

因為 $\Phi$ 只是工作區的函數，$R(\tau)$ 只透過最終狀態 $s_T$ 依賴 rollout。這意味著**兩條通過不同路徑、步驟順序不同、實作方式不同但最終工作區相同的 rollout，拿到完全相同的獎勵**。這杜絕了獎勵對「過程風格」的意外偏好。

**細節四：終局獎勵的排序仍在最頂端。**

因為 $\Phi\le 1$，任何通過的 rollout 拿到 $1+\lambda=1.25$，嚴格高於任何失敗的 rollout。所以沒有任何一條 rollout 會因為「用完成度換部分進展」而獲益。附錄 B 對隨機策略下偏好何時可能反轉給出了界。

**代入 GRPO 之後，飢餓問題被修復了。**

一組中沒有 rollout 通過時，獎勵變成 $R_i=\lambda\Phi(s_T^{(i)})$。只要不同 rollout 進展到了不同深度，這些獎勵就不同，組內優勢值非零，且**按進展深度給 rollout 排名**。

論文的圖 4 直觀展示了這個效果：同一個倉庫環境，$G=8$ 組 rollout，每輪即時打分。

- **僅終止獎勵（紅）**：所有 rollout 全部得 0。
- **漸進式獎勵**：2 條提交了不完整倉庫（圓圈）、5 條耗盡了 65k token 上下文（叉號）、1 條建構出完整倉庫。

組內獎勵終於有了差異，梯度終於有東西可學。

### 3.4 與已有做法的對比

| 方案 | 進展粒度 | 需要額外模型 | 主要缺陷 |
|------|---------|------------|---------|
| 終止獎勵（稀疏） | 終局 | 否 | 全失敗組優勢值為零，浪費 66%–92% |

### 4.5 消融實驗

消融在 9B 設定下進行。

**資料建構方式的消融：**

| 方法 | World | DAG | 隱藏真值 | 訊號 | S@1 | S@5 | P@1 | P@5 | GPU-h/step |
|------|-------|-----|---------|------|-----|-----|-----|-----|------------|
| Qwen3.5-9B (base) | – | – | – | 無 RL | 0.25 | 0.33 | 0.06 | 0.06 | – |
| **Tev-9B (ours)** | ✓ | ✓ | ✓ | ΔΦ + 終止 | **0.29** | **0.40** | **0.07** | **0.11** | 9.0 |
| Public-view verifier | ✓ | ✓ | LLM | 終止 | 0.24 | 0.35 | 0.04 | 0.06 | 22.3 |
| Prompt-first | LLM | LLM | LLM | 終止 | 0.23 | 0.32 | 0.06 | 0.06 | 11.8 |
| Sparse (僅終止) | ✓ | ✓ | ✓ | 終止 | 0.25 | 0.32 | 0.06 | 0.06 | 16.7 |
| PPRS, pooled norm. | ✓ | ✓ | ✓ | ΔΦ + 終止 | 0.28 | 0.35 | 0.06 | 0.06 | 10.9 |
| Direct reward (additive) | ✓ | ✓ | ✓ | Φ + 終止 | 0.29 | 0.35 | 0.06 | 0.06 | 9.7 |

三個讀數：

**讀數一：兩種「退化為 LLM 生成」的變體都不奏效，而且更貴。**

- **Public-view verifier**：讓模型從 agent 視角寫驗證器（放棄隱藏真值）。**88% 的抽樣組在訓練中被丟棄**，GPU 耗時 22.3 GPU-h/step，是完整方法的 2.5 倍。
- **Prompt-first**（標準 self-instruct 基線）：整條流水線換成「先出 prompt，再出輸入、驗證器、解法」，沒有潛在世界也沒有 DAG。

兩種變體的 S@1 分別是 0.24 和 0.23，**都不超過基線的 0.25**；而完整方法領先它們 0.05–0.06（S@1）和 0.05（P@5）。

**讀數二：稠密獎勵必須「整形」，不能只是「相加」。**

- **Sparse（僅終止）**：S@1 = 0.25，且 GPU 耗時最高（16.7）。
- **PPRS, pooled norm.**（每條 rollout 正規化）：S@1 = 0.28，有提升但 P@1/P@5 沒動。
- **Direct reward (additive)**（$\gamma=0$，直接用 $\Phi(s_t)$ 相加）：S@1 = 0.29，但 P@1 仍是 0.06。

完整 PPRS 相對稀疏獎勵 **S@1 提升 0.04**，且**唯一一個把 P@1 從 0.06 抬到 0.07、P@5 從 0.06 抬到 0.11 的方案**。

論文對為什麼 additive 不行的解釋很關鍵：**直接相加會反覆獎勵高勢能狀態而不向前傳播信用**，導致更多 rollout 在提交前耗盡上下文視窗，產生更長的軌跡。而完整 PPRS 用 return-to-go（$\gamma=1$）把進展向前傳播信用，用**按回合索引正規化優勢值**保留了後期回合的信用（避免把後期更小的 return 拿去跟整條 rollout 的均值比較）。

**讀數三：27B 規模下差距進一步拉開。**

論文明確指出：在 27B 上，shape 後的獎勵能訓到完成，而**僅終止獎勵產生的組幾乎全是零優勢值，一個完整的最佳化器 step 都走不出去**。

論文給了一個 ALE-CM 上 Coding & System 域的具體案例（模型從一次 kubectl 抓取、Deployment/HPA YAML 和一個崩潰 pod 的日誌，寫出帶逐字證據串和回滾結論的 JSON 根因報告）：

## 六、詳細教學：如何復現 Tev-Gym 的方法

### 步驟 1：寫生成器（階段 1–4 的核心）

一個生成器就是一個**帶種子的純函數**：`make_world(seed, scale_tier) -> World`。它必須做到：

```python
import random, hashlib

def make_world(seed: int, tier: str = "unit"):
    """生成潜在世界 W。必须是 seed 的纯函数，无副作用，无模型调用。"""
    rng = random.Random(seed)

    # 规模档位决定 |W|
    n_customers = {"unit": 30, "small": 240, "full": 480}[tier]
    n_tx_per_month = {"unit": 48, "small": 480, "full": 960}[tier]

    world = {
        "customers": [
            {"id": f"C{i:05d}", "name": f"cust_{i}"}
            for i in range(n_customers)
        ],
        "products": [
            {"id": f"P{i:05d}", "sku": f"sku-{i:04d}", "price": round(rng.uniform(1, 500), 2)}
            for i in range(n_tx_per_month)
        ],
        "transactions": [],
    }

    # ---- 不变量校验（阶段 1）----
    assert len({c["id"] for c in world["customers"]}) == n_customers, "ID 必须唯一"
    assert all(t["qty"] > 0 for t in world["transactions"]), "度量必须有限"

    # ---- 缺陷计划（阶段 1）：精确指明要损坏什么 ----
    defect_plan = {
        "operators": ["duplicate_records", "missing_records", "schema_drift"],
        "targets": rng.sample(range(len(world["transactions"])), k=2),
    }
    world["_defect_plan"] = defect_plan
    return world
```

**三條硬性紀律**：

1. **純函數。** 不讀時間、不讀環境變數、不呼叫網路、不呼叫模型。相同 `(seed, tier)` 必須產出完全相同的世界。
2. **缺陷計劃寫在世界裡。** 破壞發生在渲染之後，且計劃是種子衍生的——這樣「哪些被破壞」本身就是世界的一部分，可以被獨立重建。
3. **不 import 驗證器程式碼。** 這是角色獨立性門檻的要求，後面評分階段會檢查程式碼閉包互不相交。

### 步驟 2：定義工作流 DAG（階段 2）

DAG 決定跨度，也決定進度勢能的骨架。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Stage:
    name: str
    depends_on: tuple[str, ...]      # 显式依赖
    weight: float                     # 进度节点权重
    parallel_with: tuple[str, ...] = ()  # 允许并行

WORKFLOW = (
    Stage("profile-sources",   (),                    0.15),
    Stage("reconcile-facts",   ("profile-sources",),   0.25),
    Stage("normalize-dimensions", ("profile-sources",), 0.15),
    Stage("load-facts",        ("reconcile-facts", "normalize-dimensions"), 0.20),
    Stage("aggregate-validate",("load-facts",),        0.15),
    Stage("package-sidecars",  ("aggregate-validate",), 0.10),
)

def critical_path():
    """最长依赖链 = 任务跨度。这是结构性的度量，不受 agent 绕路影响。"""
    memo = {}
    def depth(s):
        if s.name in memo: return memo[s.name]
        memo[s.name] = 1 + max([depth(d) for d in s.depends_on], default=0)
        return memo[s.name]
    return max(depth(s) for s in WORKFLOW)
```

權重和必須正規化到 1（對應式 (3) 的 $\sum_v w_v=1$）。

### 步驟 4：施加可逆損壞（階段 4）

```python
def corrupt(world, out_dir):
    """按缺陷计划施加损坏。必须声明式、可逆。"""
    plan = world["_defect_plan"]
    for idx in plan["targets"]:
        op = plan["operators"][idx % len(plan["operators"])]
        if op == "duplicate_records":
            # 复制一条交易记录
            path = os.path.join(out_dir, "transactions.csv")
            with open(path) as f:
                lines = f.readlines()
            lines.append(lines[1])
            with open(path, "w") as f:
                f.writelines(lines)
        elif op == "missing_records":
            path = os.path.join(out_dir, "transactions.csv")
            with open(path) as f:
                lines = f.readlines()
            del lines[1]
            with open(path, "w") as f:
                f.writelines(lines)
        elif op == "schema_drift":
            path = os.path.join(out_dir, "customers.csv")
            with open(path) as f:
                lines = f.readlines()
            lines[0] = lines[0].replace("name", "full_name")  # 列名漂移

                f.writelines(lines)
```

**關鍵**：損壞必須**已宣告且可逆**。這樣 $s_0$ 才完全決定 $W$，正確答案才可由 agent 所見內容計算得出。

### 步驟 5：寫嚴格驗證器與進度打分器（階段 5–6）

兩者**必須是兩份互不相交的程式碼**。

```python
# verifier.py —— 严格通过/不通过，只看最终产出
def verify(world, output_dir) -> bool:
    """对照 W 检查 agent 的输出文件。严格、确定性、无副作用。"""
    for path, checker in world["_verifiers"]:
        if not checker(world, os.path.join(output_dir, path)):
            return False
    return True

# progress.py —— 进度打分器，独立代码闭包
def partial_score(world, output_dir) -> dict:
    """对每个进度节点给出 [0,1] 的部分分数。"""
    return {v: checker(world, output_dir) for v, checker in world["_partial_scorers"].items()}

def progress_potential(world, output_dir) -> float:
    """式 (3)：前置依赖门控的加权求和。"""
    scores = partial_score(world, output_dir)
    gated = {}
    for v, s in scores.items():
        pre = world["_prereqs"][v]
        gated[v] = min([scores[v]] + [gated[p] for p in pre]) if pre else scores[v]
    return sum(world["_weights"][v] * gated[v] for v in scores)
```

前置依賴門控的實作要點：**必須拓撲序計算**，因為 $\tilde{c}_v$ 依賴前置節點的 $\tilde{c}$，而不只是原始分數。

def qualify(world, out_dir, reference_solver, alternative_solver):

### 步驟 7：實現 PPRS 獎勵

```python
import numpy as np

LAMBDA = 0.25  # 论文中所有运行均为 0.25

def rollout_reward(workspace_states, passed: bool) -> float:
    """
    式 (4)：R(τ) = 1[passes] + λ * Φ(s_T)

    注意 telescoping：Σ ΔΦ = Φ(s_T) - Φ(s_0) = Φ(s_T)，因为 Φ(s_0)=0。
    """
    phi_final = workspace_states[-1]
    return (1.0 if passed else 0.0) + LAMBDA * phi_final

def grpo_advantages(rewards):
    """式 (2)：组内相对优势值。"""
    r = np.asarray(rewards)
    return (r - r.mean()) / (r.std() + 1e-6)
```

**訓練的三個設定要點**（這些是論文明確給出的，也是最容易搞錯的）：

1. **按回合索引正規化優勢值**（per turn），不是按整條 rollout 正規化（pooled）。前者保留了後期回合的信用。
2. **$\gamma=1$ 的 return-to-go**，把進展向前傳播到更早的動作。
3. **$\lambda=0.25$**。

對比一下反面做法：

```python
# ❌ 反面：直接相加的奖励（论文消融里 S@1=0.29 但 P@1=0.06）
def bad_reward(workspace_states, passed):
    return (1.0 if passed else 0.0) + LAMBDA * sum(workspace_states)

# ❌ 反面：仅终止奖励（论文消融里 S@1=0.25，27B 上一个完整优化器 step 都走不出去）
def bad_reward2(workspace_states, passed):
    return 1.0 if passed else 0.0
```

**這兩種做法在 S@1 上看起來差不多，但完全解出率 P@1 會卡在基線水平不動。** 論文的消融表就是靠這個差異揭示了「形狀」與「相加」的實質區別。

```python
def decontamination_check(train_prompts, eval_prompts, n=13):
    """Tev-Gym 无任何环境与评测集共享 13-gram 或 8-gram。"""
    for name, ngram_n in [("13-gram", 13), ("8-gram", 8)]:
        eval_ngrams = set()
        for p in eval_prompts:
            eval_ngrams |= {tuple(p[i:i+ngram_n]) for i in range(len(p)-ngram_n+1)}
        for p in train_prompts:
            overlap = {tuple(p[i:i+ngram_n]) for i in range(len(p)-ngram_n+1)} & eval_ngrams
            assert not overlap, f"{name} 泄漏"
```

同時檢查**結構性去污染**：任意兩個環境的公共樹雜湊必須不同，且都不與評測實例共享。

### 步驟 10：評測

論文的評測協定比多數論文嚴謹，值得照抄：

- **Agent time 是實測的，不是估算的**：記錄從 agent 第一個動作到最後一個動作的掛鐘時間，包含所有模型呼叫、重試和中間的命令執行。
- **對比語料的預算要放開**：Tev-Gym 有 28% 的 rollout 用掉超過 60 次工具呼叫，所以對 Tev-Gym 必須把預算提到不構成約束為止（論文用了 300 次工具呼叫 / 2 小時掛鐘）。
- **抽樣要分層**：論文從全部 1,170 個環境中按七個域分層抽取 100 個環境子樣本（種子 20260915）。
- **驗證子集代表性**：用 Pearson 相關檢查 CM 子集與全集 leaderboard 表現的一致性（論文達到 r=0.96 / r=0.97）。

## 七、歸納總結：論文的主要觀點與結論

### 觀點一：長跨度智能體的瓶頸不是演算法，是資料與獎勵

論文的整個框架建立在一個觀察上：**開源模型在長跨度任務上的失敗，主要不是因為最佳化演算法不夠好，而是因為既沒有訓練資料，也沒有可行的配方**。

兩個瓶頸互相糾纏：長任務難以為之建構和驗證，獎勵又極其稀疏。分開解決都不行——單獨造資料會得到稀疏獎勵下訓不動的模型；單獨設計稠密獎勵但沒有「正確答案已知」的世界，勢能分數本身就是不可信的。

### 觀點二：正確的合成方向是「從答案反推問題」

這個論斷比論文的具體實作更普適。

> 「與那些讓語言模型在沒有真實答案的情況下生成任務、輸入和檢查器的流水線不同，我們的潛在世界充當了精確的答案本，用於可靠驗證。」

論文把它歸入一個成熟的家族——從已知解反推任務：去噪、受控錯誤注入、程式碼變異、環境回溯、指令回譯、程式化謎題生成。但它們的區別在於：**這些方法損壞的是單個製品的 ground truth，而 Tev 損壞的是整個潛在世界的一個渲染**。

這個區別帶來了原子性上的差異：任務、驗證器、進度訊號都是同一個世界的函數，不會互相漂移。

### 觀點三：進度獎勵應該「可證明」而非「學出來」

稠密獎勵的主流方案要麼訓練一個 process reward model，要麼用學習式評審，要麼用語言模型當裁判。這些方案都引入了額外模型、額外偏差和額外訓練成本。

Tev 的做法是：**因為潛在世界在任務生成之前就定義了，所以每個正確中間態都能被直接渲染出來並被確定性評估**。不需要 critic，不需要 judge，不需要人工步驟標籤。

這是全文方法論上最有價值的一條：**把「獎勵從哪來」的問題，從「怎麼學一個獎勵模型」變成「怎麼保證真值已知」。**

### 觀點四：獎勵整形必須刻意偏離「最優策略不變」

標準 PBRS 會把終止勢能歸零以保證最優策略不變。PPRS 保留了 $\lambda\Phi(s_T)$，**故意改變了最佳化目標**。

這是一個明確的風險承擔。論文沒有迴避它，而是在附錄中討論了「什麼被保留、什麼沒有被保留」，並給出隨機策略下偏好何時可能反轉的界。

**很多論文會把這種偏離藏起來或者假裝不存在，Tev 把它擺在了檯面上。** 這是研究態度問題。

### 觀點五：資料品質與資料規模在這個領域是反向的

表格 1 的讀法很反直覺：

| | SWE-Smith | Tev-Gym |
|---|---|---|
| 規模 | 50.1k | 1,170 |
| 域數 | 1 | 7 |
| Agent 時間中位 | 2.0 min | 12.4 min |
| 漸進獎勵 | ✗ | ✓ |
| P@1 | 47% | 29% |

**Tev-Gym 只有既有語料的 1/40 大小，卻支撐了最強的結果。** 因為在長跨度任務上，「環境數量」早就不是瓶頸了——**「環境裡有沒有可驗證的中間狀態」才是。**

這也解釋了為什麼 1170 個環境能訓出追平 GPT-6 Astra 的模型，而 5 萬個環境訓不出。

### 觀點六：消融實驗給出的操作性教訓

三條可以直接搬走用的結論：

1. **讓模型自己寫驗證器 = 88% 的組被丟棄 + 2.5 倍算力 + 更差的效能。** 用 LLM 生成檢查器省下的時間，會在訓練階段以更貴的方式還回去。
2. **稠密獎勵的「形狀」比「密度」更重要。** 直接相加的 $\Phi(s_t)$ 在 S@1 上看起來不錯（0.29），但 P@1 完全不動（0.06）——它反覆獎勵高勢能狀態卻不傳播信用，導致 agent 繞圈直到耗盡上下文。
3. **規模越大，純終止獎勵的崩潰越徹底。** 27B 上僅終止獎勵產生的組幾乎全是零優勢值，**一個完整的最佳化器 step 都走不出去**。

### 結論

論文自己的結論段落說得很克制：

> 我們提出潛在世界優先的方法來擴展可驗證的長跨度智能體訓練。每個任務從一個已知正確的潛在世界反向建構，被渲染成相互關聯的檔案，通過受控損壞被修改，並被復用於精確驗證與稠密進度獎勵。我們把這套方法實例化為 Tev-Gym——橫跨七個領域的 1,170 個已驗證環境——並表明訓練在 ALE-CM 上同時改進了 9B 和 27B 開源模型，且增益能遷移到不同跨度的 Terminal-Bench 任務以及一個 320B 基座模型。

它也明確承認了局限：

> 當前研究的一個局限是聚焦於合成的終端環境，且最難的 benchmark 上我們的模型與前沿智能體之間仍存在差距。支持新工作流還需要編寫並驗證額外的環境組件。

## 八、設計哲學拆解

把論文的做法抽象到哲學層面，我看到五條相互支撐的原則。

### 原則一：唯一錨點原則（Single Anchor）

一個環境只有一個真值來源。所有產物——任務、輸入、驗證器、進度訊號——都是它的函數。

**這對抗的是「分散式生成」的熵。** 當四個元件由不同過程分別生成時，它們的聯合分布會漂移；有一個共同錨點時，漂移在結構上不可能發生。

**推論**：只要你發現自己在「生成任務」和「生成答案」兩個步驟之間做對齊工作，就該考慮倒過來做。

### 原則二：真值先於任務原則（Ground Truth Precedes Task）

任務不是被「生成」的，是被「導出」的。

在 agent 時代之前，這句話聽起來平淡。在 LLM 生成內容的時代，它變得激進：**你要求一個模型在它自己都不知道答案的地方生成一道需要答案的題。** Tev 的整篇論文在某種意義上是對這種做法的系統性質疑。

### 原則三：確定性優於學習原則（Determinism Over Learning）

當一個量可以被確定性計算出來時，就不要訓練一個模型去估計它。

| 需求 | 常見做法 | Tev 做法 |
|------|---------|---------|
| 判斷步驟對錯 | 訓練 PRM / 學習式評審 | 渲染正確中間態並確定性打分 |
| 判斷最終對錯 | 生成測試用例 | 對照 $W$ 嚴格校驗 |
| 判斷難度 | 讓模型試跑打分 | 定義在生成時的結構量 |

**代價是你必須先把世界造對。** 這就是為什麼 Tev 要花大力氣做六種子多樣性、雙求解器一致性和角色獨立性稽核——**因為一旦勢能不可信，整條訓練鏈路都是毒化的。**

### 原則四：門檻先於規模原則（Gates Before Scale）

在生成時就把不合格的環境擋掉，而不是靠下游 RL 去軟過濾。

論文明確對比了這種選擇：「與那些跳過驗證、依賴下游 RL 軟過濾不可解任務的流水線不同，我們在生成時就設卡，因為稠密進度訊號只有在因果性強且抗作弊時才有用。」

**這句話是全文最實用的工程建議。** 在資料生成側偷的懶，會在訓練側以算力浪費和訊號汙染的形式還回來——論文的消融裡 Public-view verifier 那 22.3 GPU-h/step 就是帳單。

### 原則五：過程即產物原則（Process as Artifact）

進度勢能被定義成**節點集合 + 前置依賴 + 權重**的顯式資料結構，而不是一個黑箱分數。

帶來的好處不只是可解釋性：

- DAG 的關鍵路徑直接就是跨度的結構度量
- 前置依賴門控天然實現了「上游沒做好，下游不給分」
- 消融實驗可以精確控制「資料變了」還是「獎勵變了」

**當獎勵被顯式建模成結構時，它才能被稽核、被質疑、被分解。**

### 一條隱藏的哲學線索：從「生成內容」到「生成世界」

我認為這才是這篇論文最深的一層。

過去兩年，AI 內容生成的範式是：**給定 prompt，採樣輸出。** 所有品質問題——幻覺、一致性、不可驗證——都源於一個根本限制：**沒有獨立於模型的知識來源。**

Tev 的做法把範式翻轉了：**給定一個完整正確的世界，導出所有產物。** 模型從「知識的來源」退回到「問題的求解者」。

在這個框架下：

- 幻覺問題變成了「渲染往返還原失敗」的工程問題
- 驗證器不可靠變成了「程式碼閉包是否相交」的靜態檢查問題
- 獎勵稀疏變成了「勢能函數是否單調」的形式化性質
- 難度控制變成了「規模檔位 × 依賴深度」兩個旋鈕

**每一個原本模糊的 AI 問題，都被轉化成了一個可以被證明、可以被測試、可以被稽核的工程問題。** 這才是「潛在世界優先」這個方法真正值錢的地方——它不只是一個更高效的造資料技巧，它是一種把 AI 系統問題工程化的思路。

而這也解釋了為什麼 Tev-Gym 只有 1,170 個環境卻能贏：因為**當問題被正確形式化之後，資料的「量」這個維度的重要性會急劇下降。**

## 九、局限、質疑與後續看點

我的評價，不是論文的自我陳述。

### 論文自己承認的局限

1. **聚焦合成終端環境。** 沒有覆蓋 GUI、真實線上服務、多智能體協作等場景。
2. **最難的 benchmark 上仍有差距。** TB 4.0-CM 上 Tev-27B 的 0.10 相比 Claude Opus 5 的 0.52，差著一個數量級。
3. **支援新工作流需要額外投入。** 每加一個領域都要寫生成器、驗證器、打分器，並過八道門檻。這是實打實的人力成本，論文沒有量化它。
4. **程式碼與資料尚未發布。** 專案主頁的 Code 和 Data 按鈕至今仍標記為 "soon"，只有模型權重可得。**這意味著當前無法獨立驗證資料集品質，也無法直接複用。**

### 我的額外質疑

**質疑一：$s_0$ 真的完全決定 $W$ 嗎？**

論文的論證是：渲染可往返還原 + 損壞已宣告且可逆 ⟹ $s_0$ 完全決定 $W$。但這個推導依賴於「損壞算子集合是封閉的、且每種算子的逆可計算」。如果某個算子（例如「類別漂移」）在某些資料上不可逆（兩個不同的原值映射到同一個漂移值），那麼嚴格意義上 $s_0$ 只能確定 $W$ 的一個**等價類**，而非 $W$ 本身。

論文提到隱藏套件裡的「變形變換」和「反事實」正是用來處理這類歧義的，但公開樹層面的確定性論證我認為仍有邊界。

**質疑二：0.03 的 base P@1 是不是太低了？**

Tev-Gym 上未訓練 Qwen3.8-27B 只有 3.2% 的環境被完全解出，平均評分分數 0.06。這確實符合「長跨度任務很難」的現實，但也意味著：**大部分訓練訊號來自 $\Phi$ 而不是來自「真的做對了」。** 模型可能在最佳化「勢能函數的爬升路徑」，而不是「任務本身的正確解法」。

論文的變形不變性門檻和陳舊輸出反事實門檻部分緩解了這個問題（它們直接針對「抄近路」），但「沿著勢能函數的最短爬升路徑最佳化」與「真正理解任務」之間的差距，論文沒有直接測量。

**質疑三：泛化到 TB 的結果需要謹慎解讀。**

TB 3.0/4.0 的 "CM" 子集是**用 Claude 判斷每個任務是否屬於計算與數學域**建構出來的。雖然論文驗證了子集與全集的高相關（r=0.96 / r=0.97），但這意味著子集劃分本身帶有一個前沿模型的判斷。用 Claude 建構的子集去評測一個與 Claude 對比的模型，這個循環性雖然不構成致命問題，但值得讀者知道。

**質疑四：P@5 追平前沿模型的表述需要限定。**

Tev-27B 的 P@5 = 0.28 與 GPT-6 Astra、Claude Opus 5 的 0.28 持平，這是一個非常亮眼的數字。但：

- Tev-27B 用的是 Vanillux2 harness，前沿模型用的是 Codex / Claude Code，**harness 本身對 agent 行為影響巨大**
- 前沿模型在 ALE-CM 上的 S@5 明顯更高（0.58 vs Tev-27B 的 0.54，且 GPT-6 Astra 的 S@5/S@1 都是 0.58），說明**前沿模型在「已經做對的任務上做得更徹底」**
- P@5 = S@5 = 0.28 這個「飽和」形態，和 Tev-27B 的 0.16/0.28（S@1/P@5）形態，含義並不相同

**我的判斷：這是一個真實的、可復現方向上的顯著進步，但「追平前沿模型」這個表述在跨 harness 比較下應當打折理解。**

**質疑五：可擴展性的瓶頸會轉移到「寫生成器」上。**

論文指出 Tev-Gym 可以透過讓 coding agent 寫生成器來進一步規模化，且**不再需要模型呼叫**。但生成器程式碼本身需要過八道門檻，而雙求解器一致性要求「兩個獨立編寫的求解器產出一致」——**人工寫一個生成器容易，為它寫兩個獨立求解器並保證一致，難度高得多。**

當規模從 1,170 往 10,000 推的時候，人工審核生成器的產能會成為真正的瓶頸。論文沒有討論這一點。

### 後續看點

1. **程式碼與資料何時發布**——這是最關鍵的觀察窗口。如果發布，社群能獨立驗證 1,170 個環境的實際品質。
2. **能否擴展到非終端環境**（瀏覽器、GUI、真實工具鏈）——這決定「潛在世界優先」是終端任務的專用技巧還是通用範式。
3. **成本曲線**——每個新領域需要多少人工工時？這個數字決定了方法的可規模化上限。
4. **$\Phi$ 與真實解題能力的相關性**——如果能直接測量「勢能更高的軌跡是否更可能真正解對任務」，就能回答我上面的質疑二。
5. **Tev-320B 的完整評測**——論文只在 TB 子集上評測了 320B 版本，ALE-CM 上的表現未知。

## 十、一句話總結

> **讓模型自己去出題，它就會連答案一起編錯。**
>
> Tev 的做法是把順序倒過來：先有一個完整正確的世界，再從它導出任務、輸入、驗證器和進度刻度。因為答案在構造上就已知，驗證是精確的，中間狀態是免費的，而訓練訊號可以稠密到每一步。
>
> 1,170 個環境，一個 27B 的開源模型，在 Agents' Last Exam 的計算與數學分片上 Pass@5 達到 0.28，與 GPT-6 Astra 和 Claude Opus 5 持平；同時零樣本遷移到從未見過的 Terminal-Bench 4.0 子集，P@1 提升 150%。
>
> 數量從來不是這個領域的主要矛盾。**「答案從哪來」才是。**
