# Waza：將工程習慣轉化為AI Agent可執行技能的開源工具

## 背景：為什麼AI Agent需要工程習慣

AI Agent 在處理程式碼任務時，具備驚人的生成能力，卻常常在執行紀律上出現問題。輸出飄忽不定、架構決策缺乏依據、程式碼審查流於形式——這些問題並非模型本體的缺陷，而是缺少一套穩定的工作流程框架。

開發者 Tw93 在超過 30 天、超過 300 場開發會話的實戰經驗中，觀察到一個核心問題：現有的人工智慧開發工具往往過於臃腫，配置複雜、學習曲線陡峭，並不適合追求高效工程的團隊。工程師在漫長的職業生涯中積累的紀律與習慣——架構規劃、系統性偵錯、刻意為之的介面設計、嚴謹的驗證流程——這些紀律無法自動轉移到 AI Agent 的行為模式中。

Waza 的出發點很簡單：不要重新發明輪子，把工程師已經知道的習慣翻譯成 AI Agent 能夠執行的技能（Skills）。每一項技能都對應一個工程師在日常工作中早已熟悉的動作，只是將其結構化、自動化，讓 Agent 在正確的時機做出正確的事情。

## 設計哲學：約束即自由

Waza 的設計圍繞三個核心原則，支撐起整個工具的方法論。

### Less is More：少即是多

市面上許多 AI Agent 工具追求功能完整，內建數十種技能，卻讓使用者陷入選擇疲勞。Waza 反其道而行，只收錄 8 項技能，每項技能都有單一明確的觸發時機與職責範圍。不使用的技能零負擔，觸發的技能零疑惑。工具精簡的代價是品質的提升——每項技能都經過 300 場以上實戰 sessions 的檢驗，每一個陷阱（gotchas）都來自真實的失敗案例。

### Structure is Efficiency：有結構才有效率

AI 的 raw output 如果沒有結構約束，就會飄向generic（通用化）、imprecise（不精確）的工作方式。Waza 為每一項技能定義了明確的 outcomes（預期結果）、red lines（禁區紅線）和 verification（驗證方式）。當模型知道終點在哪裡、什麼不能做、以及如何確認完成，執行的效率便自然提升。這種結構化並非限制模型的創造力，而是為其提供了一個可靠的工作邊界。

### Project-Aware：專案感知

Waza 內建的技能在運行時會讀取目標儲存庫的公開資訊（README、package manifests、Makefiles、CI workflows），將通用的工程習慣與特定專案的上下文結合。例如 `/check` 技能在執行時會自動解析專案的發布流程、審核標準與發布管道，確保技能產出的內容與該專案的實際需求相符，而不僅僅是一份通用的程式碼審查清單。

## 8個技能詳解

Waza 的 8 項技能對應了軟體工程師日常工作中最關鍵的 8 個環節。以下按照工作流程的時序逐一說明。

### /think：在動手之前先想清楚

**觸發時機**：開始任何新工作之前

**核心功能**：對問題進行壓力測試，審視設計選擇，生產一份決策完整的實作計畫，供後續 Agent 執行。

這項技能對應的是工程師在寫 code 之前應該先做架構規劃的習慣。多數 AI Agent 收到需求後直接開始生成程式碼，往往在實作過程中才發現架構決策存在缺陷，導致大幅重構。`/think` 將這個環節結構化為一個獨立的步驟，要求 Agent 在收到需求時先提出問題、檢驗假設、列出候選方案、最終產出一份讓人信任的實作計畫。

### /ui：介面設計不走捷徑

**觸發時機**：建構前端介面時

**核心功能**：生成具有辨識度的 UI，透過截圖驅動的美學迭代，給出有方向感的設計而非通用預設值。

前端介面是 AI 生成內容中最容易流於平淡的領域——預設色彩、預設元件、預設佈局，湊在一起就是一份「看起來像是 AI 畫的」介面。`/ui` 技能要求 Agent 先確立設計方向，再以此方向驅動每一個元件的選擇，透過截圖比對確保美學上的一致性與辨識度，而非被模型預訓練中的「平均審美」所主導。

### /check：diff review 與發布交接

**觸發時機**：任務完成後、合併或發布前

**核心功能**：審查 diff、提取專案特定約束、處理經核准的 release/publish/push/issue 流程，並以證據進行驗證。

這是將工程師「自己審查自己的程式碼」這個紀律自動化的關鍵技能。`/check` 不只是檢查語法錯誤，更會根據專案的 CI/CD 配置、發布流程和審核標準來客製化審查清單。當變動涉及發布或議題追蹤時，技能會確保對應的流程被正確觸發，而非停在「程式碼寫完了」這一步。

### /hunt：系統性偵錯

**觸發時機**：任何 bug、迴歸問題或非預期行為出現時

**核心功能**：系統性偵錯，在任何修復之前先確認根本原因，尤其當某個功能之前正常運作時。

AI Agent 修復 bug 的常見模式是「看到錯誤訊息就修」——症狀消失了，但根本原因未被理解，下一次相似的情境會再次觸發相同問題。`/hunt` 技能的設計就是要打破這種捷徑，要求 Agent 先重現問題、定位根因，再提出修復方案，並以「之前正常運作」的條件作為迴歸測試的基準。

### /write：自然的中英文寫作

**觸發時機**：撰寫或編輯文章、文件時

**核心功能**：將中英文文章改寫為自然流暢的語言，切除生硬、公式化的措辭。

AI 生成的文字常带有一种「AI腔」——過度使用連接詞、結構造型過於對稱、情感表達扁平。`/write` 技能專門用來對抗這種傾向，讓生成的文章讀起來像真實的人在表達想法，而非模型在填充句子模板。這個技能適用於行銷文案、技術文章和對外溝通場景。

### /learn：六階段研究流程

**觸發時機**：進入陌生領域時

**核心功能**：六階段研究流程：收集（collect）、消化（digest）、大綱（outline）、填充（fill in）、精煉（refine），最後自我審查與發布。

面對一個陌生的技術領域時，工程師的慣常做法是快速找幾篇文章看一下就動手，但往往因為理解不夠深入而做出錯誤的技術決策。`/learn` 將研究過程結構化為六個有序的階段，確保 Agent 在進入實作之前對領域有足夠寬廣且正確的認知地圖。

### /read：URL 與 PDF 閱讀

**觸發時機**：需要處理任何 URL 或 PDF 檔案時

**核心功能**：根據平台特性路由閱讀請求。純閱讀時回傳簡潔摘要；當被要求轉換、引述、引用、保存或餵給下游工作時，則輸出完整 Markdown 格式。

AI Agent 常見的資訊獲取問題是「讀了等於沒讀」——模型看過了文件但沒有結構化地理解內容，導致後續輸出與原始資料不一致。`/read` 技能解決了這個問題，根據不同的使用目的（純閱讀 vs. 引用）提供不同層次的輸出格式，確保資訊的獲取與使用是匹配的。

### /health：Agent 健康檢查

**觸發時機**：審計 Agent 健康狀態時

**核心功能**：檢查 Codex、Claude Code、專案指示、驗證器輸出和 AI 可維護性，在進入深度檢查之前先做一個預算敏感的總覽。

這項技能源自 Tw93 提出的六層 Claude Code 框架，旨在幫助使用者理解當前 Agent 的運作狀態是否健康——配置是否正確、額度使用是否合理、輸出的內容是否具有可維護性。它是一個元層級（meta-level）的診斷工具，確保其他所有技能都能在健康的環境中運行。

## 安裝教程

Waza 的安裝設計以「零疑惑、零錯誤」為目標，一個指令完成所有設定。

### 透過 npx 安裝（通用方式，支援大多數 Agent）

```bash
npx skills add tw93/Waza -a claude-code codex cursor antigravity-cli -g -y
```

這個指令會將 8 項技能統一安裝到 `~/.agents/skills` 目錄，這是 agents.md 標準指定的共享技能目錄。Claude Code 會自動建立符號連結，其他閱讀該目錄的 Agent（如 Codex、Cursor、Kimi Code CLI、Amp、Cline、Antigravity CLI）也會自動識別 Waza 的存在，無需額外設定。

更新指令：

```bash
npx skills update -g -y
```

### 個別 Agent 的原生安裝方式

**Claude Code 插件市場**：

```
/plugin marketplace add tw93/Waza
/plugin install waza@waza
```

**Codex 插件市場**：

```
codex plugin marketplace add tw93/Waza
codex plugin add waza@waza
```

**Claude Desktop**：下載最新發布的 [waza.zip](https://github.com/tw93/Waza/releases/latest/download/waza.zip)，然後 Customize > Skills > "+" > Create skill，直接上傳 ZIP 檔案。

**Pi 套件管理**：

```bash
pi install npm:@tw93/waza
```

### 卸載

```bash
npx skills remove tw93/Waza -g
rm -f ~/.claude/statusline.sh
rm -f ~/.claude/rules/english.md
rm -f ~/.claude/rules/anti-patterns.md
rm -f ~/.claude/rules/waza-routing.md
```

## 三部曲：Kaku、Waza、Kami

Waza 並非孤立的工具，而是 Tw93 構建的「工程師 AI 工具家族」三部曲中的一員。理解這個家族有助於掌握 Waza 的定位。

### Kaku（書く，かく）—— 父親角色

Kaku 是 Tw93 基於 WezTerm 深度客製化打造的終端機，專為 AI coding 優化。它具備零配置的 JetBrains Mono 字體、根據 macOS 自動切換深淺色主題、內建 zsh 插件和 AI 面板。作為家族中的「父親」，Kaku 負責整個工作環境的基礎設施——一個快速、輕量、為 AI 協作打造的終端。

Kaku 的核心特點包括：比上游小 40% 的執行檔大小、80MB 資源用量（上游約 100MB）、瞬間啟動、以及優化的 shell 引導流程（從 200ms 降至 100ms）。

### Waza（技，わざ）—— 姐姐角色

Waza 是家族中的「姐姐」，將工程師的紀律與習慣轉化為 AI Agent 可執行的技能。她不生成內容，而是確保生成內容的流程是可靠的。八大技能對應了工程師在整個軟體生命週期中需要用到的八個核心工作環節，從規劃到發布、從偵錯到文件寫作，全部覆蓋。

Waza 的關鍵特點是：每項技能 finish 任務後就停下來，等待使用者決定下一步，技能之間的銜接完全由人來觸發，絕不自動串接。這種設計確保了人類始终掌控工作流程的走向。

### Kami（紙，かみ）—— 妹妹角色

Kami 是文件排版的專家。她的名字在日文中意為「紙」——最終成品的承載介面。AI 固然能生成文件，但缺少設計系統約束的輸出往往流於平淡——灰色的版面、沒有層次的排版、每次 session 結果不一致的版面佈局。

Kami 提供一套完整的版面約束系統，包括：暖色羊皮紙底色（#f5f4ed）搭配墨水藍（#1B365D）作為唯一強調色、八種文件模板（One-Pager、Long Doc、Letter、Portfolio、Resume、Slides、Equity Report、Changelog）以及 Landing Page 系統、八種內嵌 SVG 圖表類型，並支援英文、中文、日文和韓文四種語言。

## 五條核心觀點

經過完整的分析，以下是關於 Waza 的五條核心觀點：

**一、工程紀律是 AI Agent 最大的缺口。** 模型能生成複雜的程式碼，但缺乏結構約束時，執行結果往往飄忽不定。Waza 的解決思路不是給模型更多能力，而是給它一個更可靠的工作框架。

**二、技能不在多，在於有紀律。** 八項技能各自有明確的觸發時機與職責範圍，這種精簡設計讓 Waza 區別於市面上過度膨脹的 Agent 工具。每一項技能都經過 300 場以上實戰 sessions 的檢驗。

**三、Project-Aware 是差異化關鍵。** Waza 的技能在運行時讀取目標專案的公開上下文，讓通用的工程習慣轉化為符合特定專案需求的行動。這種動態適配能力遠比靜態的提示詞模板更有價值。

**四、三部曲的協作模式比單一工具更有力量。** Kaku 打造環境、Waza 約束流程、Kami 交付成品，三者各司其職，共同構成一個完整的 AI 工程師工作流。這種分層設計讓工具之間的關注點明確分離，避免了單一工具承載過多功能後的膨脹與腐敗。

**五、MIT 開源授權降低了使用門檻。** 作為一個完全開源的專案，Waza 的安裝、使用和修改都沒有商業授權的障礙。同時，透過共享的 `~/.agents/skills` 目錄標準，Waza 的技能可以跨多個 Agent 平台使用，為團隊提供了工具無關的工作流一致性。
