# 深度解析 Harness：AI Agent 的"攀巖繩索"——從攀巖隱喻到開源自主權

> 核心思想：**"Agent = Model + Harness"**——AI 模型是發動機，Harness 是讓發動機安全運轉並為你服務的外殼。Harness 不是模型的附庸，而是用戶真正應該擁有和掌控的層。它決定了 AI 如何行為、使用什麼工具、以什麼節奏工作，以及——最重要的是——用戶是否保有最終的控制權。

## 引言：被誤解的"Harness"

如果你長期浸潤在 AI 資訊圈，你大概已經聽過"Agent"這個詞無數次了。但"Agent Harness"呢？

恐怕多數人聽到這個詞的第一反應是：又一個行業黑話。

Earendil 團隊写了一篇異常清晰的文章 [What is a Harness?](https://earendil.com/posts/what-is-a-harness/)，目的就是給這個概念祛魅。他們的方法很聰明——**從攀巖安全帶說起**。這個隱喻不僅好懂，而且精準：因為安全帶的核心邏輯——"連接、保護、讓你能去做更危險的事"——恰好就是 Agent Harness 在 AI 世界裡做的事。

這篇文章將圍繞 Earendil 的原文，系統性地解析 Agent Harness 是什麼、怎麼工作、為什麼重要，以及開源社區正在如何把它變成用戶手中對抗 AI 實驗室權力集中的工具。

## 一、專案背景：誰寫了這篇文章

Earendil 是一個 AI 基礎設施團隊，旗下有多個與 Agent/Harness 相關的開源專案：

- **Pi** (`pi.dev`)：最小化的開源 Agent Harness，面向個人用戶，完全運行在本地筆電上
- **Lefos**：面向電子郵件場景的 Agent Harness，核心互動媒介是 Email
- **OpenClaw**：另一個流行的開源 Agent Harness，支援 iMessage、Email 等多種介面

這篇文章是 Earendil 團隊為 Pi 所寫的產品哲學闡述，同時也是一篇面向大眾的 AI Agent 科普文章——它假設讀者完全不了解 Agent Harness，用最直白的語言解釋了這個概念。

## 二、核心隱喻：攀巖安全帶

### 2.1 現實中的安全帶

Cambridge Dictionary 對 Harness 的定義是：

> **Noun.** 一套帶有綁帶和安全帶的設備，用於控制或固定一個人、動物或物體
> **Verb.** 控制某樣東西，通常是為了利用它的力量

當我們談論攀巖安全帶時，它的實際功能是：

1. **支撐與保護**——透過連接快扣和繩索，保護攀巖者免受墜落傷害、控制下降速度、引導攀登路線
2. **可掛載工具**——粉袋、岩釘工具、快扣掛環都可以掛在安全帶上
3. **可遷移**——換一座山、換一種攀登方式，安全帶本身可以帶走，只需調整掛在上面的裝備
4. **可個人化**——特技演員和樹藝師用不同的安全帶，同一個安全帶可以被調整成完全不同的用途

### 2.2 從物理世界到 AI 世界

Earendil 指出了兩種 Harnesses 之間的結構與功能對應關係：

| 攀巖安全帶 | Agent Harness |
|-----------|---------------|
| 連接身體與繩索 | 連接 AI 模型與工具、環境 |
| 保護攀巖者免受墜落 | 保護用戶免受 AI 錯誤決策的傷害 |
| 承載粉袋、工具 | 承載工具集（搜尋、程式碼、郵件等） |
| 可遷移、可個人化 | 跨模型、跨任務、可自訂 |
| 決定攀登節奏與路線 | 決定 Agent 行為節奏與執行路徑 |

這個隱喻的核心洞見在於：**安全帶不是攀巖者本身，但它是讓攀巖者能安全探索更高處的前提條件。** 同樣，Harness 不是 AI 模型本身，但它是讓 AI 模型能可靠為用戶服務的前提條件。

## 三、什麼是 Agent Harness（核心定義）

### 3.1 基本定義

> **Agent Harness 是一種軟體，它為 AI 模型提供一個運行環境。**

與大多數 AI 模型不同（你無法"擁有"一個 AI 模型），**你可以擁有自己的 Agent Harness**。這是 Harness 區別於模型本身最根本的特點。

用戶與 Harness 的互動方式多種多樣：
- 軟體工程師可以直接在終端裡使用 Pi
- OpenClaw 可以透過 iMessage、Chat App 或 Email 與用戶互動
- Lefos 主要透過 Email 運行

無論介面如何，Harness 一般做四件事：

```
┌─────────────────────────────────────────────────────┐
│                  Agent Harness                      │
│                                                     │
│  ┌─────────────┐  ┌─────────────┐                   │
│  │ System      │  │   Tools     │                   │
│  │ Prompt      │  │  (工具集)   │                   │
│  └─────────────┘  └─────────────┘                   │
│                                                     │
│  ┌─────────────┐  ┌─────────────┐                   │
│  │ Agentic     │  │ Translation │                   │
│  │ Loop        │  │ Layer       │                   │
│  │ (代理循環)  │  │ (翻譯層)   │                   │
│  └─────────────┘  └─────────────┘                   │
└─────────────────────────────────────────────────────┘
```

## 四、四大核心構成詳解

### 4.1 System Prompt（系統提示詞）

**類比**：新員工入職第一天拿到的操作手冊。

大多數 AI 模型在訓練過程中形成了一套內嵌的規則和指南——最著名的例子是 Claude Opus 4.5 那份被廣泛傳播的 [Soul Document](https://gist.github.com/Richard-Weiss/efe157692991535403bd7e7fb20b6695)，它向 AI 模型解釋"我是誰、我應該如何行動"。

Harness 中的 System Prompt 與此類似，但有兩個關鍵區別：

1. **它不是模型內部的東西**，而是注入到每次對話中的外部指令
2. **它更像工作手冊而非本能**——模型知道應該遵循這些指令，但這些指令不是模型"天生就會的"

System Prompt 的作用是**確保 AI 模型在特定 Harness 的語境下行為得當**。不同的 Harness 可以用完全不同的 System Prompt 讓同一個模型展現出截然不同的"性格"和能力側重。

**舉例**：OpenClaw 的 System Prompt 可能是"你是一個友好、有幫助的家庭助手"；Pi 的 System Prompt 則可能更極簡、更像一個乾淨的空白畫布讓用戶自己塑造。

### 4.2 Tools（工具集）

**定義**：Tools 是 Harness 提供給模型"調用"的一系列程式碼能力。

Harness 不僅描述工具有什麼功能，還提供工具本身的程式碼實現。常見工具包括：

| 工具類型 | 功能描述 |
|---------|---------|
| WebSearch | 讓模型搜尋網路獲取最新資訊 |
| WriteCode | 讓模型編寫並執行程式碼 |
| ComposeEmail | 讓模型撰寫並發送郵件 |
| FileSystem | 讓模型讀寫本地檔案 |
| Browser | 讓模型控制瀏覽器執行操作 |

**關鍵設計原則**：Harness 通常**不規定**模型何時以及如何使用工具。它只是：
1. 清晰地描述工具是什麼
2. 提供工具的可調用介面
3. 把"何時調用、調用哪個"的決定權完全交給 AI 模型本身

這是一個微妙但重要的設計選擇——它讓 Harness 成為**環境提供方**，而不是**決策者**。

### 4.3 Agentic Loop（代理循環）

這是 Harness 最核心的概念，也是理解 AI Agent 如何"真正工作"的關鍵。

#### 4.3.1 什麼是 Agentic Loop

Agentic Loop 是 AI 模型在 Harness 環境中**自主決策循環執行**的框架。模型不是一次性給出答案就結束，而是：

1. **理解請求**（理解用戶的 prompt）
2. **規劃行動**（決定需要調用什麼工具）
3. **執行工具**（實際調用工具）
4. **評估結果**（檢查工具返回的結果是否滿足需求）
5. **決定是否繼續**（如果結果不夠，繼續調用工具或換工具）
6. **產出最終結果**（滿意後調用最終交付工具）

#### 4.3.2 具體例子：學校排名調研

Earendil 給出了一個極具說明性的例子——讓 Agent 比較本地小學的排名和考試成績並給出建議。

假設 Harness 內置了三個工具：WebSearch、WriteCode、ComposeEmail，互動媒介是 Email。用戶發郵件說："幫我比較 A 片區和 B 片區的實驗小學排名和考試分數，給出選校建議。"

Agent 的工作流程如下：

```
第1步：理解請求
────────────────
模型理解"實驗小學"、"A片區/B片區"、"排名和考試分數"這些概念

第2步：搜尋資訊
────────────────
模型構造搜尋查詢，從網路上抓取最新的學校排名和考試資料
　↓
第3步：評估搜尋結果
────────────────
模型在 Harness 環境中review搜尋結果
發現資料不夠完整或不相關
→ 自主決定再次搜尋

第4步：資料分析
────────────────
模型調用 WriteCode 工具（寫程式碼）
生成電子表格，處理資料，格式化結果
　↓
第5步：評估中間結果
────────────────
將電子表格與原始請求對比
如果資料仍不滿足，繼續搜尋或修正分析
→ 必要時"循環"回第2步

第6步：撰寫報告
────────────────
模型調用 ComposeEmail 工具
將建議寫入郵件正文，附上電子表格附件
　↓
第7步：最終確認
────────────────
模型review自己寫好的郵件和附件
確認無誤後發送

第8步：用戶收到郵件
────────────────
幾秒內，用戶收到一封包含建議摘要的郵件
正文是分析結論，附件是詳細的電子表格
```

這就是一個完整的 Agentic Loop——模型在 Harness 環境中**自主循環、直到自我判斷任務完成**。

#### 4.3.3 Loop 的意義

Agentic Loop 的存在意味著：**AI Agent 不是"問答機"，而是"任務執行者"**。它會：
- 自主判斷是否需要更多資訊
- 自主選擇使用哪個工具
- 自主決定何時迭代、何時收尾

這與傳統 AI 對話（你問一句我答一句）有本質區別。Agentic Loop 讓 AI 可以完成複雜的多步驟任務，而不僅僅是回答問題。

### 4.4 Translation Layer（翻譯層）

#### 4.4.1 什麼是翻譯層

Translation Layer（翻譯層）是讓 Harness 能夠與**不同 AI 模型**配合工作的關鍵元件。

它負責：
1. 將 Harness 的標準介面翻譯成特定模型的 API 格式
2. 將特定模型的輸出翻譯回 Harness 的標準格式
3. 允許在同一個 Agentic Loop 中根據任務需求**動態切換不同模型**

#### 4.4.2 為什麼翻譯層如此重要

**權力轉移**：翻譯層是把力量從 AI 實驗室轉移到終端用戶手裡的關鍵機制。

如果沒有翻譯層：
- 你用 Anthropic 的應用，就只能用 Claude
- 你用 OpenAI 的應用，就只能用 GPT
- 你是 AI 實驗室的"用戶"，不是真正的主人

有了翻譯層：
- 你可以把自己的 Harness 接到 Anthropic、OpenAI 或任何開源模型上
- 你可以在同一個任務裡讓 Claude 處理推理、GPT 處理生成、開源模型處理簡單任務
- 你可以用不同模型的結果對比成本和效果

**用戶主權的實現路徑**：翻譯層意味著用戶可以選擇"用哪個模型"，而不是被綁定在某個 AI 實驗室的應用裡。Harness 是用戶擁有的，模型是從外部調用的——這個主從關係是 Harness 哲學的核心。

#### 4.4.3 一個具體場景

回到前面的學校調研例子。用戶可以讓同一個 Harness：
- 同時向 OpenAI 模型、Anthropic 模型、開源模型發送同樣的請求
- 收到三個不同的回覆
- 在同一個郵箱裡比較三個版本的結果、成本和質量
- 而不是分別打開三個 App，分別登入，分別保存記錄

這正是 Harness 帶來的自由：**工具和資料屬於你，選擇權屬於你**。

## 五、開源與用戶自主權：Harness 的政治學

### 5.1 為什麼 Harness 必須是開源的

Earendil 指出了 AI 基礎設施的一個關鍵矛盾：

> 第一個流行的 Agent Harness 是 Claude Code，但它並不是為了提供"模型無關的翻譯層"而設計的——它是為了讓你在自己的電腦上用 Claude 模型寫程式碼而構建的一個應用程式。

Claude Code 的問題是：它把用戶綁定在了 Claude 模型和 Anthropic 的生態裡。你無法輕易換模型，無法輕易把工作遷移到其他 Harness。

真正讓 Harness 發揮"用戶自主權"價值的前提是：**開源 + 中立**。

### 5.2 Pi 的實踐：讓用戶真正"擁有"自己的 Harness

Earendil 在文章中詳細描述了 Pi 的設計哲學：

- **最小化**：Pi 的 System Prompt 非常短，工具集非常精簡，開箱即用、盡量不擋路
- **可擴展**：用戶可以修改 System Prompt、設計擴展包（Extensions）、調整工具集
- **社群共建**：Pi 用戶已經共享了超過 **5,000 個擴展包**
- **完全本地**：Pi 運行在你自己的筆電上，不依賴任何雲端服務
- **開源**：用戶可以審查程式碼、修改程式碼、重新分發程式碼

這意味著：
- Pi 是一個用戶**擁有**的工具，不是一個用戶**租用**的服務
- 用戶的"AI 能力"不依賴於某個公司的商業決策
- 用戶的所有對話歷史都保存在本地，不在 AI 實驗室的伺服器上

### 5.3 更大的圖景：對抗 AI 權力的工具

Earendil 在文章結尾說出了更深層的願景：

> 許多人對越來越大、越來越強勢的 AI 公司感到擔憂。一些人可能會選擇完全回避 AI。
>
> 我們 Earendil 相信，我們可以**透過精心製作軟體和開放協定來增強人類的主體性**，跨越分歧和無知，培養持久的快樂和理解。
>
> 我們不會透過忽視今天存在的技術來實現這一點，而是**以清醒的頭腦和堅定的掌控來駕馭它們**：確保我們揮舞錘子，而不是錘子揮舞我們。

這段話的潛台詞是：**與其放棄 AI，不如掌握 AI 的韁繩**。Harness 就是那根韁繩。

## 六、設計哲學：Harness 作為用戶自主權的載體

綜合 Earendil 的原文和 Pi 專案的實踐，Harness 的設計哲學可以歸納為以下幾個核心原則：

### 6.1 工具中立（Tool Agnosticism）

好的 Harness 應該對模型保持中立。用戶選擇用哪個模型是用戶的權利，Harness 應該提供這個選擇，而不是替用戶做決定。Pi 支援 OpenAI、Anthropic 以及各種開源模型的接入，正是這一原則的體現。

### 6.2 用戶主權（User Sovereignty）

用戶應該擁有並控制自己的 Harness，而不是租用 AI 實驗室提供的服務。這意味著：
- 本地運行，資料不離開用戶設備
- 開源程式碼，用戶可審查、可修改
- 會話記錄保存在用戶本地，而非雲端

### 6.3 開放擴展（Open Extensibility）

Harness 的工具集和系統提示詞應該可以被用戶自由擴展。Pi 的 5,000+ 擴展包證明了：當用戶被允許擴展工具時，生態的豐富程度遠超平台方的預期。

### 6.4 人在回路（Human in the Loop）

雖然 Agentic Loop 允許模型自主循環，但 Harness 設計應該始終保證**人在回路**：
- 模型的所有工具調用都在用戶可見的上下文裡發生
- 用戶可以隨時干預、修改或終止 Agent 的行為
- 最終交付物（郵件、檔案、程式碼）由用戶決定是否使用

### 6.5 最小化默認（Minimal Default）

Pi 的 System Prompt 非常短，工具集非常精簡。這是一種**有意識的克制**：預設配置越少，用戶重新塑造的空間越大。"少即是多"在 Harness 設計中不是美學選擇，而是哲學選擇。

## 七、觀點總結與啟示

### 觀點 1：Harness 是 AI Agent 的"操作系統層"

模型是計算資源，Harness 是調度和使用這些資源的操作系統類元件。就像 Linux 不關心你跑什麼應用（只要你遵循介面），好的 Harness 不關心你用什麼模型（只要你透過 Translation Layer 接入）。

### 觀點 2：用戶應該擁有"工作台"而不是"工具"

當前大多數 AI 產品（Claude App、ChatGPT、Cursor）本質上是**應用**——用戶在使用 AI 實驗室構建的產品。Harness 的理念是：用戶應該擁有自己的**工作台**，工作台上面跑什麼模型是可選的。應用會過時，工作台永遠是你的。

### 觀點 3：開放協定 > 封閉平台

如果每個 AI 實驗室都只提供自己的封閉 Agent，用戶就會被鎖定。開源、中立、可互操作的 Harness 協定，是防止 AI 權力集中的技術基礎。Earendil、OpenClaw、OpenCode 等專案正在建立這種開放協定的基礎設施。

### 觀點 4：Agentic Loop 是 AI 從"回答問題"到"完成任務"的分水嶺

傳統 AI 對話的局限在於"你問一句我答一句"。Agentic Loop 讓 AI 能夠自主規劃、自主迭代、自主交付——這是 AI 從"智慧問答引擎"到"自主代理"的核心跨越。

### 觀點 5：本地優先是用戶資料主權的唯一可靠保障

雲端儲存的 AI 會話記錄在商業上不可持續（AI 實驗室可以隨時存取、刪除或變現），在政治上不可靠（取決於公司政策和國家法規）。純文字檔案的本地儲存，是用戶對 AI 會話擁有完整主權的唯一技術基礎。

### 觀點 6：翻譯層的競爭將決定 AI 生態的權力格局

誰控制了翻譯層，誰就控制了用戶的選擇權。如果翻譯層是開源的、中立的，權力在用戶手裡；如果翻譯層是閉源的、商業的，權力在平台手裡。這是一個尚未被廣泛認識的戰略高地。

### 觀點 7：開源社區是 AI 民主化的希望

Claude Code 開啟了 Agent Harness 的時代，但它選擇了封閉和綁定。Pi、OpenClaw、OpenCode 等開源專案正在重新把這個權力還給用戶。5,000+ 擴展包的社群生態證明：**當用戶被賦予真正的控制權，他們能做的事情遠超平台方的想像。**

## 九、結語：握住韁繩

Earendil 在文章結尾寫道：

> 我們不會透過忽視今天存在的技術來實現（增強人類主體性），而是透過**以清醒的頭腦和堅定的掌控來駕馭它們**：確保我們揮舞錘子，而不是錘子揮舞我們。

這句話值得每個 AI 時代的參與者認真思考。

我們正在快速進入一個 AI 無處不在的世界。在這個世界裡，有兩種選擇：

1. **成為 AI 的用戶**——在 AI 實驗室建造的應用裡租用自己的"AI 能力"，接受鎖定、資料被收集、選擇權被剝奪
2. **成為 AI 的駕馭者**——擁有自己的 Harness，掌控自己的工具和資料，以清醒的頭腦決定何時、如何使用 AI

Harness 就是那根韁繩。它不是 AI 本身，但它決定了誰能控制 AI、如何控制 AI、為誰服務。

握住它。
