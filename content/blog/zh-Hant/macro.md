# Macro：統一團隊工作空間——融合所有工作工具的 All-in-One 平台

## 項目背景與核心問題

### 現代團隊的工具碎片化困境

在當今的軟件開發團隊中，我們每天需要在多個工具之間切換：

| 工具類型 | 常用軟件 | 問題 |
|---------|---------|------|
| 郵件 | Gmail、Outlook | 與聊天文檔割裂 |
| 即時通訊 | Slack、Discord | 歷史記錄難搜索 |
| 文檔 | Notion、Confluence | 與任務/郵件無鏈接 |
| 任務管理 | Linear、Jira | 與上下文分離 |
| CRM | Salesforce、HubSpot | 與日常工作割裂 |
| AI 助手 | ChatGPT、Claude | 缺乏團隊上下文 |

**核心矛盾**：每個工具單獨來看都很優秀，但組合在一起時，卻形成了信息孤島。

### Macro 的誕生

Macro 團隊在經歷多年的工具碎片化之苦後，做出了一個大膽的決定：

> **「讓我們從零開始，重新設計整個工作軟件，使其成為一個統一的系統。」**

這就是 Macro —— 一個將郵件、聊天、文檔、任務、AI 代理、電話和 CRM 融為一體的統一工作空間，擁有共享的團隊級記憶。

Macro 是一個 **All-in-One 團隊工作空間**，它的核心特點是：

```
┌─────────────────────────────────────────────────────────────────┐
│                         Macro 工作空間                            │
├─────────────────────────────────────────────────────────────────┤
│    📧 郵件     💬 聊天     📝 文檔     📋 任務                   │
│       │              │             │              │              │
│       └──────────────┴─────────────┴──────────────┘              │
│                         │                                        │
│                 ┌───────┴───────┐                               │
│                 │  雙向 @ 鏈接    │                               │
│                 │     圖譜        │                               │
│                 └───────┬───────┘                               │
│                         │                                        │
│         ┌───────────────┼───────────────┐                       │

└─────────────────────────────────────────────────────────────────┘
```

## 技術架構深度解析

### 技術棧選擇

Macro 在技術選型上做了一個非常規的決定：使用 **SolidJS + Rust**。

```
Macro 技術架構：

前端 (SolidJS)                      後端 (Rust)
┌────────────────────────┐         ┌────────────────────────┐
│ apps/web (瀏覽器)      │◄────────►│ 42 個微服務              │
│ apps/web (Tauri)       │  HTTP   │ - 郵件、聊天、文檔        │
│ apps/web (移動端)       │  gRPC   │ - 任務、AI、CRM          │
│ apps/docs              │         │ - 電話、workers          │
└────────────────────────┘         └────────────────────────┘
                                                 │
                            ┌────────────────────┴────────────────────┐
                            │         167 個 Rust Crates                 │
                            └─────────────────────────────────────────────┘
```

### 倉庫結構

```
macro/
├── apps/              # SolidJS 應用程序
│   ├── web/          # 主 Web 應用
│   └── docs/         # 文檔網站
├── services/          # 42 個可部署微服務
├── crates/           # 167 個 Rust 庫
├── packages/         # 共享 TypeScript
├── infra/            # Pulumi 基礎設施
└── docker/           # 本地開發 Compose 棧
```

## 核心功能詳解

### 1. 郵件系統：統一而非割裂

Macro 的郵件系統不僅僅是另一個 Gmail 客戶端 —— 它是**郵件與工作流程的深度集成**。

```javascript
// Macro 的郵件快捷鍵
const shortcuts = {
  'j': '下一封郵件',
  'k': '上一封郵件',
  'o': '打開郵件',
  'c t': '從郵件創建任務',  // 關鍵快捷鍵！
};
```

#### 從郵件創建任務

```
1. 查看郵件
2. 按下 'c t' 創建任務
3. 任務自動鏈接回郵件
   📧 ←→ 📋 雙向鏈接！
```

### 2. 團隊聊天：專注而非干擾

Macro 的聊天系統專為技術團隊設計，解決 Slack 的信息過載問題。

```
Slack 問題：              Macro 解決方案：
─────────────           ─────────────────
線程無限延伸              折疊顯示，僅顯示首回覆
錯過重要討論              頻道 = 主題，首回覆 = 摘要
跨頻道信息碎片化          統一搜索 + @link
```

### 3. 文檔系統：實時協作 + 離線支持

Macro 的文檔系統採用 **CRDT** 實現真正的實時協作。

### 4. AI 代理系統：團隊級記憶

這是 Macro 最具差異化的特性 —— **AI 代理擁有團隊級記憶**。

```
AI 代理架構：

                    ┌─────────────────┐
                    │   團隊記憶       │
                    │  (每夜更新)      │
                    └────────┬────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────┐
│                    AI 代理層                             │
│      OpenAI GPT-4 │ Google Gemini │ Anthropic Claude    │
└─────────────────────────────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────┐
│                    MCP 工具接口                           │
│   郵件 │ 聊天 │ 任務 │ 文檔 │ 聯繫人 │ 團隊記憶          │
└─────────────────────────────────────────────────────────┘
```

## 設計哲學深度解析

### 哲學一：雙向 @ 鏈接 = 雙向可達性

```
傳統工具的問題：
  Notion: 文檔A引用文檔B
  → 文檔B不知道自己被引用了
  → 僅單向鏈接

Macro 的解決方案：
  📧 郵件 ←──── @link ────→ 📋 任務
       │                          │
       │      雙向可追溯           │
       └────────── @link ─────────┘
```

### 哲學二：頻道即權限

```
傳統方式：
  創建文檔 → 設置權限
  發送郵件 → 選擇收件人
  Macro 方式：
  在頻道中分享內容 → 頻道成員自動獲得訪問權限
```

### 哲學三：統一收件箱 = 不遺漏重要信息

```
Macro 統一收件箱哲學：

┌───────────────────────────────────────┐
│            統一收件箱                   │
├───────────────┬───────────────────────┤
│     📢 信號    │       🔔 噪音         │
├───────────────┼───────────────────────┤
│ • @提及你的    │ • 新聞通訊             │
│ • 私信        │ • 系統通知             │
│ • 任務分配給你 │ • 頻道動態             │
└───────────────┴───────────────────────┘
```

### 哲學四：AI 是團隊的記憶，而非獨立工具

```
傳統 AI 問題：
  昨天問 ChatGPT 什麼？
  → 每次都是新對話，無記憶

Macro AI：
  我們團隊上週討論了什麼？
  → 記憶是團隊的，可追溯
```

## 快速上手教程

### 方式一：使用托管版本

**步驟 1：註冊帳號**

1. 訪問 [macro.com/app](https://macro.com/app)
2. 使用 Google 帳號登錄或郵箱註冊
3. 連接 Gmail 或 Google Workspace

**步驟 2：連接 Gmail**

```
連接 Gmail 帳戶：

1. 點擊左側邊欄「設置」
2. 選擇「郵件帳戶」
3. 點擊「添加帳戶」
4. 選擇 Gmail 或 Google Workspace
5. 授權 Macro 訪問 Gmail
6. 選擇要同步的標籤/文件夾
```

### 方式二：本地開發部署

```bash
git clone https://github.com/macro-inc/macro
cd macro

# 複製環境變量模板
cp .env.example .env

# 啟動基礎設施
docker compose up -d

# 安裝前端依賴
cd apps/web && npm install

# 啟動開發伺服器
npm run dev
```

**本地訪問：**
- 前端應用: http://localhost:3000
- API 服務: http://localhost:4000

## 核心觀點與總結

### 核心觀點

1. **All-in-One 工具是未來趨勢** — 分散的工具意味著分散的注意力。Macro 的設計哲學正是解決這個問題的。
2. **雙向鏈接是信息的生命線** — 真正的鏈接應該是雙向的，從任何地方都可以追溯到原始上下文。
3. **AI 應該成為團隊的記憶** — 團隊級記憶讓 AI 能夠跨時間記住團隊的所有工作。
4. **開源是最好的護城河** — AGPLv3 意味著任何人都可以查看、修改和自托管。

## 設計哲學總結

### 1. 統一優於集成

```
集成模式需要 Zapier/Make 連接
→ 延遲、維護成本、數據不一致

統一模式 (Macro)：
所有模塊 → 共享數據庫 → 天然一致
```

### 2. 上下文比功能更重要

```
傳統工具優先級：          Macro 優先級：
1. 功能是否完整？         1. 能否追溯上下文？
2. 性能是否良好？         2. 信息是否互聯？
3. UI 是否美觀？          3. 功能是否服務於上下文？
```

### 3. AI 是記憶，不是工具

```
個人 AI：                 團隊 AI (Macro)：
每次對話獨立              記憶是團隊的，可追溯
```

### 4. 權限隨內容流動

```
傳統：創建內容 → 設置權限 → 分發
Macro：在頻道中分享 → 成員自動獲得訪問
```

### 5. 開源是信任的基石

```
專有軟件問題：            開源 (AGPLv3) 解決方案：
無法驗證代碼安全性         代碼完全透明
擔心供應商鎖定           可以自托管
無法自行修復 bug          社區驅動改進
```

## 結語

Macro 代表了工作工具發展的一個重要方向：**從工具的集合到統一的系統**。它的雙向 @ 鏈接、團隊級 AI 記憶、統一的郵件/聊天/文檔/任務/CRM 工作空間，都指向同一個目標 —— **讓團隊的工作保持上下文連接，而不是形成信息孤島**。

在工具爆炸的時代，Macro 的出現提醒我們：**也許我們不需要更多更好的工具，而是需要一個能夠將所有工具統一起來的系統**。

開源的 AGPLv3 許可意味著 Macro 不會成為供應商鎖定的工具，而是真正屬於團隊的工具。
